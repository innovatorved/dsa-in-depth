√N Block Decomposition & Mo's Offline Query Ordering (O((N+Q)√N)) · Sqrt Block Decomposition: O(√N) query; Mo's Offline Algorithm: O((N + Q) √N) Trees · Module 3.3

Balancing block size B = √N for non-associative updates, and Mo's Hilbert/snake block sorting to bound pointer movements across Q range queries. Core Invariant: Mo's algorithm sorts offline queries `[L, R]` by `(⌊L / B⌋, R)` with block size `B = N / √Q` (alternating R direction on odd blocks), bounding total L moves to Q·B and R moves to (N/B)·N. Hardware & Production Note: Hilbert-curve query ordering further reduces pointer movement distance by ~30% on skewed query distributions.

0-1 BFS (Double-Ended Queue Shortest Path) · O(V + E) time, O(V) space Graph Theory · Module 5.1

Breadth-First Search variant on graphs with edge weights in {0, 1}. Relaxing a weight-0 edge pushes to the front of the deque while a weight-1 edge pushes to the back, maintaining the two-distance queue invariant without a priority queue.

1D/2D Prefix Sums & Difference Arrays for O(1) Range Updates · 1D/2D Range Sum: O(N) build, O(1) query; Difference Array: O(1) range add, O(N) reconstruction Foundations · Module 1.2

Duality between prefix accumulation and discrete differentiation for O(1) static range queries and batch range additions. Core Invariant: Prefix sum P[i] = ∑_{k<i} A[k] and Difference array D[i] = A[i] - A[i-1] are discrete calculus duals (integration vs differentiation): D[L] += v, D[R+1] -= v applies a step function. Hardware & Production Note: 2D inclusion-exclusion P[r2][c2] - P[r1][c2] - P[r2][c1] + P[r1][c1] executes in 4 L1-cached array reads.

2-3-4 Tree (B-Tree of Order 4) · O(log N) search/insert/delete Trees · Module 3.2

Perfectly balanced search tree where each internal node holds 1, 2, or 3 keys (2, 3, or 4 children) and all leaves reside at the exact same depth. Isomorphic to Red-Black and Left-Leaning Red-Black (LLRB) trees.

2-3-4 Trees, Red-Black Trees & Sedgewick's Left-Leaning Red-Black (LLRB) Isomorphism · Search/Insert/Delete: O(log N) worst-case; Height ≤ 2 log2(N + 1); Insert rotations: ≤ 2 Trees · Module 3.2

Mapping 2-3-4 B-tree nodes to red-black edges, proving height ≤ 2 log2(N+1), and reducing implementation to 3 lines of rotateLeft/rotateRight/flipColors. Core Invariant: Sedgewick's LLRB maps 2-3-4 nodes to BST nodes with red left-leaning glue links: (1) red links lean left, (2) no node has two red links, (3) every path has equal black height. Hardware & Production Note: Insertion rebalancing reduces to three local bottom-up rules: `if (isRed(R) && !isRed(L)) rotateLeft`, `if (isRed(L) && isRed(L.L)) rotateRight`, `if (isRed(L) && isRed(R)) flipColors`.

2-SAT (Boolean Two-Satisfiability) · O(V + E) linear time via Tarjan/Kosaraju SCC Graph Theory · Module 5.1

Constraint satisfaction problem over clauses of the form (a ∨ b). Reduced to a directed implication graph with 2N literals where each clause adds edges (¬a → b) and (¬b → a); satisfiable iff no variable x shares a Strongly Connected Component with ¬x.

2D Convex Hull: Graham Scan vs Andrew's Monotone Chain & Rotating Calipers · Andrew's Monotone Chain: O(N log N) sort + O(N) stack scan; Rotating Calipers diameter: O(H) Dynamic Programming · Module 6.4

Constructing lower and upper convex hulls without trigonometric atan2 via Andrew's lexicographic sort, and finding farthest point pairs in O(N) via Rotating Calipers. Core Invariant: Sorts points lexicographically by `(x, y)` and builds lower and upper hulls by popping the last two hull vertices whenever `cross(H[m-2], H[m-1], P[i]) ≤ 0` (right turn or collinear). Hardware & Production Note: Rotating Calipers advances antipodal pointers around the convex hull in O(H) without ever computing square roots (compares squared distances `dx^2 + dy^2`).

3-Way Partitioning (Dutch National Flag) · O(N) time, O(1) auxiliary space Hashing · Module 2.2

Dijkstra's single-pass partitioning algorithm that divides an array into three regions: [< pivot], [== pivot], and [> pivot] using pointers lo, mid, and hi. Eliminates the O(N^2) duplicate-key pathology in Quicksort.

A* Search & Bidirectional A*: Admissibility, Consistency (Triangle Inequality) & Optimality Proof · Priority `f(u) = g(u) + h(u)`; Optimal on first target pop if `h` is consistent Graph Theory · Module 5.2

Potential-reweighted Dijkstra view of A*: why admissibility (h(u) ≤ d*(u,t)) guarantees optimality and consistency (h(u) ≤ w(u,v) + h(v)) prevents re-expansions. Core Invariant: Admissibility (`h(u) ≤ d*(u, t)`) guarantees optimality; Consistency (`h(u) ≤ w(u, v) + h(v)`) is equivalent to Dijkstra on non-negative reduced weights `w_h(u, v) = w(u, v) - h(u) + h(v) ≥ 0`. Hardware & Production Note: Bidirectional Dijkstra/A* must stop only when `topKey(pqF) + topKey(pqB) ≥ bestMu`, NOT on the first node intersection.

Active Point (Ukkonen Suffix Tree) · O(1) amortized transition via suffix links Strings · Module 4.2

Triple (activeNode, activeEdge, activeLength) maintained during Ukkonen's online suffix tree construction that tracks the locus of the longest repeating suffix of the current prefix.

Adaptive Radix Tree (ART) · O(k) key length lookup, <52 bytes/key overhead Strings · Module 4.1

Memory-conscious radix tree that dynamically switches internal node representations between 4, 16 (SIMD-searched), 48, and 256 child pointers based on actual branching factor.

Admissible Heuristic (A* Search) · Optimality condition for A* Graph Theory · Module 5.2

Heuristic function h(u) that never overestimates the true shortest-path distance d*(u, t) to the goal (0 ≤ h(u) ≤ d*(u, t)). Guarantees A* finds an optimal path when the goal is popped.

Aho-Corasick Automaton: Trie + BFS Failure Links + Dictionary Suffix Links · Build Trie + BFS Failure Links: O(∑ |P_i| · |Σ|); Scan Text: O(|T| + #matches) Strings · Module 4.1

Generalizing KMP to a set of patterns: BFS failure link construction, output link compression to avoid O(N^2) empty-match traversals, and DFA completion. Core Invariant: Failure link `fail[u]` points to the longest proper suffix of string `u` that is also a prefix in the Trie; dictionary/output link `exit[u]` skips directly to the nearest terminal suffix. Hardware & Production Note: Converting `next[u][c]` into a complete DFA array during BFS (`u.next[c] = u.next[c] || fail[u].next[c]`) turns scanning into a single array lookup per byte.

Algebraic Divide-and-Conquer: Karatsuba Multiplication & Strassen's Matrix Product · Karatsuba: Θ(N^(log2 3)) ≈ O(N^1.585); Strassen: Θ(N^(log2 7)) ≈ O(N^2.807) Hashing · Module 2.3

Trading expensive multiplications for additions to reduce big-integer multiplication to O(N^1.585) and matrix multiplication to O(N^2.807). Core Invariant: Karatsuba computes `(a1·B + a0)(b1·B + b0)` using 3 half-size multiplications `z2 = a1·b1`, `z0 = a0·b0`, `z1 = (a1+a0)(b1+b0) - z2 - z0` instead of 4. Hardware & Production Note: Crosses over to schoolbook O(N^2) below ~32–64 limb words due to addition and temporary buffer overhead.

Algorithmic Complexity Attacks (HashDoS) & SipHash Defense · Unkeyed polynomial hash attack: O(N^2) CPU DoS; SipHash-1-3/2-4: O(|key|) with 128-bit secret seed Hashing · Module 2.1

How attackers craft colliding payloads to degrade O(1) hash maps into O(N^2) CPU denial-of-service, and how keyed PRFs (SipHash) prevent it. Core Invariant: Deterministic non-cryptographic hashes (DJB2, Murmur, FNV) allow attackers to precompute 10^5 colliding strings; per-process random seeds + SipHash ARX rounds make collisions computationally infeasible. Hardware & Production Note: SipHash uses Add-Rotate-XOR (ARX) word operations without lookup tables, running in ~1.2 cycles/byte.

Algorithmic Number Theory: Extended Euclidean Algorithm, Modular Inverse, CRT & Sieve of Eratosthenes · Extended GCD / Modular Inverse: O(log(min(a, b))); Linear Prime Sieve: Θ(N) Dynamic Programming · Module 6.4

Bézout coefficients ax + by = gcd(a,b), Fermat vs Extended GCD modular inverses, Garner's Chinese Remainder reconstruction, and O(N) linear prime sieve. Core Invariant: Extended Euclidean algorithm finds Bézout coefficients `a·x + b·y = gcd(a, b)`; when `gcd(a, m) == 1`, `x mod m` is `a^-1 mod m`. Linear sieve crosses out each composite `i · p` exactly once by its smallest prime factor `spf[n]`. Hardware & Production Note: Binary GCD (Stein's algorithm) replaces slow CPU `DIV` instructions with hardware trailing-zero counts (`ctz`) and bitshifts.

Aliens Trick (WQS Binary Search / Lagrangian Relaxation): Removing Cardinality Constraints · Reduces constrained O(N · K) DP to O(N · log(PenaltyRange)) via Lagrangian relaxation Dynamic Programming · Module 6.3

Eliminating the 'choose at most K items' DP dimension on convex/concave objectives by binary searching a per-item penalty λ. Core Invariant: When objective `f(k)` is convex/concave in item count `k`, binary search a per-item penalty `λ` and solve unconstrained `g(λ) = min_x (Cost(x) - λ · count(x))` until `count*(λ) == K`. Hardware & Production Note: Reconstructs the exact constrained optimum as `f(K) = g(λ*) + λ* · K` even when multiple collinear points lie on the convex hull.

All-Pairs Shortest Paths: Floyd-Warshall DP Transitive Closure & Johnson's Potential Reweighting · Floyd-Warshall: Θ(V^3) time, Θ(V^2) space; Johnson APSP: O(V E log V) Graph Theory · Module 5.2

Intermediate vertex set {1..k} DP state compression in O(V^3) vs Johnson's Bellman-Ford potential shift w'(u,v) = w(u,v) + h(u) - h(v) ≥ 0 for O(VE log V). Core Invariant: Floyd-Warshall DP `d[k][i][j] = min(d[k-1][i][j], d[k-1][i][k] + d[k-1][k][j])` requires `k` as the outermost loop; Johnson reweights edges via Bellman-Ford potentials `h(u)` so `w' ≥ 0` and runs V Dijkstras. Hardware & Production Note: Floyd-Warshall's tight `i-k-j` inner loop auto-vectorizes with AVX2 SIMD instructions, beating Johnson on graphs with `E > 10·V`.

Alpha-Beta Pruning · O(b^(d/2)) with optimal move ordering Dynamic Programming · Module 6.1

Minimax game-tree search optimization maintaining [α, β] score bounds for the maximizing and minimizing players; prunes any branch where α ≥ β since the opponent will avoid it.

Amortized Analysis: Aggregate, Banker's & Physicist's Potential (Φ) · ĉ_i = c_i + Φ(D_i) - Φ(D_{i-1}); Σ c_i = Σ ĉ_i - Φ(D_n) + Φ(D_0) Foundations · Module 1.1

Proving worst-case sequence bounds without probability using aggregate counting, accounting credits, and Tarjan's potential function Φ. Core Invariant: Tarjan potential Φ(D_i) ≥ Φ(D_0) ≥ 0 guarantees total actual cost Σ c_i never exceeds total amortized cost Σ ĉ_i across any worst-case operation sequence. Hardware & Production Note: Distinguishes deterministic worst-case sequence bounds (e.g., Splay trees, dynamic arrays) from average-case probabilistic expectations.

Amortized Potential Function (Φ) · Σ c_i ≤ Σ ĉ_i Foundations · Module 1.1

Undirected Connectivity: Tarjan's tin/low Algorithm for Bridges, Cut Vertices & BCCs · Time: Θ(V + E) single DFS pass; Space: Θ(V) Graph Theory · Module 5.1

Computing low[u] back-edge reachability to identify critical single points of failure (low[v] > tin[u] for bridges, low[v] ≥ tin[u] for cut vertices) in O(V+E). Core Invariant: `low[u]` is the minimum `tin` reachable from `u`'s DFS subtree using at most 1 back edge; tree edge `(u, v)` is a Bridge iff `low[v] > tin[u]`, and non-root `u` is a Cut Vertex iff `low[v] ≥ tin[u]`. Hardware & Production Note: Edge-biconnected components are extracted in the same pass by popping an edge stack whenever `low[v] > tin[u]`.

Storing cache-line-sized arrays inside list nodes and gap buffers to achieve O(1) localized edits without pointer overhead. Core Invariant: Packing B = 16–64 elements per linked node amortizes next/prev pointer overhead across an entire CPU cache line and eliminates 95% of pointer-chasing cache misses. Hardware & Production Note: Text editors use Gap Buffers (for single-cursor local edits) or Ropes/Piece Tables (for multi-megabyte files with O(log N) copy-on-write edits).
