Thompson Lockstep NFA Regular Expression Engine (Zero Backtracking)

Why Backtracking Regex Engines Explode (ReDoS)

Recursive backtracking engines (like standard PCRE / JavaScript RegExp without linear-time mode) explore one path through the NFA at a time. On ambiguous patterns like (a+)+b against $\text{"a"}^{35}\text{"c"}$, backtracking tries $2^{35}$ ways to partition the $\text{a}$'s before failing.

Ken Thompson's 1968 Lockstep NFA Simulation

Ken Thompson's algorithm simulates all active NFA states simultaneously:

  1. Postfix Compilation: The regex is parsed into postfix notation and assembled into NFA fragments where every state has at most 2 outgoing edges (SPLIT epsilon branches or a single character transition). An expression of length $m$ produces at most $2m$ states.
  2. Generation-Stamped Deduplication: Instead of allocating a hash set at every character step, each NFAState stores an integer lastList. Incrementing this._listId at each character step gives $O(1)$ membership checks and guarantees $|\text{clist}| \le 2m$.
  3. Strict $O(m \cdot n)$ Time: Processing each of the $n$ characters inspects at most $2m$ states, making catastrophic backtracking mathematically impossible.
