Intuition first

Quicksort's speed—and its Achilles' heel—lives entirely inside its partitioning loop. Lomuto's single-direction scan performs $3\times$ more swaps than Hoare's bidirectional pointers and degrades to $\Theta(N^2)$ when all keys are equal; Hoare's crossing pointers stay balanced on duplicates by swapping equal keys; and Dijkstra / Bentley-McIlroy 3-way partitioning groups duplicates into a dead-center band that finishes in $O(N)$ linear time when key entropy is low.

Anatomy of the Three Partition Schemes

Given a subarray $A[lo \dots hi]$ and a chosen pivot value $v$, partitioning rearranges elements in-place so keys smaller than $v$ precede keys larger than $v$. Yet the choice of pointer invariant changes swap counts, branch predictability, and duplicate-key behavior dramatically:

Loop Invariants of Lomuto, Hoare, and Dijkstra 3-Way Partitioning
  • 1. Lomuto Partition (1-Way Scan): Pivot at $v = A[hi]$. Maintains index $i$ such that $A[lo \dots i-1] \le v$, $A[i \dots j-1] > v$, and $A[j \dots hi-1]$ is unexamined.
    Fatal Flaw: On random permutations, Lomuto executes $\frac{n}{2}$ swaps on average ($3\times$ more than Hoare's $\frac{n}{6}$). Worse, if all elements equal $v$, the test A[j] <= v triggers a swap on every single element and leaves the pivot at index $hi$, recurring on $n - 1$ elements in $\Theta(n^2)$ time!
  • 2. Hoare Partition (2-Way Crossing Pointers, 1961): Pivot $v = A[lo]$. Left pointer $i$ scans right stopping on $A[i] \ge v$; right pointer $j$ scans left stopping on $A[j] \le v$. Notice both pointers stop on elements equal to $v$!
    Why stopping on $== v$ is essential: If all keys equal $v$, every step performs one redundant swap, but $i$ and $j$ meet at the exact midpoint $\lfloor(lo+hi)/2\rfloor$, splitting the array into two equal halves in $\Theta(n \log n)$ time! Note also that Hoare's scheme does not place the pivot at its final index; it returns a split index $j$ guaranteeing $\max(A[lo \dots j]) \le \min(A[j+1 \dots hi])$, so recursive calls are sort(lo, j) and sort(j + 1, hi).
  • 3. Dijkstra 3-Way (Dutch National Flag) & Bentley-McIlroy: Maintains three pointers $lt, i, gt$ partitioning $A[lo \dots hi]$ into four regions: $$\underbrace{A[lo \dots lt-1]}_{< v} \;\Big|\; \underbrace{A[lt \dots i-1]}_{= v} \;\Big|\; \underbrace{A[i \dots gt]}_{\text{unexamined}} \;\Big|\; \underbrace{A[gt+1 \dots hi]}_{> v}$$ When $i > gt$, all duplicates $A[lt \dots gt] = v$ are permanently in their final sorted positions and excluded from both recursive calls!

Entropy-Optimal Sorting & Pivot Selection

Suppose an array of $n$ elements has $k$ distinct values occurring with frequencies $f_1, f_2, \dots, f_k$ and empirical probabilities $p_i = f_i / n$. The Shannon entropy of the multiset is $H = -\sum_{i=1}^k p_i \log_2 p_i \le \log_2 k$. Sedgewick and Bentley proved that 3-way Quicksort uses $O(n H + n)$ comparisons—matching the information-theoretic lower bound $\log_2\!\left(\frac{n!}{f_1! f_2! \cdots f_k!}\right) = n H - O(k \log n)$ up to a constant factor!

To prevent adversarial inputs (sorted, reverse-sorted, or "organ-pipe" arrays) from picking extreme pivots, production implementations use:

  • Median-of-Three ($n \le 128$): Median of $(A[lo], A[mid], A[hi])$, which also places sentinels at the ends.
  • Tukey's Ninther ($n > 128$): Median of three medians of three ($9$ samples), costing only $12$ comparisons while concentrating the pivot tightly around the true median and defeating killer inputs like McIlroy's "AntiQsort" adversary when combined with pattern randomization.

Hardware Reality: Branch Mispredictions & BlockQuicksort (Edelkamp & Weiß, 2016)

On a random array, the comparison A[i] < pivot inside Lomuto or Hoare partitioning has a $50\%$ probability of being true—the exact worst-case entropy for a CPU branch predictor! Every mispredicted branch flushes the 14–20 stage out-of-order pipeline, costing ~15 cycles (often $5\times$ slower than the comparison and L1 load combined). BlockQuicksort (used in Rust's pdqsort and modern C++ stdlibs) eliminates branches from partitioning by evaluating A[i] < pivot across a block of 64 elements, storing the matching offsets into two small 64-byte index buffers using branchless pointer increments (offsets[num++] = i where num += (A[i] < pivot)), and then performing a tight cyclic permutation of the mismatched pairs!

Production C++20 Implementation: Hoare, 3-Way & Tail-Call Bounded Quicksort

#include <algorithm>
#include <concepts>
#include <cstddef>
#include <utility>

// Median-of-3 pivot selection that also sorts A[lo] <= A[mid] <= A[hi] as sentinels
template <std::totally_ordered T>
void sort_median_of_three(T* a, std::size_t lo, std::size_t mid, std::size_t hi) noexcept {
    if (a[mid] < a[lo]) std::swap(a[lo], a[mid]);
    if (a[hi]  < a[lo]) std::swap(a[lo], a[hi]);
    if (a[hi]  < a[mid]) std::swap(a[mid], a[hi]);
}

// Hoare 2-Way Partition: stops on keys == pivot to prevent O(N^2) on equal elements
template <std::totally_ordered T>
std::size_t hoare_partition(T* a, std::size_t lo, std::size_t hi) noexcept {
    const std::size_t mid = lo + (hi - lo) / 2;
    sort_median_of_three(a, lo, mid, hi);
    T pivot = a[mid];
    std::size_t i = lo;
    std::size_t j = hi;
    while (true) {
        while (a[i] < pivot) ++i;
        while (pivot < a[j]) --j;
        if (i >= j) return j;
        std::swap(a[i], a[j]);
        ++i;
        --j;
    }
}

// Dijkstra 3-Way Partition + Sedgewick Tail-Call Elimination (Guarantees O(log N) stack depth)
template <std::totally_ordered T>
void quicksort_3way(T* a, std::size_t lo, std::size_t hi) noexcept {
    while (lo < hi) {
        const std::size_t mid = lo + (hi - lo) / 2;
        sort_median_of_three(a, lo, mid, hi);
        const T pivot = a[mid];

        // Invariant: a[lo..lt-1] < pivot, a[lt..i-1] == pivot, a[gt+1..hi] > pivot
        std::size_t lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < pivot) {
                std::swap(a[lt++], a[i++]);
            } else if (pivot < a[i]) {
                std::swap(a[i], a[gt--]);
            } else {
                ++i;
            }
        }

        // Tail-Call Elimination: recurse ONLY on the smaller partition (<= N/2),
        // and iterate the while-loop on the larger partition!
        const std::size_t left_len  = (lt > lo) ? (lt - lo) : 0;
        const std::size_t right_len = (hi > gt) ? (hi - gt) : 0;

        if (left_len < right_len) {
            if (lt > lo + 1) quicksort_3way(a, lo, lt - 1);
            lo = gt + 1;
        } else {
            if (hi > gt + 1) quicksort_3way(a, gt + 1, hi);
            if (lt == 0) break; // Prevent unsigned underflow when lt == 0
            hi = lt - 1;
        }
    }
}
Two Classic Quicksort Bugs: Stack Overflow &Hoare Off-by-One Infinite Loops

1. Unbounded $O(N)$ Stack Overflow: Without recursing on the smaller partition first and tail-looping on the larger partition, an adversarial input producing $1 : (n-1)$ splits will push $n$ stack frames and crash the thread stack (~1–8 MB) at $n \approx 10^5$. Reordering so the recursive call is always on the side of size $\le n/2$ strictly bounds stack depth to $\le \log_2 n$ frames even in the $\Theta(n^2)$ time worst case!
2. Hoare Partition Infinite Recursion: In Hoare partitioning with pivot $A[lo]$, if you pick $A[hi]$ as the pivot or recurse on (lo, j - 1) and (j, hi) when $j$ can return $lo$, one partition can have size $n$ and the other size $0$, causing infinite recursion. Always pair pivot choice at $A[lo]$ (or median-of-three placed at $A[lo]$) with split (lo, j) and (j + 1, hi).

Concept Check Why Hoare Partitioning Stops on Elements Equal to the Pivot recall

In Hoare's two-pointer partition scheme with pivot $v$, the inner loops are written `while (A[i] < v) ++i;` and `while (v < A[j]) --j;`—meaning both pointers **stop** and swap whenever $A[i] == v$ and $A[j] == v$.

As Bentley and Sedgewick emphasize, stopping on keys equal to the pivot is counterintuitive on the surface (it performs unnecessary swaps of equal elements), but it is what saves 2-way Hoare Quicksort from Θ(n²) collapse on all-equal keys: by stopping on every element, `i` and `j` cross at the exact midpoint `n / 2`, producing a perfectly balanced 50/50 split!
Concept Check Dijkstra 3-Way Partition (Dutch National Flag) Pointer Transition apply

In Dijkstra's 3-way partition with invariant $A[lo \dots lt-1] < v$, $A[lt \dots i-1] == v$, $A[i \dots gt]$ unexamined, and $A[gt+1 \dots hi] > v$, the scan inspects $A[i]$ and finds $A[i] > v$.

When `A[i] < v`, we swap `A[lt++]` with `A[i++]` because `A[lt]` was already known to equal `v`. By contrast, when `A[i] > v`, we swap `A[i]` with `A[gt--]`, where the old value of `A[gt]` was in the unexamined `[i..gt]` window—so the next loop iteration must inspect the new `A[i]` before advancing `i`!
Concept Check Bounding Worst-Case Quicksort Stack Space to O(log N) apply

Even if Quicksort suffers a worst-case sequence of $1 : (n - 1)$ partition splits (taking $\Theta(n^2)$ time), Sedgewick's tail-call elimination guarantees the call stack never exceeds $\lfloor \log_2 n \rfloor + 1$ stack frames.

If you always recurse on the left partition and tail-loop on the right, an adversarial input where the left partition always has size n - 1 and the right has size 0 will still push n - 1 stack frames! By explicitly checking `if (left_size < right_size)` and recursing ONLY on the smaller side, every stack frame shrinks the problem size by at least a factor of 2, bounding stack depth by ≤ log₂ n.
Concept Check Bentley-McIlroy Split-End 3-Way Partition vs Dijkstra Dutch National Flag staff

Dijkstra's 3-way partition swaps every element $< v$ across the center $== v$ band (`swap(A[lt++], A[i++])`), even when the input has $n$ distinct keys and only $1$ copy of the pivot.

In Dijkstra's DNF, every element `< v` must be swapped with `A[lt]` even if there are no duplicate keys equal to `v` besides the pivot itself (increasing swaps from n/6 to ~n/2). Bentley-McIlroy's split-end layout parks equal keys at `[lo..p-1]` and `[q+1..hi]` only when an equal key is actually hit, matching Hoare's exact n/6 swap count on distinct keys and swapping the equal ends to the middle once `i` and `j` cross.

Key Takeaways

Lomuto partitioning performs 3x more swaps than Hoare on random inputs and degrades to Θ(N^2) when all elements are equal.
Hoare partitioning stops both pointers on elements equal to the pivot, trading minor redundant swaps on duplicates for balanced O(N log N) splits.
Dijkstra 3-way (Dutch National Flag) and Bentley-McIlroy partitioning isolate all keys equal to the pivot into a center band, achieving O(N) time on low-cardinality inputs and entropy-optimal O(N H + N) comparisons.
Always recurse on the smaller partition first and loop on the larger partition (Sedgewick tail-call elimination) to guarantee O(log N) worst-case stack space.
