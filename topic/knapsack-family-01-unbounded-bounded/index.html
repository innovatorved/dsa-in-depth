The Knapsack Family: 0/1, Unbounded, Subset Sum Bitset & Bounded Knapsack (Binary Splitting / Monotonic Queue)

Intuition first

The entire Knapsack family revolves around one question: how many copies of item i can we take? Flipping the 1D capacity loop from backward (W down to w_i) to forward (w_i up to W) turns 0/1 Knapsack into Unbounded Knapsack; packing boolean states into `std::bitset` speeds up Subset Sum by 64x via word-level shift-OR; and decomposing count k_i into powers of two solves Bounded Knapsack in O(N W log k).

1. The Four Canonical Knapsack Variants

Given $N$ item types with weights $w_i$, values $v_i$, and knapsack capacity $W$:

  1. 0/1 Knapsack ($c_i \in \{0, 1\}$): Each item taken at most once. 1D recurrence iterates $w$ backward from $W$ down to $w_i$: $$dp[w] = \max(dp[w],\; dp[w - w_i] + v_i)$$
  2. Unbounded / Complete Knapsack ($c_i \in \{0, 1, 2, \dots\}$): Unlimited copies of each item. 1D recurrence iterates $w$ forward from $w_i$ up to $W$ so $dp[w - w_i]$ already includes item $i$: $$dp[w] = \max(dp[w],\; dp[w - w_i] + v_i)$$
  3. Subset Sum Bitset Acceleration ($v_i = 0/1$ feasibility): Can a subset sum to $w$? Pack the boolean array into 64-bit machine words (std::bitset). Adding item $w_i$ becomes a single word-parallel shift-OR: $$\text{bits} \mathrel{|=} (\text{bits} \ll w_i) \quad \implies \quad O\!\left(\frac{N \cdot W}{64}\right)$$
  4. Bounded Knapsack ($c_i \in \{0, 1, \dots, k_i\}$): At most $k_i$ copies of item $i$. Naive transition checks all $c \in [0..k_i]$ in $O(N W \cdot k_i)$. How do we remove the $k_i$ factor?

Core Invariant — Binary Splitting ($O(N W \log K)$) & Monotonic Queue ($O(N W)$) for Bounded Knapsack

Method 1 (Binary Splitting): Any integer $k_i$ can be decomposed into $\lfloor \log_2 k_i \rfloor + 1$ bundles with sizes $1, 2, 4, \dots, 2^{p-1}$ plus the remainder $R = k_i - (2^p - 1)$. Every integer in $[0, k_i]$ is uniquely expressible as a subset sum of these $\approx \log_2 k_i$ bundles! Running standard 0/1 Knapsack on these bundles reduces time to $O(W \sum \log k_i)$.
Method 2 (Monotonic Deque per Residue Class $\bmod w_i$): For a fixed item $(w_i, v_i, k_i)$, transition $dp_{new}[w]$ only depends on capacities congruent to $w \pmod{w_i}$. Writing $w = q \cdot w_i + r$, we have:

$$dp_{new}[q w_i + r] = q \cdot v_i + \max_{q - k_i \le j \le q} \big(dp_{old}[j w_i + r] - j \cdot v_i\big)$$

This is a sliding-window maximum of width $k_i + 1$ over $q = 0, 1, \dots, \lfloor (W-r)/w_i \rfloor$, solvable in exact $O(W)$ time per item ($O(N W)$ total) using a monotonic deque!

2. The $\sqrt{S}$ Frequency Compression Trick for Subset Sum ($\sum w_i = S$)

When the sum of all item weights is $\sum_{i=1}^N w_i = S$, at most $O(\sqrt{S})$ distinct weight values can exist! Why? Because the minimum sum of $d$ distinct positive integers is $1 + 2 + \dots + d = d(d+1)/2 \le S \implies d \le \sqrt{2S}$. By grouping identical weights into (weight, count) pairs and applying binary splitting (or packing pairs of equal weights into a next-level weight $2w$ until at most 2 copies of each weight remain), Subset Sum on $\sum w_i = S$ runs in $O\!\left(\frac{S \sqrt{S}}{64}\right)$ time!

Hardware Reality — AVX2 / AVX-512 Word-Level Bitset Parallelism

In C++, std::bitset<100001> dp; dp |= (dp << w); compiles under -O3 -march=native to a tight loop of 256-bit AVX2 (VPXOR/VPOR/VPSLLQ) or 512-bit AVX-512 instructions processing 256 to 512 capacity states per CPU clock cycle. For $N = 2000, W = 100{,}000$, scalar DP executes $2 \times 10^8$ loop iterations (~150 ms), whereas std::bitset executes $2000 \times (100000 / 256) \approx 7.8 \times 10^5$ SIMD instructions in under 1.2 milliseconds.

4. Reference C++20 Implementation

#include <algorithm>
#include <bitset>
#include <cstdint>
#include <deque>
#include <vector>

struct BoundedItem {
    int weight;
    long long value;
    int count;
};

// 1. Bounded Knapsack in O(W * sum(log k_i)) via Binary Splitting
long long bounded_knapsack_binary_split(const std::vector<BoundedItem>& items, int capacity) {
    std::vector<long long> dp(capacity + 1, 0);

    auto apply_01_item = [&](int w, long long v) {
        for (int cap = capacity; cap >= w; --cap) {
            dp[cap] = std::max(dp[cap], dp[cap - w] + v);
        }
    };

    for (const auto& item : items) {
        int rem = item.count;
        for (int b = 1; b <= rem; b <<= 1) {
            int bundle_w = b * item.weight;
            if (bundle_w <= capacity) {
                apply_01_item(bundle_w, b * item.value);
            }
            rem -= b;
        }
        if (rem > 0 && rem * item.weight <= capacity) {
            apply_01_item(rem * item.weight, rem * item.value);
        }
    }
    return dp[capacity];
}

// 2. Bounded Knapsack in Strict O(N * W) Time via Monotonic Deque over Residue Classes
long long bounded_knapsack_monotonic_queue(const std::vector<BoundedItem>& items, int capacity) {
    std::vector<long long> dp(capacity + 1, 0);
    std::deque<std::pair<int, long long>> dq; // (quotient q, shifted_val = dp[q*w + r] - q*v)

    for (const auto& item : items) {
        const int w = item.weight;
        const long long v = item.value;
        const int k = item.count;
        if (w > capacity || k == 0) continue;

        for (int r = 0; r < w; ++r) {
            dq.clear();
            int max_q = (capacity - r) / w;
            for (int q = 0; q <= max_q; ++q) {
                long long shifted = dp[q * w + r] - q * v;
                while (!dq.empty() && dq.back().second <= shifted) {
                    dq.pop_back();
                }
                dq.emplace_back(q, shifted);
                // Evict window elements older than q - k
                if (dq.front().first < q - k) {
                    dq.pop_front();
                }
                dp[q * w + r] = dq.front().second + q * v;
            }
        }
    }
    return dp[capacity];
}

// 3. O(N * W / 64) Word-Parallel Subset Sum using std::bitset
template <std::size_t MAXW = 100001>
bool subset_sum_bitset(const std::vector<int>& weights, int target) {
    if (target < 0 || static_cast<std::size_t>(target) >= MAXW) return false;
    std::bitset<MAXW> reachable;
    reachable.set(0);
    for (int w : weights) {
        reachable |= (reachable << w);
    }
    return reachable.test(target);
}

Production Pitfall — Splitting $k_i$ into Powers of 2 Up to $\lceil \log_2 k_i \rceil$ Instead of Remainder $R$

When binary-splitting $k_i = 13$, if you emit powers of two $1, 2, 4, 8$, their sum is $15 > 13$—allowing the solver to illegally take 14 or 15 copies of the item! You must subtract $1, 2, 4, \dots$ while $2^b \le \text{rem}$ ($13 - 1 - 2 - 4 = 6$) and emit the leftover remainder $R = 6$ as the final bundle so the bundle sum equals $1 + 2 + 4 + 6 = 13$ exactly. Also note: when weights $W \le 10^9$ are huge but values $\sum v_i \le 10^5$ are small, invert the DP state and objective: let $dp[v]$ be the minimum weight required to achieve exact value $v$ in $O(N \sum v_i)$ time!

Concept Check 0/1 vs. Unbounded Knapsack 1D Loop Direction recall

Why does the 1D space-optimized 0/1 Knapsack iterate capacity $w$ **backward** (`for (int w = W; w >= w_i; --w)`), whereas Unbounded Knapsack iterates $w$ **forward** (`for (int w = w_i; w <= W; ++w)`)?

In 0/1 Knapsack, $dp_{\text{new}}[w] = \max(dp_{\text{old}}[w], dp_{\text{old}}[w - w_i] + v_i)$. If we overwrite `dp` left-to-right, `dp[w - w_i]` is already $dp_{\text{new}}[w - w_i]$, which may already contain item $i$ (the exact transition needed for Unbounded Knapsack!).

In Bounded Knapsack, an item has weight $w = 3$, value $v = 10$, and maximum count $k = 21$. When decomposing $k = 21$ via Binary Splitting into powers of two $1, 2, 4, \dots$ plus a remainder $R$, what is the count size $R$ of the final remainder bundle?

±0% accepted
Subtracting powers of two from $21$: $21 - 1 = 20$; $20 - 2 = 18$; $18 - 4 = 14$; $14 - 8 = 6$. The next power of two is $16 > 6$, so we stop and emit the remainder bundle of size $R = 6$. The bundles are $\{1, 2, 4, 8, 6\}$, which sum to $21$ and can form every integer in $[0, 21]$.
Concept Check State-Value Inversion for Huge Capacity Knapsack apply

Suppose you have a 0/1 Knapsack instance with $N = 100$ items, maximum item value $v_i \le 1{,}000$, and knapsack capacity $W = 10^9$ (with $w_i \le 10^9$). Standard $O(N \cdot W)$ DP requires $10^{11}$ operations and gigabytes of RAM. How do you solve this exactly in $O(N \cdot \sum v_i) = 10^7$ operations?

Since $N = 100$ and $v_i \le 1000$, the maximum possible total value is $V_{\max} = 100{,}000$. Defining $dp[v]$ as the minimum weight to achieve value $v$ (initialized to $dp[0] = 0$ and $+\infty$ elsewhere) runs in $O(N \cdot V_{\max}) = 10^7$ operations and 800 KB of memory.
Concept Check Monotonic Deque Residue Partition in O(NW) Bounded Knapsack staff

In the strict $O(N \cdot W)$ Bounded Knapsack algorithm using a monotonic queue for an item $(w, v, k)$, why do we partition capacities $0..W$ by their residue $r = \text{cap} \bmod w$ and slide a window over quotients $q = 0, 1, \dots, \lfloor(W-r)/w\rfloor$ of the quantity $dp_{\text{old}}[q \cdot w + r] - q \cdot v$?

Writing $c = q - j$ copies taken (where $q - k \le j \le q$), the recurrence is $dp_{\text{new}}[q w + r] = \max_{j \in [q-k, q]} (dp_{\text{old}}[j w + r] + (q - j)v) = q v + \max_{j \in [q-k, q]} (dp_{\text{old}}[j w + r] - j v)$. Factoring out $+q v$ isolates a pure function of $j$ that can be maximized over the sliding window $[q-k, q]$ in amortized $O(1)$ per state.

Key Takeaways

0/1 Knapsack iterates capacity backward (W down to w_i) so each item is used at most once; Unbounded Knapsack iterates forward (w_i up to W) to allow unlimited reuse.
Binary splitting decomposes count k_i into powers of two 1, 2, 4, ... plus remainder R, reducing Bounded Knapsack to O(W sum log k_i) 0/1 Knapsack steps.
Grouping capacities by residue r = w mod w_i transforms Bounded Knapsack into a sliding-window maximum solvable in O(N * W) via a monotonic deque.
When capacity W is huge (10^9) but total value V is small (10^5), swap state and value: compute the minimum weight needed to achieve value v in O(N * V).
