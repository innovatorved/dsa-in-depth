Intuition first

Every recursive grammar or nested expression is evaluated by a Last-In-First-Out (LIFO) stack. While compilers lower recursive functions into hardware stack frames (RSP/RBP), Edsger Dijkstra's 1961 Shunting-Yard algorithm parses arbitrary infix expressions with precedence, parenthesization, and left/right associativity into Reverse Polish Notation (RPN) or evaluates them on the fly in $O(N)$ time using a single operator stack.

Infix Ambiguity vs. Reverse Polish Notation (Postfix)

Why is an infix expression like $3 + 4 \times 2 \uparrow 3 \uparrow 2$ ambiguous without precedence and associativity rules, whereas its Reverse Polish Notation (postfix) equivalent 3 4 2 3 2 ^ ^ * + requires zero parentheses and zero precedence rules? Because in postfix notation, every operator appears immediately after its operands, encoding the exact post-order traversal of the Abstract Syntax Tree (AST)!

Evaluating an RPN token stream is a single branch-free stack machine pass: scan tokens left to right; push numbers onto an operand stack; when a binary operator $\circ$ arrives, pop the right operand $b$, pop the left operand $a$, and push $(a \circ b)$.

Parsing Invariant: Dijkstra's Shunting-Yard Precedence & Associativity Condition

When converting an infix token stream into RPN using an operator stack op_stack, incoming operators must wait on the stack until their right operand has been completely parsed. When a new binary operator $o_1$ arrives and the top of op_stack is a non-parenthesis operator $o_2$, under what exact condition must $o_2$ be popped and emitted before pushing $o_1$?

$$\text{pop } o_2 \iff \text{prec}(o_2) > \text{prec}(o_1) \;\lor\; \big(\text{prec}(o_2) == \text{prec}(o_1) \land \text{isLeftAssociative}(o_1)\big)$$

Notice how a single boolean flip handles associativity: for left-associative subtraction $a - b - c = (a - b) - c$, the second $-$ sees $\text{prec}(-) == \text{prec}(-)$ with left-associativity and pops the first $-$, emitting a b - c -. For right-associative exponentiation $2 \uparrow 3 \uparrow 2 = 2^{(3^2)} = 512$, the second $\uparrow$ sees $\text{prec}(\uparrow) == \text{prec}(\uparrow)$ with right-associativity and does not pop the first $\uparrow$, pushing onto the stack to emit 2 3 2 ^ ^!

Hardware Reality: The Hardware Return Stack Buffer (RSB) & Explicit Heap Stacks

When a program executes a machine CALL instruction, x86-64 and ARM64 CPUs push the return address not only onto the architectural stack in L1d ([RSP]), but also into a dedicated 16-to-32 entry hardware cache inside the branch predictor called the Return Stack Buffer (RSB)—allowing RET instructions to predict their jump target in 0 cycles! However, each OS thread's call stack is fixed to a contiguous 1 MB–8 MB virtual memory guard region. Recursive AST evaluation or DFS on a degenerate tree of depth $D = 200,000$ overflows the OS thread stack (SIGSEGV stack overflow), whereas an explicit std::vector-backed state stack grows dynamically on the heap up to available RAM and uses $4\times$ less memory per frame than an ABI function call frame.

Production Implementation: Shunting-Yard Evaluator with Unary Negation & Exponentiation

#include <cctype>
#include <cstdint>
#include <string_view>
#include <vector>

class ExpressionEvaluator {
  enum class Op : char { Add = '+', Sub = '-', Mul = '*', Div = '/', Pow = '^', Neg = '~', LParen = '(' };

  static int precedence(Op op) noexcept {
    switch (op) {
      case Op::Add: case Op::Sub: return 1;
      case Op::Mul: case Op::Div: return 2;
      case Op::Pow:               return 3;
      case Op::Neg:               return 4;
      default:                    return 0;
    }
  }

  static bool is_right_assoc(Op op) noexcept {
    return op == Op::Pow || op == Op::Neg;
  }

  static std::int64_t ipow(std::int64_t base, std::int64_t exp) noexcept {
    if (exp < 0) return 0;
    std::int64_t res = 1;
    while (exp > 0) {
      if (exp & 1) res *= base;
      base *= base;
      exp >>= 1;
    }
    return res;
  }

  static void apply_op(std::vector<std::int64_t>& vals, Op op) noexcept {
    if (op == Op::Neg) {
      vals.back() = -vals.back();
      return;
    }
    // CRITICAL: First popped is RIGHT operand, second popped is LEFT operand!
    const std::int64_t rhs = vals.back(); vals.pop_back();
    const std::int64_t lhs = vals.back(); vals.pop_back();
    switch (op) {
      case Op::Add: vals.push_back(lhs + rhs); break;
      case Op::Sub: vals.push_back(lhs - rhs); break;
      case Op::Mul: vals.push_back(lhs * rhs); break;
      case Op::Div: vals.push_back(lhs / rhs); break;
      case Op::Pow: vals.push_back(ipow(lhs, rhs)); break;
      default: break;
    }
  }

public:
  static std::int64_t evaluate(std::string_view expr) {
    std::vector<std::int64_t> vals;
    std::vector<Op> ops;
    bool expect_unary = true; // True at start, after '(', or after any operator

    for (std::size_t i = 0; i < expr.size();) {
      if (std::isspace(static_cast<unsigned char>(expr[i]))) {
        ++i;
        continue;
      }
      if (std::isdigit(static_cast<unsigned char>(expr[i]))) {
        std::int64_t num = 0;
        while (i < expr.size() && std::isdigit(static_cast<unsigned char>(expr[i]))) {
          num = num * 10 + (expr[i] - '0');
          ++i;
        }
        vals.push_back(num);
        expect_unary = false;
      } else if (expr[i] == '(') {
        ops.push_back(Op::LParen);
        expect_unary = true;
        ++i;
      } else if (expr[i] == ')') {
        while (!ops.empty() && ops.back() != Op::LParen) {
          apply_op(vals, ops.back());
          ops.pop_back();
        }
        if (!ops.empty()) ops.pop_back(); // Pop '('
        expect_unary = false;
        ++i;
      } else {
        Op cur_op = static_cast<Op>(expr[i]);
        if (cur_op == Op::Sub && expect_unary) {
          cur_op = Op::Neg;
        }
        while (!ops.empty() && ops.back() != Op::LParen) {
          const int p_top = precedence(ops.back());
          const int p_cur = precedence(cur_op);
          if (p_top > p_cur || (p_top == p_cur && !is_right_assoc(cur_op))) {
            apply_op(vals, ops.back());
            ops.pop_back();
          } else {
            break;
          }
        }
        ops.push_back(cur_op);
        expect_unary = true;
        ++i;
      }
    }

    while (!ops.empty()) {
      apply_op(vals, ops.back());
      ops.pop_back();
    }
    return vals.empty() ? 0 : vals.back();
  }
};
Production Pitfall: Reversed Operand Pop Order & Unary Minus Precedence

Two classic bugs break stack-based expression evaluators:

  1. Reversed Pop Order on Non-Commutative Operators: Because operands are pushed left-to-right onto the LIFO vals stack, the first value popped (vals.back()) is the right-hand operand (rhs), and the second value popped is the left-hand operand (lhs)! Reversing them leaves + and * unaffected but computes rhs - lhs and rhs / lhs for subtraction, division, and exponentiation.
  2. Replacing Unary -x with 0 - x When Exponentiation Is Present: Pushing a dummy 0 before - works if only +, -, *, / exist, but fails on 2 ^ -3 or -2 ^ 2 because binary - has precedence 1 while unary negation has higher precedence. Track a boolean state expect_unary (true at start of string, after (, or after any operator) to dispatch - as a dedicated unary operator Op::Neg.
Check yourself Question 1 of 4
Concept Check Shunting-Yard Right-Associative Precedence Rule recall

In Dijkstra's Shunting-Yard algorithm (or Pratt parsing), suppose the incoming operator is `^` (exponentiation, precedence 3, right-associative) and the operator at the top of the operator stack is also `^` (precedence 3). Should the stack top be popped before pushing the incoming `^`?

For left-associative operators like `a - b - c`, we want `(a - b) - c`, so we pop when $\text{prec}(\text{top}) \ge \text{prec}(\text{op})$. For right-associative operators like `a ^ b ^ c`, we want `a ^ (b ^ c)`, so the second `^` must bind first; hence we only pop when $\text{prec}(\text{top}) > \text{prec}(\text{op})$.
Concept Check x86-64 System V ABI Stack Alignment apply

On x86-64 Linux/macOS (System V AMD64 ABI), the hardware `CALL` instruction pushes an 8-byte return address onto the stack, decrementing `%rsp` by 8. Why does a typical function prologue execute `push %rbp` followed by `sub $16, %rsp` (or an odd multiple of 8 bytes total) before calling another function?

The System V ABI mandates that `%rsp` is 16-byte aligned immediately prior to a `CALL`. When `CALL` pushes the 8-byte return address, `%rsp` enters the callee misaligned by 8 bytes (`%rsp % 16 == 8`). Pushing the 8-byte `%rbp` restores 16-byte alignment (`%rsp % 16 == 0`), and any further stack allocation must be a multiple of 16 bytes.
Concept Check Tail-Call Elimination (TCO) Requirement apply

Consider two implementations of factorial in C/C++: `factA(n) { return n <= 1 ? 1 : n * factA(n - 1); }` and `factB(n, acc) { return n <= 1 ? acc : factB(n - 1, n * acc); }`. At the assembly level, why is `factB` directly eligible for Tail-Call Optimization (`JMP` instead of `CALL`) while `factA` is not (without compiler algebraic rewriting)?

A call is in tail position only if its return value is immediately returned by the caller with no subsequent operations (and no local variables with non-trivial destructors waiting to run). In `factB`, the current stack frame can be overwritten in place and `CALL` replaced by a direct `JMP` to the start of the function, reducing space from $O(N)$ to $O(1)$.
Concept Check Explicit Iterative DFS vs Recursive Call Stack Footprint staff

You need to run Depth-First Search on a directed graph with $2 \times 10^6$ vertices that may form a single long chain. A recursive `dfs(u)` function crashes with `SIGSEGV` (stack overflow) on a default 8 MB OS thread stack, even though `u` is just a 4-byte `int32_t`. Why does the recursive version overflow 8 MB while an explicit `std::vector<int32_t>` stack uses only 8 MB for the entire $2 \times 10^6$ vertices?

Even the leanest non-tail recursive call pushes an 8-byte return address plus at least 8 bytes for saved registers or 16-byte stack alignment (typically 32–64 bytes when local loop iterators and callee-saved registers are spilled). At 48 bytes/frame, $2 \times 10^6$ frames require ~96 MB, blowing past the 8 MB `ulimit -s` guard page.

Key Takeaways

Reverse Polish Notation (postfix) encodes the exact post-order traversal of an Abstract Syntax Tree, eliminating parentheses and precedence rules during stack evaluation.
In Dijkstra's Shunting-Yard algorithm, an incoming operator o1 pops stack-top operator o2 iff prec(o2) > prec(o1) OR (prec(o2) == prec(o1) and o1 is left-associative).
When evaluating a binary operator from an operand stack, the first pop yields the right-hand operand (rhs) and the second pop yields the left-hand operand (lhs).
Unary operators (such as unary minus) are disambiguated in O(1) by checking whether the previous token was the start of input, '(', or another operator.
