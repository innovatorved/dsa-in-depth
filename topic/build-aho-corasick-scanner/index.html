Intuition first

In this Build Lab, we assemble a production-grade, streaming Multi-Pattern Aho-Corasick Scanner capable of ingesting arbitrary 64 KB network chunks or log buffers and emitting every overlapping match (istart,  iend,  pattern_id)(i_{\text{start}},\; i_{\text{end}},\; \text{pattern\_id})(istart​,iend​,pattern_id) in strict O(N+Z)O(N + Z)O(N+Z) worst-case time. Unlike textbook snippets that require the entire text to sit in a single contiguous string or restrict the alphabet to 26 lowercase letters, a real scanner must preserve automaton state uuu and global byte offset across chunk boundaries.

We will also solve the duplicate-pattern and substring-shadowing problem: when a ruleset contains identical patterns with different rule IDs or patterns that are suffixes of longer patterns (such as "sql"\texttt{"sql"}"sql", "psql"\texttt{"psql"}"psql", and "mysql"\texttt{"mysql"}"mysql"), we chain same-node pattern IDs via a compact linked list inside the pattern table so each node stores only three 32-bit integers alongside its transition table.

1. Engineering Specifications for a Streaming Scanner

To make our Aho-Corasick engine suitable for intrusion detection, log redaction, or DLP (Data Loss Prevention) pipelines, we enforce four architectural invariants:

  1. Zero-Allocation Streaming State (ScannerCursor): The compiled AhoCorasickAutomaton is immutable and thread-safe (const), so 64 worker threads can share a single compiled dictionary while each stream maintains a tiny 16-byte ScannerCursor { int32_t state; uint64_t bytes_seen; }.
  2. Constant-Size Node Layout via Intrusive Pattern Lists: Storing a std::vector<int> inside every Trie node wastes 24 bytes of heap-vector header per state even when 95% of states are non-terminal. Instead, each node stores a single int32_t first_pat = -1, and we store next_pat_at_same_node[pat_id] in a flat array of size KKK.
  3. Exact Start & End Offset Calculation: Because matches can span across chunk boundaries (e.g., " Drop"\texttt{" Drop"}" Drop" at the end of Chunk 1 and "Table"\texttt{"Table"}"Table" at the start of Chunk 2), the cursor tracks bytes_seen, and when pattern pid of length LpidL_{\text{pid}}Lpid​ matches at global byte index pos, its exact start offset is pos + 1 - L_pid.
  4. Compressed Output Links (exit_link): During BFS, we set exit_link[u] to fail[u] if nodes[fail[u]].first_pat != -1, and to exit_link[fail[u]] otherwise.

Let T=C1∥C2∥⋯∥CmT = C_1 \mathbin{\|} C_2 \mathbin{\|} \dots \mathbin{\|} C_mT=C1​∥C2​∥⋯∥Cm​ be a stream partitioned into arbitrary byte chunks. Replacing Per-Node std::vector with Intrusive Pattern Chains

A std::vector<int> inside every Node adds 24 bytes of struct overhead plus a separate heap allocation for every terminal state, scattering terminal pattern lists across memory pages. Storing int32_t first_pat in Node (4 bytes) and int32_t next_pat[K] in a single flat array of length KKK eliminates all per-node heap allocations and cuts terminal match traversal to sequential array reads.

3. Complete Build Implementation: Streaming Aho-Corasick Engine

C++20101 lines
#include <array>
#include <cstdint>
#include <queue>
#include <string_view>
#include <vector>

struct MatchEvent {
    uint64_t start_offset; // Inclusive global byte offset
    uint64_t end_offset;   // Exclusive global byte offset
    int32_t pattern_id;
};

struct ScannerCursor {
    int32_t state = 0;
    uint64_t bytes_seen = 0;
};

class StreamingAhoCorasick {
public:
    struct Node {
        std::array<int32_t, 256> go{};
        int32_t fail = 0;
        int32_t exit_link = 0;
        int32_t first_pat = -1; // Head of intrusive linked list of pattern IDs
    };

    StreamingAhoCorasick() { nodes_.emplace_back(); }

    int32_t add_pattern(std::string_view pat) {
        int32_t pid = static_cast<int32_t>(pat_len_.size());
        pat_len_.push_back(static_cast<uint32_t>(pat.size()));

        int32_t u = 0;
        for (unsigned char c : pat) {
            if (nodes_[u].go[c] == 0) {
                nodes_[u].go[c] = static_cast<int32_t>(nodes_.size());
                nodes_.emplace_back();
            }
            u = nodes_[u].go[c];
        }
        // Prepend <code>pid</code> to node u's intrusive pattern list
        next_pat_.push_back(nodes_[u].first_pat);
        nodes_[u].first_pat = pid;
        return pid;
    }

    void freeze() {
        std::queue<int32_t> q;
        for (int c = 0; c < 256; ++c) {
            int32_t v = nodes_[0].go[c];
            if (v != 0) {
                nodes_[v].fail = 0;
                q.push(v);
            }
        }
        while (!q.empty()) {
            int32_t u = q.front();
            q.pop();
            int32_t f = nodes_[u].fail;
            nodes_[u].exit_link = (nodes_[f].first_pat != -1) ? f : nodes_[f].exit_link;

            for (int c = 0; c < 256; ++c) {
                int32_t v = nodes_[u].go[c];
                if (v != 0) {
                    nodes_[v].fail = nodes_[f].go[c];
                    q.push(v);
                } else {
                    nodes_[u].go[c] = nodes_[f].go[c];
                }
            }
        }
        frozen_ = true;
    }

    template <typename Callback>
    void scan_chunk(ScannerCursor& cursor, std::string_view chunk, Callback&& on_match) const {
        int32_t u = cursor.state;
        uint64_t pos = cursor.bytes_seen;

        for (unsigned char c : chunk) {
            u = nodes_[u].go[c];
            ++pos; // <code>pos</code> is now the exclusive end offset of any match ending here

            int32_t term = (nodes_[u].first_pat != -1) ? u : nodes_[u].exit_link;
            while (term != 0) {
                for (int32_t pid = nodes_[term].first_pat; pid != -1; pid = next_pat_[pid]) {
                    on_match(MatchEvent{pos - pat_len_[pid], pos, pid});
                }
                term = nodes_[term].exit_link;
            }
        }
        cursor.state = u;
        cursor.bytes_seen = pos;
    }

private:
    std::vector<Node> nodes_;
    std::vector<uint32_t> pat_len_;
    std::vector<int32_t> next_pat_;
    bool frozen_ = false;
};
Unsigned Byte Casting & Empty-Pattern Guards

In C and C++, char is signed on x86_64 and ARM Linux/macOS targets (−128..127-128..127−128..127). Indexing nodes_[u].go[ch] directly with a signed char on UTF-8 or binary payloads causes out-of-bounds negative array indexing whenever a byte has its high bit set (geext0x80ge ext{0x80}geext0x80)! Always cast to unsigned char or uint8_t before indexing the transition table, and reject or handle empty patterns (∣Pi∣=0|P_i| = 0∣Pi​∣=0) before insertion so root state 000 never becomes a terminal state (since our output loop terminates on term != 0).

Concept Check State Preservation Across Streaming Chunk Boundaries recall

A streaming Aho-Corasick scanner processes a 10 GB network stream in 64 KB chunks C1,C2,…C_1, C_2, \dotsC1​,C2​,…. Pattern P_0 = \texttt{&quot;DROP TABLE&quot;} starts 4 bytes before the end of C1C_1C1​ (`"...DROP"`) and finishes 6 bytes into C2C_2C2​ (`" TABLE..."`).

Because the Aho-Corasick completed DFA is a Markovian state machine where state uuu already encodes the longest matching prefix of P\mathcal{P}P that is a suffix of the stream seen so far, carrying `cursor.state` and `cursor.bytes_seen` across chunks requires zero byte buffering and zero re-scanning.
Concept Check Intrusive Pattern Linked List for Duplicate & Co-Terminal Patterns apply

In our `StreamingAhoCorasick` implementation, two different security rules register the exact same pattern string (e.g., Rule 10 and Rule 42 both add `"eval("`). Instead of storing `std::vector<int32_t> pat_ids` in every `Node`, each `Node` stores a single `int32_t first_pat = -1` alongside a flat array `next_pat_[K]`.

Each pattern ID `pid` belongs to exactly one terminal node `u` in the Trie. Therefore, a single flat array `next_pat_[pid]` of size KKK (initialized during `add_pattern`) chains all patterns ending at the same node `u` into a singly linked list headed by `nodes_[u].first_pat`, eliminating all per-node heap allocations.
Concept Check Signed `char` Indexing Bug on Binary / UTF-8 Streams apply

Suppose a developer writes `u = nodes_[u].go[chunk[i]];` in C++ where `chunk` is a `std::string_view` (`const char*`), and tests the scanner on a UTF-8 file containing `'é'` (`0xC3 0xA9`).

`std::array<int32_t, 256>::operator[]` performs unchecked pointer arithmetic `*(data() + idx)`. Passing a negative `char` value (`-128..-1`) reads memory located up to 128×4=512128 \times 4 = 512128×4=512 bytes BEFORE the start of `nodes_[u].go`, causing immediate undefined behavior and wild state jumps. Always cast to `unsigned char` or `uint8_t`.
Concept Check Memory Optimization for Large-Dictionary Aho-Corasick (`NFA-to-DFA` Hybrid) staff

When compiling K=100,000K = 100{,}000K=100,000 patterns of total length M=2×106M = 2 \times 10^6M=2×106 bytes over the full 256-byte alphabet, a naive completed DFA table `int32_t go[256]` per node requires 2×106×1024 B≈2 GB2 \times 10^6 \times 1024\text{ B} \approx 2\text{ GB}2×106×1024 B≈2 GB of RAM, blowing out the CPU's L3 cache.

In almost any real workload, the Aho-Corasick automaton spends >95%>95\%>95% of its time at depth 000, 111, or 222. Materializing the dense `int32_t go[256]` table only for the root and shallowest layers (fitting in a few hundred kilobytes of L2 cache) while keeping deep states in a sparse representation gives near-DFA throughput at a fraction of the memory footprint.

Key Takeaways

Decoupling the immutable Aho-Corasick DFA arena from a 16-byte ScannerCursor (state + bytes_seen) allows thread-safe, zero-allocation streaming across arbitrary chunk boundaries.
Replacing per-node std::vector pattern lists with an intrusive linked list (first_pat[u] + next_pat[pid]) eliminates heap allocations inside states and handles duplicate patterns cleanly.
Always index 256-entry transition tables using uint8_t / unsigned char and keep root state 0 non-terminal so the exit_link loop terminates at 0.
