Covers peak-finding invariants on bitonic/unimodal sequences, rotated sorted array midpoint classification, and unbounded search.

Intuition first

Even when an array is not globally sorted—whether it is unbounded in length, cyclically rotated at an unknown pivot, or rises to a single peak before falling—we can still eliminate a constant fraction of the search space at every probe by comparing adjacent slopes or endpoint sentinels.

1. Exponential (Galloping / Bentley-Yao) Search in O(log⁡i)O(\log i)O(logi) Time

Suppose you want to search for a target xxx in a sorted array of unknown (or enormous) size NNN, where xxx is known to sit near the beginning (at index i≪Ni \ll Ni≪N)—such as advancing a posting-list cursor in an inverted search index (Lucene/ripgrep) or TimSort's galloping merge. Standard binary search across [0,N)[0, N)[0,N) always pays ⌈log⁡2N⌉\lceil \log_2 N \rceil⌈log2​N⌉ comparisons. Exponential Search (Bentley & Yao, 1976) finds xxx in 2⌊log⁡2i⌋+2=O(log⁡i)\mathbf{2\lfloor \log_2 i \rfloor + 2 = O(\log i)}2⌊log2​i⌋+2=O(logi) comparisons:

3. Unimodal Optimization: Discrete Slope Binary Search vs. Continuous Ternary Search

Hardware Reality: Why Exponential Search Beats Binary Search on Inverted Indexes

In full-text search engines (Lucene, Tantivy) and columnar databases (ClickHouse, DuckDB), intersecting two sorted posting lists L1L_1L1​ and L2L_2L2​ requires advancing the cursor in L2L_2L2​ to the first document ID ≥d1\ge d_1≥d1​. Because successive jumps i=next_pos−cur_posi = \text{next\_pos} - \text{cur\_pos}i=next_pos−cur_pos are usually small (i∈[1,64]i \in [1, 64]i∈[1,64]), Exponential Search probes cur+1,cur+3,cur+7,…cur + 1, cur + 3, cur + 7, \dotscur+1,cur+3,cur+7,…—staying completely inside the current 64-byte L1d cache line! By contrast, a full binary search over L2[cur…N]L_2[cur \dots N]L2​[cur…N] immediately jumps to the midpoint (cur+N)/2(cur + N)/2(cur+N)/2 megabytes away in DRAM, suffering an guaranteed L3/DRAM cache miss on the very first comparison!

// 1. Exponential (Galloping) Search from cursor hint: O(log(result - hint)) time & cache-local!
template <std::totally_ordered T>
constexpr std::size_t exponential_lower_bound(const T* a, std::size_t n, const T& target, std::size_t hint = 0) noexcept {
    if (hint >= n || !(a[hint] < target)) {
        // Fallback if target <= a[hint]
        return static_cast<std::size_t>(std::lower_bound(a, a + std::min(hint + 1, n), target) - a);
    }
    std::size_t step = 1;
    std::size_t lo = hint;
    std::size_t hi = hint + 1;
    while (hi < n && a[hi] < target) {
        lo = hi;
        step <<= 1;
        hi = (n - hi > step) ? (hi + step) : n;
    }
    return static_cast<std::size_t>(std::lower_bound(a + lo + 1, a + hi, target) - a);
}

// 2. Discrete Unimodal Peak Finder in log2(n) iterations (1 slope comparison per step)
template <std::totally_ordered T>
constexpr std::size_t find_bitonic_peak(const T* a, std::size_t n) noexcept {
    std::size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        const std::size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < a[mid + 1]) {
            lo = mid + 1; // Rising slope: peak is strictly to the right
        } else {
            hi = mid;     // Falling slope: mid could be the peak
        }
    }
    return lo;
}

// 3. Continuous Golden-Section Search: maximizes unimodal f(x) on [lo, hi] reusing 1 evaluation/step!
template <typename Func>
double golden_section_maximize(Func f, double lo, double hi, int iterations = 70) {
    constexpr double inv_phi  = 1.0 / std::numbers::phi;        // (sqrt(5) - 1) / 2 ≈ 0.618034
    constexpr double inv_phi2 = 1.0 - inv_phi;                  // (3 - sqrt(5)) / 2 ≈ 0.381966

    double m1 = lo + inv_phi2 * (hi - lo);
    double m2 = lo + inv_phi  * (hi - lo);
    double f1 = f(m1);
    double f2 = f(m2);

    for (int it = 0; it < iterations; ++it) {
        if (f1 < f2) {
            lo = m1;
            m1 = m2; f1 = f2; // Reuse previous m2 evaluation!
            m2 = lo + inv_phi * (hi - lo);
            f2 = f(m2);       // Only ONE new f() call per step!
        } else {
            hi = m2;
            m2 = m1; f2 = f1; // Reuse previous m1 evaluation!
            m1 = lo + inv_phi2 * (hi - lo);
            f1 = f(m1);
        }
    }
    return 0.5 * (lo + hi);
}
Why Rotated Search With Duplicates Cannot Beat Ω(N)\Omega(N)Ω(N) in the Worst Case

Suppose a rotated sorted array allows duplicate keys and the input is [1,1,1,…,1,0,1,1][1, 1, 1, \dots, 1, 0, 1, 1][1,1,1,…,1,0,1,1] (a single 000 hidden among n−1n - 1n−1 ones). At the initial step, A[lo]=A[mid]=A[hi]=1A[lo] = A[mid] = A[hi] = 1A[lo]=A[mid]=A[hi]=1, which gives zero information about whether the 000 lies in the left half [lo,mid−1][lo, mid-1][lo,mid−1] or the right half [mid+1,hi][mid+1, hi][mid+1,hi]! Any comparison-based algorithm must inspect all nnn positions in the worst case to find the 000, proving an information-theoretic Ω(n)\Omega(n)Ω(n) worst-case lower bound when duplicates are present.

Check yourself Question 1 of 4
Concept Check Bitonic Peak Search Invariant recall

An array A[0..n-1] of distinct integers is strictly increasing up to an unknown peak index p and strictly decreasing from p to n - 1.

Because a unimodal/bitonic array increases up to p and decreases after p, A[mid] < A[mid + 1] means the sequence is still rising at mid, so mid cannot be the peak and p >= mid + 1. Conversely, A[mid] > A[mid + 1] means p <= mid.
Concept Check Worst-Case Lower Bound for Rotated Sorted Array with Duplicates apply

You are searching for a target in a rotated sorted array A[0..n-1] that may contain duplicate values. At step mid, you observe A[lo] == A[mid] && A[mid] == A[hi].

An adversary can hide a single distinct element (say 0) at any position among n - 1 copies of 1. Any probe that hits a 1 yields A[lo] == A[mid] == A[hi] == 1, revealing zero information about which half contains the 0 and proving an Omega(n) decision-tree lower bound.
Concept Check Complexity of Exponential (Galloping) Search apply

We search for a target in a sorted array of size N = 10^8 starting from a cursor at index 0. The target actually sits at index k = 50.

Bentley & Yao's exponential search finds the smallest power of two 2^m >= k in m = ceil(log_2 k) probes, then runs binary search on the bracket [2^{m-1}, 2^m] of size <= k in another ceil(log_2 k) probes, totaling 2 * log_2(k) + O(1) comparisons—AND keeping all memory accesses inside the first few cache lines!
Concept Check Why TimSort Uses Galloping Mode during Asymmetric Merges staff

In Python and Java's TimSort (and database inverted-index intersections), merging a sorted run A of length 1,000 with a sorted run B of length 1,000,000 switches from one-by-one comparison to Exponential (Galloping) Search whenever one run wins 7 times in a row.

When |A| << |B|, linear merging touches all |B| = 1,000,000 elements. Galloping search from the current cursor in B jumps over gaps d_1, d_2, ..., d_{|A|} (where sum d_i = |B|) in sum O(log d_i) <= O(|A| log(|B|/|A|)) time—matching the information-theoretic optimal bound for sorted set intersection!

Key Takeaways

Exponential (Galloping) Search doubles a step offset 1, 2, 4, ..., 2^k before binary searching [2^{k-1}, 2^k], finding an element at distance i in 2 log_2(i) + O(1) comparisons with high L1 cache locality.
In any cyclically rotated sorted array of distinct elements, comparing A[mid] with A[lo] (or A[n-1]) immediately identifies which half is strictly sorted.
When duplicates are allowed in a rotated array, A[lo] == A[mid] == A[hi] forces an Ω(N) worst-case fallback (++lo; --hi).
On a discrete unimodal/bitonic array, binary searching the adjacent difference A[mid] < A[mid+1] finds the peak in log_2(N) steps; on continuous unimodal functions, Golden Section Search improves on Ternary Search by reusing one interior point per iteration.
