Burrows-Wheeler Transform (BWT), Last-to-First (LF) Mapping & FM-Index Substring Search

7 min read Module 4.2: Suffix Structures, Sequence Alignment & Data Compression Updated Oct 23, 2026
📄 Cheat Sheet

Ben Langmead clearly illustrates the BWT matrix, why the k-th occurrence of c in L is the exact same text character as the k-th occurrence of c in F, and how FM-Index backward search works.

Intuition first

How does bzip2 permute a text so that identical characters cluster into long runs without losing a single bit of information, and how do genomics aligners (Bowtie2, BWA) index the 3-billion-base-pair human genome in under 2 GB of RAM while still counting exact occurrences of a length-$M$ DNA read in $O(M)$ time? Both feats rely on the Burrows-Wheeler Transform (BWT, 1994) and Paolo Ferragina and Giovanni Manzini's FM-Index (2000).

If we write down all $N$ cyclic rotations of $S\texttt{\$}$ sorted lexicographically into an $N \times N$ matrix $\mathcal{M}$, the first column $F$ is just the sorted characters of $S\texttt{\$}$, while the last column $L$ is the Burrows-Wheeler Transform: $L[r] = S[(\text{SA}[r] - 1 + N) \bmod N]$, the character immediately preceding suffix $\text{SA}[r]$! Because rotation shifts the last column into the first column while preserving the relative order of suffixes following identical characters, the $k$-th occurrence of character $c$ in $L$ corresponds to the exact same text position as the $k$-th occurrence of $c$ in $F$—the celebrated Last-to-First (LF) Mapping.

1. Constructing the BWT from the Suffix Array & Why It Compresses

Given $S[0..N-1]$ with unique smallest sentinel $S[N-1] = \texttt{'\$'}$ and its Suffix Array $\text{SA}[0..N-1]$, we never materialize the $N \times N$ rotation matrix $\mathcal{M}$. Row $r$ of $\mathcal{M}$ starts at $\text{SA}[r]$ and ends at $(\text{SA}[r] - 1 + N) \bmod N$, so the BWT string $L[0..N-1]$ is computed in one linear pass:

$$L[r] = \begin{cases} S[\text{SA}[r] - 1] & \text{if } \text{SA}[r] > 0 \\ S[N - 1] = \texttt{'\$'} & \text{if } \text{SA}[r] = 0 \end{cases}$$

Why does $L$ have long runs of identical characters? In English text, suffixes starting with $\texttt{"he "}$ are all grouped adjacently in $\text{SA}$; in almost every one of those suffixes, the character immediately preceding $\texttt{"he "}$ is $\texttt{'t'}$, producing a long contiguous run $\texttt{"tttt...t"}$ inside $L$! Applying Move-to-Front (MTF) coding, Run-Length Encoding (RLE), and Huffman/Arithmetic coding to $L$ is the entire pipeline of bzip2.

2. The Last-to-First (LF) Mapping & $O(N)$ Inversion

Why is the BWT reversible? Consider all rows in $\mathcal{M}$ whose last column $L[r]$ equals a specific character $c$. In those rows, the rest of the row $F[r..] $ spells the suffix immediately following that $c$. Since the rows of $\mathcal{M}$ are sorted by those suffixes $F[r..]$, the relative top-to-bottom order of all $c$'s in $L$ is identical to the relative top-to-bottom order of all rows starting with $c$ in $F$ (where $c$ is followed by the exact same sorted suffixes)!

Let $C[c]$ be the total number of characters in $S$ strictly smaller than $c$ (so the bucket for character $c$ in $F$ starts at row $C[c]$), and let $\text{Occ}(c, r)$ be the number of times character $c$ appears in the prefix $L[0..r-1]$ ($0$-indexed exclusive rank). Then row $r$ in $L$ maps to row $\text{LF}(r)$ in $F$:

$$\text{LF}(r) = C[L[r]] + \text{Occ}(L[r],\; r)$$

Starting from the row $r_0$ where $L[r_0] = \texttt{'\$'}$ (or the row corresponding to $\texttt{'\$'}$ in $F$, which is row $0$), repeatedly stepping $r \leftarrow \text{LF}(r)$ reconstructs $S$ backwards from right to left in $O(N)$ time!

3. FM-Index Backward Search in $O(M)$ Time

Even better, $C[c]$ and $\text{Occ}(c, r)$ allow us to count how many times a pattern $P[0..M-1]$ occurs in $S$ in $O(M)$ steps (faster than binary searching a Suffix Array, which takes $O(M \log N)$)! We process $P$ backwards from $j = M - 1$ down to $0$, maintaining the half-open Suffix Array interval $[sp, ep)$ of suffixes prefixed by $P[j..M-1]$:

$$sp_{\text{new}} = C[c] + \text{Occ}(c, sp), \qquad ep_{\text{new}} = C[c] + \text{Occ}(c, ep) \quad \text{where } c = P[j]$$

After $M$ steps, $ep - sp$ is the exact number of occurrences of $P$ in $S$!

LF-Mapping Rank Preservation & Backward-Search Invariant

LF Rank Preservation: For every character $c \in \Sigma$ and $k \ge 1$, the $k$-th occurrence of $c$ in the last column $L$ and the $k$-th occurrence of $c$ in the first column $F$ refer to the exact same index in the original text $S$.
FM-Index Interval: If $[sp, ep)$ is the exact contiguous range of rows in $\text{SA}$ prefixed by suffix $Q$, then $[C[c] + \text{Occ}(c, sp),\; C[c] + \text{Occ}(c, ep))$ is the exact range of rows prefixed by $cQ$.

Popcount Rank Bitvectors in Production FM-Indexes

Storing a full 2D table $\text{Occ}[|\Sigma|][N]$ would take $|\Sigma| \cdot 4N$ bytes. Instead, production genomics aligners (Bowtie2, BWA) store 64-bit bitmasks for each nucleotide ($\{\texttt{A}, \texttt{C}, \texttt{G}, \texttt{T}\}$) inside 64-byte cache-line blocks alongside a single checkpoint counter per block. Computing $\text{Occ}(c, r)$ then reduces to 1 memory load + 1 hardware __builtin_popcountll instruction!

5. Production Implementation: BWT Inversion & FM-Index Backward Search

#include <array>
#include <cstdint>
#include <string>
#include <string_view>
#include <utility>
#include <vector>

class FMIndex {
public:
    // Builds BWT and FM-Index from string s (terminated by '' at s.back()) and its SA
    FMIndex(std::string_view s_with_null, const std::vector<int>& sa)
        : n_(static_cast<int>(s_with_null.size())), bwt_(n_, ''), occ_(n_ + 1) {
        c_.fill(0);
        occ_[0].fill(0);
        for (int r = 0; r < n_; ++r) {
            int prev_idx = (sa[r] == 0) ? (n_ - 1) : (sa[r] - 1);
            uint8_t ch = static_cast<uint8_t>(s_with_null[prev_idx]);
            bwt_[r] = static_cast<char>(ch);
            c_[ch]++;
            occ_[r + 1] = occ_[r];
            occ_[r + 1][ch]++;
        }
        // Convert c_ into exclusive prefix sums (bucket start offsets in F)
        int sum = 0;
        for (int ch = 0; ch < 256; ++ch) {
            int cnt = c_[ch];
            c_[ch] = sum;
            sum += cnt;
        }
    }

    // Reconstructs the original string (excluding trailing '') in O(N) via LF-mapping
    std::string invert_bwt() const {
        std::string out(n_ - 1, '');
        int r = 0; // Row 0 in F starts with '', so L[0] is the last char of S
        for (int i = n_ - 2; i >= 0; --i) {
            uint8_t ch = static_cast<uint8_t>(bwt_[r]);
            out[i] = static_cast<char>(ch);
            r = c_[ch] + occ_[r][ch];
        }
        return out;
    }

    // Counts exact occurrences of pat in O(|pat|) time via FM-Index Backward Search
    int count_matches(std::string_view pat) const {
        int sp = 0, ep = n_;
        for (int j = static_cast<int>(pat.size()) - 1; j >= 0 && sp < ep; --j) {
            uint8_t ch = static_cast<uint8_t>(pat[j]);
            sp = c_[ch] + occ_[sp][ch];
            ep = c_[ch] + occ_[ep][ch];
        }
        return std::max(0, ep - sp);
    }

private:
    int n_;
    std::string bwt_;
    std::array<int, 256> c_{};
    std::vector<std::array<int, 256>> occ_;
};
Inclusive vs. Exclusive Occ(c, r) Indexing in FM-Index

The single most common bug when implementing FM-Index backward search is mixing up inclusive vs. exclusive rank queries $\text{Occ}(c, r)$. When maintaining a half-open Suffix Array interval $[sp, ep)$, $\text{Occ}(c, r)$ MUST count occurrences of $c$ in the prefix of length $r$ ($L[0..r-1]$, exclusive of index $r$), so that BOTH boundary updates use the exact same formula: $sp' = C[c] + \text{Occ}(c, sp)$ and $ep' = C[c] + \text{Occ}(c, ep)$!

Concept Check Relationship Between BWT and the Suffix Array recall

Let $S[0..N-1]$ be a string terminated by a unique smallest sentinel $S[N-1] = \texttt{'\$'}$, and let $\text{SA}[0..N-1]$ be its Suffix Array.

Row $r$ of the sorted cyclic rotation matrix starts with suffix $S[\text{SA}[r]..N-1]$ followed by the wrapped-around prefix $S[0..\text{SA}[r]-1]$. Therefore, the last character of row $r$ is the character immediately preceding index $\text{SA}[r]$ in cyclic order: $S[(\text{SA}[r] - 1 + N) \bmod N]$.
Concept Check Why the Last-to-First (LF) Property Holds apply

The LF-Mapping theorem states that the $k$-th occurrence of character $c$ in the last column $L$ corresponds to the exact same text character as the $k$-th occurrence of $c$ in the first column $F$.

Consider two rows ending with $c$ in $L$, representing cyclic shifts $X c$ and $Y c$ ($X < Y$). When rotated right by 1 character, they become rows $c X$ and $c Y$ in $F$. Since $X < Y \iff c X < c Y$, their top-to-bottom order in $L$ is identical to their top-to-bottom order in $F$!
Concept Check Tracing FM-Index Backward Search apply

On $S = \texttt{"banana\$"}$ ($N = 7$), the first column $F$ has bucket starts $C[\texttt{'\$'}] = 0$, $C[\texttt{'a'}] = 1$, $C[\texttt{'b'}] = 4$, $C[\texttt{'n'}] = 5$, and the BWT is $L = \texttt{"annb\$aa"}$. Suppose we search for $P = \texttt{"na"}$. After processing the last character $\texttt{'a'}$, the active half-open interval of $\texttt{'a'}$-suffixes is $[sp, ep) = [1, 4)$.

In $L = \texttt{"annb\$aa"}$, the prefix of length $1$ is $L[0..0] = \texttt{"a"}$ ($0$ `'n'`s), and the prefix of length $4$ is $L[0..3] = \texttt{"annb"}$ ($2$ `'n'`s at indices 1 and 2). Adding $C[\texttt{'n'}] = 5$ gives $[5 + 0, 5 + 2) = [5, 7)$, corresponding to rows 5 (`"na$"`) and 6 (`"nana$"`).
Concept Check Locating Text Offsets in a Compressed FM-Index via Sampled Suffix Array staff

To keep an FM-Index of the human genome under 2 GB, we do NOT store the full $12\text{ GB}$ Suffix Array $\text{SA}[0..N-1]$. Instead, we only store $\text{SA}[r]$ at rows where $\text{SA}[r]$ is a multiple of $K = 32$ (consuming $1/32$ of the space).

Each application of $r \leftarrow \text{LF}(r)$ moves backward by exactly $1$ character in the original text $S$: $\text{SA}[\text{LF}(r)] = \text{SA}[r] - 1$. Because every $K$-th text position ($0, K, 2K, \dots$) is sampled in $\text{SA}$, at most $K$ LF-steps are needed before hitting a sampled position $\text{SA}[r']$, from which $\text{SA}[r] = \text{SA}[r'] + t$!

Key Takeaways

The Burrows-Wheeler Transform L[r] = S[(SA[r] - 1 + N) mod N] groups characters that precede identical contexts into long homogeneous runs ideal for Move-to-Front and Run-Length compression.
The Last-to-First (LF) property guarantees that the k-th occurrence of character c in L is the exact same text character as the k-th occurrence of c in F, enabling O(N) inversion via LF(r) = C[L[r]] + Occ(L[r], r).
FM-Index backward search processes pattern P from right to left (j = M - 1 down to 0) updating [sp, ep) = [C[c] + Occ(c, sp), C[c] + Occ(c, ep)) to count occurrences in O(M) time.
