Prefix Tries, Compressed Radix Trees & PATRICIA Trees

6 min read Module 4.1: Tries, Exact String Matching & Multi-Pattern Automata Updated Oct 22, 2026
📄 Cheat Sheet
HackerRank Data Structures: Tries & Prefix Tree Operations Watch on YouTube ↗

Explains how prefix sharing works in standard Tries and why path-compressed Radix Trees and Adaptive Radix Trees (ART) dominate production databases and routers.

Intuition first

A balanced binary search tree comparing string keys of length $L$ across $N$ entries requires $O(L \log N)$ character comparisons because each of the $O(\log N)$ node visits re-scans shared prefixes. A Prefix Trie (named by Edward Fredkin from Infotrieval) eliminates key-to-key comparisons entirely: edges are labeled by alphabet symbols $\Sigma$, so looking up a string of length $L$ walks a path of length $L$ in $O(L)$ time independent of $N$, while automatically clustering all keys that share a common prefix into a single subtree.

However, a naive pointer-per-character Trie has two fatal flaws in production: (1) a long unique suffix of length $L$ creates $L$ unary (single-child) nodes, and (2) an alphabet of size $|\Sigma| = 256$ wastes $256 \times 8 = 2\text{ KB}$ per node even when only 1 child pointer is non-null. Compressed Radix Trees coalesce every chain of single-child nodes into a single edge labeled with a substring slice; Donald Morrison's PATRICIA Tree stores only the index of the first differing bit/byte at each internal node, bounding internal nodes to exact $N - 1$ regardless of key length $L$; and Viktor Leis's Adaptive Radix Tree (ART) dynamically resizes node fanout across 4 compact classes (Node4, Node16, Node48, Node256) to match L1 cache lines and SIMD registers.

1. From Uncompressed Tries to Compressed Radix Trees & PATRICIA

Let $\mathcal{S} = \{s_1, s_2, \dots, s_N\}$ be a set of $N$ distinct strings of total length $M = \sum |s_i|$. Compare the three structural representations:

  • Uncompressed Trie: Up to $M + 1$ nodes. Every character transition is an explicit node. Long unique keys create deep chains of degree-1 nodes that cause $L$ sequential L3/DRAM cache misses.
  • Compressed Radix Tree (Compact Prefix Tree): Every internal node must have branching degree $\ge 2$ (unless it marks the end of a key). Any unary chain is collapsed into a single edge storing a string slice $(k, \text{offset}, \text{len})$. Because every internal node branches at least two ways, a Radix Tree over $N$ keys has at most $2N$ nodes ($N$ leaves and $\le N - 1$ branching nodes)!
  • PATRICIA Tree (Practical Algorithm To Retrieve Information Coded In Alphanumeric): Stores keys only at the leaves; each internal node stores only the critical bit/byte position $d$ where its subtrees diverge. During search(q), the traversal skips intermediary bytes completely and only inspects q[d] at each internal node, performing a single full key comparison at the reached leaf to verify whether the skipped prefix segments actually match!
Radix / PATRICIA Node-Count Invariant: In a compressed Radix or PATRICIA tree storing $N \ge 2$ prefix-free keys (or keys terminated with a unique $ sentinel), every internal node has at least $2$ children. By induction on full trees, the total number of internal nodes is at most $N - 1$ and total edges at most $2N - 2$—completely independent of string length $L$!
flowchart LR N4["Node4 (1..4 children)"] <-->|"Grow > 4 / Shrink < 4"| N16["Node16 (5..16 children, SIMD)"] N16 <-->|"Grow > 16 / Shrink < 13"| N48["Node48 (17..48 children, 256B LUT)"] N48 <-->|"Grow > 48 / Shrink < 37"| N256["Node256 (49..256 children, Direct)"]
Hardware & Cache Reality — Adaptive Radix Tree (ART) in Modern In-Memory Databases (DuckDB, HyPer, Umbra): Why does ART beat both Hash Tables (on range scans) and B+ Trees (on point lookups)? Instead of allocating a 256-pointer array at every byte level, ART dynamically selects:
  • Node4 (1–4 children): 4 byte keys + 4 child pointers (fits in a single 64-byte L1 cache line).
  • Node16 (5–16 children): 16 byte keys packed into a single 128-bit SSE register; findChild(byte) broadcasts byte via _mm_set1_epi8 and finds the matching lane in 1 clock cycle via _mm_cmpeq_epi8 + _mm_movemask_epi8 + ctz!
  • Node48 (17–48 children): A 256-byte direct byte-to-slot index table pointing into a 48-element pointer array (saving 80% of the pointer space of Node256 while keeping $O(1)$ lookup).
  • Node256 (49–256 children): Direct 256-pointer array for dense nodes near the root.

2. Production Implementation: Compressed Radix Tree (Insert, Exact Lookup & Prefix Enumeration)

JAVASCRIPT
class RadixNode {
  constructor(edgeLabel = "", value = undefined) {
    this.edgeLabel = edgeLabel;
    this.value = value; // !== undefined if a key terminates at this node
    this.children = new Map(); // firstChar -> RadixNode
  }
}

/**
 * Compressed Radix Tree (Compact Prefix Tree)
 * Guarantees at most 2N nodes regardless of string length L.
 */
class RadixTree {
  constructor() {
    this.root = new RadixNode("");
    this.size = 0;
  }

  _lcpLength(a, b) {
    const len = Math.min(a.length, b.length);
    let i = 0;
    while (i < len && a.charCodeAt(i) === b.charCodeAt(i)) i++;
    return i;
  }

  insert(key, value = true) {
    let curr = this.root;
    let i = 0;
    while (i < key.length) {
      const ch = key[i];
      const child = curr.children.get(ch);
      if (!child) {
        curr.children.set(ch, new RadixNode(key.slice(i), value));
        this.size++;
        return;
      }
      const rem = key.slice(i);
      const lcp = this._lcpLength(rem, child.edgeLabel);
      if (lcp === child.edgeLabel.length) {
        // Consumed entire child edge; continue descending
        curr = child;
        i += lcp;
      } else {
        // Split child edge at index <code>lcp</code>
        const splitNode = new RadixNode(child.edgeLabel.slice(0, lcp));
        curr.children.set(ch, splitNode);

        child.edgeLabel = child.edgeLabel.slice(lcp);
        splitNode.children.set(child.edgeLabel[0], child);

        if (lcp === rem.length) {
          splitNode.value = value;
        } else {
          const newLeaf = new RadixNode(rem.slice(lcp), value);
          splitNode.children.set(newLeaf.edgeLabel[0], newLeaf);
        }
        this.size++;
        return;
      }
    }
    if (curr.value === undefined) this.size++;
    curr.value = value;
  }

  get(key) {
    let curr = this.root;
    let i = 0;
    while (i < key.length) {
      const child = curr.children.get(key[i]);
      if (!child) return undefined;
      const label = child.edgeLabel;
      if (key.length - i < label.length) return undefined;
      for (let j = 0; j < label.length; j++) {
        if (key.charCodeAt(i + j) !== label.charCodeAt(j)) return undefined;
      }
      curr = child;
      i += label.length;
    }
    return curr.value;
  }

  keysWithPrefix(prefix) {
    let curr = this.root;
    let i = 0;
    let accumulated = "";
    while (i < prefix.length) {
      const child = curr.children.get(prefix[i]);
      if (!child) return [];
      const rem = prefix.slice(i);
      const lcp = this._lcpLength(rem, child.edgeLabel);
      if (lcp < rem.length && lcp < child.edgeLabel.length) return [];
      accumulated += child.edgeLabel;
      curr = child;
      i += lcp;
    }
    const results = [];
    const dfs = (node, path) => {
      if (node.value !== undefined) results.push(path);
      for (const child of node.children.values()) {
        dfs(child, path + child.edgeLabel);
      }
    };
    dfs(curr, accumulated);
    return results;
  }
}

Common Pitfall — Skipping One-Way Edge Verification in PATRICIA Lookups: In a PATRICIA tree (or an ART using optimistic path compression where only the edge length prefixLen is stored instead of the full substring), internal nodes skip non-branching bytes and only branch on critical differing bytes. If you return true upon reaching a leaf without comparing the full search key q against the leaf's stored key, any query string that matches at the critical branch bytes but differs at the skipped positions will produce a false positive match! Always perform one full key comparison at the reached leaf.
Check yourself Question 1 of 4
Concept Check Radix Tree Node Count Bound recall

A compressed Radix Tree (Patricia Trie) stores $K$ distinct keys over alphabet $\Sigma$ by merging every unary chain of single-child nodes into a single edge labeled with a substring slice.

In a compressed Radix Tree, every internal node that does not itself hold a terminal key must have at least 2 children (otherwise its single incoming and outgoing edges would be merged). A tree with $L \le K$ leaves where every non-key internal node has degree $\ge 2$ has at most $L - 1$ branching internal nodes, giving at most $2K - 1$ nodes in total—completely independent of string lengths.
Concept Check PATRICIA Single-Bit Branching Verification apply

In Morrison's PATRICIA tree (or Bernstein's Crit-Bit tree), internal nodes store only the critical bit index $b_u$ where the left and right subtries first differ, without storing the intervening shared prefix bits along edges.

Because PATRICIA skips over shared prefix bits between critical bit positions $b_u$, a query $Q$ that differs from every key in the tree on one of those skipped bits will still follow some path to a leaf $K$. A single full equality check $Q == K$ at the leaf verifies all skipped bits at once; if $Q \neq K$, the most significant bit of $Q \oplus K$ gives the exact new critical bit where $Q$ must be branched.
Concept Check Adaptive Radix Tree (ART) Node48 Layout apply

Leis et al.'s Adaptive Radix Tree (ART) uses four adaptive node sizes (`Node4`, `Node16`, `Node48`, `Node256`) to avoid allocating a 256-pointer array (`2 KB`) at every sparse internal node.

`Node48` avoids both binary/SIMD search overhead (once $>16$ children exist) and the $2048$-byte cost of `Node256` by introducing one level of byte indirection: `uint8_t child_index[256]` (256 bytes) indexes directly into `Node* children[48]` (384 bytes), totaling 640 bytes (~3x smaller than `Node256`).
Concept Check Pointer Invalidation in Contiguous `std::vector<Node>` Arenas staff

Consider this C++ Trie insertion snippet using a flat `std::vector<Node> arena`: ```cpp int u = 0; for (char ch : word) { int& next_id = arena[u].child[ch - 'a']; if (next_id == 0) { arena.emplace_back(); next_id = static_cast<int>(arena.size()) - 1; // <-- BUG! } u = next_id; } ```

Taking `int& next_id = arena[u].child[c]` holds a raw memory address inside `arena.data()`. When `arena.emplace_back()` exceeds `arena.capacity()`, `std::vector` allocates a new buffer, moves existing elements, and frees the old buffer—leaving `next_id` pointing into deallocated memory. Always compute the new index first or assign `arena[u].child[c] = new_idx` after `emplace_back()`.

Key Takeaways

Uncompressed Tries achieve O(L) lookup independent of N, but suffer O(N * L) worst-case node count on long unique strings and high pointer overhead on large alphabets.
Compressed Radix Trees collapse unary paths into single edges labeled with substring slices, bounding total nodes to at most 2N (<= N - 1 internal branching nodes).
PATRICIA trees store only the critical bit/byte offset at internal nodes and perform a single full-key verification at the leaf.
Adaptive Radix Trees (ART) dynamically transition nodes between Node4, Node16 (SIMD), Node48 (256B LUT), and Node256 to combine trie speed with B-tree cache density.
