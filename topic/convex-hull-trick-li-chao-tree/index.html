Explains the geometric duality between algebraically expanding quadratic DP transitions into y = mx + b lines and maintaining their lower envelope with a deque or Li Chao Segment Tree.

Intuition first

Suppose a DP transition looks like dp[i]=min⁡j<i(dp[j]+(xi−xj)2)dp[i] = \min_{j < i} (dp[j] + (x_i - x_j)^2)dp[i]=minj<i​(dp[j]+(xi​−xj​)2). Expanding the square gives dp[i]=xi2+min⁡j<i(−2xj⏟mj⋅xi+dp[j]+xj2⏟bj)dp[i] = x_i^2 + \min_{j < i} (\underbrace{-2x_j}_{m_j} \cdot x_i + \underbrace{dp[j] + x_j^2}_{b_j})dp[i]=xi2​+minj<i​(mj​−2xj​​​⋅xi​+bj​dp[j]+xj2​​​). Each previous state jjj defines a straight line Lj(x)=mjx+bjL_j(x) = m_j x + b_jLj​(x)=mj​x+bj​, and finding the best jjj at query point xix_ixi​ is simply evaluating the lower envelope of a set of lines! When slopes mjm_jmj​ are inserted monotonically, a stack/deque maintains the lower envelope in O(1)O(1)O(1) amortized time. 1. Formal Invariant — Lower Envelope & Li Chao Midpoint Dominance

Invariant 1: Monotonic Deque CHT Redundancy Condition

Given three lines L1,L2,L3L_1, L_2, L_3L1​,L2​,L3​ with strictly decreasing slopes m1>m2>m3m_1 > m_2 > m_3m1​>m2​>m3​ (for minimum queries), the middle line L2L_2L2​ is completely redundant (never strictly minimal at any xxx) if and only if the intersection x(L1,L3)x(L_1, L_3)x(L1​,L3​) lies to the left of or at x(L1,L2)x(L_1, L_2)x(L1​,L2​):

Invariant 2: Li Chao Segment Tree Midpoint Property

Each node covering coordinate range [L,R][L, R][L,R] with midpoint M=⌊(L+R)/2⌋M = \lfloor (L + R) / 2 \rfloorM=⌊(L+R)/2⌋ stores a line seg\text{seg}seg that is dominant at MMM. 3. Choosing the Right Envelope Data Structure

Depending on monotonicity of inserted slopes mjm_jmj​ and query coordinates xix_ixi​, four regimes arise:

  1. Slopes mjm_jmj​ monotonic + Queries xix_ixi​ monotonic: Use a std::deque with a moving front pointer and back-hull pruning in O(1)O(1)O(1) amortized per step (O(N)O(N)O(N) total).
  2. Slopes mjm_jmj​ monotonic + Queries xix_ixi​ arbitrary: Maintain the hull in a std::vector and binary search the optimal line at xix_ixi​ in O(log⁡N)O(\log N)O(logN) per query.
  3. Slopes mjm_jmj​ arbitrary + Queries xix_ixi​ arbitrary (Integer/Bounded Domain): Use a Li Chao Segment Tree (or dynamic implicit Li Chao Tree) in O(Nlog⁡(range))O(N \log(\text{range}))O(Nlog(range)) time—completely free of division or floating-point intersection bugs!
  4. Slopes mjm_jmj​ arbitrary + Floating-Point Domain: Use KACTL's LineContainer (std::multiset ordered by slope maintaining right-intersection endpoints) in O(Nlog⁡N)O(N \log N)O(NlogN) time.

4. Hardware & Cache Behavior

In cross-multiplication (b3−b1)(m1−m2)≤(b2−b1)(m1−m3)(b_3 - b_1)(m_1 - m_2) \le (b_2 - b_1)(m_1 - m_3)(b3​−b1​)(m1​−m2​)≤(b2​−b1​)(m1​−m3​), if bj∼1015b_j \sim 10^{15}bj​∼1015 and mj∼109m_j \sim 10^9mj​∼109, the product reaches 102410^{24}1024, overflowing int64_t! 6. Production-Grade C++20 Implementation (Dynamic Implicit Li Chao Tree)

C++2082 lines
#include <vector>
#include <cstdint>
#include <limits>
#include <algorithm>

class DynamicLiChaoTree {
public:
    static constexpr int64_t INF = std::numeric_limits<int64_t>::max() / 4;

    struct Line {
        int64_t m = 0;
        int64_t b = INF;
        int64_t eval(int64_t x) const { return m * x + b; }
    };

private:
    struct Node {
        Line line;
        int left = -1;
        int right = -1;
    };

    int64_t x_min_, x_max_;
    std::vector<Node> pool_;

    int new_node() {
        pool_.push_back(Node{});
        return static_cast<int>(pool_.size()) - 1;
    }

    void add_line(int u, int64_t l, int64_t r, Line nw) {
        int64_t mid = l + (r - l) / 2;
        bool left_better = nw.eval(l) < pool_[u].line.eval(l);
        bool mid_better  = nw.eval(mid) < pool_[u].line.eval(mid);

        if (mid_better) {
            std::swap(pool_[u].line, nw);
        }
        if (l == r) return;

        if (left_better != mid_better) {
            if (pool_[u].left == -1) {
                int c = new_node();
                pool_[u].left = c;
            }
            add_line(pool_[u].left, l, mid, nw);
        } else {
            if (pool_[u].right == -1) {
                int c = new_node();
                pool_[u].right = c;
            }
            add_line(pool_[u].right, mid + 1, r, nw);
        }
    }

    int64_t query(int u, int64_t l, int64_t r, int64_t x) const {
        if (u == -1) return INF;
        int64_t res = pool_[u].line.eval(x);
        if (l == r) return res;
        int64_t mid = l + (r - l) / 2;
        if (x <= mid) {
            return std::min(res, query(pool_[u].left, l, mid, x));
        } else {
            return std::min(res, query(pool_[u].right, mid + 1, r, x));
        }
    }

public:
    DynamicLiChaoTree(int64_t x_min, int64_t x_max, int reserve_nodes = 200000)

    }

    void insert(int64_t m, int64_t b) {

    }

    int64_t query(int64_t x) const {
        return query(0, x_min_, x_max_, x);
    }
};

Production Pitfall — Reference Invalidations When Allocating Nodes

In a std::vector<Node> pool, never write pool_[u].left = new_node() as a single expression! In C++, the left-hand side pool_[u].left reference may be evaluated before new_node() triggers a std::vector reallocation, leaving a dangling reference and corrupting memory. Always store int c = new_node(); first and then assign pool_[u].left = c;.

Key Takeaways

Whenever a DP transition can be factored into f(i) + min_j (m(j) * x(i) + b(j)), it reduces to evaluating the lower envelope of lines y = m_j x + b_j.
With monotonic slopes and monotonic queries, a deque maintains the lower envelope in O(1) amortized time using __int128_t cross-products to check intersection ordering.
A Li Chao Segment Tree stores at each node the line dominant at the interval midpoint M; since two lines cross at most once, the loser at M can only win on one half, bounding insertion to O(log X).
In dynamic node pools backed by std::vector, always capture the index returned by new_node() in a local variable before indexing pool_[u] to prevent reallocation UB.
