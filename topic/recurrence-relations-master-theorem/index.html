Systematically derives the three cases of the Master Theorem for T(n) = aT(n/b) + f(n) by comparing leaf work n^(log_b a) against root driving work f(n).

Intuition first

Every divide-and-conquer algorithm splits a problem of size nnn into aaa subproblems of size n/bn/bn/b and spends f(n)f(n)f(n) non-recursive work dividing and combining results, yielding the recurrence T(n)=a T(n/b)+f(n)T(n) = a\,T(n/b) + f(n)T(n)=aT(n/b)+f(n). When you unroll this recurrence into a recursion tree of depth log⁡bn\log_b nlogb​n, a fundamental tug-of-war emerges between two forces: the geometric proliferation of subproblems (ada^dad nodes at depth ddd, reaching alog⁡bn=nlog⁡baa^{\log_b n} = n^{\log_b a}alogb​n=nlogb​a leaves at the bottom) and the shrinking per-node cost f(n/bd)f(n / b^d)f(n/bd).

The Master Theorem resolves this tug-of-war immediately by comparing the non-recursive driving function f(n)f(n)f(n) against the watershed function nlog⁡ban^{\log_b a}nlogb​a: either the leaves dominate (Case 1), all log⁡bn\log_b nlogb​n tree levels contribute equally (Case 2), or the root dominates (Case 3).

Formal Specification: Polynomial Gap Requirement & The Substitution Method

In Case 1 and Case 3, f(n)f(n)f(n) must be polynomially smaller or larger than nlog⁡ban^{\log_b a}nlogb​a by a factor of n±ϵn^{\pm \epsilon}n±ϵ for some constant ϵ>0\epsilon > 0ϵ>0. Hardware Reality: Recursion Tree Base-Case Coarsening (nleaf=32–64n_{\text{leaf}} = 32\text{–}64nleaf​=32–64)

In a naive recursive implementation of Mergesort or Strassen's algorithm that recurses all the way down to n=1n = 1n=1, Case 1 and Case 2 show that the recursion tree generates Θ(nlog⁡ba)\Theta(n^{\log_b a})Θ(nlogb​a) leaves. In fact, in a binary recursion tree (a=2,b=2a = 2, b = 2a=2,b=2), 50% of all recursive function calls occur at the very bottom leaf level (n=1n = 1n=1), and 75% occur in the bottom two levels! If you coarsen the base case to switch to an in-place iterative kernel (like Insertion Sort for Mergesort or an AVX-512 register micro-kernel for GEMM) at nbase=32n_{\text{base}} = 32nbase​=32, you prune the bottom log⁡232=5\log_2 32 = 5log2​32=5 levels of the recursion tree, eliminating 96.875%96.875\%96.875% (31/3231/3231/32) of all function call frames while keeping each leaf tile completely inside L1 cache.

// C++20: Coarsened Divide-and-Conquer with L1-Cache Base Case (Eliminating 97% of Call Frames)
#include <algorithm>
#include <cstddef>
#include <span>

// Base case threshold: 32 int64_t elements = 256 bytes (4 L1 cache lines)
constexpr size_t kLeafThreshold = 32;

void insertionSortBase(std::span<int64_t> a) noexcept {
    for (size_t i = 1; i < a.size(); ++i) {
        int64_t key = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1] > key) {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = key;
    }
}

// Recurrence: T(n) = 2 T(n/2) + Theta(n), pruned at n <= 32
void coarsenedMergeSort(std::span<int64_t> a, std::span<int64_t> scratch) noexcept {
    const size_t n = a.size();
    if (n <= kLeafThreshold) {
        insertionSortBase(a); // Prunes bottom 5 levels of recursion tree!
        return;
    }
    const size_t mid = n / 2;
    coarsenedMergeSort(a.first(mid), scratch.first(mid));
    coarsenedMergeSort(a.subspan(mid), scratch.subspan(mid));

    // Skip merge if already ordered across boundary (Best-Case Theta(n))
    if (a[mid - 1] <= a[mid]) return;

    std::merge(a.first(mid).begin(), a.first(mid).end(),
               a.subspan(mid).begin(), a.subspan(mid).end(),
               scratch.begin());
    std::copy(scratch.begin(), scratch.begin() + n, a.begin());
}

Concept Check Number of Leaves & Watershed Function in a Recursion Tree recall

In the divide-and-conquer recurrence `T(n) = a T(n/b) + f(n)` with `a ≥ 1` and `b > 1`, what is the recursion tree depth and how many leaf subproblems exist at the bottom level?

Each level divides the problem size by `b`, reaching size 1 at depth `d = log_b(n)`. Since the branching factor is `a`, level `d` has `a^d = a^{log_b(n)} = n^{log_b(a)}` leaves.
Concept Check Solving Polylogarithmic Gap Recurrences (Generalized Case 2) apply

Consider the recurrence `T(n) = 4 T(n/2) + n² / log₂(n)`. Why does Master Theorem Case 1 NOT apply, and what is the tight closed-form solution?

Here `n^{log_b a} = n^{log₂ 4} = n²`. Although `f(n) = n² / log n` is asymptotically smaller than `n²`, the ratio `n² / f(n) = log n` is `o(n^ε)` for every `ε > 0`, violating Case 1's polynomial gap requirement. Summing work across `log₂ n` levels yields `n² Σ_{j=1}^{log n} (1/j) = Θ(n² log log n)`.
Concept Check Change of Variables for Square-Root Recurrences apply

What is the tight asymptotic bound for the recurrence `T(n) = 2 T(√n) + log₂(n)` (which governs helper operations in van Emde Boas trees)?

Let `m = log₂ n` so `n = 2^m` and `√n = 2^{m/2}`. Defining `S(m) = T(2^m)` transforms the recurrence into `S(m) = 2 S(m/2) + m`. By Master Theorem Case 2 (`a=2, b=2, f(m)=m`), `S(m) = Θ(m log m)`. Substituting back `m = log₂ n` gives `T(n) = Θ(log n · log log n)`.
Concept Check Strengthening Inductive Hypotheses in the Substitution Method staff

You want to prove by mathematical induction that `T(n) = 2 T(⌊n/2⌋) + 1` satisfies `T(n) ∈ O(n)`. When you test the inductive hypothesis `T(k) ≤ c·k`, the inductive step yields `T(n) ≤ 2(c·(n/2)) + 1 = c·n + 1`, which fails to be `≤ c·n`. How do you fix this proof rigorously?

Changing the constant `c` between levels is a classic mathematical fallacy (since `Σ (1/n)` across `log n` levels diverges or inflates `c`). Subtracting a lower-order term `T(k) ≤ c·k - d` gets doubled by the `2 T(n/2)` branching factor into `-2d`, easily absorbing the `+1` additive overhead when `d ≥ 1`.

Key Takeaways

In T(n) = a T(n/b) + f(n), the recursion tree has depth log_b(n) and exactly a^(log_b n) = n^(log_b a) leaves, defining the watershed function.
Master Theorem Case 1 (leaf-heavy) and Case 3 (root-heavy) require a polynomial gap n^(±ε) between f(n) and n^(log_b a); polylogarithmic gaps fall into generalized Case 2.
When proving an upper bound via the Substitution Method fails by a lower-order additive term (e.g., cn + 1), strengthen the inductive hypothesis by subtracting a lower-order term (cn - d).
