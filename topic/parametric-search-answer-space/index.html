Intuition first

When a problem asks to minimize the maximum resource XXX (or maximize the minimum separation XXX) and computing the optimal XXX directly feels intractable, flip the question on its head: 'If someone hands me a fixed budget XXX, can I verify whether XXX is achievable in O(N)O(N)O(N) time?' Optimization vs. Decision Duality (Megiddo's Parametric Search)

Many combinatorial optimization problems have the form:

min⁡ {X∈[L,R]:feasible(X)=True}ormax⁡ {X∈[L,R]:feasible(X)=True}\min \,\{ X \in [L, R] : \text{feasible}(X) = \text{True} \} \quad \text{or} \quad \max \,\{ X \in [L, R] : \text{feasible}(X) = \text{True} \}min{X∈[L,R]:feasible(X)=True}ormax{X∈[L,R]:feasible(X)=True}

Constructing the globally optimal schedule or partition from scratch can require dynamic programming in O(N2K)O(N^2 K)O(N2K) time. Yet checking the decision problem—given a candidate threshold XXX, does there exist a valid configuration with cost ≤X\le X≤X?—can often be solved by a simple O(N)O(N)O(N) greedy scan! This reduction is valid whenever the feasibility predicate satisfies monotonicity:

  • Minimization (False →\to→ True): If budget XXX is sufficient, any larger budget X′>XX' > XX′>X is also sufficient ([F,F,…,F,T,T,…,T][F, F, \dots, F, T, T, \dots, T][F,F,…,F,T,T,…,T]). We seek the first True.
  • Maximization (True →\to→ False): If minimum separation XXX is achievable, any smaller separation X′<XX' < XX′<X is also achievable ([T,T,…,T,F,F,…,F][T, T, \dots, T, F, F, \dots, F][T,T,…,T,F,F,…,F]). We seek the last True.

Hardware Reality: Floating-Point Binary Search Trap (while (hi - lo > eps) Infinite Loops!)

When binary searching over continuous IEEE-754 double values, writing while (hi - lo > 1e-9) is a classic production time-bomb! An IEEE-754 double has 53 bits of significand precision (approx15ext–17approx 15 ext{–}17approx15ext–17 decimal digits). If your answer XXX is around 10810^8108, the spacing between adjacent representable doubles (1 ULP = 2−52×108≈2.2×10−82^{-52} \times 10^8 \approx 2.2 \times 10^{-8}2−52×108≈2.2×10−8) is larger than 1e-9! At that point, mid = (lo + hi) * 0.5 rounds to either exact lo or exact hi, and while (hi - lo > 1e-9) spins in an infinite loop forever. Golden Rule: For floating-point binary search, always use a fixed iteration count (for (int iter = 0; iter < 70; ++iter)), which halves the interval 270≈10212^{70} \approx 10^{21}270≈1021 times down to machine epsilon and guarantees termination!

// 1. Discrete Parametric Search: Split array w of non-negative ints into <= k contiguous subarrays
//    minimizing the maximum subarray sum. Time: O(N log(sum(w))), Space: O(1).
std::int64_t minimize_max_subarray_sum(const std::vector<std::int64_t>& w, std::size_t k) noexcept {
    std::int64_t lo = *std::max_element(w.begin(), w.end());
    std::int64_t hi = std::accumulate(w.begin(), w.end(), std::int64_t{0});

    auto feasible = [&](std::int64_t cap) noexcept -> bool {
        std::size_t buckets = 1;
        std::int64_t cur = 0;
        for (std::int64_t x : w) {
            if (cur + x > cap) {
                ++buckets;
                cur = x;
                if (buckets > k) return false; // Early exit!
            } else {
                cur += x;
            }
        }
        return true;
    };

    while (lo < hi) {
        const std::int64_t mid = lo + (hi - lo) / 2;
        if (feasible(mid)) hi = mid;
        else               lo = mid + 1;
    }
    return lo;
}

// 2. Continuous Parametric Search (0-1 Fractional Programming):
//    Choose exactly k items to maximize (sum a_i) / (sum b_i) where b_i > 0.
double maximize_ratio_subset(const std::vector<double>& a,
                             const std::vector<double>& b,
                             std::size_t k) {
    const std::size_t n = a.size();
    double lo = 0.0, hi = 0.0;
    for (std::size_t i = 0; i < n; ++i) hi = std::max(hi, a[i] / b[i]);

    std::vector<double> residuals(n);
    // Fixed 64 iterations: immune to IEEE-754 ULP underflow infinite loops!
    for (int iter = 0; iter < 64; ++iter) {
        const double mid = lo + 0.5 * (hi - lo);
        for (std::size_t i = 0; i < n; ++i) {
            residuals[i] = a[i] - mid * b[i];
        }
        // Use O(N) Introselect (nth_element) instead of O(N log N) sort to sum top k residuals!
        std::nth_element(residuals.begin(),
                         residuals.begin() + static_cast<std::ptrdiff_t>(k),
                         residuals.end(),
                         std::greater<double>{});
        double top_k_sum = 0.0;
        for (std::size_t i = 0; i < k; ++i) top_k_sum += residuals[i];

        if (top_k_sum >= 0.0) lo = mid;
        else                  hi = mid;
    }
    return lo;
}

Concept Check Necessary and Sufficient Condition for Parametric Search recall

You want to find the minimum capacity X required to complete a scheduling task within K days by binary searching over X in [lo, hi].

Binary search on the answer space requires only that the boolean predicate feasible(X) be monotonic—transitioning at most once from false to true (for minimization) or from true to false (for maximization).
Concept Check Tight Search Bounds & Negative-Weight Failure in Split Array Largest Sum apply

Given an array w of N integers and an integer K, we want to partition w into at most K contiguous subarrays to minimize the maximum subarray sum.

When all weights are >= 0, prefix sums within a subarray grow monotonically, so the greedy strategy 'pack as many items as possible until cur + w[i] > X' is optimal. With negative weights, a subarray sum could exceed X at index i and later drop below X at index i + 3, invalidating the greedy oracle.
Concept Check 0/1 Fractional Programming via Dinkelbach's Transformation apply

Each of N items has profit a_i and positive cost b_i > 0. You must select exactly K items to maximize the ratio (sum_{i in S} a_i) / (sum_{i in S} b_i).

Because b_i > 0, (sum_{i in S} a_i) / (sum_{i in S} b_i) >= lambda is algebraically equivalent to sum_{i in S} (a_i - lambda * b_i) >= 0. Selecting the K items with the largest transformed weights d_i = a_i - lambda * b_i via std::nth_element tests feasibility in O(N) time!
Concept Check IEEE-754 ULP Starvation in Floating-Point Binary Search staff

In a production geometry service, a continuous binary search over `double lo = 0.0, hi = 1e9;` uses the loop `while (hi - lo > 1e-9) { double mid = 0.5 * (lo + hi); ... }`. In production, the service intermittently hangs at 100% CPU.

IEEE-754 double has 53 bits of mantissa (~15-17 significant decimal digits). At magnitude 10^9, adjacent representable doubles differ by ~2.22e-7, so `hi - lo` can never shrink below 1e-9 without becoming 0. Running a fixed number of iterations (e.g., 70 iterations) halves the interval 2^70 times and always terminates.

Key Takeaways

Parametric Search transforms min-max or max-min optimization problems into a binary search over candidate answers X coupled with a fast O(N) feasibility check.
In 0-1 Fractional Programming, testing whether (∑ a_i) / (∑ b_i) >= λ reduces to checking whether the top-k largest values of (a_i - λ b_i) sum to >= 0 (solvable in O(N) per step via std::nth_element).
For floating-point binary search, always run a fixed number of iterations (60–80) rather than while (hi - lo > eps) to prevent infinite loops when eps is smaller than 1 ULP.
Always verify that item weights satisfy the greedy oracle's precondition (e.g., w_i >= 0 for greedy prefix packing).
