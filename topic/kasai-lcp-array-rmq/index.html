Kasai's O(N) LCP Array Algorithm & Counting Distinct Substrings via SA + LCP

7 min read Module 4.2: Suffix Structures, Sequence Alignment & Data Compression Updated Oct 23, 2026
📄 Cheat Sheet
WilliamFiset Kasai's LCP Array Algorithm and Suffix Array Applications Watch on YouTube ↗

Demonstrates Kasai's h >= lcp - 1 invariant in text order and shows how SA + LCP immediately counts distinct substrings and finds longest repeated substrings.

Intuition first

A Suffix Array $\text{SA}[0..N-1]$ by itself loses the internal branching depth information of a Suffix Tree. We restore all of that power by computing the Longest Common Prefix (LCP) Array $\text{lcp}[0..N-2]$, where $\text{lcp}[r]$ is the length of the longest common prefix between adjacent sorted suffixes $\text{SA}[r]$ and $\text{SA}[r+1]$. Computing $\text{lcp}[r]$ naively in sorted rank order $r = 0..N-2$ takes $O(N^2)$ time because two adjacent suffixes in $\text{SA}$ can come from completely unrelated positions in the text.

Toru Kasai et al. (2001) discovered that if you compute LCP values in text order ($i = 0, 1, \dots, N-1$) instead of rank order, dropping the first character of suffix $S[i..]$ and its predecessor in $\text{SA}$ moves you to suffix $S[i+1..]$ while reducing their shared common prefix by at most $1$ character: $\text{lcp}[\text{rank}[i+1]] \ge \text{lcp}[\text{rank}[i]] - 1$! Just like KMP and the Z-algorithm, the matched length $h$ decreases at most $N$ times and increases at most $N$ times, constructing the entire LCP array in $O(N)$ time.

1. Kasai's Theorem: Why $\text{LCP}$ Drops by at Most $1$ in Text Order

Let $\text{rank}[i] \in [0, N-1]$ be the inverse permutation of $\text{SA}$, so $\text{SA}[\text{rank}[i]] = i$. Suppose suffix $i$ at rank $r = \text{rank}[i] < N - 1$ shares a longest common prefix of length $h > 0$ with the next suffix in sorted order, $j = \text{SA}[r + 1]$:

$$\text{LCP}(S[i..],\; S[j..]) = h > 0 \implies S[i..i+h-1] = S[j..j+h-1]$$

Now delete the first character $S[i] = S[j]$ from both suffixes! We obtain suffix $S[i+1..]$ and suffix $S[j+1..]$:

  1. Because $S[i..]$ is lexicographically smaller than $S[j..]$ and their first characters are identical ($h \ge 1$), suffix $S[i+1..]$ MUST still be lexicographically smaller than $S[j+1..]$, so $\text{rank}[i+1] < \text{rank}[j+1]$.
  2. Moreover, $S[i+1..]$ and $S[j+1..]$ share a common prefix of length exactly $h - 1$: $S[i+1..i+h-1] = S[j+1..j+h-1]$.
  3. By the LCP Range Minimum Property, any suffix lying lexicographically between $\text{rank}[i+1]$ and $\text{rank}[j+1]$ in $\text{SA}$ (specifically the immediate neighbor $\text{SA}[\text{rank}[i+1] + 1]$) must ALSO share a common prefix of length at least $h - 1$ with $S[i+1..]$!

Therefore, when moving from text index $i$ to $i + 1$, we simply set if (h > 0) --h; and start comparing characters from offset $h$ onward!

2. Three Classic Applications of $\text{SA} + \text{LCP}$

  • Arbitrary Suffix LCP via RMQ: For any two suffixes at ranks $r_1 < r_2$ in $\text{SA}$, the length of their longest common prefix is the minimum of adjacent LCPs between them: $$\text{LCP}(\text{SA}[r_1],\; \text{SA}[r_2]) = \min_{r_1 \le k < r_2} \text{lcp}[k]$$ Building a Sparse Table over $\text{lcp}[0..N-2]$ answers $\text{LCP}(i, j)$ for any two text positions in $O(1)$ time!
  • Counting Distinct Substrings in $O(N)$: Every substring of $S$ is a prefix of some suffix $\text{SA}[r]$. Suffix $\text{SA}[r]$ has length $N - \text{SA}[r]$, so it contributes $N - \text{SA}[r]$ prefixes in total, of which $\text{lcp}[r-1]$ were already counted as prefixes of the preceding suffix $\text{SA}[r-1]$. Summing the newly introduced prefixes across all ranks gives: $$\text{Distinct Substrings}(S) = \frac{N(N + 1)}{2} - \sum_{r=0}^{N-2} \text{lcp}[r]$$
  • Longest Repeated Substring: The maximum value $\max_{0 \le r < N-1} \text{lcp}[r]$ is the exact length of the longest substring that appears at least twice in $S$.

Kasai Lower-Bound & LCP-RMQ Duality Invariant

For every text position $i \in [0, N-2]$ with $\text{rank}[i] < N - 1$, $\text{lcp}[\text{rank}[i + 1]] \ge \text{lcp}[\text{rank}[i]] - 1$. Furthermore, for any sorted ranks $0 \le l < r < N$, $\text{LCP}(\text{SA}[l], \text{SA}[r]) = \min_{l \le k < r} \text{lcp}[k]$, which is the exact array-based dual of the Lowest Common Ancestor (LCA) depth of leaves $l$ and $r$ in the Suffix Tree.

64-Bit Overflow in N(N + 1) / 2 Distinct Substring Counts

For a string of length $N = 10^5$, the total number of substrings $\frac{N(N + 1)}{2}$ is approximately $5 \times 10^9$, which overflows a signed 32-bit int (max $\approx 2.14 \times 10^9$). Always accumulate $\frac{N(N+1)}{2} - \sum \text{lcp}[r]$ in a 64-bit integer (int64_t / long long).

4. Production Implementation: Kasai's $O(N)$ LCP & Distinct Substring Counter

#include <cstdint>
#include <numeric>
#include <string_view>
#include <vector>

// Kasai's O(N) Algorithm: returns lcp[0..N-2] where lcp[r] = LCP(SA[r], SA[r+1])
std::vector<int> build_lcp_kasai(std::string_view s, const std::vector<int>& sa) {
    const int n = static_cast<int>(s.size());
    if (n <= 1) return {};

    std::vector<int> rank(n, 0);
    for (int r = 0; r < n; ++r) {
        rank[sa[r]] = r;
    }

    std::vector<int> lcp(n - 1, 0);
    int h = 0;
    for (int i = 0; i < n; ++i) {
        if (rank[i] == n - 1) {
            h = 0;
            continue;
        }
        int j = sa[rank[i] + 1];
        while (i + h < n && j + h < n && s[i + h] == s[j + h]) {
            ++h;
        }
        lcp[rank[i]] = h;
        if (h > 0) --h;
    }
    return lcp;
}

// Counts total distinct non-empty substrings of S in O(N) after SA + LCP construction
int64_t count_distinct_substrings(int64_t n, const std::vector<int>& lcp) {
    int64_t total_substrings = n * (n + 1) / 2;
    int64_t duplicate_prefixes = std::accumulate(lcp.begin(), lcp.end(), int64_t{0});
    return total_substrings - duplicate_prefixes;
}
Off-By-One Convention in LCP Indexing

Two conventions exist in textbooks and competitive programming libraries: some define $\text{lcp}[r] = \text{LCP}(\text{SA}[r], \text{SA}[r+1])$ of length $N - 1$ (so $\text{LCP}(\text{SA}[l], \text{SA}[r]) = \min_{l \le k < r} \text{lcp}[k]$), while others define $\text{lcp}[r] = \text{LCP}(\text{SA}[r-1], \text{SA}[r])$ of length $N$ with $\text{lcp}[0] = 0$ (so $\text{LCP}(\text{SA}[l], \text{SA}[r]) = \min_{l + 1 \le k \le r} \text{lcp}[k]$). Notice that in both conventions the RMQ interval spans $r - l$ elements, NOT $r - l + 1$! Querying $\min_{l \le k \le r} \text{lcp}[k]$ accidentally includes the boundary with $\text{SA}[r+1]$ (or $\text{SA}[l-1]$) and corrupts the LCP query.

Concept Check Kasai's Core Inequality recall

In Kasai's $O(N)$ LCP construction algorithm, we iterate through suffixes in text order $i = 0, 1, \dots, N-1$ rather than sorted Suffix Array order $r = 0, 1, \dots, N-1$.

Deleting the first matched character $S[i] = S[j]$ leaves a common prefix of length $h - 1$ between $S[i+1..]$ and $S[j+1..]$ while preserving their lexicographical order ($\text{rank}[i+1] < \text{rank}[j+1]$). Since LCP between two suffixes is the minimum of adjacent LCPs between their ranks, the first adjacent LCP $\text{lcp}[\text{rank}[i+1]]$ must be $\ge \text{LCP}(S[i+1..], S[j+1..]) = h - 1$.
Concept Check Counting Distinct Substrings from SA and LCP apply

For $S = \texttt{"abab"}$ ($N = 4$), the sorted suffixes are: - Rank 0: `"ab"` ($\text{SA}[0] = 2$) - Rank 1: `"abab"` ($\text{SA}[1] = 0$), with $\text{lcp}[0] = \text{LCP}(\texttt{"ab"}, \texttt{"abab"}) = 2$ - Rank 2: `"b"` ($\text{SA}[2] = 3$), with $\text{lcp}[1] = \text{LCP}(\texttt{"abab"}, \texttt{"b"}) = 0$ - Rank 3: `"bab"` ($\text{SA}[3] = 1$), with $\text{lcp}[2] = \text{LCP}(\texttt{"b"}, \texttt{"bab"}) = 1$

Out of the $\frac{4 \times 5}{2} = 10$ total non-empty substrings (prefixes of all suffixes), $\text{lcp}[0] = 2$ (`"a"`, `"ab"`) and $\text{lcp}[2] = 1$ (`"b"`) are duplicate prefixes already counted in the preceding sorted suffix. Subtracting $2 + 0 + 1 = 3$ leaves $7$ distinct substrings.
Concept Check RMQ Range Bounds for Arbitrary Suffix LCP apply

We define $\text{lcp}[k] = \text{LCP}(\text{SA}[k], \text{SA}[k + 1])$ for $0 \le k \le N - 2$. Suppose two suffixes $S[i..]$ and $S[j..]$ have sorted ranks $r_1 = \text{rank}[i] = 2$ and $r_2 = \text{rank}[j] = 5$.

Between ranks $2$ and $5$ there are $5 - 2 = 3$ adjacent steps: $(2, 3)$ stored at $\text{lcp}[2]$, $(3, 4)$ stored at $\text{lcp}[3]$, and $(4, 5)$ stored at $\text{lcp}[4]$. Including $\text{lcp}[5] = \text{LCP}(\text{SA}[5], \text{SA}[6])$ is an off-by-one error that leaks information from rank $6$.
Concept Check Sum of $\text{LCP}(S[i..], S[j..])$ Over All Pairs $0 \le i < j < N$ staff

You are asked to compute $\sum_{0 \le i < j < N} \text{LCP}(S[i..], S[j..])$ for a string of length $N = 2 \times 10^5$ in $O(N \log N)$ or $O(N)$ time.

Reindexing pairs $(i, j)$ by their sorted Suffix Array ranks $(r_1, r_2)$ with $0 \le r_1 < r_2 < N$ shows that every pair $(r_1, r_2)$ corresponds bijectively to a contiguous subarray $\text{lcp}[r_1 .. r_2 - 1]$ of the LCP array, and its value is the subarray minimum! A standard monotonic stack computes the sum of minimums of all subarrays of `lcp[0..N-2]` in $O(N)$ time.

Key Takeaways

Kasai's algorithm computes the LCP array in O(N) time by iterating in text order i = 0..N-1 and exploiting the inequality lcp[rank[i+1]] >= lcp[rank[i]] - 1.
The LCP of any two arbitrary suffixes at sorted ranks l < r equals the range minimum min_{l <= k < r} lcp[k], turning SuffixTree LCA queries into O(1) Sparse Table RMQ queries.
The number of distinct non-empty substrings in a string of length N is exactly N(N + 1)/2 - sum_{r=0}^{N-2} lcp[r].
