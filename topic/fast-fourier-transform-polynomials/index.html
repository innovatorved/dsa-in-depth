Intuition first

Multiplying two degree-N polynomials in coefficient form takes O(N^2) convolutions, but multiplying them in point-value form at 2N sample points takes O(N) pointwise products! Evaluating a polynomial at 2N arbitrary points still takes O(N^2)—unless we split the polynomial into even and odd powers A(x) = A_even(x^2) + x * A_odd(x^2) and choose the 2N-th complex roots of unity, whose squares collapse by half at every level down to O(N log N).

Hardware Reality: Bit-Reversal In-Place Iterative FFT vs. Recursive Out-of-Place

A recursive FFT allocates temporary arrays at every level to separate even indices (0,2,4,60, 2, 4, 60,2,4,6) and odd indices (1,3,5,71, 3, 5, 71,3,5,7). Observe what happens to the binary representation of index iii as we repeatedly partition by parity (least significant bit first, then second bit, etc.): an index iii ends up at the position given by reversing its log⁡2N\log_2 Nlog2​N binary bits! By permuting the array in-place via a single O(N)O(N)O(N) bit-reversal pass upfront, we can execute all log⁡2N\log_2 Nlog2​N butterfly stages purely in-place and bottom-up (len=2,4,8,…,Nlen = 2, 4, 8, \dots, Nlen=2,4,8,…,N) with zero heap allocations and sequential SIMD memory strides.

using cd = std::complex<double>;

// In-place Iterative Radix-2 Cooley-Tukey FFT (invert = false) and IFFT (invert = true)
void fft_inplace(std::vector<cd>& a, bool invert) noexcept {
    const std::size_t n = a.size();

    // 1. O(N) In-place Bit-Reversal Permutation
    for (std::size_t i = 1, j = 0; i < n; ++i) {
        std::size_t bit = n >> 1;
        for (; j & bit; bit >>= 1) {
            j ^= bit;
        }
        j ^= bit;
        if (i < j) std::swap(a[i], a[j]);
    }

    // 2. Bottom-Up Butterfly Stages: len = 2, 4, 8, ..., n
    for (std::size_t len = 2; len <= n; len <<= 1) {
        const double ang = 2.0 * std::numbers::pi / static_cast<double>(len) * (invert ? -1.0 : 1.0);
        const cd wlen(std::cos(ang), std::sin(ang));
        const std::size_t half = len >> 1;

        for (std::size_t i = 0; i < n; i += len) {
            cd w(1.0, 0.0);
            for (std::size_t j = 0; j < half; ++j) {
                const cd u = a[i + j];
                const cd v = a[i + j + half] * w;
                a[i + j]        = u + v;
                a[i + j + half] = u - v;
                w *= wlen;
            }
        }
    }

    // 3. Normalize by 1/N for Inverse FFT
    if (invert) {
        const double inv_n = 1.0 / static_cast<double>(n);
        for (cd& x : a) x *= inv_n;
    }
}

// Convolves two integer polynomials A and B in O(N log N) time
std::vector<std::int64_t> multiply_polynomials_fft(const std::vector<std::int64_t>& A,
                                                   const std::vector<std::int64_t>& B) {
    if (A.empty() || B.empty()) return {};
    const std::size_t result_len = A.size() + B.size() - 1;
    std::size_t n = 1;
    while (n < result_len) n <<= 1;

    std::vector<cd> fa(n, cd(0.0, 0.0)), fb(n, cd(0.0, 0.0));
    for (std::size_t i = 0; i < A.size(); ++i) fa[i] = static_cast<double>(A[i]);
    for (std::size_t i = 0; i < B.size(); ++i) fb[i] = static_cast<double>(B[i]);

    fft_inplace(fa, false);
    fft_inplace(fb, false);
    for (std::size_t i = 0; i < n; ++i) {
        fa[i] *= fb[i];
    }
    fft_inplace(fa, true);

    std::vector<std::int64_t> result(result_len);
    for (std::size_t i = 0; i < result_len; ++i) {
        result[i] = static_cast<std::int64_t>(std::llround(fa[i].real()));
    }
    return result;
}

Key Takeaways

Multiplying polynomials of degree < n takes O(n^2) in coefficient form (convolution) but O(n) in point-value form (pointwise product).
Splitting A(x) = A_even(x^2) + x * A_odd(x^2) and evaluating at complex N-th roots of unity collapses the evaluation points in half at every level via (omega_N^k)^2 = omega_{N/2}^k.
The Inverse FFT uses the conjugate roots omega_N^{-k} and scales by 1/N because the Vandermonde Fourier matrix is unitary up to scale N.
Bit-reversal permutation orders the leaves upfront so all log_2 N butterfly stages run bottom-up and in-place with zero extra memory allocations.
