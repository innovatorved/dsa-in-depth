The Ω(N log N) Comparison Lower Bound via Stirling's Approximation

7 min read Module 2.2: Sorting Mechanics, Hybrid Sorts & Linear-Time Order Statistics Updated Oct 19, 2026
📄 Cheat Sheet
Back To Back SWE Why Comparison-Based Sorting Algorithms Require Ω(N log N) — Decision Tree Proof Watch on YouTube ↗

Erik Demaine formulates the comparison decision-tree model, proves why any correct comparison sort must have at least n! reachable leaves, and derives the n log_2 n - 1.443n lower bound.

Intuition first

Every binary comparison $A[i] \lessgtr A[j]$ yields at most $1$ bit of information—splitting the set of remaining consistent input permutations in at most half. Because $n$ distinct items can arrive in $n!$ possible relative orders and a deterministic comparison sort must distinguish all $n!$ permutations at its leaves, the tree height must be at least $\lceil \log_2(n!) \rceil = n \log_2 n - \frac{n}{\ln 2} + \Theta(\log n)$.

The Comparison Decision-Tree Model

In the comparison model of computation, elements are treated as abstract black boxes: an algorithm may copy or swap elements, but the only way it can inspect key values is by executing a binary comparison $a_i : a_j$ (returning $<, =, >$, or for distinct keys, simply $a_i < a_j$ vs. $a_i > a_j$). Operations like bit extraction, array indexing by key value ($C[A[i]]$), or hashing key bytes are disallowed.

Any comparison sort on an input of fixed size $n$ can be unrolled into a finite binary decision tree $T_n$:

  • Each internal node is labeled by a pair of indices $(i : j)$ and branches left if $A[i] < A[j]$ or right if $A[i] > A[j]$.
  • Each leaf is labeled by a permutation $\pi = (\pi(1), \pi(2), \dots, \pi(n)) \in S_n$ that reorders the input into sorted order $A[\pi(1)] < A[\pi(2)] < \dots < A[\pi(n)]$.
  • The worst-case number of comparisons on inputs of size $n$ equals the height $h(T_n)$ (longest root-to-leaf path).
  • The average-case number of comparisons over a uniform distribution of all $n!$ permutations equals the average leaf depth $\frac{\text{IPL}(T_n)}{n!}$.
Theorem (Information-Theoretic Worst-Case & Average-Case Lower Bound)

Step 1 (Injectivity of Leaves): Suppose two distinct input permutations $\sigma_1 \ne \sigma_2 \in S_n$ follow the exact same sequence of comparison outcomes from the root to the same leaf $\ell$. Then the algorithm applies the exact same output permutation $\pi$ to both $\sigma_1$ and $\sigma_2$. Since $\sigma_1 \ne \sigma_2$, at least one of $\pi(\sigma_1)$ or $\pi(\sigma_2)$ fails to be sorted! Hence every one of the $n!$ permutations must reach a distinct leaf, so the number of reachable leaves $L$ satisfies $L \ge n!$.

Step 2 (Binary Tree Capacity): A binary tree of height $h$ has at most $2^h$ leaves ($L \le 2^h$). Combining both inequalities gives $2^h \ge L \ge n!$, or:

$$h \ge \lceil \log_2(n!) \rceil$$

Step 3 (Stirling's Approximation): Using Stirling's lower bound $n! = \sqrt{2\pi n}\left(\frac{n}{e}\right)^n e^{\theta_n}$ (where $\frac{1}{12n+1} < \theta_n < \frac{1}{12n}$), or equivalently bounding the sum $\ln(n!) = \sum_{k=1}^n \ln k \ge \int_1^n \ln x\,dx = n \ln n - n + 1$:

$$\log_2(n!) = n \log_2 n - \frac{n}{\ln 2} + \frac{1}{2}\log_2(2\pi n) + O\!\left(\frac{1}{n}\right) \approx n \log_2 n - 1.4427\,n + \frac{1}{2}\log_2(2\pi n)$$

Step 4 (Average-Case & Randomized Lower Bound): By convexity of $f(d) = 2^d$ (or Kraft's inequality), among all binary trees with $L \ge n!$ leaves, the sum of leaf depths $\sum_{\ell=1}^{L} d(\ell)$ is minimized when the tree is almost complete (all leaves at depth $\lfloor \log_2 L \rfloor$ or $\lceil \log_2 L \rceil$), yielding average leaf depth $\ge \log_2(n!) - 1 = n \log_2 n - O(n)$. By Yao's Minimax Principle, any randomized comparison sort also requires $\ge \log_2(n!) - O(1)$ expected comparisons!

Exact Minimum Comparisons for Small $N$ & Adversary Arguments

How close is $\lceil \log_2(n!) \rceil$ to the true minimum worst-case comparisons $S(n)$? For $n = 1 \dots 11$, Ford and Johnson's Merge-Insertion Sort (1959) matches $\lceil \log_2(n!) \rceil$ to the exact single comparison:

  • $n = 3$: $\lceil \log_2 6 \rceil = 3$ comparisons.
  • $n = 4$: $\lceil \log_2 24 \rceil = 5$ comparisons.
  • $n = 5$: $\lceil \log_2 120 \rceil = 7$ comparisons! (Whereas standard Merge Sort and Insertion Sort take $8$ or $10$ comparisons; sorting $5$ elements in $7$ comparisons requires pairing $(a,b)$ and $(c,d)$, comparing their winners, and binary-inserting $e$ and the loser along a 3-element chain).
  • $n = 12$: $\lceil \log_2(12!) \rceil = 29$, but Wells (1965) proved by exhaustive computer search that $S(12) = 30$, showing that no comparison tree can split $12!$ into perfectly balanced $50/50$ subsets at every step!

Hardware Reality: Sorting Networks ($N \le 16$) Beat $\lceil \log_2(N!) \rceil$ via Branchless SIMD min/max

On modern CPUs, performing 7 heavily branched comparisons to sort 5 integers is actually slower than executing 9 branchless conditional-move (CMOV) or SIMD (_mm_min_epi32 / _mm_max_epi32) compare-and-swap operations in a Sorting Network (Batcher's Odd-Even Merge or optimal 5-element / 8-element Bose-Nelson networks). Because all comparator wires in a sorting network layer are data-independent, a superscalar CPU executes 3–4 compare-and-swaps in a single clock cycle with zero branch mispredictions!

Production C++20 Implementation: Optimal 7-Comparison 5-Sort vs. Branchless Sorting Network

C++20
#include <array>
#include <cmath>
#include <concepts>
#include <cstdint>
#include <utility>

// Information-theoretic lower bound ceil(log2(n!)) using exact log-gamma / sum of log2(k)
inline std::uint64_t comparison_lower_bound(std::uint64_t n) noexcept {
    double log2_fact = 0.0;
    for (std::uint64_t k = 2; k <= n; ++k) {
        log2_fact += std::log2(static_cast<double>(k));
    }
    return static_cast<std::uint64_t>(std::ceil(log2_fact - 1e-12));
}

// Ford-Johnson Merge-Insertion Sort for N = 5 in AT MOST 7 Comparisons (Optimal!)
template <std::totally_ordered T>
std::array<T, 5> sort5_optimal_7cmps(T a, T b, T c, T d, T e) noexcept {
    if (b < a) std::swap(a, b); // Cmp 1: a <= b
    if (d < c) std::swap(c, d); // Cmp 2: c <= d
    if (d < b) {                // Cmp 3: order pairs by larger element (b <= d)
        std::swap(a, c);
        std::swap(b, d);
    }
    // Now we have main chain: a <= b <= d, and c <= d.
    // Step 4-5: Binary insert <code>e</code> into the 3-element chain [a, b, d] (2 comparisons)
    std::array<T, 4> chain;
    if (e < b) {                // Cmp 4
        if (e < a) chain = {e, a, b, d}; // Cmp 5a
        else       chain = {a, e, b, d};
    } else {
        if (e < d) chain = {a, b, e, d}; // Cmp 5b
        else       chain = {a, b, d, e};
    }
    // Step 6-7: Since c <= d, <code>c</code> is smaller than <code>d</code> (which is at chain[2] or chain[3]),
    // so <code>c</code> only needs to be binary-inserted into the first 3 elements chain[0..2] (2 comparisons)!
    if (c < chain[1]) {         // Cmp 6
        if (c < chain[0]) return {c, chain[0], chain[1], chain[2], chain[3]}; // Cmp 7a
        else              return {chain[0], c, chain[1], chain[2], chain[3]};
    } else {
        if (c < chain[2]) return {chain[0], chain[1], c, chain[2], chain[3]}; // Cmp 7b
        else              return {chain[0], chain[1], chain[2], c, chain[3]};
    }
}

// Contrast: Branchless 9-Comparator Sorting Network for N = 5 (Compiles to CMOV / min-max)
template <std::totally_ordered T>
void sort5_branchless_network(T* v) noexcept {
    auto cmp_swap = [](T& x, T& y) noexcept {
        T mn = (y < x) ? y : x;
        T mx = (y < x) ? x : y;
        x = mn; y = mx;
    };
    cmp_swap(v[0], v[1]); cmp_swap(v[3], v[4]);
    cmp_swap(v[2], v[4]); cmp_swap(v[2], v[3]);
    cmp_swap(v[0], v[3]); cmp_swap(v[0], v[2]);
    cmp_swap(v[1], v[4]); cmp_swap(v[1], v[3]);
    cmp_swap(v[1], v[2]);
}
How to Bypass the $\Omega(N \log N)$ Lower Bound

Whenever an interview or systems design problem asks you to sort in $o(N \log N)$ time, ask: Which assumption of the comparison decision-tree model can we violate?
1. Non-Comparison Multi-Way Branching: Counting Sort and Radix Sort use key digits as direct array indices ($b$-way branching per step instead of $2$-way), yielding height $\log_b(n!)$.
2. Restricted Input Space ($L \ll n!$): If the array has at most $O(n)$ inversions or comes from merging $O(1)$ sorted streams, there are only $2^{O(n)}$ valid inputs, so an adaptive comparison sort finishes in $\Theta(n)$ comparisons!

Check yourself Question 1 of 4
Concept Check Why a Comparison Sort Decision Tree Must Have at Least n! Leaves recall

Consider a deterministic comparison-based sorting algorithm executed on $n$ distinct keys.

At a leaf of the decision tree, all comparisons have completed and the algorithm emits a fixed permutation π of the input indices. Since a permutation π is a bijection, there is only ONE input ordering σ = π⁻¹ that π maps to sorted order. Thus all n! possible input permutations of n distinct elements must terminate at distinct leaves.
Concept Check Exact Minimum Comparisons to Sort 5 Elements apply

Standard Insertion Sort takes up to $\binom{5}{2} = 10$ comparisons to sort $n = 5$ elements, and top-down Merge Sort takes up to $8$ comparisons.

Since 5! = 120 and 2^6 = 64 < 120 ≤ 128 = 2^7, the lower bound is 7 comparisons. Ford-Johnson sorts 5 elements in 7 comparisons: (1) compare a:b, (2) compare c:d, (3) compare winners b:d to form a 3-chain a < b < d with c < d (3 cmps so far), (4-5) binary insert the 5th element e into [a,b,d] (2 cmps), and (6-7) binary insert c into the 3 elements smaller than d (2 cmps) = 7 total!
Concept Check Information-Theoretic Lower Bound for Sorting a Multiset with Duplicates apply

You need to sort an array of length $n$ that is known to contain only $k = 3$ distinct values (e.g., `0`, `1`, `2`), each appearing $n / 3$ times.

When keys have multiplicities f₁, ..., f_k, indistinguishable permutations of identical keys do not need separate leaves (or under 3-way <, =, > comparisons, equal keys collapse). There are only n! / (f₁! ... f_k!) distinct multiset permutations. Taking log₂ via Stirling's approximation gives n H(p₁,...,p_k) = n log₂ k comparisons when frequencies are equal—linear in n for constant k!
Concept Check Sorting Networks vs Decision Trees on Superscalar CPUs staff

To sort $n = 4$ integers, a decision tree requires $\lceil \log_2(4!) \rceil = 5$ branched comparisons, whereas an optimal 4-element Sorting Network executes $5$ unconditional compare-and-swap (`min`/`max`) gates, and for $n = 5$ a sorting network executes $9$ compare-and-swap gates vs. Ford-Johnson's $7$ branched comparisons.

Decision trees minimize the *number of comparisons*, assuming comparisons are expensive and branches are free. On modern out-of-order CPUs, integer comparisons take 1 cycle while an unpredictable branch misprediction costs ~15 cycles! A 5-element sorting network executes 9 `CMOV` compare-and-swaps across 5 dependency layers in ~5 cycles total with zero branches, beating a 7-branch decision tree by 4–6×.

Key Takeaways

Any deterministic or randomized comparison sort on n distinct keys must distinguish all n! input permutations at the leaves of its binary decision tree.
Because a binary tree of height h has at most 2^h leaves, worst-case and average-case comparisons are bounded below by log_2(n!) = n log_2 n - (n / ln 2) + Θ(log n) ≈ n log_2 n - 1.443n.
When inputs have restricted entropy (k duplicates, k-nearly-sorted, or I inversions), the lower bound drops to log_2(L) where L is the number of valid input permutations.
Ford-Johnson Merge-Insertion Sort achieves the exact information-theoretic minimum 7 comparisons for n = 5, while branchless sorting networks trade 2 extra comparisons for zero branch mispredictions.
