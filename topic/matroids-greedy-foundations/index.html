Explains the axiomatic structure of matroids, the Rado-Edmonds Theorem, and why Kruskal's MST and Gaussian basis selection are the exact same greedy algorithm.

Intuition first

Why does the greedy algorithm effortlessly find a Maximum Weight Spanning Forest or a Maximum Weight Linearly Independent XOR Basis, yet fail miserably on Maximum Weight Bipartite Matching? The answer is the Rado-Edmonds Theorem: the universal greedy algorithm is guaranteed optimal for arbitrary non-negative weights if and only if the underlying independence system is a Matroid.

1. The Three Matroid Axioms & The Rado-Edmonds Theorem

A subset system M=(E,I)M = (E, \mathcal{I})M=(E,I), where EEE is a finite ground set and I⊆2E\mathcal{I} \subseteq 2^EI⊆2E is a family of independent sets, is called a Matroid (Whitney, 1935) if it satisfies three axioms:

  1. Non-Emptiness: ∅∈I\emptyset \in \mathcal{I}∅∈I.
  2. Hereditary Property (Downward Closure): If B∈IB \in \mathcal{I}B∈I and A⊆BA \subseteq BA⊆B, then A∈IA \in \mathcal{I}A∈I.
  3. Exchange Property (Augmentation): If A,B∈IA, B \in \mathcal{I}A,B∈I and ∣A∣<∣B∣|A| < |B|∣A∣<∣B∣, then there exists some element x∈B∖Ax \in B \setminus Ax∈B∖A such that A∪{x}∈IA \cup \{x\} \in \mathcal{I}A∪{x}∈I. (Consequently, all maximal independent sets—called bases—have the exact same cardinality rank(E)\text{rank}(E)rank(E)!)

Hardware Reality — 64-Bit F2\mathbb{F}_2F2​ XOR Basis Fits in 8 Cache Lines

A linear matroid basis over 64-bit integers (uint64_t basis[64]) occupies exactly 64×8=51264 \times 8 = 51264×8=512 bytes (8 L1 cache lines). Testing whether a number xxx is linearly independent of the current basis iterates through the set bits of xxx using __builtin_ctzll(x) (or from bit 636363 down to 000) and XORs with basis[b] in under 20 CPU clock cycles—making maximum-weight XOR basis queries practically instantaneous.

// 1. Linear Matroid over GF(2): Maximum Weight Linearly Independent XOR Basis
struct WeightedVector {
    std::uint64_t mask;
    long long weight;
};

long long max_weight_xor_basis(std::vector<WeightedVector> elements) {
    // Rado-Edmonds Greedy: sort descending by weight
    std::sort(elements.begin(), elements.end(), [](const WeightedVector& a, const WeightedVector& b) {
        return a.weight > b.weight;
    });

    std::array<std::uint64_t, 64> basis{};
    long long total_weight = 0;

    auto try_insert = [&](std::uint64_t x) -> bool {
        for (int b = 63; b >= 0; --b) {
            if (!((x >> b) & 1ULL)) continue;
            if (basis[b] == 0) {
                basis[b] = x;
                return true; // x is linearly independent of current basis!
            }
            x ^= basis[b];
        }
        return false; // x reduced to 0 -> linearly dependent
    };

    for (const auto& elem : elements) {
        if (elem.weight <= 0) break;
        if (try_insert(elem.mask)) {
            total_weight += elem.weight;
        }
    }
    return total_weight;
}

// 2. Unit-Time Deadline Scheduling Matroid with DSU Slot Allocation
struct DeadlineJob {
    int deadline; // 1-indexed deadline in [1..n]
    long long profit;
};

long long max_profit_deadline_scheduling(std::vector<DeadlineJob> jobs, int max_deadline) {
    std::sort(jobs.begin(), jobs.end(), [](const DeadlineJob& a, const DeadlineJob& b) {
        return a.profit > b.profit;
    });

    // parent[t] points to the latest available time slot <= t (0 means no slot free)
    std::vector<int> parent(max_deadline + 1);
    std::iota(parent.begin(), parent.end(), 0);

    auto find_free_slot = [&](auto& self, int t) -> int {
        return parent[t] == t ? t : (parent[t] = self(self, parent[t]));
    };

    long long total_profit = 0;
    for (const auto& job : jobs) {
        if (job.profit <= 0) break;
        int d = std::min(job.deadline, max_deadline);
        int free_slot = find_free_slot(find_free_slot, d);
        if (free_slot > 0) {
            total_profit += job.profit;
            // Occupy <code>free_slot</code> by merging it into <code>free_slot - 1</code>
            parent[free_slot] = find_free_slot(find_free_slot, free_slot - 1);
        }
    }
    return total_profit;
}

Production Pitfall — Confusing Maximum Weight Independent Set with Maximum Weight Base

When weights can be negative, the problem of finding a maximum-weight independent set stops adding elements as soon as w(ei)≤0w(e_i) \le 0w(ei​)≤0. However, if the problem requires a maximum-weight basis (maximal independent set of size rank(E)\text{rank}(E)rank(E), such as a Spanning Tree where negative edges are mandatory to connect the graph), you must continue scanning all elements until ∣S∣=rank(E)|S| = \text{rank}(E)∣S∣=rank(E) even when w(ei)<0w(e_i) < 0w(ei​)<0.

Key Takeaways

A matroid (E, I) satisfies non-emptiness, downward closure (hereditary), and the exchange axiom (if |A| < |B|, some x in B \ A can augment A).
The Rado-Edmonds Theorem proves that sorting by weight descending and greedily adding independent elements is optimal for all weight functions iff (E, I) is a matroid.
Kruskal's MST algorithm is the Rado-Edmonds greedy algorithm on the Graphic Matroid; Gaussian XOR elimination is the same algorithm on the F_2 Linear Matroid.
Unit-time job scheduling with deadlines and profits forms a matroid whose independence check runs in O(alpha(N)) per job via Disjoint Set Union.
