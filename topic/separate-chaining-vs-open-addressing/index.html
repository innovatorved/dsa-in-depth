Collision Resolution: Separate Chaining vs Linear/Quadratic/Double Probing

7 min read Module 2.1: Hash Tables, Modern Probing & Probabilistic Sketches Updated Oct 23, 2026
📄 Cheat Sheet
MIT OpenCourseWare (Srini Devadas) MIT 6.006 Lecture 10: Open Addressing, Linear/Double Probing & Tombstone Deletions Watch on YouTube ↗

Srini Devadas derives the probe sequence invariants of open addressing, explains why deletions require tombstones, and contrasts primary clustering in linear probing against double hashing.

Intuition first

When two distinct keys collide at bucket $h(k)$, a hash table must choose between two memory topologies: Separate Chaining allocates auxiliary linked nodes outside the bucket array, whereas Open Addressing stores all keys directly inside a flat contiguous array and probes alternative slots $h(k, i)$ for $i = 0, 1, \dots, m-1$ until an empty slot is found.

In the theoretical RAM model, Double Hashing ($1/(1-\alpha)$ probes) strictly dominates Linear Probing ($\frac{1}{2}(1 + 1/(1-\alpha)^2)$ probes) because Linear Probing suffers from primary clustering—long runs of occupied slots snow-ball as wider targets for new insertions. On physical CPUs, however, Linear Probing scans 8 consecutive 8-byte slots inside a single 64-byte L1 cache line up to $\alpha \le 0.75$, outperforming pointer-chased Separate Chaining and cache-missing Double Hashing by $3\times$ to $8\times$.

Separate Chaining vs Open Addressing Probe Sequences

Define the load factor $\alpha = n / m$, where $n$ is the number of stored elements and $m$ is the number of bucket slots:

  • Separate Chaining ($alpha$ can exceed $1$): Each slot stores a pointer to a linked list (or small inline vector) of colliding entries. Under uniform hashing, an unsuccessful search inspects $\alpha$ nodes and a successful search inspects $1 + \alpha/2$ nodes on average. However, every node allocation incurs malloc overhead (16 bytes) + an 8-byte next pointer, and traversing a chain dereferences non-contiguous heap addresses (L3/DRAM cache misses).
  • Linear Probing ($h(k, i) = (h(k) + i) \bmod m$): Probes adjacent slots sequentially. Maximizes spatial locality and hardware stream prefetching, but suffers from primary clustering: any key hashing anywhere inside a contiguous cluster of length $L$ extends that cluster to $L + 1$ with probability $(L + 1)/m$.
  • Quadratic Probing ($h(k, i) = (h(k) + c_1 i + c_2 i^2) \bmod m$): Eliminates primary clustering by jumping quadratically, leaving only milder secondary clustering (keys with the exact same initial $h(k)$ follow the same trajectory). When $m = 2^r$ and $c_1 = c_2 = 1/2$, the triangular numbers $h(k, i) = (h(k) + i(i+1)/2) \bmod 2^r$ are guaranteed to visit every slot in $\{0, \dots, 2^r - 1\}$ exactly once!
  • Double Hashing ($h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m$): Uses a second independent hash $h_2(k)$ coprime to $m$ (e.g., $h_2(k)$ odd when $m = 2^r$, or $h_2(k) \in [1, m-1]$ when $m$ is prime). Generates $m^2$ distinct probe sequences, eliminating both primary and secondary clustering at the cost of a new cache miss on nearly every probe step.

Formal Specification:Probe Chain Continuity & The Tombstone Invariant

Probe Chain Invariant: For every key $k$ present at slot $h(k, j)$ in an open-addressed table, every preceding probe slot $h(k, 0), h(k, 1), \dots, h(k, j-1)$ must be strictly non-empty (either OCCUPIED or TOMBSTONE).

Why Naive Deletion Corrupts Open Addressing: Suppose $k_1$ and $k_2$ both hash to slot $4$, so $k_1$ sits at slot $4$ and $k_2$ probes to slot $5$. If erase(k1) resets slot $4$ to EMPTY, a subsequent find(k2) starts at slot $4$, sees EMPTY, and falsely returns NOT_FOUND! Therefore, standard open addressing replaces deleted entries with a TOMBSTONE sentinel: find treats TOMBSTONE as occupied (keep probing), whereas insert records the first TOMBSTONE seen and reuses it once it verifies $k$ does not already exist further down the probe chain.

Hardware Reality: Why Tombstones Silently Degrade $O(1)$ Tables

In workloads with heavy churn (frequent insert and erase keeping live count $n$ constant), TOMBSTONE slots accumulate. Because unsuccessful lookups (find for missing keys) can only stop at a true EMPTY slot, the effective load factor for misses is $\alpha_{\text{eff}} = (n_{\text{live}} + n_{\text{tomb}}) / m$. Even if $n_{\text{live}} / m = 0.25$, once $n_{\text{tomb}} / m$ reaches $0.70$, every cache-miss lookup scans $\frac{1}{2}(1 + 1/(1 - 0.95)^2) \approx 200$ slots! Production open-addressed tables track n_live + n_tomb and trigger a same-capacity tombstone-purging rehash when n_live + n_tomb > 0.75 * m while n_live < 0.50 * m.

Production C++20 Implementation: Power-of-Two Triangular Quadratic Probing

// C++20: Open-Addressed Hash Table with Triangular Quadratic Probing & Tombstone Rehash
#include <vector>
#include <cstdint>
#include <optional>

template <typename K, typename V>
class TriangularProbeMap {
    enum class State : uint8_t { EMPTY = 0, OCCUPIED = 1, TOMBSTONE = 2 };
    struct Slot {
        K key{};
        V val{};
        State state = State::EMPTY;
    };

    std::vector<Slot> table_;
    size_t live_ = 0;
    size_t tombs_ = 0;

    static uint64_t hash64(uint64_t x) noexcept {
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }

    void rehash(size_t newCap) {
        std::vector<Slot> old = std::move(table_);
        table_.assign(newCap, Slot{});
        live_ = 0;
        tombs_ = 0;
        for (auto& s : old) {
            if (s.state == State::OCCUPIED) insert(std::move(s.key), std::move(s.val));
        }
    }

public:
    explicit TriangularProbeMap(size_t pow2Cap = 16) : table_(pow2Cap) {}

    bool insert(K key, V val) {
        // Trigger resize or same-size tombstone cleanup when occupied + tombstones >= 75%
        if ((live_ + tombs_) * 4 >= table_.size() * 3) {
            size_t nextCap = (live_ * 2 >= table_.size()) ? table_.size() * 2 : table_.size();
            rehash(nextCap);
        }
        const size_t mask = table_.size() - 1;
        size_t idx = hash64(static_cast<uint64_t>(key)) & mask;
        size_t firstTomb = static_cast<size_t>(-1);

        for (size_t step = 1; ; ++step) {
            Slot& s = table_[idx];
            if (s.state == State::EMPTY) {
                Slot& target = (firstTomb != static_cast<size_t>(-1))
                               ? (--tombs_, table_[firstTomb]) : s;
                target.key = std::move(key);
                target.val = std::move(val);
                target.state = State::OCCUPIED;
                ++live_;
                return true;
            }
            if (s.state == State::TOMBSTONE) {
                if (firstTomb == static_cast<size_t>(-1)) firstTomb = idx;
            } else if (s.key == key) {
                s.val = std::move(val);
                return false;
            }
            // Triangular step: idx_{i} = (idx_{i-1} + step) mod 2^r visits all 2^r slots!
            idx = (idx + step) & mask;
        }
    }

    std::optional<V> find(const K& key) const {
        const size_t mask = table_.size() - 1;
        size_t idx = hash64(static_cast<uint64_t>(key)) & mask;
        for (size_t step = 1; ; ++step) {
            const Slot& s = table_[idx];
            if (s.state == State::EMPTY) return std::nullopt;
            if (s.state == State::OCCUPIED && s.key == key) return s.val;
            idx = (idx + step) & mask;
        }
    }
};

Failure Modes & Adversarial Pitfalls

  • Inserting Immediately at the First Tombstone Without Checking Remainder of Probe Chain: If insert(k, v) stops immediately upon seeing a TOMBSTONE and writes k there without continuing until EMPTY or k, a key k that already exists later in the probe chain will be duplicated in the table! Always record firstTomb and continue probing until EMPTY or an existing match.
  • Non-Coprime Step Size in Double Hashing: If $h_2(k)$ shares a common factor $g = \gcd(h_2(k), m) > 1$ with table size $m$, the probe sequence visits only $m / g$ slots before cycling infinitely. With $m = 2^r$, always enforce h2 = (raw_h2 * 2) | 1 so $h_2$ is strictly odd.

Concept Check Knuth's Expected Probe Bound for Linear Probing recall

Under the uniform hashing model at load factor α = n / m < 1, what is Knuth's asymptotic expected number of probes for an UNSUCCESSFUL search (miss) in Linear Probing?

Because primary clustering causes long contiguous runs to grow faster than short runs, an unsuccessful search in Linear Probing scales quadratically with 1/(1 - α): 0.5 * (1 + 1/(1 - α)^2), compared to 1/(1 - α) in Double Hashing.
Concept Check Triangular Number Quadratic Probing on Power-of-Two Tables apply

In an open-addressed table of size m = 2^r, why is the quadratic probe sequence h(k, i) = (h(k) + i(i + 1)/2) mod 2^r strongly preferred over h(k, i) = (h(k) + i^2) mod 2^r?

Squares modulo 2^r visit fewer than 1/4 of the buckets in a power-of-two table, causing insertions to fail even when 75% of the table is empty! By contrast, triangular numbers T_i = i(i+1)/2 (computed iteratively by idx = (idx + step) & mask) visit all 2^r slots.
Concept Check Duplicate Key Bug When Reusing Tombstones on Insert apply

During `insert(k, v)` in an open-addressed table with tombstones, the probe loop encounters a `TOMBSTONE` at index `t`. Why is it a critical correctness bug to immediately write `(k, v)` at `table[t]` and return?

If `k` was inserted earlier when `t` was occupied by another key, `k` sits past `t` in the probe sequence. `insert` must record `firstTomb = t` and continue probing until it either finds `k` (updating it in place) or hits `EMPTY` (placing the new key at `firstTomb`).
Concept Check Tombstone Contamination Under Steady-State Churn staff

A cache service stores at most n = 200,000 live keys in an open-addressed table of capacity m = 1,048,576 (live load factor α_live = 0.19). After millions of mixed `insert(new_key)` and `erase(old_key)` operations, p99 latency for cache-miss lookups (`find` on missing keys) spikes by 30x without `size()` ever increasing. Why, and how do production tables fix this?

Unsuccessful lookups must scan past all OCCUPIED and TOMBSTONE slots until reaching a true EMPTY slot. Thus miss performance is governed by α_eff = (n_live + n_tomb) / m. Rebuilding at the same capacity purges all tombstones when α_live is still low.

Key Takeaways

Linear Probing suffers from primary clustering with expected miss cost 1/2 (1 + 1/(1-α)^2), yet outperforms Separate Chaining for α ≤ 0.75 due to 64-byte L1 cache line spatial locality.
Triangular quadratic probing h(k, i) = (h(k) + i(i+1)/2) mod 2^r visits every slot of a power-of-two table exactly once while eliminating primary clustering.
Open-addressed deletion requires TOMBSTONE sentinels so existing probe chains are not severed; insert must still scan past tombstones to prevent duplicate keys.
Rehashing thresholds must monitor (n_live + n_tombstones) / m, running a same-capacity compaction rehash when tombstones bloat unsuccessful lookup latency.
