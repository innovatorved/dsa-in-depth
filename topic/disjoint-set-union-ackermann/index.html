Intuition first

Maintaining dynamic connected components under edge insertions is one of the most fundamental operations in computer science. A naive array of component IDs supports O(1)O(1)O(1) connectivity queries but requires O(N)O(N)O(N) scans to merge two components; conversely, naive parent-pointer trees merge in O(1)O(1)O(1) but degenerate into O(N)O(N)O(N) linked lists on queries.

By combining two deceptively simple heuristics—Union by Rank (or Size) and Path Compression—Robert Tarjan proved in 1975 that a sequence of MMM operations on NNN elements executes in O(M⋅α(N))O(M \cdot \alpha(N))O(M⋅α(N)) time, where α(N)≤4\alpha(N) \le 4α(N)≤4 is the inverse Ackermann function for all physically conceivable inputs (N<265536N < 2^{65536}N<265536).

Tree Height Invariants & The Inverse Ackermann Bound

A Disjoint Set Union (DSU) forest represents each set as a rooted tree where every node xxx stores a parent pointer parent[x]\text{parent}[x]parent[x], and the root rrr of a set satisfies parent[r]=r\text{parent}[r] = rparent[r]=r (or parent[r]<0\text{parent}[r] < 0parent[r]<0 in the negative-size encoding).

Hardware Reality — Single-Array Negative-Size Encoding & Path Halving

Instead of allocating two vectors parent[N] and size[N] (8N8N8N bytes across two cache streams), production C++ DSU implementations use a single signed array p[N] (4N4N4N bytes) initialized to -1: if p[x] < 0, xxx is a root of size -p[x]; if p[x] >= 0, p[x] is xxx's parent index. Furthermore, iterative Path Halving (while (p[x] >= 0 && p[p[x]] >= 0) { p[x] = p[p[x]]; x = p[x]; }) achieves the exact same O(α(N))O(\alpha(N))O(α(N)) amortized bound in a single top-free upward pass without function-call recursion!

Production Implementation: Single-Array Signed DSU with Path Compression

#include <vector>
#include <utility>

class DisjointSetUnion {
public:
    explicit DisjointSetUnion(int n) : parentOrNegSize(n, -1), numComponents(n) {}

    int find(int x) noexcept {
        int root = x;
        while (parentOrNegSize[root] >= 0) {
            root = parentOrNegSize[root];
        }
        while (x != root) {
            int next = parentOrNegSize[x];
            parentOrNegSize[x] = root;
            x = next;
        }
        return root;
    }

    bool unite(int a, int b) noexcept {
        a = find(a);
        b = find(b);
        if (a == b) return false;
        // Remember: more negative means LARGER component size!
        if (parentOrNegSize[a] > parentOrNegSize[b]) {
            std::swap(a, b);
        }
        parentOrNegSize[a] += parentOrNegSize[b];
        parentOrNegSize[b] = a;
        --numComponents;
        return true;
    }

    bool connected(int a, int b) noexcept { return find(a) == find(b); }
    int componentSize(int x) noexcept { return -parentOrNegSize[find(x)]; }
    int components() const noexcept { return numComponents; }

private:
    std::vector<int> parentOrNegSize;
    int numComponents;
};
Failure Mode — Updating Rank by Subtree Height During Path Compression

In Union by Rank, rank[r] is an upper bound on height, not the exact height after path compression (since recomputing exact subtree height after compressing paths would cost O(N)O(N)O(N)). Moreover, only increments rank[ra]++ when merging two trees of equal rank; if using Union by Size, always add size[ra] += size[rb] on every merge.

Concept Check Maximum Tree Height under Union by Rank recall
Section: Rank & Size Invariants

In a Disjoint Set Union (DSU) forest of NNN elements using Union by Rank (even without Path Compression), what is the tight upper bound on the rank (height) of any root node?

A root's rank increments from k to k+1 only when two roots of equal rank k are merged, doubling the minimum subtree size from 2^k to 2^(k+1). Thus 2^rank <= N, or rank <= floor(log_2 N).
Concept Check Single-Array DSU Root Representation apply
Section: Negative-Size Encoding

In the cache-friendly single-array DSU representation `parentOrSize[0..N-1]` initialized to `-1`, what does `parentOrSize[x] = -12` signify?

Non-negative entries store the parent index `p >= 0`, whereas negative entries mark a root `r` and encode the component cardinality as `-parentOrSize[r]`.
Concept Check Path Compression Without Union by Rank apply
Section: Heuristic Combinations

What happens to the amortized time complexity of MMM operations on NNN elements if you implement Path Compression in `find(x)` but use naive linking (`parent[ra] = rb` arbitrarily) instead of Union by Rank/Size?

Without Union by Rank/Size, carefully linking large flat trees under single nodes before compressing can force O(log n) pointer hops per operation (Tarjan & van Leeuwen 1984).
Concept Check Why Rank Stays Frozen During Path Compression staff
Section: Inverse Ackermann Proof

When Path Compression flattens a subtree during `find(x)`, the actual height of ancestor nodes decreases, yet the algorithm never decrements `rank[u]`. Why is `rank[u]` kept frozen as an upper bound rather than recomputed?

Keeping rank as a monotonic upper bound preserves both key invariants required by the Ackermann bucket proof: strict increase along parent pointers (`rank[u] < rank[p]`) and exponential scarcity of high-rank nodes (`<= N / 2^r`).

Key Takeaways

Combining Union by Rank/Size with Path Compression (or Path Halving) achieves O(alpha(N)) amortized time per operation, where alpha(N) <= 4 for all N < 2^65536.
Without path compression, Union by Size guarantees that every tree has depth at most floor(log_2 N) because every step up a tree at least doubles the subtree size.
Encoding both parent indices (>= 0) and negated component sizes (< 0) in a single int32 array cuts memory usage in half (4N bytes) and eliminates dual-array cache misses.
Using Path Compression alone without Union by Rank/Size still allows O(log N) amortized sequences; both heuristics are required for O(alpha(N)).
