Randomized Quicksort: Indicator Random Variables & 1.386 N ln N Proof

Intuition first

Instead of solving a messy recurrence over all $n$ possible partition sizes, track each pair of elements $z_i < z_j$ in sorted rank order. Two elements are compared at most once—only if one is chosen as a pivot—and they are compared if and only if the very first pivot chosen from the contiguous rank interval $\{z_i, z_{i+1}, \dots, z_j\}$ is either $z_i$ or $z_j$, an event of exact probability $\frac{2}{j - i + 1}$.

Why Randomize Pivot Selection?

Any deterministic Quicksort that picks a fixed index ($A[lo]$, $A[hi]$, or even $A[mid]$) has inputs for which every partition is $0 : (n-1)$, requiring $\sum_{k=1}^{n-1} k = \frac{n(n-1)}{2} = \Theta(n^2)$ comparisons. Randomized Quicksort defeats fixed-input adversaries by either shuffling the array upfront (Knuth-Fisher-Yates) or picking a pivot index uniformly at random from $\{lo, \dots, hi\}$ at every recursive step. The expected runtime then holds over the algorithm's internal random coin flips for every input array of $n$ distinct elements.

Theorem (Exact Expected Comparisons of Randomized Quicksort)

Let $z_1 < z_2 < \dots < z_n$ denote the $n$ distinct elements of the input array in sorted order (by rank). Define the indicator random variable: $$X_{ij} = \mathbb{I}\{\text{elements } z_i \text{ and } z_j \text{ are compared at any point during Randomized Quicksort}\} \quad (1 \le i < j \le n)$$ Because every comparison in Quicksort compares some element against the current pivot, and the pivot is never included in either recursive call, any pair $(z_i, z_j)$ is compared at most once. Thus the total number of comparisons is $X = \sum_{i=1}^{n-1}\sum_{j=i+1}^{n} X_{ij}$.

Crucial Observation: Consider the set of elements $Z_{ij} = \{z_i, z_{i+1}, \dots, z_j\}$ of cardinality $j - i + 1$. So long as no pivot is chosen from $Z_{ij}$, the entire set $Z_{ij}$ remains together in the same recursive subarray (either all strictly less than the pivot, or all strictly greater than the pivot). The very first time a pivot $p$ is chosen from $Z_{ij}$:

  • If $p = z_i$ or $p = z_j$, then $z_i$ and $z_j$ are compared during that partition pass ($X_{ij} = 1$).
  • If $z_i < p < z_j$, then $z_i$ is placed in the left partition ($< p$) and $z_j$ is placed in the right partition ($> p$); they are permanently separated and will never be compared ($X_{ij} = 0$).

Since each of the $j - i + 1$ elements in $Z_{ij}$ is equally likely to be the first one chosen as a pivot from $Z_{ij}$:

$$\Pr[X_{ij} = 1] = \frac{2}{j - i + 1}$$

Summing the Harmonic Series: Where $1.386\,n \log_2 n$ Comes From

By linearity of expectation (which holds even though the indicator variables $X_{ij}$ are not mutually independent!):

$$\mathbb{E}[X] = \sum_{i=1}^{n-1} \sum_{j=i+1}^{n} \frac{2}{j - i + 1}$$

Substitute the span length $k = j - i$ (so $k$ ranges from $1$ to $n - 1$, and there are $n - k$ pairs with span $k$):

$$\mathbb{E}[X] = \sum_{k=1}^{n-1} (n - k) \frac{2}{k + 1} = 2(n + 1)\sum_{k=1}^{n-1}\frac{1}{k + 1} - 2(n - 1) = 2(n + 1)(H_n - 1) - 2(n - 1) = 2(n + 1)H_n - 4n$$

Using the harmonic number expansion $H_n = \sum_{m=1}^n \frac{1}{m} = \ln n + \gamma + O(1/n)$ and converting from natural log to base-2 log ($\ln n = \ln(2) \cdot \log_2 n \approx 0.69315 \log_2 n$):

$$\mathbb{E}[X] \approx 2n \ln n = (2 \ln 2)\, n \log_2 n \approx 1.3863\, n \log_2 n$$

Notice how remarkably close this is to the information-theoretic optimum: Randomized Quicksort performs only $38.6\%$ more comparisons than Merge Sort ($1.0\, n \log_2 n$), and with Median-of-Three pivot selection, the constant drops further to $\frac{12}{7} \ln(2)\, n \log_2 n \approx 1.188\, n \log_2 n$!

Hardware Reality: Fast Unbiased Random Range Generation (Lemire's Multiply-Shift)

Calling std::rand() % len inside a Quicksort recursion loop has two flaws: (1) 64-bit integer modulo (DIV) takes 20–40 cycles, and (2) rand() % len introduces modulo bias when len does not divide $2^{32}$. Production randomized algorithms pair a fast register-resident PRNG (such as SplitMix64 or xoshiro256**, ~2 cycles) with Daniel Lemire's Fast Range reduction: (uint64_t(rng32()) * uint64_t(len)) >> 32, mapping a 32-bit random word into $[0, len)$ in a single 3-cycle multiply-high instruction without division!

Production C++20 Implementation: Randomized Quicksort & Empirical $2(n+1)H_n - 4n$ Verifier

#include <cmath>
#include <cstddef>
#include <cstdint>
#include <utility>
#include <vector>

struct SplitMix64 {
    std::uint64_t state;
    explicit constexpr SplitMix64(std::uint64_t seed = 0x9E3779B97F4A7C15ULL) noexcept : state(seed) {}

    constexpr std::uint64_t next() noexcept {
        std::uint64_t z = (state += 0x9E3779B97F4A7C15ULL);
        z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9ULL;
        z = (z ^ (z >> 27)) * 0x94D049BB133111EBULL;
        return z ^ (z >> 31);
    }

    // Lemire's multiply-shift into [0, bound)
    constexpr std::size_t uniform(std::size_t bound) noexcept {
        return static_cast<std::size_t>((__uint128_t(next()) * __uint128_t(bound)) >> 64);
    }
};

// Instrumented Randomized Quicksort counting exact key comparisons
template <typename T>
std::uint64_t randomized_quicksort_count(T* a, std::ptrdiff_t lo, std::ptrdiff_t hi, SplitMix64& rng) noexcept {
    if (lo >= hi) return 0;

    const std::ptrdiff_t len = hi - lo + 1;
    const std::ptrdiff_t piv_idx = lo + static_cast<std::ptrdiff_t>(rng.uniform(static_cast<std::size_t>(len)));
    std::swap(a[piv_idx], a[hi]);
    const T pivot = a[hi];

    std::uint64_t cmps = 0;
    std::ptrdiff_t i = lo;
    for (std::ptrdiff_t j = lo; j < hi; ++j) {
        ++cmps;
        if (a[j] < pivot) {
            std::swap(a[i++], a[j]);
        }
    }
    std::swap(a[i], a[hi]);

    cmps += randomized_quicksort_count(a, lo, i - 1, rng);
    cmps += randomized_quicksort_count(a, i + 1, hi, rng);
    return cmps;
}

// Exact theoretical expectation E[X] = 2(n + 1)*H_n - 4n for n distinct keys
inline double theoretical_expected_comparisons(std::size_t n) noexcept {
    double h_n = 0.0;
    for (std::size_t k = 1; k <= n; ++k) {
        h_n += 1.0 / static_cast<double>(k);
    }
    return 2.0 * static_cast<double>(n + 1) * h_n - 4.0 * static_cast<double>(n);
}
Las Vegas vs. Monte Carlo & Why Introsort Still Adds a Depth Cap

Randomized Quicksort is a Las Vegas randomized algorithm: its output is always 100% sorted, and only its running time is a random variable. While Chernoff bounds guarantee $\Pr[X > 4n \ln n] \le n^{-2}$, in safety-critical real-time systems or deterministic standard library APIs (where a global PRNG state cannot be mutated inside std::sort), David Musser's Introsort (1997) tracks recursion depth and deterministically switches to Heapsort if depth ever exceeds $2\lfloor\log_2 n\rfloor$, upgrading expected $O(n \log n)$ into strict worst-case $O(n \log n)$ with zero extra memory.

Concept Check Probability That Two Rank-Ordered Elements Are Compared in Randomized Quicksort recall

Let $z_1 < z_2 < \dots < z_n$ be the elements of an array sorted by rank. Consider $z_2$ (the 2nd smallest element) and $z_7$ (the 7th smallest element).

Any pivot chosen outside Z_{2,7} = {z_2, ..., z_7} puts all 6 elements of Z_{2,7} into the same recursive call without comparing z_2 and z_7. The first pivot chosen from inside Z_{2,7} is equally likely to be any of its 7 - 2 + 1 = 6 elements; if it is z_2 or z_7 (2 choices out of 6), they are compared; if it is z_3, z_4, z_5, or z_6, they are separated into different partitions and never compared.
Concept Check Adjacent-Rank Comparison Probability in Quicksort apply

Again let $z_1 < z_2 < \dots < z_n$ denote the $n$ distinct keys in sorted order.

For j = i + 1, the set Z_{i, i+1} = {z_i, z_{i+1}} has size 2 and no interior elements! No pivot can ever fall strictly between z_i and z_{i+1}, so they stay in the same subarray until one of them is inevitably selected as a pivot and compared against the other. In fact, every correct comparison sort must compare every adjacent-rank pair (z_i, z_{i+1}) to certify z_i < z_{i+1}!
Concept Check Comparing Constant Factors: Randomized Quicksort vs Merge Sort apply

For large $n$, Merge Sort performs $\approx 1.000\, n \log_2 n$ comparisons, whereas Randomized Quicksort performs $\approx 2n \ln n = (2\ln 2)\,n \log_2 n \approx 1.386\, n \log_2 n$ comparisons.

For scalar keys where comparisons are cheap (1 cycle) relative to memory bandwidth, data movement dominates runtime. Hoare Quicksort moves elements only when both pointers stop on out-of-place keys (1/6 n swaps = 1/3 n writes per pass), which is over 4× fewer writes than Merge Sort and requires zero O(n) auxiliary buffer allocations.
Concept Check Why Linearity of Expectation Applies Despite Correlated Indicator Variables staff

In the proof $\mathbb{E}[X] = \sum_{i < j} \mathbb{E}[X_{ij}] = \sum_{i < j} \frac{2}{j - i + 1}$, a reviewer objects that the events $X_{1,3}$ and $X_{2,4}$ are NOT independent (if $z_2$ is chosen as the first pivot, $X_{1,3} = 0$ and $X_{2,4} = 1$).

Linearity of expectation is an identity of integrals/sums over the sample space and requires zero independence assumptions! Thus E[X] = 2(n+1)H_n - 4n is 100% exact. To prove high-probability tail concentration (since X_{ij} are dependent), we instead analyze the recursion tree depth: along any root-to-leaf path, each step hits the middle 50% of pivots independently with probability 1/2, so a path exceeds 24 ln n depth with probability ≤ n^{-3} by standard binomial Chernoff bounds.

Key Takeaways

Two rank-ordered elements z_i and z_j are compared in Quicksort at most once, and if and only if either z_i or z_j is the first pivot selected from Z_{ij} = {z_i, ..., z_j}.
Because all j - i + 1 elements in Z_{ij} are equally likely to be chosen first, Pr[z_i and z_j compared] = 2 / (j - i + 1).
Summing over all pairs via linearity of expectation yields the exact closed form E[X] = 2(n+1)H_n - 4n ≈ 2n ln n ≈ 1.386 n log_2 n comparisons.
Although Randomized Quicksort performs ~38.6% more comparisons than Merge Sort, it performs 3–4x fewer data movements and operates in-place in L1/L2 cache.
