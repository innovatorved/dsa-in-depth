Modeling Problems as State-Space Graphs: Layered Graphs ((u, k) States) & Bitmask Dijkstra

Shows how augmenting vertex definitions with auxiliary state variables turns constrained optimization problems into standard Dijkstra.

Intuition first

Senior engineers rarely modify the internal code of Dijkstra's algorithm; instead, they modify the definition of a vertex. Whenever a shortest-path problem introduces resource constraints, coupons, fuel tanks, or required key collections, the naive graph G=(V,E)G = (V, E)G=(V,E) violates the Markov property because the best future path from uuu depends on how you arrived at uuu.

By lifting the graph into a product state space V′=V×SV' = V \times \mathcal{S}V′=V×S—such as (u,k)(u, k)(u,k) where kkk is the number of free-edge coupons used, or (u,mask)(u, \text{mask})(u,mask) where mask∈[0,2K−1]\text{mask} \in [0, 2^K - 1]mask∈[0,2K−1] tracks collected keys—the problem becomes memoryless again and is solved by unmodified Dijkstra on G′=(V′,E′)G' = (V', E')G′=(V′,E′).

The Product Graph Lifting Principle

Suppose we want the shortest path from sss to ttt in G=(V,E,w)G = (V, E, w)G=(V,E,w), given at most KKK uses of a special transition (e.g., halving or zeroing an edge's weight). In the base graph GGG, reaching uuu with cost 101010 and 000 coupons left is incomparable to reaching uuu with cost 151515 and 222 coupons left. We restore total ordering per state by defining the (K+1)(K+1)(K+1)-Layer Graph:

Formal Construction — Layered State-Space Graph GK=(V×{0..K},EK)G_K = (V \times \{0..K\}, E_K)GK​=(V×{0..K},EK​)

For each original vertex u∈Vu \in Vu∈V and layer k∈{0,1,…,K}k \in \{0, 1, \dots, K\}k∈{0,1,…,K}, create state (u,k)(u, k)(u,k) indexed in a flat 1D array as id(u,k)=u⋅(K+1)+k\text{id}(u, k) = u \cdot (K + 1) + kid(u,k)=u⋅(K+1)+k. For each original edge (u,v)(u, v)(u,v) of weight www:

  • Intra-Layer Transition (Normal Edge): For all 0≤k≤K0 \le k \le K0≤k≤K, add edge (u,k)→(v,k)(u, k) \to (v, k)(u,k)→(v,k) with weight www.

Hardware Reality — Implicit Transitions vs. Materializing GKG_KGK​ in RAM

Never allocate a physical adjacency list for GKG_KGK​! Generating KKK copies of EEE edges wastes O(K⋅E)O(K \cdot E)O(K⋅E) memory and pollutes L3 cache. Instead, keep the original graph GGG read-only in L1/L2 cache, flatten the distance table to dist[u * (K + 1) + k], and generate the intra-layer and inter-layer transitions on-the-fly inside the Dijkstra loop.

Production Implementation: Implicit Layered Dijkstra (KKK Free Edges)

C++2050 lines
#include <vector>
#include <queue>
#include <limits>
#include <algorithm>

struct FlightEdge {
    int to;
    long long cost;
};

long long shortestPathWithKCoupons(int n, int kMax, int src, int dst,
                                   const std::vector<std::vector<FlightEdge>>& adj) {
    constexpr long long INF = std::numeric_limits<long long>::max() / 4;
    const int stride = kMax + 1;
    std::vector<long long> dist(n * stride, INF);

    using State = std::pair<long long, int>; // (cost, encodedState = u * stride + k)
    std::priority_queue<State, std::vector<State>, std::greater<State>> pq;

    dist[src * stride + 0] = 0;
    pq.emplace(0, src * stride + 0);

    while (!pq.empty()) {
        auto [d, state] = pq.top();
        pq.pop();
        if (d > dist[state]) continue;

        int u = state / stride;
        int k = state % stride;
        if (u == dst) return d; // First time any layer of dst is popped is global min!

        for (const auto& e : adj[u]) {
            // 1. Normal edge on layer k
            int nextSame = e.to * stride + k;
            if (d + e.cost < dist[nextSame]) {
                dist[nextSame] = d + e.cost;
                pq.emplace(dist[nextSame], nextSame);
            }
            // 2. Coupon transition to layer k + 1 (if available)
            if (k < kMax) {
                int nextUp = e.to * stride + (k + 1);
                if (d < dist[nextUp]) {
                    dist[nextUp] = d;
                    pq.emplace(dist[nextUp], nextUp);
                }
            }
        }
    }
    return -1;
}
Failure Mode — Dominance Pruning Neglect & State Explosion

In layered graphs where a larger resource kkk is strictly worse (i.e., kkk counts coupons used), if you already have dist[v][k′]≤dnew\text{dist}[v][k'] \le d_{\text{new}}dist[v][k′]≤dnew​ for some k′<kk' < kk′<k, then state (v,k)(v, k)(v,k) is Pareto-dominated by (v,k′)(v, k')(v,k′) and never needs to be pushed! Checking dominance or propagating downward bounds across layers prevents redundant heap expansions.

In the Weight-Constrained Shortest Path problem (minimize toll cost subject to travel time ≤Tmax⁡\le T_{\max}≤Tmax​), why don't you need to expand a state `(u, time2)` of cost `cost2` if you have already settled `(u, time1)` with `time1 <= time2` and `cost1 <= cost2`?

Since Dijkstra pops states in non-decreasing order of `cost`, the first time a state at `u` is popped it has minimum cost; any subsequent pop at `u` has `cost2 >= cost1`, so it is only useful if its `time2 < minTimeSeen[u]`.

Key Takeaways

Whenever path validity or cost depends on history (coupons used, fuel remaining, keys collected, path parity), augment the vertex state space V' = V x S so transitions become memoryless.
Keep the base graph G read-only and generate state transitions implicitly inside Dijkstra's loop to avoid O(|S| * E) memory overhead.
Splitting resource recharges into unit transitions (u, f) -> (u, f+1) keeps vertex out-degree O(1) instead of O(F).
Because Dijkstra pops states in non-decreasing order of cost, the first time any target state (dst, k) is popped is guaranteed to be the minimum across all layers.
