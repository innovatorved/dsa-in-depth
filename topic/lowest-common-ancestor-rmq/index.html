Lowest Common Ancestor (LCA): Binary Lifting vs Euler Tour + ±1 RMQ Reduction

6 min read Module 3.3: Range Query & Sublinear Decomposition Structures Updated Oct 21, 2026
📄 Cheat Sheet
WilliamFiset Lowest Common Ancestor (LCA) — Euler Tour & RMQ Reduction + Binary Lifting Watch on YouTube ↗

Clearly contrasts O(log N) binary lifting jump pointers against the O(1) query Euler Tour + Sparse Table RMQ reduction.

Intuition first

Given a rooted tree $T$ with $N$ vertices, the Lowest Common Ancestor $\text{LCA}(u, v)$ is the deepest node that is an ancestor of both $u$ and $v$. LCA is the key to computing the distance between any two tree vertices in fast time via $\text{dist}(u, v) = \text{depth}[u] + \text{depth}[v] - 2 \cdot \text{depth}[\text{LCA}(u, v)]$, as well as aggregating paths and building virtual trees.

Two paradigms dominate production and algorithmic practice. Binary Lifting precomputes $\text{up}[k][u]$—the $2^k$-th ancestor of $u$—using the recurrence $\text{up}[k][u] = \text{up}[k-1][\text{up}[k-1][u]]$, answering both $\text{LCA}(u, v)$ and $k$-th ancestor queries ( + "kthAncestor(u, k)" + ) in $O(\log N)$ time. Alternatively, Bender & Farach-Colton's Euler Tour Reduction records every vertex visit (including return visits after each child subtree) in an array $E[0 \dots 2N-2]$. Because the DFS must climb up to $\text{LCA}(u, v)$ to pass from $u$'s subtree to $v$'s subtree and never climbs above $\text{LCA}(u, v)$ in between, $\text{LCA}(u, v)$ is simply the shallowest node in the Euler Tour subarray between $\text{first}[u]$ and $\text{first}[v]$—reducing LCA to an $O(1)$ Sparse Table RMQ!

1. Paradigm A: Binary Lifting ($2^k$ Jump Pointers & Path Aggregates)

Binary Lifting stores a table $\text{up}[k][u]$ for $0 \le k \le \lfloor \log_2 N \rfloor$, where $\text{up}[0][u] = \text{parent}[u]$ and $\text{up}[k][u] = \text{up}[k-1][\text{up}[k-1][u]]$. Combined with entry/exit timestamps ($\text{tin}[u], \text{tout}[u]$), we can test whether $u$ is an ancestor of $v$ in $O(1)$ time:

$$\text{isAncestor}(u, v) \iff \text{tin}[u] \le \text{tin}[v] \;\land\; \text{tout}[v] \le \text{tout}[u]$$

To find $\text{LCA}(u, v)$ when neither is an ancestor of the other, iterate $k$ from $\lfloor \log_2 N \rfloor$ down to $0$: if $\text{up}[k][u]$ is not an ancestor of $v$, jump $u \leftarrow \text{up}[k][u]$. After the loop, $u$ is the immediate child of $\text{LCA}(u, v)$ along the path, so $\text{up}[0][u]$ is the exact LCA!

Euler Tour RMQ Invariant (Harel & Tarjan 1984 / Bender & Farach-Colton 2000): Let $E[0 \dots 2N-2]$ be the sequence of vertices visited in an Euler tour of $T$ (appending $u$ upon entering $u$ and again upon returning to $u$ from each child), and let $\text{first}[u]$ be the index of $u$'s first appearance in $E$. Assuming $\text{first}[u] \le \text{first}[v]$, the Lowest Common Ancestor is the unique vertex minimizing depth in $E[\text{first}[u] \dots \text{first}[v]]$: $$\text{LCA}(u, v) = \arg\min_{w \in E[\text{first}[u] \dots \text{first}[v]]} \text{depth}[w]$$ Moreover, adjacent depths in $E$ differ by exactly $+1$ or $-1$ ($|\text{depth}[E[i]] - \text{depth}[E[i-1]]| = 1$). By partitioning $E$ into blocks of size $b = \frac{1}{2}\log_2 N$ and precomputing all $2^{b-1} = O(\sqrt{N})$ normalized $\pm 1$ block shapes (the Method of Four Russians), LCA achieves optimal $\Theta(N)$ build and $\Theta(1)$ query time!

Hardware & Cache Reality — Packing (depth << 20) | node into a Single 32-bit Integer: In the Euler Tour RMQ approach, instead of looking up depth[euler[i]] via a double pointer indirection inside your Sparse Table comparison, pack each Euler tour entry as a single 32-bit integer packed[i] = (depth[u] << 20) | u (for $N < 2^{20} \approx 10^6$). Now Math.min(a, b) automatically compares by depth first and breaks ties, and the winning node ID is extracted via minVal & ((1 << 20) - 1) with zero extra array lookups!

2. Production Implementation: Binary Lifting (lca, kthAncestor, dist) & $O(1)$ Euler Tour RMQ

JAVASCRIPT
/**
 * 1. Binary Lifting LCA + K-th Ancestor + Tree Distance
 * Build: O(N log N) | Query LCA / kthAncestor / dist: O(log N)
 */
class BinaryLiftingLCA {
  constructor(n, adj, root = 0) {
    this.n = n;
    this.LOG = Math.max(1, 32 - Math.clz32(n));
    this.up = Array.from({ length: this.LOG }, () => new Int32Array(n));
    this.depth = new Int32Array(n);
    this.tin = new Int32Array(n);
    this.tout = new Int32Array(n);
    this._build(adj, root);
  }

  _build(adj, root) {
    let timer = 0;
    // Iterative DFS to avoid call-stack overflow on deep trees (N = 2e5)
    const stack = [[root, root, 0]]; // [u, parent, childIdx]
    while (stack.length > 0) {
      const top = stack[stack.length - 1];
      const u = top[0], p = top[1], idx = top[2];
      if (idx === 0) {
        this.tin[u] = ++timer;
        this.up[0][u] = p;
        for (let k = 1; k < this.LOG; k++) {
          this.up[k][u] = this.up[k - 1][this.up[k - 1][u]];
        }
      }
      const neighbors = adj[u];
      if (idx < neighbors.length) {
        const v = neighbors[idx];
        top[2]++;
        if (v !== p) {
          this.depth[v] = this.depth[u] + 1;
          stack.push([v, u, 0]);
        }
      } else {
        this.tout[u] = ++timer;
        stack.pop();
      }
    }
  }

  isAncestor(u, v) {
    return this.tin[u] <= this.tin[v] && this.tout[v] <= this.tout[u];
  }

  kthAncestor(u, k) {
    if (k > this.depth[u]) return -1;
    for (let bit = 0; k > 0; bit++, k >>= 1) {
      if (k & 1) u = this.up[bit][u];
    }
    return u;
  }

  lca(u, v) {
    if (this.isAncestor(u, v)) return u;
    if (this.isAncestor(v, u)) return v;
    for (let k = this.LOG - 1; k >= 0; k--) {
      if (!this.isAncestor(this.up[k][u], v)) {
        u = this.up[k][u];
      }
    }
    return this.up[0][u];
  }

  dist(u, v) {
    const w = this.lca(u, v);
    return this.depth[u] + this.depth[v] - 2 * this.depth[w];
  }
}

Common Pitfall — Subtree Euler Tour ($N$ Entries) vs Full LCA Euler Tour ($2N - 1$ Entries): Do not confuse the $N$-element preorder traversal tin[u] (used for subtree queries) with the $(2N - 1)$-element Euler Tour E[0..2N-2] required for RMQ-LCA! In an $N$-element preorder array, the LCA of $u$ and $v$ does not appear between tin[u] and tin[v] (it appears before both of them!). Only when you re-append parent $u$ to E[] after returning from every child subtree does the LCA appear inside $[\text{first}[u], \text{first}[v]]$.
Check yourself Question 1 of 4
Concept Check Tree Distance Formula via Lowest Common Ancestor recall

In a rooted tree where `depth[u]` is the distance (or sum of edge weights) from the root to vertex $u$, how is the shortest path distance $\text{dist}(u, v)$ between any two vertices $u$ and $v$ computed using $\text{LCA}(u, v)$?

The path from root to u has length `depth[u] = dist(root, LCA) + dist(LCA, u)`, and the path from root to v has length `depth[v] = dist(root, LCA) + dist(LCA, v)`. Adding them counts `dist(root, LCA) = depth[LCA(u, v)]` twice, so subtracting `2 * depth[LCA(u, v)]` yields `dist(u, LCA) + dist(LCA, v) = dist(u, v)`.
Concept Check Why Binary Lifting Iterates From Highest Bit Down to 0 apply

In Binary Lifting LCA, after checking that neither $u$ nor $v$ is an ancestor of the other, we run `for (int k = LOG - 1; k >= 0; k--) if (!isAncestor(up[k][u], v)) u = up[k][u];` and finally return `up[0][u]`.

Let `w = LCA(u, v)` and let `u'` be the child of `w` on the path to `u` (at distance `d = depth[u] - depth[w] - 1 >= 0` above `u`). A node on `u`'s ancestor chain is NOT an ancestor of `v` if and only if its distance from `u` is `<= d`. Testing powers `2^k` from largest to smallest accumulates the exact binary bits of `d`, landing `u` at `u'`, whose parent `up[0][u']` is `w = LCA(u, v)`.
Concept Check Length of the Full Euler Tour Array for RMQ-LCA apply

To reduce $\text{LCA}(u, v)$ to a Range Minimum Query over vertex depths, we record a vertex in the Euler Tour array $E[]$ when entering the vertex AND every time the DFS returns to the vertex after finishing a child's subtree.

A tree with N vertices has N - 1 edges. An Euler tour starts at the root (1 entry) and traverses each of the N - 1 undirected edges twice (once downward to the child, once upward returning to the parent), appending the destination vertex on each step: 1 + 2*(N - 1) = 2N - 1 entries.
Concept Check Bender & Farach-Colton's ±1 RMQ (Method of Four Russians) staff

Using a standard Sparse Table on the Euler Tour array takes $\Theta(N \log N)$ preprocessing time and space to achieve $O(1)$ LCA queries. How do Bender and Farach-Colton shave the preprocessing down to **optimal $\Theta(N)$ time and space** while keeping $O(1)$ query time?

Because |D[i] - D[i-1]| = 1 at every step of the Euler tour, a block of length b = (1/2) log2(N) is completely determined (up to its starting offset D[0]) by a (b - 1)-bit binary mask of +1/-1 steps. There are only 2^{b-1} <= sqrt(N) distinct bitmasks! Precomputing the intra-block RMQ table for all sqrt(N) bitmasks takes o(N) time, and building a Sparse Table over the M = 2N / b block minimums takes O(M log M) = O((N / log N) log N) = O(N) time!

Key Takeaways

Binary Lifting stores 2^k jump pointers up[k][u] = up[k-1][up[k-1][u]], answering both LCA(u, v) and kthAncestor(u, k) in O(log N) time.
Using entry/exit timestamps (tin[u] <= tin[v] && tout[v] <= tout[u]) checks ancestry in O(1) time and simplifies binary lifting.
Recording a vertex every time an Euler Tour enters it or returns from a child produces an array E[0..2N-2] where LCA(u, v) is the minimum-depth vertex in E[first[u] .. first[v]].
Because adjacent depths in the Euler Tour differ by exactly +1 or -1, Sparse Table (O(N log N) build) or Four Russians ±1 RMQ (O(N) build) answers LCA queries in O(1) time.
