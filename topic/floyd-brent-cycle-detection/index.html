Pointer Chasing: Floyd's Tortoise-and-Hare vs Brent's Cycle Detection

📄 Cheat Sheet

Intuition first

Any deterministic sequence $x_{k+1} = f(x_k)$ over a finite state space eventually enters a cycle (forming a Greek letter $\rho$ with tail length $\mu$ and cycle length $\lambda$). Floyd's Tortoise-and-Hare detects the cycle and locates its exact entrance in $O(\mu + \lambda)$ time and $O(1)$ space via modular congruence, while Richard Brent's teleporting-turtle algorithm finds $\lambda$ directly with $36\%$ fewer step evaluations.

The $\rho$ (Rho) Topology & Floyd's Modular Congruence Proof

Consider a singly linked list (or iterated function $x_{i+1} = f(x_i)$ in Pollard's rho integer factorization and PRNG period testing) that has a non-cyclic prefix (tail) of $\mu$ edges leading to a cycle entrance node $E$, followed by a directed cycle of $\lambda$ edges. In Floyd's Cycle-Finding Algorithm (attributed to Robert W. Floyd, 1967, in Knuth TAOCP Vol. 2), a slow pointer $T$ (Tortoise) advances 1 step per iteration ($t_k = k$) and a fast pointer $H$ (Hare) advances 2 steps per iteration ($h_k = 2k$):

  • Phase 1 (Cycle Detection & Meeting Point): Once $k \ge \mu$, both pointers are inside the cycle of length $\lambda$. Since $H$ closes the gap to $T$ by exactly $2 - 1 = 1$ edge per iteration, $H$ cannot jump over $T$ without landing on it. They meet at the smallest step $k \ge \mu$ where the distance between them $2k - k = k$ is an exact multiple of the cycle length $\lambda$: $$k = m \cdot \lambda \quad \text{for some integer } m \ge 1$$
  • Phase 2 (Finding the Exact Cycle Entrance $\mu$): At the meeting step $k = m \lambda$, the Tortoise is at position $\mu + (k - \mu) \bmod \lambda$—meaning it has traveled $(k - \mu) \equiv -\mu \pmod \lambda$ steps past the cycle entrance $E$. Therefore, advancing a further $\mu$ steps along the cycle reaches offset $(k - \mu) + \mu = k = m \lambda \equiv 0 \pmod \lambda$, which is precisely the cycle entrance $E$! Resetting one pointer to head (distance $\mu$ from $E$) and advancing both pointers at speed 1 causes them to collide at $E$ after exactly $\mu$ steps.
Algorithmic Invariant: Brent's Power-of-Two Teleporting Turtle (1980)

In Floyd's algorithm, every iteration advances $T$ by 1 step and $H$ by 2 steps—costing 3 pointer dereferences (or $f(x)$ evaluations) per step, and requiring a post-processing loop to count the cycle length $\lambda$. Richard P. Brent (1980) asked: why move both pointers continuously when we can keep the Tortoise stationary and teleport it to the Hare's position at exponentially growing powers of two ($2^0, 2^1, 2^2, \dots, 2^i$)?

In Brent's algorithm, the Hare advances 1 step at a time while incrementing the current segment length $\lambda$. Whenever $H == T$, the exact cycle length $\lambda$ is already known! Whenever $\lambda$ reaches the current power-of-two limit $P = 2^i$, we teleport $T \leftarrow H$, reset $\lambda \leftarrow 0$, and double $P \leftarrow 2P$. Once the first power of two $2^i \ge \max(\mu, \lambda)$ is reached, $T$ is parked inside the cycle and $H$ is guaranteed to collide with $T$ in exactly $\lambda$ steps—performing only 1 function evaluation per step and directly yielding $\lambda$!

Hardware Reality: Why Brent's Algorithm Dominates Pollard's Rho & Pointer Chasing

In pointer-chasing workloads where nodes do not fit in L1/L2 cache, every pointer dereference stalls the CPU for ~60–100 ns waiting on DRAM. In Floyd's algorithm, the Tortoise lags behind the Hare by $k / 2$ nodes; if the cycle exceeds L2 cache capacity, the Hare's cache lines are evicted before the Tortoise reaches them, so all 3 pointer dereferences per iteration miss cache! In Brent's algorithm, the Tortoise sits completely stationary in a CPU register while only the Hare advances 1 step per iteration—cutting DRAM traffic and ALU evaluations by up to $3\times$ per step.

Production Implementation: Floyd's Entrance Finder & Brent's Cycle Detector

#include <cstddef>
#include <utility>
#include <vector>

struct ListNode {
  int val;
  ListNode* next;
};

// Floyd's Tortoise and Hare: Returns cycle entrance node (or nullptr if acyclic)
ListNode* floyd_find_cycle_entrance(ListNode* head) noexcept {
  ListNode* slow = head;
  ListNode* fast = head;

  // Phase 1: Find meeting point inside cycle
  while (fast != nullptr && fast->next != nullptr) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) {
      // Phase 2: Reset one pointer to head; advance both at speed 1
      ListNode* finder = head;
      while (finder != slow) {
        finder = finder->next;
        slow = slow->next;
      }
      return finder; // Exact cycle entrance!
    }
  }
  return nullptr;
}

// Brent's Teleporting Turtle: Returns {cycle_entrance, cycle_length_lambda}
std::pair<ListNode*, std::size_t> brent_find_cycle(ListNode* head) noexcept {
  if (head == nullptr) return {nullptr, 0};

  std::size_t power = 1;
  std::size_t lambda = 1;
  ListNode* tortoise = head;
  ListNode* hare = head->next;

  // Phase 1: Find cycle length lambda with 1 pointer chase per iteration!
  while (hare != nullptr && tortoise != hare) {
    if (power == lambda) {
      tortoise = hare; // Teleport tortoise to hare
      power *= 2;
      lambda = 0;
    }
    hare = hare->next;
    ++lambda;
  }
  if (hare == nullptr) return {nullptr, 0};

  // Phase 2: Advance hare lambda steps ahead of head, then move both at speed 1
  tortoise = head;
  hare = head;
  for (std::size_t i = 0; i < lambda; ++i) {
    hare = hare->next;
  }
  while (tortoise != hare) {
    tortoise = tortoise->next;
    hare = hare->next;
  }
  return {tortoise, lambda};
}
Production Pitfall: Starting slow = head and fast = head->next Breaks Phase 2 Entrance Math!

A frequent bug in Floyd's cycle entrance implementation is initializing slow = head; fast = head->next; in Phase 1 (to make a while (slow != fast) loop condition work) and then running standard Phase 2 (finder = head; while (finder != slow) ...). If fast starts at head->next (1 step ahead at $k = 0$), then after $k$ steps fast is at $2k + 1$ while slow is at $k$, so their meeting satisfies $k + 1 = m \lambda$, shifting the meeting point backward by 1 node and causing Phase 2 to spin forever or return the wrong node! Always initialize both slow = head and fast = head at step $0$ and step them before testing if (slow == fast).

Check yourself Question 1 of 4
Concept Check Floyd's Cycle Entry Mathematical Identity recall

In Floyd's Tortoise and Hare algorithm, let $\mu$ be the distance from the list head to the start of the cycle, $\lambda$ be the cycle length, and $k$ be the distance from the cycle start to the meeting point of `slow` and `fast`. Why does resetting one pointer to `head` and advancing both by 1 step per iteration guarantee they meet at the cycle entry?

When `slow` has taken $d = \mu + k$ steps and `fast` has taken $2d$ steps, their difference $d = c\lambda$ is an exact multiple of the cycle length. Thus $\mu + k = c\lambda \implies \mu = (c-1)\lambda + (\lambda - k)$. Advancing $\mu$ steps from `head` reaches the entry; advancing $\mu$ steps from offset $k$ inside the cycle wraps $(c-1)$ times and advances $\lambda - k$ steps, landing on offset $0$ (the cycle entry).
Concept Check Brent's Teleporting Turtle Advantage apply

Compare Floyd's Tortoise and Hare against Brent's cycle detection algorithm on a linked list where each `node = node->next` step incurs a dependent L3/DRAM cache miss. Why is Brent's algorithm ~36% faster in practice?

In Floyd's algorithm, every loop iteration performs 3 pointer dereferences (2 for `fast`, 1 for `slow`). In Brent's algorithm, only `hare` moves (1 dereference per step), and `tortoise` is updated via register assignment (`tortoise = hare`) whenever the step count reaches $2^i$. Additionally, Brent's algorithm finds the exact cycle length $\lambda$ directly during Phase 1.
Concept Check Meeting Position Computation apply

A corrupted singly linked list has a non-cyclic tail of length $\mu = 5$ nodes (indices $0, 1, 2, 3, 4$) leading into a cycle of length $\lambda = 7$ nodes (cycle offsets $0$ through $6$, where index $5$ is cycle offset $0$). Both `slow` and `fast` start at index $0$. At which cycle offset $k \in [0, 6]$ do `slow` and `fast` first meet?

The collision occurs at the smallest non-negative integer $k$ such that $\mu + k$ is a non-zero multiple of $\lambda$. With $\mu = 5$ and $\lambda = 7$, the smallest multiple of $7$ that is $\ge 5$ is $7$ itself, giving $5 + k = 7 \implies k = 2$.
Concept Check Pollard's Rho and Functional Graph Equivalence staff

You are given an immutable read-only array `nums` of length $n + 1$ containing integers in $[1, n]$. Treating `f(x) = nums[x]` as a functional graph starting from index $0$, why is index $0$ guaranteed to be outside any cycle, and what happens if you instead start Floyd's algorithm from an index whose value can appear in `nums`?

A duplicate value $v$ means two distinct indices $i \ne j$ satisfy `nums[i] == nums[j] == v`, giving node $v$ an in-degree $\ge 2$ (the entry to a rho-shaped cycle). Because values are in $[1, n]$, node $0$ has in-degree $0$ and cannot be part of a cycle ($\mu \ge 1$), guaranteeing a path that enters a cycle at the duplicate value $v$.

Why must Floyd's duplicate-finding algorithm start at index `0` when values are in `[1, n]`?

A duplicate value $v$ means two distinct indices $i \ne j$ satisfy `nums[i] == nums[j] == v`, giving node $v$ an in-degree $\ge 2$ (the entry to a rho-shaped cycle). Because values are in $[1, n]$, node $0$ has in-degree $0$ and cannot be part of a cycle ($\mu \ge 1$), guaranteeing a path that enters a cycle at the duplicate value $v$.

Key Takeaways

In Floyd's Tortoise and Hare, the pointers meet at step k = m * lambda inside the cycle, leaving the slow pointer exactly (-mu mod lambda) steps past the cycle entrance E.
Resetting one pointer to head and stepping both pointers by 1 causes them to collide at the exact cycle entrance E after mu steps.
Brent's cycle detection keeps the Tortoise stationary and teleports it to the Hare at powers of two (2^i), performing only 1 pointer chase per step and yielding the cycle length lambda directly.
Any read-only array of N + 1 integers with values in [1..N] forms an implicit functional graph i -> nums[i] rooted at 0, where the duplicate value is the cycle entrance.
