The ρ\rhoρ (Rho) Topology & Floyd's Modular Congruence Proof

Consider a singly linked list (or iterated function xi+1=f(xi)x_{i+1} = f(x_i)xi+1​=f(xi​) in Pollard's rho integer factorization and PRNG period testing) that has a non-cyclic prefix (tail) of μ\muμ edges leading to a cycle entrance node EEE, followed by a directed cycle of λ\lambdaλ edges. In Floyd's Cycle-Finding Algorithm (attributed to Robert W. Floyd, 1967, in Knuth TAOCP Vol. 2), a slow pointer TTT (Tortoise) advances 1 step per iteration (tk=kt_k = ktk​=k) and a fast pointer HHH (Hare) advances 2 steps per iteration (hk=2kh_k = 2khk​=2k):

  • Phase 1 (Cycle Detection & Meeting Point): Once k≥μk \ge \muk≥μ, both pointers are inside the cycle of length λ\lambdaλ. Since HHH closes the gap to TTT by exactly 2−1=12 - 1 = 12−1=1 edge per iteration, HHH cannot jump over TTT without landing on it. They meet at the smallest step k≥μk \ge \muk≥μ where the distance between them 2k−k=k2k - k = k2k−k=k is an exact multiple of the cycle length λ\lambdaλ: k=m⋅λfor some integer m≥1k = m \cdot \lambda \quad \text{for some integer } m \ge 1k=m⋅λfor some integer m≥1
  • Phase 2 (Finding the Exact Cycle Entrance μ\muμ): At the meeting step k=mλk = m \lambdak=mλ, the Tortoise is at position μ+(k−μ) mod λ\mu + (k - \mu) \bmod \lambdaμ+(k−μ)modλ—meaning it has traveled (k−μ)≡−μ(modλ)(k - \mu) \equiv -\mu \pmod \lambda(k−μ)≡−μ(modλ) steps past the cycle entrance EEE. Therefore, advancing a further μ\muμ steps along the cycle reaches offset (k−μ)+μ=k=mλ≡0(modλ)(k - \mu) + \mu = k = m \lambda \equiv 0 \pmod \lambda(k−μ)+μ=k=mλ≡0(modλ), which is precisely the cycle entrance EEE! Resetting one pointer to head (distance μ\muμ from EEE) and advancing both pointers at speed 1 causes them to collide at EEE after exactly μ\muμ steps.
Algorithmic Invariant: Brent's Power-of-Two Teleporting Turtle (1980)

In Floyd's algorithm, every iteration advances TTT by 1 step and HHH by 2 steps—costing 3 pointer dereferences (or f(x)f(x)f(x) evaluations) per step, and requiring a post-processing loop to count the cycle length λ\lambdaλ. Richard P. Brent (1980) asked: why move both pointers continuously when we can keep the Tortoise stationary and teleport it to the Hare's position at exponentially growing powers of two (20,21,22,…,2i2^0, 2^1, 2^2, \dots, 2^i20,21,22,…,2i)?

In Brent's algorithm, the Hare advances 1 step at a time while incrementing the current segment length λ\lambdaλ. Whenever H==TH == TH==T, the exact cycle length λ\lambdaλ is already known! Whenever λ\lambdaλ reaches the current power-of-two limit P=2iP = 2^iP=2i, we teleport T←HT \leftarrow HT←H, reset λ←0\lambda \leftarrow 0λ←0, and double P←2PP \leftarrow 2PP←2P. Once the first power of two 2i≥max⁡(μ,λ)2^i \ge \max(\mu, \lambda)2i≥max(μ,λ) is reached, TTT is parked inside the cycle and HHH is guaranteed to collide with TTT in exactly λ\lambdaλ steps—performing only 1 function evaluation per step and directly yielding λ\lambdaλ!

Hardware Reality: Why Brent's Algorithm Dominates Pollard's Rho & Pointer Chasing

In pointer-chasing workloads where nodes do not fit in L1/L2 cache, every pointer dereference stalls the CPU for ~60–100 ns waiting on DRAM. In Floyd's algorithm, the Tortoise lags behind the Hare by k/2k / 2k/2 nodes; if the cycle exceeds L2 cache capacity, the Hare's cache lines are evicted before the Tortoise reaches them, so all 3 pointer dereferences per iteration miss cache! In Brent's algorithm, the Tortoise sits completely stationary in a CPU register while only the Hare advances 1 step per iteration—cutting DRAM traffic and ALU evaluations by up to 3×3\times3× per step.

Production Implementation: Floyd's Entrance Finder & Brent's Cycle Detector

C++2064 lines
#include <cstddef>
#include <utility>
#include <vector>

struct ListNode {
  int val;
  ListNode* next;
};

// Floyd's Tortoise and Hare: Returns cycle entrance node (or nullptr if acyclic)
ListNode* floyd_find_cycle_entrance(ListNode* head) noexcept {
  ListNode* slow = head;
  ListNode* fast = head;

  // Phase 1: Find meeting point inside cycle
  while (fast != nullptr && fast->next != nullptr) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) {
      // Phase 2: Reset one pointer to head; advance both at speed 1
      ListNode* finder = head;
      while (finder != slow) {
        finder = finder->next;
        slow = slow->next;
      }
      return finder; // Exact cycle entrance!
    }
  }
  return nullptr;
}

// Brent's Teleporting Turtle: Returns {cycle_entrance, cycle_length_lambda}
std::pair<ListNode*, std::size_t> brent_find_cycle(ListNode* head) noexcept {
  if (head == nullptr) return {nullptr, 0};

  std::size_t power = 1;
  std::size_t lambda = 1;
  ListNode* tortoise = head;
  ListNode* hare = head->next;

  // Phase 1: Find cycle length lambda with 1 pointer chase per iteration!
  while (hare != nullptr && tortoise != hare) {
    if (power == lambda) {
      tortoise = hare; // Teleport tortoise to hare
      power *= 2;
      lambda = 0;
    }
    hare = hare->next;
    ++lambda;
  }
  if (hare == nullptr) return {nullptr, 0};

  // Phase 2: Advance hare lambda steps ahead of head, then move both at speed 1
  tortoise = head;
  hare = head;
  for (std::size_t i = 0; i < lambda; ++i) {
    hare = hare->next;
  }
  while (tortoise != hare) {
    tortoise = tortoise->next;
    hare = hare->next;
  }
  return {tortoise, lambda};
}
Production Pitfall: Starting slow = head and fast = head->next Breaks Phase 2 Entrance Math!

A frequent bug in Floyd's cycle entrance implementation is initializing slow = head; fast = head->next; in Phase 1 (to make a while (slow != fast) loop condition work) and then running standard Phase 2 (finder = head; while (finder != slow) ...). If fast starts at head->next (1 step ahead at k=0k = 0k=0), then after kkk steps fast is at 2k+12k + 12k+1 while slow is at kkk, so their meeting satisfies k+1=mλk + 1 = m \lambdak+1=mλ, shifting the meeting point backward by 1 node and causing Phase 2 to spin forever or return the wrong node! Always initialize both slow = head and fast = head at step 000 and step them before testing if (slow == fast).

Concept Check Floyd's Cycle Entry Mathematical Identity recall

In Floyd's Tortoise and Hare algorithm, let μ\muμ be the distance from the list head to the start of the cycle, λ\lambdaλ be the cycle length, and kkk be the distance from the cycle start to the meeting point of `slow` and `fast`. Why does resetting one pointer to `head` and advancing both by 1 step per iteration guarantee they meet at the cycle entry?

When `slow` has taken d=μ+kd = \mu + kd=μ+k steps and `fast` has taken 2d2d2d steps, their difference d=cλd = c\lambdad=cλ is an exact multiple of the cycle length. Thus μ+k=cλ  ⟹  μ=(c−1)λ+(λ−k)\mu + k = c\lambda \implies \mu = (c-1)\lambda + (\lambda - k)μ+k=cλ⟹μ=(c−1)λ+(λ−k).
