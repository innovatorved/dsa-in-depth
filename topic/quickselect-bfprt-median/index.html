Order Statistics: Randomized Quickselect vs Deterministic BFPRT Median-of-Medians

7 min read Module 2.2: Sorting Mechanics, Hybrid Sorts & Linear-Time Order Statistics Updated Oct 23, 2026
📄 Cheat Sheet
Algorithms by Sharma Thankachan Linear-Time Selection: Deterministic Median-of-Medians (BFPRT) Algorithm Watch on YouTube ↗

Proves why grouping elements into columns of 5 guarantees a 30/70 partition split and solves T(n) <= T(n/5) + T(7n/10) + O(n) = O(n).

Intuition first

Quicksort recurses on both partitions ($T(n) = 2T(n/2) + \Theta(n) = \Theta(n \log n)$), whereas finding the $k$-th smallest element only needs to recurse on the one partition containing index $k$, turning the geometric series $n + \frac{n}{2} + \frac{n}{4} + \dots$ into $\Theta(n)$ expected time. And by grouping elements into columns of $5$ and recursively selecting the median of those column medians (BFPRT), we guarantee a pivot that eliminates at least $30\%$ of elements in the worst case—yielding deterministic $O(n)$ selection because $\frac{1}{5} + \frac{7}{10} = \frac{9}{10} < 1$!

Hoare's Quickselect (FIND, 1961): Expected $\Theta(N)$ Selection

Given an unsorted array $A[0 \dots n-1]$ and a target rank $k \in [0, n-1]$, the selection problem asks to rearrange $A$ (like C++'s std::nth_element) such that $A[k]$ holds the element that would appear at index $k$ if $A$ were sorted, with $A[0 \dots k-1] \le A[k] \le A[k+1 \dots n-1]$.

Randomized Quickselect picks a random pivot, partitions $A[lo \dots hi]$ around it to land at index $p$, and branches three ways:

  • If $k == p$: Done! Return $A[p]$.
  • If $k < p$: Recurse (or loop) only on the left subarray $A[lo \dots p-1]$.
  • If $k > p$: Recurse (or loop) only on the right subarray $A[p+1 \dots hi]$.

Because a random pivot lands in the middle $50\%$ of the current subarray (ranks $[n/4, 3n/4]$) with probability $1/2$, every $2$ expected partitions shrink the active subarray to at most $\frac{3}{4}$ of its previous size. Summing the geometric series gives:

$$\mathbb{E}[T(n)] \le \sum_{j=0}^{\infty} 2 \cdot c n \left(\frac{3}{4}\right)^j = 8cn = \Theta(n)$$

More precisely, using indicator random variables $X_{ij}$, Quickselect performs at most $2(n + 1 + (k+1)\ln\frac{n}{k} + (n-k)\ln\frac{n}{n-k}) \le (2 + 2\ln 2)n \approx 3.386n$ expected comparisons to find the median, and $2n + o(n)$ to find the minimum or maximum.

The BFPRT (Blum-Floyd-Pratt-Rivest-Tarjan, 1973) Median-of-Medians Proof

Can we guarantee a good pivot deterministically in $O(n)$ worst-case time? Suppose we partition $n$ elements into $\lceil n/5 \rceil$ groups of $5$, sort each group of $5$ in $O(1)$ comparisons (at most 6 comparisons per group), and recursively call bfprt_select on the $\lceil n/5 \rceil$ group medians to find their exact median $x$ (the Median of Medians).

How many elements are guaranteed to be $\le x$ (and symmetrically $\ge x$)?

  • At least half of the $\lceil n/5 \rceil$ group medians are $\le x$ (that is, $\ge \frac{1}{2}\lceil n/5 \rceil$ groups).
  • In every such group of $5$ (ignoring the one partial group and the pivot's own group), the group median and the $2$ smaller elements in its column of $5$ are all $\le x$—contributing $3$ elements per group!
  • Therefore, at least $3\left(\left\lceil \frac{1}{2}\left\lceil \frac{n}{5} \right\rceil \right\rceil - 2\right) \ge \frac{3n}{10} - 6$ elements are $\le x$, and symmetrically at least $\frac{3n}{10} - 6$ elements are $\ge x$.
  • Consequently, whichever side of $x$ we recurse into after partitioning contains at most $\frac{7n}{10} + 6$ elements!

This yields the celebrated BFPRT recurrence:

$$T(n) \le \underbrace{T\!\left(\left\lceil \frac{n}{5} \right\rceil\right)}_{\text{find median of medians}} + \underbrace{T\!\left(\frac{7n}{10} + 6\right)}_{\text{recurse on survivor side}} + \underbrace{\Theta(n)}_{\text{5-sorts + partition}}$$

Because $\frac{1}{5} + \frac{7}{10} = \frac{9}{10} < 1$, the work decays geometrically at every level of the recursion tree ($1 + 0.9 + 0.81 + \dots = 10$), proving by induction (or Akra-Bazzi with $p = 1$) that $T(n) \le 10cn = \Theta(n)$ in the strict worst case!

Hardware Reality: Why std::nth_element Uses Introselect Instead of Pure BFPRT

Although BFPRT runs in strict worst-case $O(n)$ time, its constant factor is $\approx 16n\text{–}24n$ comparisons and requires recursive median-of-medians passes that touch memory multiple times—making pure BFPRT slower than sorting the entire array with std::sort up to $n \approx 10^6$! Consequently, C++ standard libraries (libstdc++ and libc++) implement David Musser's Introselect (or Alexandrescu's Adaptive Quickselect / Median of Ninthers): it runs standard Median-of-Three Hoare Quickselect in a tight iterative loop ($approx 3n$ comparisons) and only invokes BFPRT (or Heapselect) if the recursion depth/bad-split counter exceeds a logarithmic threshold.

Production C++20 Implementation: Iterative 3-Way Quickselect & In-Place BFPRT

#include <algorithm>
#include <concepts>
#include <cstddef>
#include <utility>

template <std::totally_ordered T>
void small_insertion_sort(T* a, std::size_t lo, std::size_t hi) noexcept {
    for (std::size_t i = lo + 1; i <= hi; ++i) {
        T v = std::move(a[i]);
        std::size_t j = i;
        while (j > lo && v < a[j - 1]) {
            a[j] = std::move(a[j - 1]);
            --j;
        }
        a[j] = std::move(v);
    }
}

// Deterministic In-Place BFPRT (Median-of-Medians) with 3-Way Partitioning for Duplicates
template <std::totally_ordered T>
void bfprt_select(T* a, std::size_t lo, std::size_t hi, std::size_t k) noexcept {
    while (hi - lo > 16) {
        const std::size_t n = hi - lo + 1;
        const std::size_t num_groups = n / 5;

        // 1. Sort each group of 5 in-place and swap its median to the front [lo .. lo + num_groups - 1]
        for (std::size_t g = 0; g < num_groups; ++g) {
            const std::size_t g_lo = lo + g * 5;
            small_insertion_sort(a, g_lo, g_lo + 4);
            std::swap(a[lo + g], a[g_lo + 2]);
        }

        // 2. Recursively select the exact median of the group medians at a[lo + num_groups / 2]
        const std::size_t mom_idx = lo + num_groups / 2;
        bfprt_select(a, lo, lo + num_groups - 1, mom_idx);
        const T pivot = a[mom_idx];

        // 3. 3-Way Dutch National Flag Partition around pivot (handles all-equal keys in O(N)!)
        std::size_t lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < pivot)      std::swap(a[lt++], a[i++]);
            else if (pivot < a[i]) std::swap(a[i], a[gt--]);
            else                   ++i;
        }

        // 4. Tail-loop into whichever region contains target rank k
        if (k < lt) {
            hi = lt - 1;
        } else if (k > gt) {
            lo = gt + 1;
        } else {
            return; // k lies inside [lt .. gt], so a[k] == pivot is in its exact final spot!
        }
    }
    small_insertion_sort(a, lo, hi);
}
Why BFPRT Must Use 3-Way Partitioning on Duplicate Keys

In the classical textbook proof of BFPRT, all elements are assumed to be distinct. If an input array contains $n$ identical elements and you use a 2-way Lomuto partition inside BFPRT, the median-of-medians pivot $x$ is equal to every element, yet 2-way Lomuto places all $n - 1$ equal elements on one side—breaking the $\le 7n/10$ size bound and degrading BFPRT to $\Theta(n^2)$! Using 3-way Dutch National Flag partitioning inside BFPRT and Quickselect guarantees that all elements strictly $< x$ ($ge 3n/10$ minus duplicates) and strictly $> x$ are separated while all duplicates equal to $x$ are coalesced into $[lt \dots gt]$ in one linear pass.

Concept Check Why Quickselect Runs in O(N) Expected Time While Quicksort Takes O(N log N) recall

Both Randomized Quicksort and Randomized Quickselect execute the exact same linear-time partition step at the root ($\Theta(n)$ work).

In Master Theorem / recursion-tree terms, T(n) = 2T(n/2) + cn has work cn at every level across log₂ n levels = cn log₂ n. By contrast, T(n) = T(αn) + cn (with α < 1, e.g., expected α = 3/4) is a geometric series bounded by cn / (1 - α) = O(n) total work.
Concept Check Deriving the 3n/10 Elimination Bound in BFPRT Median-of-Medians apply

In the BFPRT algorithm, $n$ elements are divided into $\lfloor n/5 \rfloor$ groups of $5$, each group is sorted, and $x$ is chosen recursively as the median of the $\lfloor n/5 \rfloor$ group medians.

In the 2D grid where columns are sorted groups of 5 and columns are ordered by their middle row (the group medians), x sits at the center of the middle row. Every element in the top 3 rows of the left 50% of columns is ≤ its column median ≤ x. That quadrant contains (1/2)(n/5) columns × 3 rows = 3n/10 elements!
Concept Check Why BFPRT With Groups of 3 Fails to Achieve Linear Time apply

Suppose you modify BFPRT to divide the array into $\lfloor n/3 \rfloor$ groups of $3$ instead of groups of $5$, finding the median of the $n/3$ group medians.

With groups of 3, half the n/3 medians (n/6 groups) are ≤ x, and each group of 3 contributes 2 elements ≤ x (its median and its minimum), totaling (n/6) × 2 = n/3 elements guaranteed ≤ x. Thus the survivor partition can have up to n - n/3 = 2n/3 elements. Since the recursive subproblem sizes n/3 and 2n/3 sum to (1/3 + 2/3)n = 1.0n, there is no geometric decay and T(n) = Θ(n log n).
Concept Check Finding the Top-K Smallest Elements Unsorted vs Sorted in Optimal Time staff

A search backend needs to extract the top $k = 100$ highest-scoring documents from $n = 10{,}000{,}000$ candidate scores stored in an in-memory vector, and then return just those $100$ documents sorted descending by score.

While `std::partial_sort` (heap-based) takes O(n log k) comparisons, `std::nth_element` (Introselect) partitions the k largest elements to the front in O(n) time (~3n comparisons, streaming sequentially in cache), after which sorting just `k = 100` elements takes ~600 comparisons (< 1 microsecond), yielding optimal Θ(n + k log k) time!

Key Takeaways

Randomized Quickselect recurses on only one side of the partition, shrinking the subarray geometrically to run in Θ(n) expected time (~3.39n comparisons for the median).
BFPRT (Median-of-Medians) partitions elements into groups of 5, sorts each group, and recursively finds the median of those n/5 medians as its pivot.
At least half of the n/5 group medians are <= the Median-of-Medians x, and each contributes 3 elements <= x, guaranteeing at least 3n/10 elements are eliminated on either side.
The recurrence T(n) <= T(n/5) + T(7n/10) + Θ(n) solves to worst-case Θ(n) because 1/5 + 7/10 = 9/10 < 1 (whereas groups of 3 give 1/3 + 2/3 = 1 and degrade to Θ(n log n)).
