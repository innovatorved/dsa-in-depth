Intuition first

We proved in Module 07 that if keys are inserted in a uniformly random permutation, a plain BST has expected depth 1.386log⁡2N1.386 \log_2 N1.386log2​N and expected height O(log⁡N)O(\log N)O(logN). What if an adversary feeds keys in sorted order online? In 1989, Cecilia Aragon and Raimund Seidel invented the Treap (Tree + Heap): assign each node a 64-bit uniformly random priority p(u)p(u)p(u) upon creation, and maintain BST order on keys k(u)k(u)k(u) simultaneously with Max-Heap order on priorities p(u)p(u)p(u)!

By the uniqueness theorem of Cartesian Trees (Vuillemin 1980), for any set of nodes with distinct keys and distinct priorities, there exists one and only one binary tree that is simultaneously a BST on keys and a Heap on priorities—namely, the exact BST that would be produced if the keys were inserted in decreasing order of their random priorities! Even better, in 1998 Guy Blelloch and Margaret Reid-Miller showed that we can discard rotations entirely and express every operation using two 10-line functional primitives: split(T, k) and merge(L, R).

The split and merge Paradigm & Implicit Treaps (Dynamic Rope Arrays)

Instead of bottom-up rotations, every Treap operation reduces to two recursive primitives that run in O(log⁡N)O(\log N)O(logN) expected time:

  • split(T, key) -> (L, R): Partitions Treap TTT into two valid Treaps: LLL (all nodes with key ≤key\le \text{key}≤key) and RRR (all nodes with key >key> \text{key}>key). If T.key≤keyT.\text{key} \le \text{key}T.key≤key, then TTT and all of T.leftT.\text{left}T.left belong to LLL; we recursively split T.rightT.\text{right}T.right into (T.right,R)(T.\text{right}, R)(T.right,R) and return (T,R)(T, R)(T,R). Symmetric when T.key>keyT.\text{key} > \text{key}T.key>key.
  • merge(L, R) -> T: Combines two Treaps LLL and RRR under the precondition that every key in LLL is strictly ≤\le≤ every key in RRR (max(L)≤min⁡(R)max(L) \le \min(R)max(L)≤min(R)). Whichever root has the higher random priority (L.prio>R.prioL.\text{prio} > R.\text{prio}L.prio>R.prio) becomes the combined root, and we recursively merge its right child with RRR (or LLL with R.leftR.\text{left}R.left).

With split and merge, every dictionary and sequence operation is a 2-line composition:

  • insert(T, newNode): (L, R) = split(T, newNode.key); return merge(merge(L, newNode), R);
  • erase(T, key): (L, M) = split(T, key - 1); (Target, R) = split(M, key); return merge(L, R);
  • Implicit Treap (Index-Keyed Sequence / Rope): Drop explicit keys altogether! Maintain only subtree sizes sz(u)=1+sz(u.left)+sz(u.right)\text{sz}(u) = 1 + \text{sz}(u.\text{left}) + \text{sz}(u.\text{right})sz(u)=1+sz(u.left)+sz(u.right). Now a node's 0-based array index in the current subtree is simply sz(u.left)\text{sz}(u.\text{left})sz(u.left)! Calling splitBySize(T, k) cuts an array of length NNN at position kkk in O(log⁡N)O(\log N)O(logN) time, enabling O(log⁡N)O(\log N)O(logN) arbitrary range cut-and-paste, range reversal (via a lazy bool rev bit that swaps children), and range sum/min queries!

Cartesian Tree Uniqueness Theorem (Aragon & Seidel, 1989)

Given NNN nodes (ki,pi)(k_i, p_i)(ki​,pi​) with distinct keys kik_iki​ and distinct priorities pip_ipi​, why is the Treap topology 100% independent of insertion order? Because:

  1. By the Max-Heap property on priorities, the root of any non-empty subset SSS must be the unique element u∗=arg⁡max⁡u∈Sp(u)u^* = \arg\max_{u \in S} p(u)u∗=argmaxu∈S​p(u).
  2. By the BST property on keys, the left subtree must contain S<={u∈S:k(u)<k(u∗)}S_{<} = \{u \in S : k(u) < k(u^*)\}S<​={u∈S:k(u)<k(u∗)} and the right subtree must contain S>={u∈S:k(u)>k(u∗)}S_{>} = \{u \in S : k(u) > k(u^*)\}S>​={u∈S:k(u)>k(u∗)}.

By induction on ∣S∣|S|∣S∣, the tree is uniquely determined and is identical to inserting the keys in decreasing order of pip_ipi​. Since pip_ipi​ are independent uniform random variables, their rank order is a uniformly random permutation π∈SN\pi \in S_Nπ∈SN​—forcing E[depth]=2ln⁡N≈1.386log⁡2N\mathbb{E}[\text{depth}] = 2 \ln N \approx 1.386 \log_2 NE[depth]=2lnN≈1.386log2​N even when an attacker inserts keys in sorted order 1,2,…,N1, 2, \dots, N1,2,…,N!

// C++20: Implicit Treap supporting O(log N) Subarray Reversal [l, r] via split & merge
#include <cstdint>
#include <utility>

struct ImplicitTreapNode {
    int val;
    uint64_t prio;
    int sz = 1;
    bool rev = false; // Lazy range-reversal tag
    ImplicitTreapNode *l = nullptr, *r = nullptr;

    ImplicitTreapNode(int v, uint64_t p) : val(v), prio(p) {}
};

inline int size(const ImplicitTreapNode* t) noexcept { return t ? t->sz : 0; }

inline void pull(ImplicitTreapNode* t) noexcept {
    if (t) t->sz = 1 + size(t->l) + size(t->r);
}

inline void pushLazy(ImplicitTreapNode* t) noexcept {
    if (t && t->rev) {
        std::swap(t->l, t->r);
        if (t->l) t->l->rev ^= true;
        if (t->r) t->r->rev ^= true;
        t->rev = false;
    }
}

// Splits T into L (first k elements) and R (remaining N - k elements)
std::pair<ImplicitTreapNode*, ImplicitTreapNode*> splitBySize(ImplicitTreapNode* t, int k) {
    if (!t) return {nullptr, nullptr};
    pushLazy(t);
    int leftCount = size(t->l);
    if (k <= leftCount) {
        auto [L, R] = splitBySize(t->l, k);
        t->l = R;
        pull(t);
        return {L, t};
    } else {
        auto [L, R] = splitBySize(t->r, k - leftCount - 1);
        t->r = L;
        pull(t);
        return {t, R};
    }
}

ImplicitTreapNode* merge(ImplicitTreapNode* L, ImplicitTreapNode* R) {
    if (!L || !R) return L ? L : R;
    pushLazy(L);
    pushLazy(R);
    if (L->prio > R->prio) {
        L->r = merge(L->r, R);
        pull(L);
        return L;
    } else {
        R->l = merge(L, R->l);
        pull(R);
        return R;
    }
}

// Reverses contiguous subarray [l, r] (0-indexed inclusive) in O(log N) expected time
ImplicitTreapNode* reverseRange(ImplicitTreapNode* root, int l, int r) {
    auto [t1, t23] = splitBySize(root, l);
    auto [t2, t3]  = splitBySize(t23, r - l + 1);
    if (t2) t2->rev ^= true;
    return merge(t1, merge(t2, t3));
}

  • Violating merge(L, R) Precondition (max(L)lemin(R)max(L) le min(R)max(L)lemin(R)): merge(L, R) is NOT a general set-union operation—it strictly requires that every key in LLL is lelele every key in RRR! Calling merge on overlapping key ranges silently destroys the BST invariant. (To union two overlapping Treaps in O(Mlog(N/M))O(M log(N/M))O(Mlog(N/M)), split the lower-priority root's tree by the higher-priority root's key and recursively union both sides.)
  • Using 16-Bit std::rand() on Windows (RAND_MAX = 32767): On MSVC/Windows, C's rand() only returns a 15-bit integer (0dots327670 dots 327670dots32767). An Implicit Treap represents a dynamic array A[0..N−1]A[0..N-1]A[0..N−1] by replacing explicit keys with subtree sizes (`left.size + 1`). To reverse the subarray A[l..r]A[l..r]A[l..r] in O(log⁡N)O(\log N)O(logN) time, how are `splitBySize`, lazy `rev` tags, and `merge` combined?

First, `splitBySize(T, l)` isolates the prefix A[0..l-1] in T1 (size l) and the suffix A[l..N-1] in T23. Second, `splitBySize(T23, r - l + 1)` isolates the exact target range A[l..r] (which has length r - l + 1) as the root of T2. Toggling `T2.rev ^= 1` lazily swaps left and right children whenever nodes of T2 are visited, and `merge(T1, merge(T2, T3))` reassembles the array in O(log N) time.

By backwards analysis over random permutations, the expected length of each spine is 1 - 1/k + 1/n < 1, so the total expected number of rotations per insertion or deletion is strictly less than 2!

Key Takeaways

A Treap assigns each node a random priority and enforces BST order on keys and Max-Heap order on priorities, guaranteeing the exact distribution of a Randomly Built BST regardless of input order.
Every Treap operation can be implemented without rotations using two O(log N) primitives: split(T, key) and merge(L, R) (where max(L) <= min(R)).
An Implicit Treap replaces explicit keys with dynamic subtree sizes sz(u.left), turning a balanced BST into a dynamic array supporting O(log N) insert, delete, cut-and-paste, and range reversal.
Always generate priorities with a fast 64-bit PRNG (e.g., SplitMix64 or mt19937_64) to prevent birthday-paradox priority collisions.
