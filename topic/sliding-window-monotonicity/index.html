Fixed & Variable Sliding Windows: Monotonicity & Two-Pointer Validity

7 min read Module 1.2: Contiguous Arrays, Bit Manipulation & Pointer Idioms Updated Oct 23, 2026

Intuition first

A variable-size sliding window $[L, R]$ achieves $O(N)$ time if and only if the validity predicate $P(L, R)$ is monotonic with respect to window expansion and contraction—guaranteeing that the optimal left boundary $L^*(R)$ is a non-decreasing function of $R$, so $L$ and $R$ never need to move backward.
0:00 / --:--

When Is a Sliding Window Mathematically Valid?

Given an array $A[0 \dots N-1]$ and a validity predicate $P(L, R) \in \{\text{true}, \text{false}\}$ defined on contiguous subarrays $A[L \dots R]$, a variable sliding window advances $R$ from $0$ to $N-1$ and increments $L$ while maintaining validity. For this algorithm to be correct without ever backtracking $L$, the predicate $P$ must be hereditary (monotonic under inclusion):

$$[L', R'] \subseteq [L, R] \text{ and } P(L, R) = \text{true} \implies P(L', R') = \text{true}$$

Equivalently, by contraposition: if $[L, R]$ violates the constraint ($P(L, R) = \text{false}$), then any super-interval $[L, R']$ with $R' > R$ also violates the constraint, and any sub-interval $[L', R]$ with $L' > L$ moves closer to satisfying it. Define $L^*(R)$ as the smallest index $L$ (for longest valid window) or largest index $L$ (for shortest valid window) paired with right endpoint $R$. Monotonicity guarantees:

$$R_1 < R_2 \implies L^*(R_1) \le L^*(R_2)$$

Because both $L$ and $R$ start at $0$, only increment, and never exceed $N$, the inner while loop executes at most $N$ times across the entire run of the outer loop, proving an exact bound of at most $2N$ pointer steps ($O(1)$ amortized work per element).

Architectural Invariant: The "Exactly $K$" Reduction via $\text{atMost}(K) - \text{atMost}(K - 1)$

Suppose we want to count the number of subarrays with exactly $K$ distinct elements (or sum $= K$ over binary/non-negative arrays). A naive single sliding window fails because for a fixed $R$, there is not a single boundary $L$, but a whole contiguous range $[L_{\text{min}}, L_{\text{max}}]$ of valid left endpoints where the window has exactly $K$ distinct elements.

However, the predicate $P_K(L, R) \equiv (\text{distinct}(A[L \dots R]) \le K)$ is strictly monotonic! For each $R$, once we shrink $L$ until $\text{distinct}(A[L \dots R]) \le K$, every subarray starting at $i \in [L, R]$ and ending at $R$ is a subset of $[L, R]$ and therefore also has $\le K$ distinct elements—contributing exactly $(R - L + 1)$ valid subarrays ending at $R$. By set difference:

$$\text{countExactly}(K) = \text{countAtMost}(K) - \text{countAtMost}(K - 1)$$

Hardware Reality: Flat Frequency Arrays vs. std::unordered_map in Sliding Windows

Inside a sliding window loop, every step increments freq[A[R]] and decrements freq[A[L]]. Using std::unordered_map<char, int> for ASCII/UTF-8 byte streams or bounded integer alphabets performs a hash computation, bucket pointer dereference, and linked-list node chase on every single character—turning a 1-cycle operation into a 40-cycle L1/L2 cache stall. Allocating a stack-resident flat array int32_t freq[256] = {0} occupies exactly 1 KB (16 cache lines), remains permanently pinned in L1d cache, and executes window expansions/contractions in ~1.2 CPU clock cycles per byte.

Production Implementation: Count Subarrays with Exactly K Distinct Integers

C++20
#include <cstdint>
#include <vector>

// Prerequisite: 0 <= nums[i] <= max_val (or coordinate-compressed to [0, N))
std::int64_t subarrays_at_most_k_distinct(const std::vector<int>& nums, int k, int max_val) {
  if (k <= 0) return 0;
  std::vector<int> freq(static_cast<std::size_t>(max_val + 1), 0);
  int distinct = 0;
  std::size_t left = 0;
  std::int64_t total_subarrays = 0;

  for (std::size_t right = 0; right < nums.size(); ++right) {
    if (freq[nums[right]]++ == 0) {
      ++distinct;
    }
    while (distinct > k) {
      if (--freq[nums[left]] == 0) {
        --distinct;
      }
      ++left;
    }
    // Every subarray [i .. right] with left <= i <= right has <= k distinct elements
    total_subarrays += static_cast<std::int64_t>(right - left + 1);
  }
  return total_subarrays;
}

std::int64_t subarrays_exactly_k_distinct(const std::vector<int>& nums, int k, int max_val) {
  return subarrays_at_most_k_distinct(nums, k, max_val)
       - subarrays_at_most_k_distinct(nums, k - 1, max_val);
}
Production Pitfall: Applying Two-Pointer Sliding Windows to Arrays with Negative Numbers

Never use a standard two-pointer sliding window to find the shortest or longest subarray with sum $\ge K$ or $\le K$ when the input array can contain negative numbers! With negative values, shrinking the window by advancing $L$ past a negative number $A[L] < 0$ increases the window sum, and advancing $R$ across a negative number decreases the window sum. Monotonicity is destroyed, and $L^*(R)$ is no longer non-decreasing. When negative numbers are present:

  • For Subarray Sum Equals $K$: use Prefix Sums + Hash Map ($O(N)$ time, $O(N)$ space).
  • For Shortest Subarray with Sum $\ge K$ (LeetCode 862): use Prefix Sums + a Monotonic Increasing Deque ($O(N)$ time, $O(N)$ space).

Check yourself Question 1 of 4
Concept Check Amortized O(N) Complexity Proof of Variable Sliding Window recall

A variable-size sliding window algorithm consists of an outer `for (right = 0; right < N; ++right)` loop and an inner `while (!valid(left, right)) { ++left; }` loop.

Even though a single iteration of `right` could advance `left` by $O(N)$ steps, those elements are permanently evicted and never re-examined. Since `left` is monotonically non-decreasing in $[0, N]$, $\sum_{right=0}^{N-1} (\text{inner iterations}) = \text{final\_left} \le N$.
Concept Check Counting Subarrays with Exactly K Distinct Elements apply

You need to count the total number of contiguous subarrays of $A[0 \dots N-1]$ that contain <strong>exactly $K$</strong> distinct integers in $O(N)$ time.

For a fixed `right`, the set of left endpoints `i` with `distinct(i, right) <= K` forms a single contiguous interval `[left .. right]` of size `right - left + 1`. Subtracting the count of subarrays with $\le K - 1$ distinct elements leaves those with *exactly* $K$ distinct elements.
Concept Check Why Negative Numbers Break Sliding Window Sum Monotonicity apply

Consider finding the length of the shortest contiguous subarray of $A[0 \dots N-1]$ with sum $\ge K$, where $A$ contains both positive and negative integers (e.g., `A = [3, -2, 5]`, `K = 4`).

In `[3, -2, 5]` with `K = 4`, at `R = 2` (`sum = 6 >= 4`), shrinking `L` from `0` to `1` drops `3` (`sum = 3 < 4`), causing the standard loop to stop shrinking and miss `[5]` (`L = 2, R = 2, sum = 5 >= 4`)! Maintaining a monotonic increasing deque of candidate prefix sums $P[L]$ solves the problem in $O(N)$.
Concept Check L1 Cache Footprint: Flat Alphabet Array vs Hash Map in Byte-Stream Windows staff

You are optimizing a high-throughput packet inspection filter that runs a sliding window over 10 GB/s of raw byte payloads (`uint8_t`), tracking character frequencies inside the active window.

16 general-purpose 64-bit registers hold only 128 bytes, so a 1 KB array lives in L1d cache (32 KB–48 KB), where indexed loads/stores (`freq[byte]++`) retire in 1 cycle. By contrast, `std::unordered_map` incurs hash calculation, bucket lookup, and linked-node pointer dereferences.

Key Takeaways

A two-pointer sliding window is valid if and only if the window predicate P(L, R) is monotonic under interval inclusion, guaranteeing L*(R) is non-decreasing.
Because L and R each start at 0 and increment at most N times without ever backtracking, the inner while loop runs at most N times total across the entire algorithm (O(N) amortized).
Problems asking for 'exactly K' of a monotonic metric (like distinct elements or odd numbers) reduce to countAtMost(K) - countAtMost(K - 1).
Negative numbers destroy sum monotonicity; replace plain sliding windows with Prefix Sums + Hash Map (for exact sum K) or Prefix Sums + Monotonic Deque (for shortest sum >= K).
