Count-Min Sketch & Streaming Frequency Estimation Error Bounds

Erik Demaine proves the (ε, δ) Markov inequality bound for Count-Min Sketch, shows why pairwise independence suffices, and demonstrates dyadic range heavy-hitter queries.

Intuition first

Imagine monitoring a core network router processing N=1010N = 10^{10}N=1010 packets per minute across billions of distinct (src_ip, dst_ip) flows. Maintaining an exact hash table of flow frequencies requires gigabytes of DRAM, whereas high-speed SRAM on an ASIC switch is measured in megabytes. The Count-Min Sketch (CMS) (Cormode & Muthukrishnan, 2005) maintains a compact 2D matrix of d×wd \times wd×w counters Whose size is completely independent of the number of distinct keys, depending only on the desired additive error ε\varepsilonε and failure probability δ\deltaδ!

By choosing width w=⌈e/ε⌉w = \lceil e / \varepsilon \rceilw=⌈e/ε⌉ and depth d=⌈ln⁡(1/δ)⌉d = \lceil \ln(1/\delta) \rceild=⌈ln(1/δ)⌉ with ddd pairwise-independent hash functions, taking the minimum across the ddd rows (f^x=min⁡jC[j][hj(x)]\hat{f}_x = \min_{j} C[j][h_j(x)]f^​x​=minj​C[j][hj​(x)]) guarantees via Markov's inequality that fx≤f^x≤fx+εNf_x \le \hat{f}_x \le f_x + \varepsilon Nfx​≤f^​x​≤fx​+εN with probability at least 1−δ1 - \delta1−δ.

Hardware Reality: Flat Power-of-Two Row Alignment & Linear Mergeability

When implementing Count-Min Sketch in C++ or Rust, rounding the width w=⌈e/ε⌉w = \lceil e / \varepsilon \rceilw=⌈e/ε⌉ up to the next power of two W=2rW = 2^rW=2r replaces slow modulo arithmetic with a single bitwise mask h & (W - 1) and allows all ddd rows to be stored in a single contiguous 1D allocation table[(j << r) | (h & (W - 1))]. Furthermore, standard CMS (without conservative update) is a linear sketch: two sketches C(A)C^{(A)}C(A) and C(B)C^{(B)}C(B) computed on separate CPU cores or data centers with the same seeds can be merged in-place via vectorized SIMD addition C(A+B)=C(A)+C(B)C^{(A+B)} = C^{(A)} + C^{(B)}C(A+B)=C(A)+C(B) (_mm256_add_epi64).

Production C++20 Implementation: Count-Min Sketch with Conservative Update & Heavy-Hitter Heap

// C++20: Count-Min Sketch with Power-of-2 Width, Conservative Update & Distributed Merge
#include <vector>
#include <cstdint>
#include <algorithm>
#include <limits>
#include <bit>
#include <cmath>

class CountMinSketch {
    uint32_t depth_;
    uint32_t width_;      // Power of 2 >= ceil(e / eps)
    uint32_t widthMask_;
    uint32_t widthShift_;
    std::vector<uint64_t> table_;
    std::vector<uint64_t> seeds_;

    uint32_t hashRow(uint64_t key, uint32_t row) const noexcept {
        uint64_t x = key ^ seeds_[row];
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return static_cast<uint32_t>(x ^ (x >> 31)) & widthMask_;
    }

public:
    CountMinSketch(double epsilon, double delta) {
        uint32_t rawW = static_cast<uint32_t>(std::ceil(2.718281828459045 / epsilon));
        width_ = std::bit_ceil(std::max(16U, rawW));
        widthMask_ = width_ - 1;
        widthShift_ = std::countr_zero(width_);
        depth_ = std::max(1U, static_cast<uint32_t>(std::ceil(std::log(1.0 / delta))));
        table_.assign(static_cast<size_t>(depth_) * width_, 0ULL);
        seeds_.resize(depth_);
        for (uint32_t j = 0; j < depth_; ++j) {
            seeds_[j] = 0x9e3779b97f4a7c15ULL * (j + 1) + 0x6a09e667f3bcc908ULL;
        }
    }

    // Standard linear update (supports distributed sketch addition & deletions)
    void updateLinear(uint64_t key, uint64_t count = 1) noexcept {
        for (uint32_t j = 0; j < depth_; ++j) {
            uint32_t col = hashRow(key, j);
            table_[(static_cast<size_t>(j) << widthShift_) | col] += count;
        }
    }

    // Conservative update: tightens accuracy by only raising counters to min_est + count
    uint64_t updateConservative(uint64_t key, uint64_t count = 1) noexcept {
        uint64_t target = estimate(key) + count;
        for (uint32_t j = 0; j < depth_; ++j) {
            uint32_t col = hashRow(key, j);
            uint64_t& cell = table_[(static_cast<size_t>(j) << widthShift_) | col];
            if (cell < target) cell = target;
        }
        return target;
    }

    uint64_t estimate(uint64_t key) const noexcept {
        uint64_t ans = std::numeric_limits<uint64_t>::max();
        for (uint32_t j = 0; j < depth_; ++j) {
            uint32_t col = hashRow(key, j);
            ans = std::min(ans, table_[(static_cast<size_t>(j) << widthShift_) | col]);
        }
        return ans;
    }
};

Failure Modes & Adversarial Pitfalls

  • Using Conservative Update When Deletions or Linear Sketch Merging Are Required: Conservative update is non-linear: if you apply conservative updates and later subtract counts on deletion, or add two conservatively updated sketches from two servers together, the invariant f^x≥fx\hat{f}_x \ge f_xf^​x​≥fx​ is violated and you can suffer underestimation errors! Use standard updateLinear whenever deletions or distributed sketch merges are required.
  • Taking the Minimum When Negative Updates (Turnstile Model) Are Present: In turnstile streams where keys can be both incremented and decremented (ct∈Zc_t \in \mathbb{Z}ct​∈Z) with bounded negative noise, taking the min fails if a colliding key had a net negative update. In the general turnstile model, query the median across rows (or use Charikar's Count Sketch with ±1\pm 1±1 Rademacher sign hashes).

Concept Check Count-Min Sketch Error Guarantee and Direction of Bias recall

A Count-Min Sketch (Cormode & Muthukrishnan) is initialized with d=⌈ln⁡(1/δ)⌉d = \lceil \ln(1/\delta) \rceild=⌈ln(1/δ)⌉ rows and w=⌈e/ε⌉w = \lceil e / \varepsilon \rceilw=⌈e/ε⌉ counters per row, processing a non-negative insertion-only stream of total weight N=∑ifiN = \sum_i f_iN=∑i​fi​.

In a non-negative stream, every counter C[j][h_j(x)] equals the true frequency f_x plus the sum of frequencies of other items colliding in row j. Since every row is an upper bound (C[j][h_j(x)] ≥ f_x), the minimum over all d rows is also ≥ f_x and fails to beat f_x + εN only if EVERY one of the d independent rows suffers collision mass > εN, which by Markov's inequality happens with probability at most (1/e)^d = δ.

You want to track per-flow packet counts on a router such that the additive error is at most ε=0.001\varepsilon = 0.001ε=0.001 (0.1%0.1\%0.1% of total traffic NNN) with failure probability at most δ=0.01\delta = 0.01δ=0.01 (99%99\%99% confidence) using 32-bit (4-byte) counters.

Concept Check Conservative Update (Count-Min-CU) Optimization apply

When a packet for key xxx arrives with weight 111, the five counters for xxx in a Count-Min Sketch currently hold values `[12, 19, 12, 45, 23]`.

Before the update, we know f_x ≤ min(12, 19, 12, 45, 23) = 12. After adding 1 to x's frequency, the new true frequency is at most 13. Setting C[j][h_j(x)] = max(C[j][h_j(x)], 13) maintains the exact invariant C[j][h_j(x)] ≥ f_x while avoiding unnecessary inflation of counters that already suffered collisions, cutting average estimation error by up to 2–5× in skewed Zipfian streams.
Concept Check Why Count Sketch Uses Median of Signed Counters vs Count-Min's Minimum staff

In Count Sketch, E[s_j(x) C[j][h_j(x)]] = f_x because E[s_j(x)s_j(y)] = 0 for y ≠ x. However, the noise sum ∑_{y≠x} s_j(x)s_j(y)f_y can be negative as well as positive, so taking the minimum would select the most negatively biased row! By Chebyshev + Chernoff concentration across d rows, the median of bounded-variance unbiased estimators gives ±ε‖f_{-k}‖₂ error, which is dramatically tighter than ε‖f‖₁ on heavy-tailed Zipfian distributions.

Key Takeaways

Count-Min Sketch estimates point frequencies within additive error +εN with probability ≥ 1 - δ using w = ⌈e/ε⌉ columns and d = ⌈ln(1/δ)⌉ pairwise-independent rows.
The error proof relies only on linearity of expectation (pairwise independence) to bound expected row collision noise by εN/e, followed by Markov's inequality and row independence.
Conservative Update only increments counters up to min_j C[j][h_j(x)] + c, dramatically reducing overestimation on positive-only streams at the cost of losing linearity.
Pairing a Count-Min Sketch with an O(K)-sized Min-Heap identifies streaming φ-heavy hitters in O(d + log K) time per packet.
