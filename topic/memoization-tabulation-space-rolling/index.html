Top-Down Memoization vs Bottom-Up Tabulation & Rolling-Array Space Compression

Compares top-down DFS memoization against bottom-up topological tabulation and demonstrates how sliding dependency windows compress space.

Intuition first

Top-down memoization is DFS on the state DAG that lazily visits only the states reachable from the query; bottom-up tabulation is topological relaxation that strips away recursion stack overhead, enables SIMD vectorization, and lets us free old rows the instant no future state depends on them.

1. Top-Down Memoization vs. Bottom-Up Tabulation

Given the same state DAG G=(V,E)G = (V, E)G=(V,E), how should we evaluate it?

  • Top-Down Memoization (DFS Post-Order): Starts at the target state ttt and recursively evaluates predecessors, caching results in a table or hash map.
    • When Top-Down Wins: When the state space VVV is sparse—only a tiny fraction of states in the bounding box are actually reachable from the initial state (e.g., Digit DP with tight bounds, Game DP with strange step sizes, or Interval DP with sparse valid cuts).
    • Where Top-Down Loses: Recursion stack frames cost 323232–646464 bytes per depth (risking stack overflow at depth N=105N = 10^5N=105), function call prologue/epilogue overhead, non-contiguous memory access, and inability to apply rolling-array space compression.
  • Bottom-Up Tabulation (Explicit Topological Order): Iterates through nested loops in an order where all dependencies of state xxx are already computed.
    • When Bottom-Up Wins: Dense state spaces where most states are visited, tight time limits requiring L1 cache locality and auto-vectorization (SIMD), or memory limits requiring O(M)O(M)O(M) rolling-array compression instead of O(N⋅M)O(N \cdot M)O(N⋅M).

Core Invariant — The Dependency Horizon & Rolling-Array Compression

Suppose a 2D recurrence dp[i][j]dp[i][j]dp[i][j] depends only on states in rows iii and i−1i-1i−1: dp[i][j]=f(dp[i−1][… ],dp[i][… ])dp[i][j] = f(dp[i-1][\dots], dp[i][\dots])dp[i][j]=f(dp[i−1][…],dp[i][…]). Once row iii is completely computed, row i−1i-1i−1 is dead (out-degree 000 to any future row i′>ii' > ii′>i). Thus we only ever need to store the active dependency frontier:
1. Two-Row Ping-Pong (dp[2][M]): Index rows via i & 1 (current) and (i - 1) & 1 (previous).
2. Single-Row In-Place (dp[M]): Overwrite dp[j] in-place by choosing the inner loop direction (j=0→Mj = 0 \to Mj=0→M vs. j=M→0j = M \to 0j=M→0) so we never clobber a value from row i−1i-1i−1 that a later j′j'j′ in row iii still needs!

2. Choosing the Inner Loop Direction for 1-Row Compression

When compressing dp[i][j]dp[i][j]dp[i][j] into a 1D array dp[j]dp[j]dp[j]:

  • If dp[i][j]dp[i][j]dp[i][j] depends on dp[i−1][j−w]dp[i-1][j - w]dp[i−1][j−w] (strictly smaller column from the previous row, as in 0/1 Knapsack), we must iterate jjj backward (W→wW \to wW→w) so that when computing dp[j]dp[j]dp[j], dp[j−w]dp[j - w]dp[j−w] still holds its untouched value from row i−1i-1i−1.
  • If dp[i][j]dp[i][j]dp[i][j] depends on dp[i][j−w]dp[i][j - w]dp[i][j−w] (smaller column from the current row, as in Unbounded Knapsack), we iterate jjj forward (w→Ww \to Ww→W) so that dp[j−w]dp[j - w]dp[j−w] already holds the updated row-iii value.
  • If dp[i][j]dp[i][j]dp[i][j] depends on dp[i−1][j]dp[i-1][j]dp[i−1][j], dp[i][j−1]dp[i][j-1]dp[i][j−1], and dp[i−1][j−1]dp[i-1][j-1]dp[i−1][j−1] (as in Edit Distance / LCS), we iterate jjj forward while saving the single overwritten diagonal scalar prev_diag = dp[j] in a temporary register!

#include <algorithm>
#include <cstdint>
#include <string_view>
#include <vector>

// Space-Optimized O(min(N, M)) Longest Common Subsequence using 1 Row + 1 Diagonal Register
int lcs_rolling_one_row(std::string_view a, std::string_view b) {
    // Always make <code>b</code> the shorter string so our 1D array uses O(min(N, M)) space!
    if (a.size() < b.size()) std::swap(a, b);
    const int n = static_cast<int>(a.size());
    const int m = static_cast<int>(b.size());

    std::vector<int> dp(m + 1, 0);

    for (int i = 1; i <= n; ++i) {
        int prev_diag = 0; // Holds dp[i - 1][j - 1]
        for (int j = 1; j <= m; ++j) {
            int saved_up = dp[j]; // Save dp[i - 1][j] before overwriting dp[j]
            if (a[i - 1] == b[j - 1]) {
                dp[j] = prev_diag + 1;
            } else {
                dp[j] = std::max(dp[j], dp[j - 1]); // max(dp[i-1][j], dp[i][j-1])
            }
            prev_diag = saved_up; // Advance diagonal register for j + 1
        }
    }
    return dp[m];
}

// Two-Row Ping-Pong Template (i & 1) when transitions read multiple non-adjacent columns
long long min_falling_path_ping_pong(const std::vector<std::vector<int>>& grid) {
    const int n = static_cast<int>(grid.size());
    const int m = static_cast<int>(grid[0].size());
    constexpr long long INF = 1LL << 60;

    std::vector<long long> dp[2];
    dp[0].assign(grid[0].begin(), grid[0].end());
    dp[1].assign(m, INF);

    for (int i = 1; i < n; ++i) {
        const int cur = i & 1;
        const int prv = (i - 1) & 1;
        for (int j = 0; j < m; ++j) {
            long long best = dp[prv][j];
            if (j > 0) best = std::min(best, dp[prv][j - 1]);
            if (j + 1 < m) best = std::min(best, dp[prv][j + 1]);
            dp[cur][j] = grid[i][j] + best;
        }
    }
    const auto& last_row = dp[(n - 1) & 1];
    return *std::min_element(last_row.begin(), last_row.end());
}

Production Pitfall — Failing to Reset dp[i & 1] in Ping-Pong Buffers

When using a two-row ping-pong buffer dp[2][M] with dp[cur][j] = std::min(dp[cur][j], ...) (especially in Push DP or multi-transition loops), remember that dp[cur] still holds stale values from row i - 2! You must reset std::fill(dp[cur].begin(), dp[cur].end(), INF) (or overwrite dp[cur][j] unconditionally first) at the start of every outer loop iteration.

Because `cur = i & 1` alternates between `0` and `1`, at iteration `i`, buffer `dp[cur]` contains the results written during iteration `i - 2`. Key Takeaways

Top-down memoization visits only reachable states from the query via DFS, excelling on sparse state spaces.
Bottom-up tabulation eliminates recursion overhead, streams sequentially through cache lines, and enables rolling-array space compression.
When dp[i][j] depends only on row i-1 and row i, space compresses from O(N * M) to O(min(N, M)) by swapping the shorter dimension to the inner loop.
