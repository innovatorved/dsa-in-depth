1. Primary vs. Secondary Columns in Generalized Exact Cover

Many real-world Constraint Satisfaction Problems (CSPs) combine two types of constraints:

  • Primary Constraints (Exact Cover — $\sum_{r \in R^*} A[r, c] = 1$): Every column $c \in [1..N_{\text{primary}}]$ must be covered by the final solution. Example: In $N$-Queens, each of the $N$ rows and $N$ columns must contain exactly one queen. In Sudoku, all $324$ cell/row/col/box constraints are primary.
  • Secondary Constraints (At-Most-One — $\sum_{r \in R^*} A[r, c] \le 1$): Each column $c \in [N_{\text{primary}} + 1 .. N_{\text{total}}]$ may be covered at most once. Example: In $N$-Queens, the $2N - 1$ main diagonals and $2N - 1$ anti-diagonals can hold at most one queen (some diagonals remain empty!).

Core Invariant — Secondary Column Header Initialization Trick

How does Knuth's DLX support secondary columns with zero changes to cover(), uncover(), or search()?
During initialization, link only the primary column headers $1..N_{\text{primary}}$ into the circular horizontal list of the master root node 0. Initialize each secondary column header $c > N_{\text{primary}}$ as a self-loop horizontally (L[c] = R[c] = c)!
Because secondary columns are not reachable from nodes[0].R, search() never requires them to be covered. Yet when a chosen row contains a $1$ in a secondary column $c$, cover(c) still traverses c.D and removes all conflicting rows that also touch column $c$!

2. End-to-End Sudoku Compiler to 324-Column DLX Torus

For a $9 \times 9$ Sudoku grid, candidate $(r, c, d)$ with $r, c, d \in \{0..8\}$ maps to row ID $81r + 9c + d$ and covers 4 primary columns (1-indexed in $1..324$):

  1. $ ext{Col}_{ ext{cell}} = 1 + (9r + c) \in [1..81]$
  2. $ ext{Col}_{ ext{row}} = 81 + 1 + (9r + d) \in [82..162]$
  3. $ ext{Col}_{ ext{col}} = 162 + 1 + (9c + d) \in [163..243]$
  4. $ ext{Col}_{ ext{box}} = 243 + 1 + (9 \cdot (3\lfloor r/3 \rfloor + \lfloor c/3 \rfloor) + d) \in [244..324]$

If cell $(r, c)$ is already pre-filled with clue $d_0$, we emit only the single row $(r, c, d_0)$ instead of all 9 digits $d \in \{0..8\}$. At depth 0 of search(), the S-heuristic sees $S[\text{Col}_{\text{cell}}(r, c)] = 1$ and immediately unit-propagates every pre-filled clue before making a single guess!

Hardware Reality — Fixed-Capacity Stack Allocation for Sub-Millisecond Solves

A $9 \times 9$ Sudoku DLX instance has at most $325$ header nodes plus $729 \times 4 = 2{,}916$ matrix nodes, for a strict upper bound of $3{,}241$ nodes. By storing the entire torus in a fixed-capacity std::vector reserved upfront (or std::array<Node, 3250>), the entire solver state occupies $3{,}250 \times 24 \text{ bytes} = 78 \text{ KB}$, executing zero dynamic heap allocations during search.

4. Complete Production C++20 Build Lab Implementation

#include <array>
#include <cstdint>
#include <string>
#include <vector>

class GeneralizedDLX {
    struct Node {
        int L, R, U, D, col, row_id;
    };
    std::vector<Node> nodes;
    std::vector<int> col_size;
    std::vector<int> partial_sol;

    void cover(int c) {
        nodes[nodes[c].R].L = nodes[c].L;
        nodes[nodes[c].L].R = nodes[c].R;
        for (int i = nodes[c].D; i != c; i = nodes[i].D) {
            for (int j = nodes[i].R; j != i; j = nodes[j].R) {
                nodes[nodes[j].D].U = nodes[j].U;
                nodes[nodes[j].U].D = nodes[j].D;
                --col_size[nodes[j].col];
            }
        }
    }

    void uncover(int c) {
        for (int i = nodes[c].U; i != c; i = nodes[i].U) {
            for (int j = nodes[i].L; j != i; j = nodes[j].L) {
                ++col_size[nodes[j].col];
                nodes[nodes[j].D].U = j;
                nodes[nodes[j].U].D = j;
            }
        }
        nodes[nodes[c].R].L = c;
        nodes[nodes[c].L].R = c;
    }

public:
    GeneralizedDLX(int num_primary, int num_secondary = 0, int reserve_nodes = 4096)
        : nodes(num_primary + num_secondary + 1),
          col_size(num_primary + num_secondary + 1, 0) {
        nodes.reserve(reserve_nodes);
        // Link primary columns [1..num_primary] into master header 0
        for (int c = 0; c <= num_primary; ++c) {
            nodes[c] = { (c == 0 ? num_primary : c - 1),
                         (c == num_primary ? 0 : c + 1),
                         c, c, c, -1 };
        }
        // Secondary columns [num_primary+1 .. total] are self-looped horizontally!
        for (int c = num_primary + 1; c <= num_primary + num_secondary; ++c) {
            nodes[c] = { c, c, c, c, c, -1 };
        }
    }

    void add_row(int row_id, const std::vector<int>& cols) {
        int first = -1;
        for (int c : cols) {
            int idx = static_cast<int>(nodes.size());
            int up = nodes[c].U;
            nodes.push_back({ idx, idx, up, c, c, row_id });
            nodes[up].D = idx;
            nodes[c].U = idx;
            ++col_size[c];
            if (first == -1) {
                first = idx;
            } else {
                int left = nodes[first].L;
                nodes[idx].L = left;
                nodes[idx].R = first;
                nodes[left].R = idx;
                nodes[first].L = idx;
            }
        }
    }

    bool solve_one(std::vector<int>& out_solution) {
        if (nodes[0].R == 0) {
            out_solution = partial_sol;
            return true;
        }
        int best_c = nodes[0].R;
        for (int c = nodes[0].R; c != 0; c = nodes[c].R) {
            if (col_size[c] < col_size[best_c]) {
                best_c = c;
                if (col_size[best_c] <= 1) break; // Early exit if 0 (dead) or 1 (forced unit)
            }
        }
        if (col_size[best_c] == 0) return false;

        cover(best_c);
        for (int r = nodes[best_c].D; r != best_c; r = nodes[r].D) {
            partial_sol.push_back(nodes[r].row_id);
            for (int j = nodes[r].R; j != r; j = nodes[j].R) cover(nodes[j].col);
            if (solve_one(out_solution)) return true;
            for (int j = nodes[r].L; j != r; j = nodes[j].L) uncover(nodes[j].col);
            partial_sol.pop_back();
        }
        uncover(best_c);
        return false;
    }
};

// Complete 9x9 Sudoku Solver compiled to 324-Column Exact Cover
bool solve_sudoku_dlx(std::array<std::string, 9>& board) {
    GeneralizedDLX dlx(324, 0, 3250);
    for (int r = 0; r < 9; ++r) {
        for (int c = 0; c < 9; ++c) {
            int box = (r / 3) * 3 + (c / 3);
            for (int d = 0; d < 9; ++d) {
                if (board[r][c] != '.' && board[r][c] != ('1' + d)) continue;
                int row_id = r * 81 + c * 9 + d;
                int col_cell = 1 + (r * 9 + c);
                int col_row  = 81 + 1 + (r * 9 + d);
                int col_col  = 162 + 1 + (c * 9 + d);
                int col_box  = 243 + 1 + (box * 9 + d);
                dlx.add_row(row_id, { col_cell, col_row, col_col, col_box });
            }
        }
    }
    std::vector<int> sol;
    if (!dlx.solve_one(sol)) return false;
    for (int row_id : sol) {
        int r = row_id / 81;
        int c = (row_id / 9) % 9;
        int d = row_id % 9;
        board[r][c] = static_cast<char>('1' + d);
    }
    return true;
}

Production Pitfall — Branching on Secondary Columns or Duplicate Column Indices in a Row

Never choose a secondary column in the S-heuristic selection loop (it is prevented automatically when secondary columns are initialized with L[c] = R[c] = c outside the 0 header list). Also ensure that no single row passed to add_row() contains the same column index twice—duplicate columns in a single row corrupt the vertical doubly-linked list during cover().

Concept Check Primary vs. Secondary Columns in Generalized DLX recall

In Knuth's generalized Exact Cover formulation (e.g., for $N$-Queens where rows and columns are Primary and diagonals are Secondary), what is the exact semantic difference between a Primary column and a Secondary column?

Primary columns enforce exact partitioning ($\sum_{r \in R^*} A[r, c] = 1$), whereas Secondary columns enforce mutual exclusion without requiring coverage ($\sum_{r \in R^*} A[r, c] \le 1$), such as board diagonals that may remain empty.

Concept Check Secondary Column Header Initialization in DLX apply

How do we initialize a Secondary column header $c$ in the DLX node table so that `cover()`, `uncover()`, and `search()` require **zero extra `if` branches** to distinguish Primary from Secondary columns?

Because `search()` only scans `for (int c = nodes[0].R; c != 0; c = nodes[c].R)`, any column header not linked into `0`'s horizontal ring is never required to be covered. Yet when a row containing a $1$ in secondary column $c$ is chosen, calling `cover(c)` executes `nodes[nodes[c].R].L = nodes[c].L` (a harmless no-op on a self-loop) and proceeds to unlink all conflicting rows in `c`'s vertical list!
Concept Check S-Heuristic Unit Propagation Equivalence in Sudoku DLX staff

When a $9 \times 9$ Sudoku grid with pre-filled clues is compiled into a 324-column DLX matrix by emitting only 1 row for each clue cell $(r, c, d_0)$ and 9 rows for each empty cell, what happens during the very first calls to `solve_one()` under the S-heuristic (`col_size[best_c]` minimum)?

In Sudoku DLX, a column with `S[c] == 1` in the `col_cell` range is a Naked Single (only 1 candidate digit fits in that cell), and a column with `S[c] == 1` in `col_row`/`col_col`/`col_box` is a Hidden Single (only 1 position in that unit can hold digit $d$). Key Takeaways

Generalized Exact Cover partitions columns into Primary (covered == 1) and Secondary (covered <= 1) constraints.
Initializing secondary column headers with L[c] = R[c] = c excludes them from the master header loop while preserving automatic conflict removal when covered.
Compiling 9x9 Sudoku into 324 primary columns and at most 729 rows allows the S-heuristic to automatically perform unit propagation (S=1) and bivalue branching (S=2).
Breaking out of the S-heuristic column scan as soon as S[c] <= 1 saves O(|C|) header scans on forced unit propagations.
