Geometric Divide-and-Conquer: Planar Closest Pair of Points in O(N log N)

6 min read Module 2.3: Binary Search on Monotonic Spaces & Divide-and-Conquer Updated Oct 19, 2026
📄 Cheat Sheet
Algorithms by Sharma Thankachan Planar Closest Pair of Points in O(N log N) via Divide and Conquer (7-Neighbor Strip Proof) Watch on YouTube ↗

Erik Demaine derives the O(N log N) planar closest-pair divide-and-conquer algorithm and proves the geometric packing lemma bounding strip comparisons to at most 7 neighbors.

Intuition first

Checking all N(N-1)/2 pairs of 2D points takes O(N^2) time. Splitting the plane at the median X-coordinate solves the left and right halves recursively to get minimum distance delta = min(delta_L, delta_R). The cross-boundary merge only needs to inspect points inside a vertical strip of width 2*delta centered at the split line—and because no two points in the same half can be closer than delta, a simple 8-box pigeonhole packing proves each point in the Y-sorted strip only needs to be compared against the next 7 points!

Exhaustive pairwise inspection requires (N2)=Θ(N2)\binom{N}{2} = \Theta(N^2)(2N​)=Θ(N2) distance calculations. Can we apply spatial Divide-and-Conquer like Merge Sort to reach O(Nlog⁡N)O(N \log N)O(NlogN)?

  1. Divide: Presort all points by XXX-coordinate (PXP_XPX​) and by YYY-coordinate (PYP_YPY​) once in O(Nlog⁡N)O(N \log N)O(NlogN) time. The 7-Neighbor Geometric Packing Lemma

Suppose we iterate through the strip SSS in ascending order of YYY-coordinate. For any point p=S[i]p = S[i]p=S[i] with vertical coordinate y0y_0y0​, any subsequent point q=S[j]q = S[j]q=S[j] (j>ij > ij>i) with ∥p−q∥2<δ\|p - q\|_2 < \delta∥p−q∥2​<δ must lie inside the bounding rectangle R=[xm−δ,xm+δ]×[y0,y0+δ]R = [x_m - \delta, x_m + \delta] \times [y_0, y_0 + \delta]R=[xm​−δ,xm​+δ]×[y0​,y0​+δ] of width 2δ2\delta2δ and height δ\deltaδ.

Partition RRR into eight squares of side δ2×δ2\frac{\delta}{2} \times \frac{\delta}{2}2δ​×2δ​ (four in the left half x≤xmx \le x_mx≤xm​, four in the right half x≥xmx \ge x_mx≥xm​). The maximum distance between any two points inside the same δ2×δ2\frac{\delta}{2} \times \frac{\delta}{2}2δ​×2δ​ square is its diagonal:

diam(δ2×δ2)=(δ2)2+(δ2)2=δ2≈0.7071δ<δ\text{diam}\left(\frac{\delta}{2} \times \frac{\delta}{2}\right) = \sqrt{\left(\frac{\delta}{2}\right)^2 + \left(\frac{\delta}{2}\right)^2} = \frac{\delta}{\sqrt{2}} \approx 0.7071\delta < \deltadiam(2δ​×2δ​)=(2δ​)2+(2δ​)2​=2​δ​≈0.7071δ<δ

Because every pair of points inside PLP_LPL​ has distance ≥δL≥δ\ge \delta_L \ge \delta≥δL​≥δ and every pair inside PRP_RPR​ has distance ≥δR≥δ\ge \delta_R \ge \delta≥δR​≥δ, at most one point can occupy each of the 8 squares! Counting S[i]S[i]S[i] itself as occupying one square, at most 7 subsequent points S[i+1],…,S[i+7]S[i+1], \dots, S[i+7]S[i+1],…,S[i+7] can lie inside RRR.

Hardware Reality: Combining Bottom-Up Y-Merge vs. Top-Down Partitioning

Instead of passing down a pre-sorted PYP_YPY​ vector and partitioning it on the way down (which requires scattered writes depending on whether a point belongs to PLP_LPL​ or PRP_RPR​), production implementations perform the YYY-sort bottom-up during the unwind phase—identical to standard Merge Sort! After recursive calls on [lo,mid)[lo, mid)[lo,mid) and [mid,hi)[mid, hi)[mid,hi) return δL\delta_LδL​ and δR\delta_RδR​ AND leave both subarrays sorted by YYY, a single streaming std::merge by YYY takes O(N)O(N)O(N) sequential L1-cached reads, followed immediately by the strip filter and 7-neighbor scan. Furthermore, comparing squared Euclidean distances Δx2+Δy2<δ2\Delta x^2 + \Delta y^2 < \delta^2Δx2+Δy2<δ2 inside the inner loop avoids hardware sqrtpd latency (~12–15 cycles) until the final return.

#include <algorithm>
#include <cmath>
#include <cstddef>
#include <cstdint>
#include <limits>
#include <vector>

struct Point2D {
    double x;
    double y;
    std::uint32_t id;
};

struct ClosestPairResult {
    double min_dist;
    std::uint32_t id1;
    std::uint32_t id2;
};

inline double dist_sq(const Point2D& a, const Point2D& b) noexcept {
    const double dx = a.x - b.x;
    const double dy = a.y - b.y;
    return dx * dx + dy * dy;
}

ClosestPairResult solve_closest_pair(std::vector<Point2D>& pts) {
    const std::size_t n = pts.size();
    if (n < 2) return {std::numeric_limits<double>::infinity(), 0, 0};

    // 1. Sort initially by X-coordinate (tie-break by Y)
    std::sort(pts.begin(), pts.end(), [](const Point2D& a, const Point2D& b) {
        return (a.x != b.x) ? (a.x < b.x) : (a.y < b.y);
    });

    std::vector<Point2D> scratch(n);
    std::vector<Point2D> strip(n);
    double best_d2 = std::numeric_limits<double>::infinity();
    std::uint32_t best_u = 0, best_v = 0;

    auto update_best = [&](const Point2D& a, const Point2D& b) noexcept {
        const double d2 = dist_sq(a, b);
        if (d2 < best_d2) {
            best_d2 = d2;
            best_u = a.id;
            best_v = b.id;
        }
    };

    auto rec = [&](auto& self, std::size_t lo, std::size_t hi) -> void {
        if (hi - lo <= 8) {
            // Small base case: O(1) brute force + insertion sort by Y
            for (std::size_t i = lo; i < hi; ++i) {
                for (std::size_t j = i + 1; j < hi; ++j) {
                    update_best(pts[i], pts[j]);
                }
            }
            std::sort(pts.begin() + lo, pts.begin() + hi,
                      [](const Point2D& a, const Point2D& b) { return a.y < b.y; });
            return;
        }

        const std::size_t mid = lo + (hi - lo) / 2;
        const double mid_x = pts[mid].x;

        self(self, lo, mid);
        self(self, mid, hi);

        // Merge [lo, mid) and [mid, hi) by Y-coordinate in O(N) time
        std::merge(pts.begin() + lo, pts.begin() + mid,
                   pts.begin() + mid, pts.begin() + hi,
                   scratch.begin() + lo,
                   [](const Point2D& a, const Point2D& b) { return a.y < b.y; });
        std::copy(scratch.begin() + lo, scratch.begin() + hi, pts.begin() + lo);

        // Collect points within horizontal distance sqrt(best_d2) of mid_x
        std::size_t s_len = 0;
        for (std::size_t i = lo; i < hi; ++i) {
            const double dx = pts[i].x - mid_x;
            if (dx * dx < best_d2) {
                strip[s_len++] = pts[i];
            }
        }

        // Scan Y-sorted strip: inner loop executes at most 7 times per point!
        for (std::size_t i = 0; i < s_len; ++i) {
            for (std::size_t j = i + 1; j < s_len; ++j) {
                const double dy = strip[j].y - strip[i].y;
                if (dy * dy >= best_d2) break; // Early exit on vertical distance
                update_best(strip[i], strip[j]);
            }
        }
    };

    rec(rec, 0, n);
    return {std::sqrt(best_d2), best_u, best_v};
}
Pitfall: Splitting by Coordinate Value Instead of Array Index

Suppose N2\frac{N}{2}2N​ points lie on the exact same vertical line x=xmx = x_mx=xm​. If you partition PYP_YPY​ using the predicate p.x < mid_x vs. p.x >= mid_x, all collinear points fall into the right partition, causing an unbalanced O(N2)O(N^2)O(N2) recursion tree! Either split strictly by original array index / identity when top-down partitioning PYP_YPY​, or use the bottom-up std::merge by YYY shown above, which always splits indices at mid = lo + (hi - lo) / 2 regardless of duplicate XXX-coordinates.

Check yourself Question 1 of 4
Concept Check The 2-Delta Vertical Strip Filter recall

In the Shamos-Hoey planar closest-pair divide-and-conquer algorithm, the left and right recursive calls return minimum distances delta_L and delta_R around dividing line x = x_m, and we set delta = min(delta_L, delta_R).

For a pair (p_L, p_R) with p_L.x <= x_m <= p_R.x to have Euclidean distance < delta, both horizontal distances |p_L.x - x_m| and |p_R.x - x_m| must be strictly less than delta.
Concept Check Why Each Strip Point Checks at Most 7 Subsequent Neighbors apply

In the Y-sorted strip S of width 2*delta, for each point S[i] at vertical coordinate y_0, we only inspect subsequent points S[j] (j > i) with S[j].y < y_0 + delta.

Four (delta/2) x (delta/2) squares cover the left [x_m - delta, x_m] x [y_0, y_0 + delta] region (all in P_L) and four cover the right region (all in P_R). Since any two points inside the same half are at distance >= delta and each small square has diameter delta/sqrt(2) < delta, each of the 8 squares holds at most 1 point!
Concept Check Avoiding O(N log^2 N) by Bottom-Up Y-Merging apply

A developer implements the closest-pair divide-and-conquer algorithm and calls `std::sort(strip.begin(), strip.end(), cmp_y)` inside every recursive call before scanning the strip.

In the worst case, all N points can lie inside the 2*delta strip, so calling std::sort by Y at each recursion level costs O(N log N) work per level across log N levels = O(N log^2 N). Merging the two already-Y-sorted subarrays via std::merge takes O(N) time per level.
Concept Check Degenerate Collinear Points & Top-Down Y-Partitioning Pitfall staff

In an alternative top-down implementation, you pass both X-sorted array P_X and Y-sorted array P_Y down the recursion and partition P_Y into P_YL and P_YR using `if (p.x < mid_x) P_YL.push_back(p); else P_YR.push_back(p);`.

Splitting purely by coordinate inequality `p.x < mid_x` fails when many points lie on the vertical line `x == mid_x`. Either compare the full tuple `(p.x, p.y, p.id) < (mid_p.x, mid_p.y, mid_p.id)` when partitioning top-down, or merge by Y bottom-up over exact index ranges `[lo, mid)` and `[mid, hi)`.

Key Takeaways

Sorting by X initially and merging by Y bottom-up during recursion satisfies T(N) = 2T(N/2) + O(N) = O(N log N).
Only points with |p.x - x_mid| < delta can form a cross-boundary pair closer than delta = min(delta_L, delta_R).
Partitioning the 2*delta x delta bounding box into eight (delta/2 x delta/2) squares of diagonal delta/sqrt(2) < delta proves that each point in the Y-sorted strip needs to check at most 7 subsequent points.
Tracking squared distance best_d2 eliminates slow hardware square-root instructions from the recursive inner loop.
