Proving Greedy Correctness: Greedy Stays Ahead & Exchange Arguments (Interval Scheduling, Minimizing Lateness)

Rigorous derivation of the Earliest Finish Time (Greedy Stays Ahead) and Earliest Deadline First (Exchange Argument) correctness proofs.

Intuition first

Anyone can invent five plausible greedy heuristics in two minutes; four of them will fail on a 4-element counterexample. To prove a greedy algorithm is 100% optimal, we either show by induction that every greedy prefix finishes at least as early as any valid solution ('Greedy Stays Ahead'), or we take a hypothetical optimal solution O* and surgically swap its choices into our greedy choices without hurting the objective ('Exchange Argument').

1. Proof Paradigm I: "Greedy Stays Ahead" (Unweighted Interval Scheduling)

Given $n$ intervals $[s_i, f_i)$, select a maximum-size subset of mutually compatible intervals ($f_i \le s_j$ or $f_j \le s_i$). Plausible heuristics like Earliest Start Time, Shortest Duration ($f_i - s_i$), or Fewest Conflicts all fail on simple counterexamples. The unique simple rule that works is Earliest Finish Time (EFT): sort intervals by $f_1 \le f_2 \le \dots \le f_n$ and greedily pick the next compatible interval.

Core Invariant — Greedy Stays Ahead Lemma

Let $G = (i_1, i_2, \dots, i_k)$ be the intervals chosen by EFT, and let $O = (j_1, j_2, \dots, j_m)$ be any mutually compatible set of intervals ordered chronologically. Then for every index $r \le \min(k, m)$:

$$f(i_r) \le f(j_r)$$

Proof by Induction: For $r = 1$, $i_1$ has the minimum finish time among all intervals, so $f(i_1) \le f(j_1)$. Assuming $f(i_{r-1}) \le f(j_{r-1})$, since $O$ is compatible we know $f(j_{r-1}) \le s(j_r)$, which implies $f(i_{r-1}) \le s(j_r)$. Thus $j_r$ is in the candidate pool of compatible intervals available when EFT chooses $i_r$. Since EFT picks the candidate with minimum finish time, $f(i_r) \le f(j_r)$. If $m > k$, then $f(i_k) \le f(j_k) \le s(j_{k+1})$, meaning EFT would have also picked $j_{k+1}$—contradiction! Hence $k = m$.

2. Proof Paradigm II: Adjacent Exchange Argument (Minimizing Maximum Lateness & Smith's Rule)

When every item must be scheduled (a permutation problem), we use a Local Exchange Argument:

  • Minimizing Maximum Lateness ($L_{\max} = \max_i \max(0, C_i - d_i)$): Each job $i$ has processing time $t_i > 0$ and deadline $d_i$. Earliest Deadline First (EDF) sorts jobs by $d_1 \le d_2 \le \dots \le d_n$. Suppose an optimal schedule $O^*$ has an inversion ($d_i > d_j$, yet $i$ is scheduled immediately before $j$). Swapping adjacent jobs $i$ and $j$ leaves all other jobs unchanged, moves $j$ earlier (reducing $L_j$), and finishes $i$ at $j$'s old completion time $C'_i = C_j$. Since $d_i > d_j$, the new lateness $C_j - d_i < C_j - d_j \le L_{\max}(O^*)$. Thus swapping adjacent inversions never increases $L_{\max}$!
  • Weighted Completion Time ($\sum_i w_i C_i$, Smith's Rule): Sort jobs by $w_i / t_i$ descending (i.e., $w_i t_j > w_j t_i$). Swapping an adjacent pair $(i, j)$ changes the total objective by $\Delta = w_i t_j - w_j t_i$, so an optimal schedule cannot contain any adjacent pair with $w_i / t_i < w_j / t_j$.

Hardware Reality — Cross-Multiplication vs. Floating-Point Division in Comparators

When sorting by ratio $w_i / t_i$ (Smith's Rule) or $a_i / b_i$ in C++, writing (double)a.w / a.t > (double)b.w / b.t suffers from two bugs: hardware floating-point division takes 10–14 cycles (vs. 3 cycles for 64-bit integer IMUL), and for 64-bit integers $> 2^{53}$, IEEE-754 double loses precision, which can violate strict weak ordering ($a < b$ and $b < c$ but $a \not< c$) and cause std::sort to segfault out-of-bounds! Always compare via 64-bit or 128-bit integer cross-multiplication: 1LL * a.w * b.t > 1LL * b.w * a.t.

4. Reference C++20 Implementation

#include <algorithm>
#include <cstdint>
#include <vector>

struct Interval {
    long long start;
    long long finish;
};

// 1. Maximum Disjoint Intervals via Earliest Finish Time (Greedy Stays Ahead)
int max_disjoint_intervals(std::vector<Interval> intervals) {
    if (intervals.empty()) return 0;
    std::sort(intervals.begin(), intervals.end(), [](const Interval& a, const Interval& b) {
        return a.finish < b.finish;
    });

    int count = 1;
    long long last_finish = intervals[0].finish;
    for (std::size_t i = 1; i < intervals.size(); ++i) {
        if (intervals[i].start >= last_finish) {
            ++count;
            last_finish = intervals[i].finish;
        }
    }
    return count;
}

struct Job {
    long long processing_time;
    long long deadline;
    long long weight;
};

// 2. Minimize Maximum Lateness via Earliest Deadline First (Exchange Argument)
long long minimize_max_lateness(std::vector<Job> jobs) {
    std::sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) {
        return a.deadline < b.deadline;
    });
    long long current_time = 0;
    long long max_lateness = 0;
    for (const auto& job : jobs) {
        current_time += job.processing_time;
        max_lateness = std::max(max_lateness, current_time - job.deadline);
    }
    return max_lateness;
}

// 3. Minimize Weighted Sum of Completion Times via Smith's Rule (w_i / t_i descending)
long long minimize_weighted_completion_time(std::vector<Job> jobs) {
    std::sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) {
        return static_cast<__int128>(a.weight) * b.processing_time >
               static_cast<__int128>(b.weight) * a.processing_time;
    });
    long long current_time = 0;
    long long total_weighted_cost = 0;
    for (const auto& job : jobs) {
        current_time += job.processing_time;
        total_weighted_cost += job.weight * current_time;
    }
    return total_weighted_cost;
}

Production Pitfall — Non-Transitive Custom Comparators & Weighted Intervals

When devising an exchange comparator between two items $i$ and $j$ (such as monsters with damage/healing or tower bricks with weight/strength), always verify that your pairwise preference relation $i \prec j$ is transitive! If $i \prec j$ and $j \prec k$ does not imply $i \prec k$, std::sort exhibits undefined behavior. Also remember: the moment intervals carry weights (Weighted Interval Scheduling) or jobs have release times $r_i$ in $\min L_{\max}$, greedy fails completely—Weighted Interval Scheduling requires $O(N \log N)$ Dynamic Programming, and $1 | r_j | L_{\max}$ is strongly NP-hard!

Concept Check Interval Scheduling Greedy Criterion recall

Which greedy sorting criterion is guaranteed to find a maximum-cardinality subset of mutually non-overlapping intervals $[s_i, f_i)$?

Earliest Finish Time (EFT) frees up the resource as early as possible, satisfying the Greedy Stays Ahead invariant $f(i_r) \le f(j_r)$ for every index $r$ against any valid schedule.
Napkin Math · Capacity Minimizing Maximum Lateness (EDF Trace) apply

Three jobs have processing times and deadlines $(t_i, d_i)$ as follows: Job A $(t=4, d=6)$, Job B $(t=2, d=4)$, and Job C $(t=3, d=5)$. Starting at time $0$, what is the minimum possible maximum lateness $L_{\max} = \max_i \max(0, C_i - d_i)$ achieved by Earliest Deadline First (EDF)?

±0% accepted
EDF sorts jobs by deadline ascending: Job B ($d=4$), Job C ($d=5$), Job A ($d=6$). Completion times: $C_B = 2$ (lateness $\max(0, 2-4) = 0$), $C_C = 2 + 3 = 5$ (lateness $\max(0, 5-5) = 0$), $C_A = 5 + 4 = 9$ (lateness $\max(0, 9-6) = 3$). Thus $L_{\max} = 3$.
Concept Check Smith's Rule Exchange Cost Calculation apply

We wish to schedule $n$ jobs with processing times $t_i > 0$ and positive weights $w_i > 0$ on a single machine to **minimize** the weighted sum of completion times $\sum_{i=1}^n w_i C_i$. By an adjacent exchange argument on jobs $i$ and $j$, in what order should the jobs be sorted?

If job $i$ immediately precedes job $j$ starting at time $T$, their contribution is $w_i(T + t_i) + w_j(T + t_i + t_j)$. Swapping them changes the cost by $\Delta = w_i t_j - w_j t_i$. For $i$ before $j$ to be optimal ($\Delta \ge 0$), we need $w_i t_j \ge w_j t_i \iff w_i / t_i \ge w_j / t_j$.

Standard library `std::sort` implementations use unguarded insertion sort and Hoare partitioning that rely on the pivot itself acting as a sentinel (`comp(pivot, pivot) == false`). If `comp(a, b)` returns `true` for equal elements, the pointer increments past the pivot and out of bounds of the underlying buffer.

Key Takeaways

Always test greedy intuition by searching for a 3-element counterexample or proving optimality via Greedy Stays Ahead or an Exchange Argument.
Earliest Finish Time (EFT) solves unweighted interval scheduling in O(N log N) because the k-th greedy interval finishes no later than the k-th interval of any valid schedule.
Adjacent exchange arguments prove permutation schedules optimal by showing that removing an inversion between adjacent items i and j never degrades the objective.
Use 64-bit or 128-bit integer cross-multiplication instead of floating-point division inside std::sort comparators to preserve strict weak ordering.
