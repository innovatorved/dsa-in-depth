DP on Trees: Maximum Independent Set, Subtree Knapsack (O(N^2) Amortized Proof) & All-Roots Rerooting

6 min read Module 6.2: Dynamic Programming Foundations & Classical Archetypes Updated Oct 24, 2026
📄 Cheat Sheet
Prince Gupta Rerooting DP on Trees Tutorial — All-Roots Subtree Aggregation Watch on YouTube ↗

Explains bottom-up subtree aggregation, the O(N^2) tree knapsack complexity proof, and the 2-pass prefix/suffix rerooting technique.

Intuition first

A rooted tree is already a DAG where information naturally flows from leaves up to the root in DFS post-order. Two miracles make Tree DP remarkably fast: first, merging knapsack arrays across child subtrees looks like O(N^3) but is actually O(N^2) because every pair of nodes meets only once at their LCA; second, the Rerooting (Up-Down) technique computes the answer for all N possible roots in O(N) total time.

1. Bottom-Up Subtree DP & The O(N2)O(N^2)O(N2) Tree Knapsack Theorem

By rooting an undirected tree arbitrarily at vertex 000, every vertex uuu defines a subproblem on its subtree TuT_uTu​, solved in DFS post-order:

  • Maximum Weight Independent Set on a Tree (House Robber III): Maintain two states per node: dp[u][0]dp[u][0]dp[u][0] (max weight in TuT_uTu​ if uuu is excluded) and dp[u][1]dp[u][1]dp[u][1] (if uuu is included): dp[u][0]=∑v∈children(u)max⁡(dp[v][0],dp[v][1]),dp[u][1]=wu+∑v∈children(u)dp[v][0]dp[u][0] = \sum_{v \in \text{children}(u)} \max(dp[v][0], dp[v][1]), \qquad dp[u][1] = w_u + \sum_{v \in \text{children}(u)} dp[v][0]dp[u][0]=v∈children(u)∑​max(dp[v][0],dp[v][1]),dp[u][1]=wu​+v∈children(u)∑​dp[v][0]
  • Subtree Dependency Knapsack (Selecting KKK Connected Nodes): Suppose at node uuu we merge a knapsack table of size sz[u]\text{sz}[u]sz[u] with child vvv's table of size sz[v]\text{sz}[v]sz[v]. A naive bound where both loops run up to NNN gives O(N3)O(N^3)O(N3). However, if we bound the loop ranges strictly by the current accumulated subtree size sz[u]\text{sz}[u]sz[u] and child size sz[v]\text{sz}[v]sz[v] before updating sz[u]+=sz[v]\text{sz}[u] \mathrel{+}= \text{sz}[v]sz[u]+=sz[v], what is the true complexity?

Core Invariant — The O(N2)O(N^2)O(N2) (and O(N⋅K)O(N \cdot K)O(N⋅K)) Tree Knapsack Complexity Proof

When merging child vvv into parent uuu's partial subtree via nested loops of lengths szcur[u]\text{sz}_{\text{cur}}[u]szcur​[u] and sz[v]\text{sz}[v]sz[v], the number of inner-loop operations performed at that merge step is szcur[u]×sz[v]\text{sz}_{\text{cur}}[u] \times \text{sz}[v]szcur​[u]×sz[v].
Combinatorial interpretation: szcur[u]×sz[v]\text{sz}_{\text{cur}}[u] \times \text{sz}[v]szcur​[u]×sz[v] equals the exact number of pairs of vertices (x,y)(x, y)(x,y) such that xxx belongs to a previously merged branch of uuu, y∈Tvy \in T_vy∈Tv​, and LCA(x,y)=u\text{LCA}(x, y) = uLCA(x,y)=u! Since every pair of vertices (x,y)(x, y)(x,y) in the tree has a unique Lowest Common Ancestor uuu, summing over the entire tree counts each pair (x,y)(x, y)(x,y) at most once:

∑u∑v∈children(u)szcur[u]⋅sz[v]=(N2)=O(N2)\sum_{u} \sum_{v \in \text{children}(u)} \text{sz}_{\text{cur}}[u] \cdot \text{sz}[v] = \binom{N}{2} = O(N^2)u∑​v∈children(u)∑​szcur​[u]⋅sz[v]=(2N​)=O(N2)

2. The All-Roots Rerooting Technique (Up-Down / In-Out DP)

What if we need the tree DP answer when every vertex u∈{0..N−1}u \in \{0..N-1\}u∈{0..N−1} is chosen as the root (e.g., Sum of Distances in Tree, Minimum Height Trees, or Maximum Path from Every Node)? Running NNN separate DFS traversals takes O(N2)O(N^2)O(N2). Instead, Two-Pass Rerooting solves all NNN roots in O(N)O(N)O(N):

  1. Pass 1 (Post-Order Downward DP down[u]): Root at 000 and compute down[u] for every subtree TuT_uTu​.
  2. Pass 2 (Pre-Order Upward DP up[v]): As we step from parent uuu to child vvv, the "complement subtree" T∖TvT \setminus T_vT∖Tv​ seen by vvv consists of uuu's upward contribution up[u] merged with all siblings w∈children(u)∖{v}w \in \text{children}(u) \setminus \{v\}w∈children(u)∖{v}. To avoid division (which fails on max⁡/min⁡\max/\minmax/min or  mod p\bmod pmodp zeroes), precompute prefix and suffix merges of uuu's children!

Hardware Reality — Why Bound-Capped Tree Knapsack Must Update sz[u] += sz[v] AFTER the Merge Loop

A single-line bug turns an O(N2)O(N^2)O(N2) Tree Knapsack into an O(N3)O(N^3)O(N3) TLE: if you increment sz[u] += sz[v] before the merge loop (or loop up to the precomputed total subtree size instead of the running accumulated size), the first child merge at the root iterates N×sz[v1]N \times \text{sz}[v_1]N×sz[v1​] instead of 1×sz[v1]1 \times \text{sz}[v_1]1×sz[v1​], destroying the LCA pair-counting invariant!

#include <algorithm>
#include <cstdint>
#include <vector>

// 1. All-Roots Rerooting DP: Compute sum of distances from EVERY node u to all other nodes in O(N)
std::vector<long long> sum_of_distances_in_tree(int n, const std::vector<std::pair<int, int>>& edges) {
    std::vector<std::vector<int>> adj(n);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    std::vector<int> sz(n, 1);
    std::vector<long long> ans(n, 0);

    // Pass 1 (Bottom-Up): Compute subtree sizes and ans[0] = sum of depths from root 0
    auto dfs_down = [&](auto& self, int u, int p) -> void {
        for (int v : adj[u]) {
            if (v == p) continue;
            self(self, v, u);
            sz[u] += sz[v];
            ans[0] += ans[v] + sz[v]; // momentarily use ans[u] to accumulate subtree dist sum
        }
        if (u != 0) {
            long long sub_sum = 0;
            for (int v : adj[u]) if (v != p) sub_sum += ans[v] + sz[v];
            ans[u] = sub_sum;
        }
    };
    dfs_down(dfs_down, 0, -1);

    // Pass 2 (Top-Down Rerooting): Shift root from u to child v in O(1):
    // Nodes in T_v (sz[v] of them) get 1 step closer; nodes outside T_v (n - sz[v]) get 1 step farther!
    auto dfs_up = [&](auto& self, int u, int p) -> void {
        for (int v : adj[u]) {
            if (v == p) continue;
            ans[v] = ans[u] - sz[v] + (n - sz[v]);
            self(self, v, u);
        }
    };
    dfs_up(dfs_up, 0, -1);
    return ans;
}

// 2. O(N * K) Tree Dependency Knapsack (Must pick parent u to pick any node in T_u)
std::vector<long long> tree_knapsack_Exact_ONK(
    int n, int k, const std::vector<int>& parent, const std::vector<long long>& profit) {
    std::vector<std::vector<int>> children(n);
    int root = 0;
    for (int i = 0; i < n; ++i) {
        if (parent[i] == -1) root = i;
        else children[parent[i]].push_back(i);
    }

    constexpr long long NEG_INF = -(1LL << 60);
    std::vector<std::vector<long long>> dp(n);
    std::vector<int> sz(n, 0);

    auto dfs = [&](auto& self, int u) -> void {
        sz[u] = 1;
        dp[u] = { 0LL, profit[u] }; // Size 0 -> 0, Size 1 (just u) -> profit[u]

        for (int v : children[u]) {
            self(self, v);
            int new_cap = std::min(k, sz[u] + sz[v]);
            std::vector<long long> next_dp(new_cap + 1, NEG_INF);
            next_dp[0] = 0;

            // CRITICAL: Bound i by current sz[u] and j by sz[v] BEFORE adding sz[v] to sz[u]!
            for (int i = 1; i <= std::min(k, sz[u]); ++i) {
                for (int j = 0; j <= std::min(k - i, sz[v]); ++j) {
                    next_dp[i + j] = std::max(next_dp[i + j], dp[u][i] + dp[v][j]);
                }
            }
            dp[u] = std::move(next_dp);
            sz[u] += sz[v]; // Update sz[u] AFTER the merge!
        }
    };
    dfs(dfs, root);
    return dp[root];
}

Key Takeaways

Rooting a tree turns it into a DAG where subtree states dp[u] are computed bottom-up in DFS post-order.
Merging subtree knapsack tables bounded by running subtree sizes sz[u] and sz[v] runs in O(N^2) (or O(N * K)) total time because every pair of nodes meets only once at their LCA.
Two-pass Rerooting DP computes all-roots answers in O(N) via a bottom-up post-order pass followed by a top-down pre-order pass.
When transitions use non-invertible operators (max, min, GCD, or multiplication mod M), use prefix and suffix child arrays during the top-down rerooting pass.
