Synthesizes Sedgewick's LLRB 2-3 rotation invariants with subtree size augmentation to support O(log N) rank, select, and range count queries.

Intuition first

Standard C++ (std::set, std::map), Java (TreeSet, TreeMap), and Go/Rust collections share a frustrating limitation: even though their keys are stored in a balanced search tree, they only expose bidirectional iterators—so computing the index of a key (rank(key)), looking up the $k$-th smallest key by index (select(k)), or counting how many elements fall in $[lo, hi]$ (rangeCount(lo, hi)) degrades to an $O(N)$ linear iterator walk!

In this Build Lab, you will combine Sedgewick's Left-Leaning Red-Black (LLRB) Tree with the CLRS Order-Statistic Augmentation (sz = 1 + sz(left) + sz(right)). Because LLRB encapsulates all structural rebalancing into rotateLeft, rotateRight, and flipColors, maintaining exact subtree sizes requires only two lines of size transfer inside the rotation helpers—giving you a complete, self-contained $O(\log N)$ Order-Statistic Set in under 95 lines of production C++!

Architectural Synthesis: LLRB Rebalancing + Subtree Size Invariant

Let us trace how sz (subtree node count) interacts with the three LLRB primitive transformations:

  1. rotateLeft(h) (promotes $x = h.\text{right}$ above $h$): Before rotation, $h$ was the root of the local subtree; after rotation, $x$ is the root of the exact same set of nodes! Therefore, we set x->sz = h->sz and recompute h->sz = 1 + size(h->left) + size(h->right) in $O(1)$ time.
  2. rotateRight(h) (promotes $x = h.\text{left}$ above $h$): Symmetric—set x->sz = h->sz and recompute h->sz = 1 + size(h->left) + size(h->right).
  3. flipColors(h): Only flips boolean color bits without changing any parent-child links, so all sz fields remain untouched!

With sz maintained at every node, we unlock three $O(\log N)$ analytical queries:

  • rank(key): Returns the exact number of elements in the set strictly less than key ($|\{x \in S : x < \text{key}\}|$).
  • select(k) ($0 \le k < N$): Returns the unique key $x \in S$ whose rank(x) == k.
  • rangeCount(lo, hi) ($lo \le hi$): Returns the number of keys in the closed interval $[lo, hi]$ in $O(\log N)$ time via rank(hi) - rank(lo) + (contains(hi) ? 1 : 0)!

Exact Dual Identity Between rank and select

For any Order-Statistic Tree $T$ storing $N$ distinct keys:

$$\forall k \in \{0, 1, \dots, N-1\}: \quad \text{rank}(\text{select}(k)) == k$$

$$\forall x \in T: \quad \text{select}(\text{rank}(x)) == x$$

Furthermore, for any query key $q$ (even if $q \notin T$), $\text{rank}(q)$ satisfies the recursive invariant at node $u$:

$$\text{rank}(u, q) = \begin{cases} 0 & \text{if } u == \text{null} \\ \text{rank}(u.\text{left}, q) & \text{if } q < u.\text{key} \\ \text{size}(u.\text{left}) & \text{if } q == u.\text{key} \\ 1 + \text{size}(u.\text{left}) + \text{rank}(u.\text{right}, q) & \text{if } q > u.\text{key} \end{cases}$$

Hardware Reality: Iterative rank and select Without Recursion

While LLRB insert uses bottom-up recursion along the $O(\log N)$ path so rotations can unwind cleanly, rank(key), select(k), and contains(key) are read-only downward walks! Writing rank, select, and contains as tight while (u != nullptr) loops avoids all stack-frame push/pop overhead and executes in $\le 2 \log_2 N$ branch-predicted pointer hops.

Production Reference Implementation: Complete LLRB Order-Statistic Tree

// C++20: Complete Left-Leaning Red-Black (LLRB) Order-Statistic Tree
#include <cstdint>
#include <cassert>

template <typename Key>
class LLRBOrderStatisticTree {
    struct Node {
        Key key;
        int32_t sz = 1;
        bool red = true;
        Node *left = nullptr, *right = nullptr;
        explicit Node(Key k) : key(k) {}
    };

    Node* root = nullptr;

    static bool isRed(const Node* u) noexcept { return u != nullptr && u->red; }
    static int32_t size(const Node* u) noexcept { return u ? u->sz : 0; }
    static void pull(Node* u) noexcept { u->sz = 1 + size(u->left) + size(u->right); }

    static Node* rotateLeft(Node* h) noexcept {
        Node* x = h->right;
        h->right = x->left;
        x->left = h;
        x->red = h->red;
        h->red = true;
        x->sz = h->sz; // x replaces h as root of this exact subtree
        pull(h);        // Recompute demoted node h
        return x;
    }

    static Node* rotateRight(Node* h) noexcept {
        Node* x = h->left;
        h->left = x->right;
        x->right = h;
        x->red = h->red;
        h->red = true;
        x->sz = h->sz;
        pull(h);
        return x;
    }

    static void flipColors(Node* h) noexcept {
        h->red = !h->red;
        h->left->red = !h->left->red;
        h->right->red = !h->right->red;
    }

    static Node* insertRec(Node* h, const Key& key) {
        if (!h) return new Node(key);
        if (key < h->key)      h->left  = insertRec(h->left, key);
        else if (h->key < key) h->right = insertRec(h->right, key);

        if (isRed(h->right) && !isRed(h->left))      h = rotateLeft(h);
        if (isRed(h->left)  && isRed(h->left->left))  h = rotateRight(h);
        if (isRed(h->left)  && isRed(h->right))       flipColors(h);

        pull(h);
        return h;
    }

public:
    int32_t size() const noexcept { return size(root); }

    void insert(const Key& key) {
        root = insertRec(root, key);
        root->red = false; // Root is always Black
    }

    bool contains(const Key& key) const noexcept {
        const Node* u = root;
        while (u) {
            if (key < u->key)      u = u->left;
            else if (u->key < key) u = u->right;
            else return true;
        }
        return false;
    }

    // Number of keys strictly less than 'key' in O(log N) time
    int32_t rank(const Key& key) const noexcept {
        const Node* u = root;
        int32_t count = 0;
        while (u) {
            if (key < u->key) {
                u = u->left;
            } else if (u->key < key) {
                count += 1 + size(u->left);
                u = u->right;
            } else {
                return count + size(u->left);
            }
        }
        return count;
    }

    // 0-indexed k-th smallest key in O(log N) time
    const Key& select(int32_t k) const noexcept {
        assert(k >= 0 && k < size(root));
        const Node* u = root;
        while (u) {
            int32_t leftSz = size(u->left);
            if (k == leftSz) return u->key;
            if (k < leftSz) {
                u = u->left;
            } else {
                k -= (leftSz + 1);
                u = u->right;
            }
        }
        return root->key;
    }

    // Count of keys in closed interval [lo, hi] in O(log N) time
    int32_t rangeCount(const Key& lo, const Key& hi) const noexcept {
        if (hi < lo) return 0;
        return rank(hi) - rank(lo) + (contains(hi) ? 1 : 0);
    }
};

Failure Modes & Adversarial Pitfalls

  • Unconditionally Incrementing h->sz++ on Descent When Inserting a Duplicate Key: If insert(key) is called with a key that already exists in the set, no new leaf is created! Incrementing sz on the way down corrupts every ancestor's size whenever a duplicate is inserted. Always recompute h->sz = 1 + size(h->left) + size(h->right) bottom-up on the way back up (pull(h)).
  • Off-By-One in rangeCount(lo, hi): Because rank(key) counts elements strictly less than key, rank(hi) - rank(lo) counts keys in the half-open interval $[lo, hi)$. To count the closed interval $[lo, hi]$, you must add $+1$ if contains(hi) is true (or compute rank(hi_successor) - rank(lo)).
Check yourself Question 1 of 4
Concept Check Order of Size Recomputations During a Left Rotation recall

In your augmented LLRB Order-Statistic Tree, `rotateLeft(h)` promotes `x = h.right` to be the new root of the subtree, with `h` becoming `x.left`.

After `h.right = x.left; x.left = h;`, `h` is now the left child of `x`. Therefore `h`'s subtree has shrunk (it lost `x` and `x.right`), while `x`'s subtree now encompasses the entire set of nodes that `h` previously rooted. Thus we must recompute `h.size = 1 + size(h.left) + size(h.right)` first, and then set `x.size = 1 + size(x.left) + size(x.right)` (which equals the old `h.size`).
Concept Check Duplicate Key Insertion Bug if Size Is Incremented Top-Down apply

Suppose an engineer tries to optimize `insert(h, key)` in an Order-Statistic Tree by incrementing `h.size++` at the top of the recursive function before descending into `h.left` or `h.right`, instead of recomputing `h.size = 1 + size(h.left) + size(h.right)` on the way back up.

When inserting into a set (unique keys), we do not know until reaching the bottom of the search path whether `key` is already present. Moreover, rotations on the way back up rearrange parent-child relationships. Recomputing `h.size = 1 + size(h.left) + size(h.right)` bottom-up inside `fixUp(h)` (and inside `rotateLeft`/`rotateRight`) guarantees `size` is always exact regardless of duplicate keys or rotations.
Concept Check `rangeCount(lo, hi)` Boundary Handling for Absent Endpoints apply

In an Order-Statistic Tree where `rank(k)` returns the exact count of keys in the tree strictly less than `k` ($|\{x \in T : x < k\}|$), we want `rangeCount(lo, hi)` to return the count of keys in the closed interval $[lo, hi]$ ($|\{x \in T : lo \le x \le hi\}|$). Note that `lo` and `hi` themselves might or might not be present in the tree.

By definition, `rank(hi) - rank(lo)` counts keys satisfying `lo <= x < hi` (the half-open interval `[lo, hi)`), whether or not `lo` is in the tree! To convert `[lo, hi)` into the closed interval `[lo, hi]`, we simply need to include `hi` itself if and only if `hi` is actually present in the tree: `rank(hi) - rank(lo) + (contains(hi) ? 1 : 0)`. Note that `rank(hi + 1)` only works for integers and fails for floating-point or string keys.

Key Takeaways

Combining Sedgewick's LLRB 2-3 tree with subtree size augmentation sz(u) = 1 + sz(L) + sz(R) yields a self-balancing Order-Statistic Tree in under 95 lines of code.
Inside rotateLeft(h) and rotateRight(h), the promoted node x inherits x.sz = h.sz while the demoted node h recomputes h.sz = 1 + sz(h.left) + sz(h.right); flipColors(h) does not alter sizes.
Always recompute sz bottom-up via pull(h) after recursive insertion so duplicate key insertions never inflate subtree counts.
Using rank(key) (strictly less than key), closed-interval range counts [lo, hi] equal rank(hi) - rank(lo) + (contains(hi) ? 1 : 0) in O(log N) time.
