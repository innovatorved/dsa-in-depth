Intuition first

If an element appears strictly more than ⌊N/2⌋\lfloor N / 2 \rfloor⌊N/2⌋ times in a stream, it survives pairwise annihilation against every non-matching element. Generalizing pairwise cancellation to (kext−way)(k ext{-way})(kext−way) tuple cancellation yields the Misra-Gries algorithm: maintaining k−1k - 1k−1 counters in O(k)O(k)O(k) space identifies every 'heavy hitter' occurring strictly more than N/kN / kN/k times.

Pairwise Annihilation & The kkk-Tuple Cancellation Invariant

Suppose a stream of length NNN contains a strict majority element mmm with frequency f(m)>N/2f(m) > N / 2f(m)>N/2. Imagine pairing each occurrence of mmm with one distinct element x≠mx \neq mx=m and deleting both from the stream. Because all non-mmm elements combined total N−f(m)<N/2N - f(m) < N / 2N−f(m)<N/2, they cannot annihilate all occurrences of mmm! Robert S. Boyer and J Strother Moore (1981) turned this observation into an O(N)O(N)O(N) time, O(1)O(1)O(1) space streaming algorithm with two variables (candidate, count):

  • If count == 0, adopt the current element xxx as candidate = x and set count = 1.
  • Else if x == candidate, increment ++count.
  • Else (x != candidate), annihilate the pair by decrementing --count.

In 1982, Jayadev Misra and David Gries generalized this to find all elements occurring strictly more than ⌊N/k⌋\lfloor N / k \rfloor⌊N/k⌋ times using at most k−1k - 1k−1 candidate counters: when a new element xxx arrives and is not among the k−1k - 1k−1 tracked keys (and all k−1k - 1k−1 slots are non-zero), decrement all k−1k - 1k−1 counters by 1—forming a cancelled kkk-tuple of kkk mutually distinct elements!

Hardware Reality: Register-Pinned Counters & Distributed Tree-AllReduce Merging

For k=2k = 2k=2 (Boyer-Moore) and k=3k = 3k=3 (2 candidates), the entire state fits inside 2 to 4 general-purpose CPU registers (rax, rbx, rcx, rdx) with zero memory allocations and zero L1 cache traffic during the scan. Even more importantly for distributed telemetry engines (such as Google Monarch or ClickHouse), Boyer-Moore and Misra-Gries summaries form a commutative monoid approximation: two worker nodes can scan 1 billion log lines each in parallel and merge their (cand,count)(cand, count)(cand,count) pairs in O(k)O(k)O(k) time by adding matching candidate counts and subtracting the kkk-th largest count from all survivors.

Production Implementation: Boyer-Moore & k=3k=3k=3 Misra-Gries with 2-Pass Verification

#include <cstdint>
#include <optional>
#include <vector>

// Boyer-Moore Majority Vote with mandatory verification pass
std::optional<int> find_majority_element(const std::vector<int>& nums) noexcept {
  int candidate = 0;
  std::size_t count = 0;

  for (int x : nums) {
    if (count == 0) {
      candidate = x;
      count = 1;
    } else if (x == candidate) {
      ++count;
    } else {
      --count;
    }
  }

  // Pass 2: Verify that candidate actually occurs > N / 2 times
  std::size_t exact = 0;
  for (int x : nums) {
    if (x == candidate) ++exact;
  }
  if (exact > nums.size() / 2) return candidate;
  return std::nullopt;
}

// Misra-Gries (k = 3): Find all elements appearing strictly more than floor(N / 3) times
std::vector<int> majority_element_n_over_3(const std::vector<int>& nums) {
  int cand1 = 0, cand2 = 1; // Initialize to distinct dummy values
  std::size_t count1 = 0, count2 = 0;

  for (int x : nums) {
    // CRITICAL: Check equality with cand1 and cand2 FIRST before checking count == 0!
    if (count1 > 0 && x == cand1) {
      ++count1;
    } else if (count2 > 0 && x == cand2) {
      ++count2;
    } else if (count1 == 0) {
      cand1 = x;
      count1 = 1;
    } else if (count2 == 0) {
      cand2 = x;
      count2 = 1;
    } else {
      // 3 distinct elements {cand1, cand2, x} annihilate each other
      --count1;
      --count2;
    }
  }

  // Pass 2: Verify exact counts of surviving candidates
  std::size_t exact1 = 0, exact2 = 0;
  for (int x : nums) {
    if (count1 > 0 && x == cand1) ++exact1;
    else if (count2 > 0 && x == cand2) ++exact2;
  }

  std::vector<int> result;
  const std::size_t threshold = nums.size() / 3;
  if (exact1 > threshold) result.push_back(cand1);
  if (exact2 > threshold) result.push_back(cand2);
  return result;
}
Production Pitfall: Omitting Pass 2 Verification & Duplicate Candidate Adoption in k=3k=3k=3

Two subtle bugs break majority-vote implementations in interviews and production:

  1. Skipping Pass 2 when majority is not guaranteed: On the input [1, 1, 2, 2, 3], Boyer-Moore returns candidate = 3 with count = 1, even though 3 appears only once (20%20\%20% of the stream)! Pass 1 only guarantees: if a majority element exists, it is the survivor. Unless the problem statement mathematically guarantees a majority exists, Pass 2 is mandatory.
  2. Checking count2 == 0 before x == cand1 in k=3k = 3k=3: If you check if (count1 == 0) ... else if (count2 == 0) before checking if (x == cand1), then on the input [5, 5, ...], the second 5 will be assigned to cand2, placing the same key into both slots! Always test equality against active candidates before claiming an empty slot.

Concept Check Why Boyer-Moore Majority Vote Requires a Second Pass When Majority Is Unproven recall

You run Pass 1 of the Boyer-Moore Majority Vote algorithm on the array `nums = [1, 1, 2, 2, 3]`. At termination, `candidate == 3` and `count == 1`.

In `[1, 1, 2, 2, 3]`, the two `1`s and two `2`s mutually annihilate each other (`count` drops back to `0` at index 3), leaving `3` unchallenged at index 4. Thus `count > 0` after Pass 1 never proves majority without Pass 2.

A developer writes Pass 1 of the k=3k = 3k=3 Misra-Gries algorithm (to find all elements appearing >⌊N/3⌋> \lfloor N / 3 \rfloor>⌊N/3⌋ times) using the following `if/else` order: ```cpp if (count1 == 0) { cand1 = x; count1 = 1; } else if (count2 == 0) { cand2 = x; count2 = 1; } else if (x == cand1) { ++count1; } else if (x == cand2) { ++count2; } else { --count1; --count2; } ```

At `nums[0] = 7`, `cand1 = 7, count1 = 1, count2 = 0`. At `nums[1] = 7`, if `else if (count2 == 0)` is evaluated before `else if (x == cand1)`, then `cand2` also becomes `7`! You must ALWAYS check `x == cand1` and `x == cand2` before claiming an empty `count == 0` slot.

Key Takeaways

Boyer-Moore Majority Vote pairs each majority occurrence against a distinct element, finding the > N/2 candidate in O(N) time and O(1) space.
Misra-Gries generalizes pairwise cancellation to k-tuple cancellation using k - 1 counters, guaranteeing f(x) - N/k <= f_hat(x) <= f(x).
Always execute a second linear verification pass when the input is not guaranteed to contain a heavy hitter exceeding N/k.
In multi-candidate Misra-Gries (such as k = 3), always check if the incoming element matches an existing active candidate before assigning it to a zero-count slot.
