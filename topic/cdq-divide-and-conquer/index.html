Explains how divide-and-conquer eliminates one coordinate dimension per recursion level, the foundational principle behind CDQ divide-and-conquer.

Intuition first

In 2D dominance (counting inversions), Merge Sort sorts by X first and merges by Y while counting how many left-half elements beat each right-half element. What about 3D dominance (x_i <= x_j, y_i <= y_j, z_i <= z_j)? Instead of building an expensive 2D Segment Tree of O(N log^2 N) space, CDQ Divide-and-Conquer sorts by X, recurses on [lo, mid) and [mid, hi), and merges by Y while maintaining a lightweight 1D Fenwick Tree on Z—eliminating one dimension via D&C in O(N) space!

What Is CDQ Divide-and-Conquer?

Popularized by IOI gold medalist Chen Danqi (CDQ) in 2008 (and rooted in Bentley's 1980 multidimensional divide-and-conquer), CDQ Divide-and-Conquer is an offline technique that eliminates one dimension of a multidimensional query problem (or eliminates the "time" dimension of a dynamic update-and-query problem) by recursing on array halves [lo,mid)[lo, mid)[lo,mid) and [mid,hi)[mid, hi)[mid,hi) and computing only the cross-half contribution where left-half elements update right-half elements.

The Canonical Problem: 3D Partial Order (3D Dominance Counting)

Given NNN points Pi=(xi,yi,zi)P_i = (x_i, y_i, z_i)Pi​=(xi​,yi​,zi​) in R3\mathbb{R}^3R3 (with coordinates compressed to [1,N][1, N][1,N]), for each point jjj we want to count how many points i≠ji \neq ji=j satisfy:

Let's see how each dimension is systematically neutralized:

  1. Dimension 1 (XXX-Coordinate) — Initial Presort: Sort all points lexicographically by (x,y,z)(x, y, z)(x,y,z) and collapse identical points (x,y,z)(x, y, z)(x,y,z) into weighted unique points. Now, throughout the entire recursion on [lo,hi)[lo, hi)[lo,hi), every point in the left half i∈[lo,mid)i \in [lo, mid)i∈[lo,mid) is guaranteed to satisfy xi≤xjx_i \le x_jxi​≤xj​ for every point in the right half j∈[mid,hi)j \in [mid, hi)j∈[mid,hi)!
  2. Dimension 2 (YYY-Coordinate) — Two-Pointer Merge: Assume recursively that [lo,mid)[lo, mid)[lo,mid) and [mid,hi)[mid, hi)[mid,hi) are sorted by YYY. Sweep pointer pLp_LpL​ across [lo,mid)[lo, mid)[lo,mid) and pointer pRp_RpR​ across [mid,hi)[mid, hi)[mid,hi) in ascending YYY-order. Whenever P[pL].y≤P[pR].yP[p_L].y \le P[p_R].yP[pL​].y≤P[pR​].y, advance pLp_LpL​; otherwise advance pRp_RpR​. At the moment we process pRp_RpR​, every left-half point already passed by pLp_LpL​ satisfies both xi≤xjx_i \le x_jxi​≤xj​ and yi≤yjy_i \le y_jyi​≤yj​!
  3. Dimension 3 (ZZZ-Coordinate) — 1D Fenwick Tree (BIT): When advancing pLp_LpL​, insert its ZZZ-coordinate into a 1D Fenwick Tree: bit.add(P[p_L].z, P[p_L].weight). The CDQ Cross-Boundary Invariant & Rollback Requirement

At any node [lo,hi)[lo, hi)[lo,hi) of the CDQ recursion tree, left-half elements i∈[lo,mid)i \in [lo, mid)i∈[lo,mid) only update the Fenwick Tree, and right-half elements j∈[mid,hi)j \in [mid, hi)j∈[mid,hi) only query the Fenwick Tree. Why is it illegal to call std::fill(bit.begin(), bit.end(), 0) to reset the Fenwick Tree at the end of [lo,hi)[lo, hi)[lo,hi)? Because std::fill takes O(N)O(N)O(N) time at every recursive call, blowing total time up to O(N2)O(N^2)O(N2)! Instead, you must undo only the insertions performed during that merge by calling bit.add(P[i].z, -P[i].weight) for each i∈[lo,pL)i \in [lo, p_L)i∈[lo,pL​), keeping work at node [lo,hi)[lo, hi)[lo,hi) strictly O((hi−lo)log⁡N)O((hi - lo) \log N)O((hi−lo)logN).

Hardware Reality: Why Deduplicating Equal (x,y,z)(x, y, z)(x,y,z) Triples Is Mandatory

Suppose two distinct input items AAA and BBB have the exact same coordinates (x,y,z)(x, y, z)(x,y,z). After sorting, one of them (AAA) appears before the other (BBB). In CDQ divide-and-conquer, an element on the left can contribute to an element on the right, buuuuut the element on the right (BBB) can never contribute back to the element on the left (AAA)! Consequently, AAA would undercount its equal partner BBB. By collapsing identical (x,y,z)(x, y, z)(x,y,z) points into a single representative with multiplicity cnt before starting CDQ (and adding cnt - 1 to its own dominance count), strict ordering between distinct triples is restored.

Production C++20 Implementation: 3D Dominance Counting via CDQ Divide-and-Conquer

#include <algorithm>
#include <cstddef>
#include <cstdint>
#include <vector>

struct Point3D {
    int x, y, z;
    int weight;   // Multiplicity of identical (x, y, z) points
    int dom_cnt;  // Number of points dominated by this unique point
    int orig_id;
};

class FenwickTree {
public:
    explicit FenwickTree(std::size_t max_z) : tree_(max_z + 1, 0) {}

    void add(int idx, int delta) noexcept {
        for (std::size_t i = static_cast<std::size_t>(idx); i < tree_.size(); i += i & (~i + 1)) {
            tree_[i] += delta;
        }
    }

    int query(int idx) const noexcept {
        int sum = 0;
        for (std::size_t i = static_cast<std::size_t>(idx); i > 0; i &= i - 1) {
            sum += tree_[i];
        }
        return sum;
    }

private:
    std::vector<int> tree_;
};

// Solves 3D Partial Order (1 <= z_i <= max_z) in O(N log^2 N) time and O(N) space.
// Returns for each unique point the total weight of other points it dominates.
void solve_3d_dominance_cdq(std::vector<Point3D>& pts, int max_z) {
    if (pts.empty()) return;

    // 1. Sort lexicographically by (x, y, z)
    std::sort(pts.begin(), pts.end(), [](const Point3D& a, const Point3D& b) {
        if (a.x != b.x) return a.x < b.x;
        if (a.y != b.y) return a.y < b.y;
        return a.z < b.z;
    });

    // 2. Deduplicate identical (x, y, z) triples and accumulate multiplicity weight
    std::vector<Point3D> uniq;
    uniq.reserve(pts.size());
    for (const auto& p : pts) {
        if (!uniq.empty() && uniq.back().x == p.x &&
            uniq.back().y == p.y && uniq.back().z == p.z) {
            uniq.back().weight += p.weight;
        } else {
            uniq.push_back(p);
        }
    }

    const std::size_t m = uniq.size();
    std::vector<Point3D> scratch(m);
    FenwickTree bit(static_cast<std::size_t>(max_z));

    auto cdq = [&](auto& self, std::size_t lo, std::size_t hi) -> void {
        if (hi - lo <= 1) return;
        const std::size_t mid = lo + (hi - lo) / 2;

        self(self, lo, mid);
        self(self, mid, hi);

        // Both [lo, mid) and [mid, hi) are now sorted by Y.
        // Merge them by Y while applying left-half BIT updates to right-half queries.
        std::size_t pL = lo, pR = mid, out = lo;
        while (pL < mid && pR < hi) {
            if (uniq[pL].y <= uniq[pR].y) {
                bit.add(uniq[pL].z, uniq[pL].weight);
                scratch[out++] = uniq[pL++];
            } else {
                uniq[pR].dom_cnt += bit.query(uniq[pR].z);
                scratch[out++] = uniq[pR++];
            }
        }
        while (pR < hi) {
            uniq[pR].dom_cnt += bit.query(uniq[pR].z);
            scratch[out++] = uniq[pR++];
        }
        // Rollback Fenwick tree for all left-half elements that were inserted!
        for (std::size_t i = lo; i < pL; ++i) {
            bit.add(uniq[i].z, -uniq[i].weight);
        }
        while (pL < mid) {
            scratch[out++] = uniq[pL++];
        }

        std::copy(scratch.begin() + lo, scratch.begin() + hi, uniq.begin() + lo);
    };

    cdq(cdq, 0, m);

    // Account for self-dominance among identical (x, y, z) duplicates
    for (auto& u : uniq) {
        u.dom_cnt += (u.weight - 1);
    }
    pts = std::move(uniq);
}
Pre-Order vs. Post-Order CDQ for Dynamic Programming Transitions

In pure counting problems (like 3D dominance or offline 2D range queries), left and right subproblems are independent, so standard post-order Merge-Sort CDQ (cdq(lo, mid); cdq(mid, hi); merge();) works fastest because the merge step sorts by YYY bottom-up. However, if you use CDQ to optimize 1D/2D Dynamic Programming where dp[j]=max⁡i<j(dots)dp[j] = \max_{i < j}(dots)dp[j]=maxi<j​(dots) requires dp[i]dp[i]dp[i] for the entire left half [lo,mid)[lo, mid)[lo,mid) to be fully finalized before propagating to [mid,hi)[mid, hi)[mid,hi), you MUST execute CDQ in in-order: cdq(lo, mid); cross_update(lo, mid, mid, hi); cdq(mid, hi);!

Concept Check How CDQ Divide-and-Conquer Eliminates Three Dimensions recall

In the offline 3D Partial Order problem, we want to count for each point j how many points i != j satisfy x_i <= x_j, y_i <= y_j, and z_i <= z_j in O(N log^2 N) time and O(N) space.

Each mechanism strips away one coordinate constraint: (1) presorting by X guarantees x_i <= x_j for any i in the left half and j in the right half; (2) merging by Y guarantees y_i <= y_j for all left-half elements processed before j; and (3) the 1D Fenwick Tree counts how many of those also have z_i <= z_j.
Concept Check The Fenwick Tree Reset Trap in CDQ Divide-and-Conquer apply

Inside the CDQ recursive function `cdq(size_t lo, size_t hi)`, after merging `[lo, mid)` and `[mid, hi)` using the shared 1D Fenwick Tree `bit` of size N, an engineer clears the Fenwick tree via `std::fill(bit.begin(), bit.end(), 0);`.

Note that allocating a vector of size N inside every recursive call (option D) ALSO takes O(N) per call -> Theta(N^2) total time! In CDQ, the work inside `cdq(lo, hi)` MUST be bounded by a function of the subarray length `(hi - lo)`, never the global size `N`.
Concept Check Why Identical (x, y, z) Points Must Be Deduplicated Before CDQ apply

Suppose two input points P_a and P_b have the exact same coordinates (5, 5, 5). After sorting, P_a is at index 3 (in the left half) and P_b is at index 4 (in the right half).

CDQ assumes a directed DAG of contributions from smaller indices i < j to larger indices j. When two points are strictly equal in all 3 coordinates, they mutually dominate each other (i dominates j AND j dominates i). Deduplicating identical triples upfront into one node with `weight = k` (and adding `k - 1` at the end) restores strict asymmetry.
Concept Check In-Order vs. Post-Order Traversal in CDQ for Dynamic Programming staff

You are using CDQ Divide-and-Conquer to compute a 1D Dynamic Programming array where `dp[j] = max_{i < j, x_i <= x_j, y_i <= y_j} (dp[i] + w_j)`. You write the recursion in standard Merge-Sort post-order: cdq(lo, mid); cdq(mid, hi); cross_update(lo, mid, mid, hi);

For non-cumulative counting (like 3D dominance), a point's contribution weight is static and known upfront, so post-order Merge Sort works. For DP, `dp[mid]` is NOT finalized until `[0, mid)` has transferred into `mid`! Running `cdq(lo, mid)`, then transferring `[lo, mid) -> [mid, hi)`, and ONLY THEN recursing `cdq(mid, hi)` guarantees that `dp[k]` is 100% finalized before `k` is ever used as a left-half source.

Key Takeaways

CDQ Divide-and-Conquer eliminates one coordinate (or time) dimension by sorting on X initially and computing only left-half-to-right-half interactions across the recursion tree.
For 3D Dominance, X is handled by the divide split, Y is handled by a two-pointer merge, and Z is handled by a 1D Fenwick Tree.
Total complexity is O(N log^2 N) time and O(N) space—avoiding the O(N log^2 N) memory explosion and pointer-chasing overhead of 2D Segment Trees.
Always deduplicate identical (x, y, z) points upfront and rollback the Fenwick Tree by undoing only the [lo, p_L) insertions rather than zeroing the entire BIT array.
