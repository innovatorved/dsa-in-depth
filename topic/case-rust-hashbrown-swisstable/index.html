Production Case Study: Google Abseil SwissTable & Rust hashbrown SIMD Probing

6 min read Module 2.1: Hash Tables, Modern Probing & Probabilistic Sketches Updated Oct 19, 2026
📄 Cheat Sheet
CppCon CppCon 2017: Matt Kulukundis — Designing a Fast, Efficient, Cache-friendly Hash Table, Step by Step Watch on YouTube ↗

Matt Kulukundis walks through the exact engineering of Google's absl::flat_hash_map (SwissTable), showing how 1-byte H2 metadata control arrays and 16-way SSE2 bitmask instructions replace legacy std::unordered_map.

Intuition first

For a decade, C++'s std::unordered_map was notorious for slow performance because the C++11 standard mandated pointer stability across insertions, forcing implementations into pointer-chased Separate Chaining with malloc per node. Even open-addressed Robin Hood tables (which served as Rust's std::collections::HashMap from 2014 to 2018) had to store an 8-byte hash or PSL alongside every (Key, Value) slot, wasting alignment padding and polluting L1 cache lines during probing.

In 2017, Google engineers (Matt Kulukundis, Alkis Evlogimenos et al.) introduced SwissTable (absl::flat_hash_map), later ported to Rust as hashbrown (the default std::collections::HashMap since Rust 1.36). SwissTable decouples metadata from slots: it stores a contiguous array of 1-byte control bytes (16 bytes = 1 SSE2/NEON vector register) containing a 7-bit hash fingerprint H2, enabling a single SIMD instruction (_mm_cmpeq_epi8) to probe 16 buckets in parallel in 1 CPU cycle up to an 87.5%87.5\%87.5% (7/87/87/8) load factor!

Inside SwissTable / hashbrown: H1/H2 Split & 1-Byte Control Metadata

Given a 64-bit hash h=hash(k)h = \text{hash}(k)h=hash(k), SwissTable splits hhh into two components:

  • H1(h) = h >> 7 (57 bits): Selects the starting 16-slot Probe Group index pos = H1(h) & mask.
  • H2(h) = h & 0x7F (7 bits): A 7-bit fingerprint stored in the corresponding 1-byte Control Byte (ctrl[i]). Because the top bit (bit 7, the sign bit 0x80) of every occupied H2 byte is strictly 0 (0b0xxxxxxx), the top bit 1 (0b1xxxxxxx) is reserved for special empty/deleted sentinels!

Look at the cleverness of the three sentinel byte encodings in hashbrown / Abseil:

  • OCCUPIED: 0b0xxxxxxx (0x00 to 0x7F) — Bit 7 is 0, bits [6..0] hold the 7-bit H2 hash tag.
  • EMPTY: 0b11111111 (0xFF, signed -1, or 0x80 -128 in Abseil) — Bit 7 is 1.
  • DELETED (Tombstone): 0b10000000 (0x80 in hashbrown / 0xFE -2 in Abseil) — Bit 7 is 1.

Because both EMPTY and DELETED have their sign bit (bit 7) set to 1, a single x86 SSE2 instruction _mm_movemask_epi8(ctrl_group) extracts the MSB of all 16 control bytes simultaneously into a 16-bit integer mask of all non-occupied slots!

Formal Specification: The 16-Way SIMD Lookup State Machine

To find key with (h1, h2): start at group_idx = h1 & mask and step = 0. In each iteration:

  1. Load 16 control bytes starting at ctrl + group_idx into a 128-bit SIMD register g = _mm_loadu_si128(...).
  2. Match H2: match_mask = _mm_movemask_epi8(_mm_cmpeq_epi8(g, _mm_set1_epi8(h2))). Iterate over set bits via tz = countr_zero(match_mask) and match_mask &= match_mask - 1. Only for those rare lanes where the 7-bit H2 matches (false positive rate 1/27=0.78%1/2^7 = 0.78\%1/27=0.78%) do we touch the slots[] data array to compare slots[idx].key == key!
  3. Check EMPTY: empty_mask = _mm_movemask_epi8(_mm_cmpeq_epi8(g, _mm_set1_epi8(EMPTY))). If empty_mask != 0, at least one slot in this 16-slot group has never been occupied, so the probe chain terminates immediately (return NOT_FOUND).
  4. Triangular Group Advance: If all 16 slots are OCCUPIED or DELETED, advance to the next group via triangular probing: step += 16; group_idx = (group_idx + step) & mask.

Hardware Reality: Portable 64-Bit SWAR Group Probing & Mirrored Tail Bytes

What if an unaligned probe group starts at index m−5m - 5m−5 near the end of the capacity-mmm array? Instead of branching to wrap around the end of the ctrl array, SwissTable allocates m+16m + 16m+16 control bytes and mirrors the first 16 control bytes ctrl[0..15] at ctrl[m..m+15]! This allows _mm_loadu_si128(&ctrl[pos]) to execute an unbranched 16-byte load from any index pos in [0,m−1][0, m-1][0,m−1]. On targets without SSE2/NEON, SwissTable falls back to 8-byte SWAR (SIMD Within A Register) bit manipulation in a standard uint64_t.

Production C++20 Implementation: Portable 8-Way SWAR / SSE2 SwissTable Group Matcher

C++2051 lines
// C++20: SwissTable / hashbrown Control Group Matcher (8-Way SWAR + x86 SSE2)
#include <cstdint>
#include <cstring>
#include <bit>
#if defined(__SSE2__)
#include <emmintrin.h>
#endif

// Portable 8-Byte SWAR Group (Used by hashbrown on 64-bit targets without SIMD)
struct SwarGroup8 {
    uint64_t ctrl; // 8 control bytes: 0x00..0x7F = H2, 0xFF = EMPTY, 0x80 = DELETED

    explicit SwarGroup8(const uint8_t* ptr) noexcept {
        std::memcpy(&ctrl, ptr, sizeof(uint64_t));
    }

    // Returns bitmask with bit (i*8 + 7) set for each byte matching h2 (0..127)
    uint64_t matchByte(uint8_t h2) const noexcept {
        constexpr uint64_t LO_BITS = 0x0101010101010101ULL;
        constexpr uint64_t HI_BITS = 0x8080808080808080ULL;
        uint64_t x = ctrl ^ (LO_BITS * h2);
        return (x - LO_BITS) & ~x & HI_BITS;
    }

    // Returns bitmask with bit (i*8 + 7) set for each EMPTY (0xFF) or DELETED (0x80) byte
    uint64_t matchEmptyOrDeleted() const noexcept {
        return ctrl & 0x8080808080808080ULL;
    }

    static uint32_t trailingMatchedIndex(uint64_t bitmask) noexcept {
        return static_cast<uint32_t>(std::countr_zero(bitmask) >> 3);
    }
};

#if defined(__SSE2__)
struct Sse2Group16 {
    __m128i ctrl;

    explicit Sse2Group16(const uint8_t* ptr) noexcept {
        ctrl = _mm_loadu_si128(reinterpret_cast<const __m128i*>(ptr));
    }

    uint32_t matchH2(uint8_t h2) const noexcept {
        return static_cast<uint32_t>(_mm_movemask_epi8(_mm_cmpeq_epi8(ctrl, _mm_set1_epi8(static_cast<char>(h2)))));
    }

    uint32_t matchEmpty() const noexcept {
        return static_cast<uint32_t>(_mm_movemask_epi8(_mm_cmpeq_epi8(ctrl, _mm_set1_epi8(static_cast<char>(0xFF)))));
    }
};
#endif

Failure Modes & Adversarial Pitfalls

  • Pointer/Reference Invalidation on flat_hash_map Insert: Unlike std::unordered_map, where node pointers remain valid across rehashes, absl::flat_hash_map and hashbrown::HashMap store (K, V) inline. Any insertion that triggers a resize invalidates all existing pointers and references! When pointer stability or large value types (>64> 64>64 bytes) are required, use absl::node_hash_map.
  • Poor Low/High Bit Entropy in Custom Hash Functions: Because SwissTable uses the upper 57 bits (H1) for bucket selection and the lowest 7 bits (H2) for the SIMD control byte, a custom hash function whose lowest 7 bits are constant (e.g., an unmixed aligned pointer reinterpret_cast<uintptr_t>(ptr)) sets H2 = 0 for every single key—turning all 16 SIMD lanes into 100%100\%100% false positives! Always pass custom hashes through a finalizer mixer.

Concept Check SwissTable 1-Byte Control Metadata and H1/H2 Hash Split recall

In Abseil's `flat_hash_map` and Rust's `hashbrown` (SwissTable), a 64-bit hash is split into a 57-bit H1H_1H1​ (probe position) and a 7-bit H2H_2H2​ (fingerprint stored in the control byte).

By encoding Full slots as 0b0xxxxxxx (non-negative signed int8, 0..127) and Empty/Deleted/Sentinel with the top bit set (negative signed int8: EMPTY = -128 or -1 depending on Abseil vs hashbrown variant, where MSB=1), _mm_movemask_epi8(ctrl) directly extracts a 16-bit mask of all Empty-or-Deleted slots in 1 cycle, while _mm_cmpeq_epi8(ctrl, _mm_set1_epi8(h2)) matches all slots with the 7-bit fingerprint!
Concept Check Bitmask Iteration with Trailing Zeros in SwissTable Lookup apply

During a SwissTable lookup, `_mm_movemask_epi8(_mm_cmpeq_epi8(ctrl_group, h2_vec))` returns the 16-bit integer `mask = 0b00000100_00100000` (`0x0420`).

__builtin_ctz(0x0420) compiles to a single x86 TZCNT instruction returning 5. After testing key equality at offset 5, `mask &= mask - 1` (BLSR instruction) clears bit 5, leaving 0x0400. The next TZCNT returns 10, and the next BLSR yields 0, terminating the inner loop in just 2 iterations. And because 7-bit H2 has a 1/128 false-positive rate, full key equality must still be verified on match.

At α = 7/8, an average 16-slot group still contains 2 empty slots, so most searches terminate within the very first 16-byte control group! Even when a group is completely full, scanning an entire 16-slot group costs only a single 16-byte SIMD comparison against the contiguous `ctrl_` array—zero cache lines of the actual `Slot { K, V }` array are touched unless the 7-bit H2 fingerprint matches.
Concept Check Purpose of the Cloned Trailing Control Group (Mirror Bytes) staff

When a SwissTable allocates a table of capacity C=2kC = 2^kC=2k slots, it allocates C+16C + 16C+16 bytes for the `ctrl_` array, where `ctrl_[C ... C + 15]` mirrors `ctrl_[0 ... 15]`.

SwissTable starts probing at any slot `pos = H1(hash) & mask`, not just multiples of 16. If `pos` is in `[C - 15, C - 1]`, a 16-byte SIMD load starting at `&ctrl_[pos]` reads past index `C - 1`. By mirroring `ctrl_[0..15]` into `ctrl_[C..C+15]` (with a branchless mirror update `ctrl[(i - 16) & mask + (16 & mask)] = h2`), every probe performs a single unaligned 16-byte load without splitting into two loads at the wrap-around boundary!
