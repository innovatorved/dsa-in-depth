Erik Demaine builds Skip Lists from linked lists of express lanes and proves with high probability (via backwards coin-flip analysis) that search takes O(log N) steps.

Intuition first

William Pugh invented the Skip List in 1989 as a probabilistic alternative to complex self-balancing BST rotations. By promoting each inserted node to level h+1h+1h+1 with independent coin-flip probability ppp, a Skip List builds a hierarchy of express lanes where the reverse search path climbs O(log⁡N)O(\log N)O(logN) levels in expectation with high probability—and supports lock-free CAS concurrency far more easily than Red-Black Trees.

Probabilistic Express Lanes & The Backwards Search Proof

In a sorted singly linked list, even though the keys are ordered, binary search is impossible because we lack random access. Suppose we construct a hierarchy of linked lists L0,L1,…,LHL_0, L_1, \dots, L_{H}L0​,L1​,…,LH​: level L0L_0L0​ contains all NNN elements, and each element present in level LkL_kLk​ is independently promoted to level Lk+1L_{k+1}Lk+1​ with probability p∈(0,1)p \in (0, 1)p∈(0,1) (typically p=1/2p = 1/2p=1/2 or p=1/4p = 1/4p=1/4). Search starts at the highest level of the sentinel head node: at the current node uuu and level kkk, we advance horizontally (u = u->forward[k]) as long as u->forward[k]->key < target; when the next key would overshoot target (or is nullptr), we drop down vertically to level k−1k - 1k−1.

How do we prove that the expected search cost is O(log⁡N)O(\log N)O(logN)? Follow Pugh's elegant Backwards Analysis: trace the search path in reverse, starting from the found node at level 000 and climbing up and left back to the sentinel head at level HHH. At any node on the reverse path at level kkk:

  • Did we arrive at this node by dropping down from level k+1k+1k+1? That happens if and only if this node's tower was promoted to level k+1k+1k+1, which occurs with probability ppp (we climb UP 1 level).
  • Otherwise, with probability 1−p1 - p1−p, this node's tower stopped at level kkk, so the forward search must have reached it horizontally from the left (we step LEFT 1 node at level kkk).
Probabilistic Invariant: Expected Pointers per Node =11−p= \frac{1}{1 - p}=1−p1​ & Expected Search Cost =log⁡1/pNp= \frac{\log_{1/p} N}{p}=plog1/p​N​

Let C(K)C(K)C(K) be the expected number of reverse steps required to climb KKK levels. In one step (+1+1+1), with probability ppp we climb up to K−1K - 1K−1 remaining levels, and with probability 1−p1 - p1−p we move left and still have KKK levels to climb:

C(K)=1+p⋅C(K−1)+(1−p)⋅C(K)  ⟹  p⋅C(K)=1+p⋅C(K−1)  ⟹  C(K)=KpC(K) = 1 + p \cdot C(K - 1) + (1 - p) \cdot C(K) \implies p \cdot C(K) = 1 + p \cdot C(K - 1) \implies C(K) = \frac{K}{p}C(K)=1+p⋅C(K−1)+(1−p)⋅C(K)⟹p⋅C(K)=1+p⋅C(K−1)⟹C(K)=pK​

Since the expected number of nodes at level L=log⁡1/pNL = \log_{1/p} NL=log1/p​N is N⋅pL=1N \cdot p^L = 1N⋅pL=1, setting K=log⁡1/pNK = \log_{1/p} NK=log1/p​N yields an expected search path length of log⁡1/pNp=O(log⁡N)\frac{\log_{1/p} N}{p} = O(\log N)plog1/p​N​=O(logN)! Meanwhile, the number of forward pointers in a node's tower follows a Geometric(1−p1 - p1−p) distribution with expected height:

E[height]=∑k=0∞pk=11−p\mathbb{E}[\text{height}] = \sum_{k=0}^{\infty} p^k = \frac{1}{1 - p}E[height]=k=0∑∞​pk=1−p1​

For p=1/2p = 1/2p=1/2, each node stores on average 11−1/2=2.0\frac{1}{1 - 1/2} = 2.01−1/21​=2.0 pointers. For p=1/4p = 1/4p=1/4 (used by Redis zskiplist and LevelDB / RocksDB MemTable), each node stores on average only 11−1/4=1.333\frac{1}{1 - 1/4} = 1.3331−1/41​=1.333 pointers—less pointer overhead than a binary tree (2.02.02.0 pointers/node)!

Hardware Reality: Flexible Array Members (forward[]) & Single-Allocation Towers

A naive Skip List implementation defines struct Node { int key; std::vector<Node*> forward; }. That design is a cache disaster: every node incurs two separate heap allocations (one for the Node and one for the std::vector's dynamic buffer), and stepping u->forward[k] requires an extra pointer dereference to reach the vector's heap array! Production Skip Lists (such as Redis's zskiplistNode and LevelDB's SkipList::Node) allocate the Node header and its exact hhh-element Node* forward[h] array in a single contiguous block of memory of size sizeof(Node) + h * sizeof(Node*) using a C99 flexible array member (or placement new), keeping the key and its tower pointers in the same 64-byte cache line.

Production Implementation: Single-Allocation Skip List with p=1/4p = 1/4p=1/4 Geometric PRNG

C++2092 lines
#include <array>
#include <cstdint>
#include <cstdlib>
#include <new>

class SkipList {
  static constexpr int MAX_LEVEL = 16; // Supports up to 4^16 = 4.29B elements

  struct Node {
    int key;
    int value;
    int top_level;
    Node* forward[1]; // Flexible trailing array allocated to size <code>top_level + 1</code>
  };

  Node* head_;
  int cur_max_level_ = 0;
  std::uint64_t rng_state_ = 0x853c49e6748fea9bULL;

  static Node* allocate_node(int key, int val, int level) {
    const std::size_t bytes = sizeof(Node) + static_cast<std::size_t>(level) * sizeof(Node*);
    void* raw = ::operator new(bytes);
    Node* node = static_cast<Node*>(raw);
    node->key = key;
    node->value = val;
    node->top_level = level;
    for (int i = 0; i <= level; ++i) node->forward[i] = nullptr;
    return node;
  }

  // Fast xorshift64* PRNG sampling Geometric(p = 1/4) height
  int random_level() noexcept {
    int lvl = 0;
    while (lvl < MAX_LEVEL - 1) {
      rng_state_ ^= rng_state_ >> 12;
      rng_state_ ^= rng_state_ << 25;
      rng_state_ ^= rng_state_ >> 27;
      if (((rng_state_ * 0x2545F4914F6CDD1DULL) >> 62) != 0) break; // 1/4 probability
      ++lvl;
    }
    return lvl;
  }

public:
  SkipList() {
    head_ = allocate_node(-2147483648, 0, MAX_LEVEL - 1);
  }

  const int* find(int target) const noexcept {
    const Node* curr = head_;
    for (int i = cur_max_level_; i >= 0; --i) {
      while (curr->forward[i] != nullptr && curr->forward[i]->key < target) {
        curr = curr->forward[i];
      }
    }
    curr = curr->forward[0];
    if (curr != nullptr && curr->key == target) return &curr->value;
    return nullptr;
  }

  void insert(int key, int value) {
    std::array<Node*, MAX_LEVEL> update{};
    Node* curr = head_;

    for (int i = cur_max_level_; i >= 0; --i) {
      while (curr->forward[i] != nullptr && curr->forward[i]->key < key) {
        curr = curr->forward[i];
      }
      update[i] = curr;
    }

    curr = curr->forward[0];
    if (curr != nullptr && curr->key == key) {
      curr->value = value;
      return;
    }

    const int new_lvl = random_level();
    if (new_lvl > cur_max_level_) {
      for (int i = cur_max_level_ + 1; i <= new_lvl; ++i) {
        update[i] = head_;
      }
      cur_max_level_ = new_lvl;
    }

    Node* inserted = allocate_node(key, value, new_lvl);
    for (int i = 0; i <= new_lvl; ++i) {
      inserted->forward[i] = update[i]->forward[i];
      update[i]->forward[i] = inserted;
    }
  }
};
Production Pitfall: Unbounded MAX_LEVEL & Adversarial Seed Attacks

Never allow random_level() to grow unboundedly without a hard cap MAX_LEVEL (e.g., 16 or 32), or a lucky streak of coin flips on a 10-element list can create a 25-level tower where 20 levels contain only a single node—wasting vertical steps on every query. Furthermore, if you use a fixed deterministic PRNG seed while exposing a Skip List to untrusted external keys, an adversary who knows your PRNG sequence can time insertions so that high towers are assigned to useless keys and level-0 towers are assigned to hot keys; always seed the level generator from hardware entropy (getrandom / std::random_device).

In a lock-free concurrent skip list (such as RocksDB's `InlineSkipList` or Java's `ConcurrentSkipListMap`), when inserting a new node of height hhh, why MUST the forward pointers be spliced from bottom to top (level 000 first, up to level h−1h-1h−1) rather than top to bottom?

Concept Check Flexible Array Member Single-Allocation Layout staff

A naive skip list implementation defines `struct Node { int key; Node** forward; }` and performs two `malloc` calls per node (one for `Node`, one for the `forward` array). How do production C/C++ engines eliminate the second allocation and the extra pointer indirection?

By placing a flexible array member `Node* forward[]` at the tail of `struct Node` and sizing the single allocation to match the randomly chosen tower height hhh, `node->forward[i]` is accessed as a direct fixed offset `*(node + offset + i * 8)` with zero extra pointer indirection and inside the same cache line as `node->key`.

Key Takeaways

Skip Lists replace complex deterministic tree rotations with probabilistic multi-level express lanes, achieving O(log N) search, insert, and delete with high probability.
Tracing the search path backwards from level 0 to the top of the head sentinel proves that climbing K levels takes K / p expected steps.
With promotion probability p = 1/4 (used by Redis and RocksDB), the expected number of pointers per node is 1 / (1 - 1/4) = 1.33, using less memory than a binary search tree.
In concurrent systems (RocksDB MemTable, Java ConcurrentSkipListMap), Skip Lists enable lock-free atomic CAS insertions because inserting a node only splices local forward pointers without global tree rotations.
