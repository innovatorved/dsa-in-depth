Rabin-Karp Rolling Hash: Mersenne Prime Moduli (2^61 - 1) & Birthday Collision Avoidance

6 min read Module 4.1: Tries, Exact String Matching & Multi-Pattern Automata Updated Oct 22, 2026
📄 Cheat Sheet
Abdul Bari Rabin-Karp Algorithm & Polynomial Rolling Hash Watch on YouTube ↗

Explains the polynomial view of strings and how sliding a window updates the hash in O(1) arithmetic operations.

Intuition first

Karp and Rabin (1987) turned string comparison into modular arithmetic by treating a string $S[0..N-1]$ as a polynomial evaluated at a random base $B$ modulo a prime $M$: $H(S) = \left(\sum_{i=0}^{N-1} S[i] \cdot B^{N-1-i}\right) \bmod M$. By precomputing prefix hashes $P[i] = (P[i-1] \cdot B + S[i]) \bmod M$ and base powers $B^k \bmod M$ in $O(N)$ time, the hash of any arbitrary substring $S[L..R]$ can be extracted in $O(1)$ time via $(P[R+1] - P[L] \cdot B^{R - L + 1}) \bmod M$! This unlocks algorithms that deterministic automata cannot easily express, such as $O(\log N)$ Longest Common Prefix (LCP) of any two substrings via binary search, or $O(N \log N)$ Longest Duplicate Substring.

However, naive 32-bit rolling hashes ( + "M = 10^9 + 7" + ) fail catastrophically whenever a problem compares $\Theta(N)$ substring hashes: by the Birthday Paradox, comparing $K = 10^5$ hashes has collision probability $\approx 1 - e^{-K^2 / (2M)} \approx 99.3\%$! Using the 61-bit Mersenne prime $M = 2^{61} - 1$ with fast bit-shift modular reduction ( + "(x & M) + (x >> 61)" + ) and a runtime-randomized base $B$ shrinks the collision probability for $10^5$ substrings down to $\approx 2 \times 10^{-9}$.

1. Polynomial Prefix Hashing & $O(1)$ Substring Extraction

Define the 1-indexed prefix hash array $P[0..N]$ with $P[0] = 0$ and recurrence $P[i] = (P[i-1] \cdot B + S[i-1]) \bmod M$, alongside power table $\text{powB}[k] = B^k \bmod M$. Notice that $P[R+1]$ contains $P[L]$ shifted left by $R - L + 1$ powers of $B$, plus the polynomial of $S[L..R]$:

$$P[R+1] = P[L] \cdot B^{R - L + 1} + \sum_{j=L}^{R} S[j] \cdot B^{R - j} \pmod M$$

Subtracting $P[L] \cdot \text{powB}[R - L + 1]$ modulo $M$ isolates the exact canonical hash of $S[L..R]$ in $O(1)$ time!

Schwartz-Zippel Lemma & Birthday Paradox Bound:
  • Single Pair Comparison: Two distinct strings of length $L$ define a non-zero difference polynomial of degree $< L$. By the Schwartz-Zippel Lemma (Lagrange's Theorem), if base $B$ is chosen uniformly at random from $[1, M-1]$, the probability that $H(S_1) \equiv H(S_2) \pmod M$ is at most $\frac{L - 1}{M - 1}$.
  • All-Pairs / Set of $K$ Substrings (Birthday Paradox): When inserting $K$ substring hashes of length $L$ into a hash set (or sorting them), there are $\binom{K}{2} \approx \frac{K^2}{2}$ pairs. By the union bound, the failure probability is bounded by $\frac{K^2 \cdot L}{2M}$. With $M = 10^9 + 7$ and $K = 10^5$, $\frac{K^2}{2M} \approx 5 > 1$ (guaranteed collision!). With $M = 2^{61} - 1 \approx 2.3 \times 10^{18}$ (or a Double Hash $(M_1, M_2)$), $\frac{K^2}{2M} \approx 2.1 \times 10^{-9}$.

Hardware & Cache Reality — Why $M = 2^{61} - 1$ Avoids Hardware DIV Bottlenecks and Anti-Hash Tests: Integer division (idiv on x86-64) has a latency of 25–45 CPU clock cycles and cannot be pipelined well. For the Mersenne prime $M = 2^{61} - 1$, $2^{61} \equiv 1 \pmod M$, so any product $x = \text{hi} \cdot 2^{61} + \text{lo}$ satisfies $x \equiv \text{hi} + \text{lo} \pmod M$—computable using only bit shifts, bitwise AND, and addition! Furthermore, never use unsigned int64 overflow ($M = 2^{64}$) with a fixed base: the Thue-Morse sequence ($T_0 = \text{'a'}, T_1 = \text{'ab'}, T_2 = \text{'abba'}, \dots$) has degree-$12$ root collisions at $2^{64}$ for every odd base $B$! Choosing $M = 2^{61} - 1$ with a runtime-randomized base $B$ is immune to Thue-Morse anti-hash tests.

2. Production Implementation: Mersenne $2^{61}-1$ Rolling Hash with $O(1)$ Substring Hash & $O(\log N)$ LCP

JAVASCRIPT
const MOD61 = (1n << 61n) - 1n;
// Random odd base chosen per process startup in [257 .. 10^9] to defeat adversarial inputs
const RANDOM_BASE = BigInt(257 + Math.floor(Math.random() * 1000000000));

function mod61(x) {
  let res = (x & MOD61) + (x >> 61n);
  if (res >= MOD61) res -= MOD61;
  return res;
}

function mul61(a, b) {
  return mod61(a * b);
}

/**
 * RollingHash61: O(N) build, O(1) arbitrary substring hash, O(log N) substring LCP & compare
 */
class RollingHash61 {
  constructor(str, base = RANDOM_BASE) {
    this.str = str;
    this.n = str.length;
    this.pref = new BigUint64Array(this.n + 1);
    this.pow = new BigUint64Array(this.n + 1);
    this.pow[0] = 1n;

    for (let i = 0; i < this.n; i++) {
      const code = BigInt(str.charCodeAt(i));
      this.pref[i + 1] = mod61(this.pref[i] * base + code);
      this.pow[i + 1] = mul61(this.pow[i], base);
    }
  }

  // O(1) hash of closed substring str[l..r] (0-indexed); returns 0n for empty range l > r
  getHash(l, r) {
    if (l > r) return 0n;
    const sub = this.pref[r + 1] + MOD61 - mul61(this.pref[l], this.pow[r - l + 1]);
    return sub >= MOD61 ? sub - MOD61 : sub;
  }

  // O(log N) Longest Common Prefix of suffixes str[i..] and str[j..]
  lcp(i, j) {
    let lo = 0;
    let hi = this.n - Math.max(i, j);
    while (lo < hi) {
      const mid = (lo + hi + 1) >> 1;
      if (this.getHash(i, i + mid - 1) === this.getHash(j, j + mid - 1)) {
        lo = mid;
      } else {
        hi = mid - 1;
      }
    }
    return lo;
  }

  // O(log N) lexicographical comparison of substrings str[l1..r1] and str[l2..r2]
  compareSubstrings(l1, r1, l2, r2) {
    const len1 = r1 - l1 + 1, len2 = r2 - l2 + 1;
    const common = Math.min(len1, len2, this.lcp(l1, l2));
    if (common >= Math.min(len1, len2)) return len1 - len2;
    return this.str.charCodeAt(l1 + common) - this.str.charCodeAt(l2 + common);
  }
}

Check yourself Question 1 of 4
Concept Check Birthday Paradox Collision Threshold for Single 32-Bit Hash recall

A developer uses a single polynomial hash modulo $M = 10^9 + 7 \approx 2^{30}$ to deduplicate all substrings of length $L$ in a text of length $N = 10^5$ without verifying matching substrings character-by-character.

When hashing $N$ substrings and checking all $\binom{N}{2} \approx N^2 / 2$ pairs (e.g., via a hash set or sorting hashes during binary search for Longest Duplicate Substring), collisions become likely as soon as $N \approx \sqrt{M}$. For $M \approx 10^9$, $\sqrt{M} \approx 31{,}622$, so $N = 10^5$ is virtually guaranteed to suffer a hash collision unless a 61-bit modulus ($M = 2^{61} - 1$) or double hashing is used.
Concept Check Fast Mersenne Modular Reduction Modulo $2^{61} - 1$ apply

We compute the 128-bit product `unsigned __int128 prod = (unsigned __int128)a * b` where $a, b < M = 2^{61} - 1$, and want to reduce `prod` modulo $M$ without the slow hardware `divq` instruction.

Because $2^{61} = (2^{61} - 1) + 1 \equiv 1 \pmod{M}$, writing $\text{prod} = \text{hi} \cdot 2^{61} + \text{lo}$ where $\text{lo} = \text{prod} \mathbin{\&} M$ and $\text{hi} = \text{prod} \gg 61$ immediately gives $\text{prod} \equiv \text{hi} + \text{lo} \pmod M$. A single conditional subtraction `if (res >= M) res -= M;` then normalizes the result into $[0, M - 1]$.
Concept Check Substring Hash Extraction Formula apply

Given prefix hashes $H[i] = \sum_{k=0}^{i-1} S[k] \cdot B^{i-1-k} \bmod M$ with $H[0] = 0$ and precomputed powers $P[k] = B^k \bmod M$.

In the highest-power-first prefix definition, $H[r] = H[l] \cdot B^{r - l} + \text{hash}(S[l..r)) \pmod M$. Multiplying $H[l]$ by $P[r - l] = B^{r - l} \bmod M$ aligns the powers of $S[0..l-1]$ with their shifted positions inside $H[r]$, and subtracting modulo $M$ isolates $\text{hash}(S[l..r))$.
Concept Check Thue-Morse Universal Collision Attack on `uint64_t` Overflow Hashing staff

Many competitive programmers implement rolling hash using natural `uint64_t` overflow ($M = 2^{64}$) with an odd base $B$. Define the Thue-Morse string sequence by $T_0 = \texttt{"a"}$, $T_0' = \texttt{"b"}$, and $T_k = T_{k-1} + T_{k-1}'$, $T_k' = T_{k-1}' + T_{k-1}$ for $k \ge 1$.

By Euler's / Lifting-the-Exponent lemma on $2$-adic valuations, for any odd $B$, $v_2(B - 1) \ge 1$, $v_2(B^2 - 1) \ge 3$, and $v_2(B^{2^i} - 1) \ge i + 2$ for $i \ge 1$. Thus $v_2(\prod_{i=0}^{k-1} (B^{2^i} - 1)) \ge 1 + \sum_{i=1}^{k-1} (i + 2) = 1 + \frac{(k-1)(k+4)}{2}$. For $k = 10$, this is $1 + 63 = 64$, so $\text{hash}(T_{10}) \equiv \text{hash}(T_{10}') \pmod{2^{64}}$ simultaneously for ALL odd bases $B$!

Key Takeaways

Precomputing prefix polynomial hashes P[i] = (P[i-1]*B + S[i-1]) mod M allows O(1) hash extraction of any substring S[L..R] via (P[R+1] - P[L]*B^(R-L+1)) mod M.
By the Birthday Paradox, comparing K = 10^5 substrings requires a modulus M >> K^2; a single 32-bit prime (10^9 + 7) collides with >99% probability.
The Mersenne prime M = 2^61 - 1 with a runtime-randomized base supports division-free reduction (x & M) + (x >> 61) and defeats both Birthday collisions and Thue-Morse anti-hash strings.
Combining O(1) substring hashing with binary search computes the Longest Common Prefix (LCP) and lexicographical order of any two substrings in O(log N) time.
