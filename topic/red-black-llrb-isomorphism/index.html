2-3-4 Trees, Red-Black Trees & Sedgewick's Left-Leaning Red-Black (LLRB) Isomorphism

Robert Sedgewick explains how Guibas & Sedgewick (1978) derived Red-Black Trees from 2-3-4 B-trees and how LLRB trees reduce implementation to 3 lines of rotation/flip code.

Intuition first

Why do textbook Red-Black Tree implementations span 400 lines of intricate uncle/grandparent case analysis? Because they present Red-Black Trees as an arbitrary set of four color rules divorced from their true origin! In 1978, Leo Guibas and Robert Sedgewick introduced Red-Black Trees as a binary-tree encoding of a perfectly balanced 2-3-4 B-Tree: every Red link is simply an internal horizontal glue edge binding 2 or 3 keys together into a single logical 3-node or 4-node, while every Black link is a vertical child edge of the 2-3-4 tree.

In 2008, Sedgewick perfected this bijection with Left-Leaning Red-Black (LLRB) 2-3 Trees: by requiring that every 3-node lean exclusively to the left, there is a strict $1$-to-$1$ isomorphism between 2-3 trees and LLRB trees, and the entire insertion rebalancing logic collapses into three 3-line local operations: rotateLeft (fix right-leaning red link), rotateRight (fix two consecutive left red links), and flipColors (split a temporary 4-node)!

The Four Classical Red-Black Invariants & The 2-3-4 B-Tree Bijection

In a standard Red-Black Tree (CLRS Chapter 13), every node (or incoming parent link) is colored either Red or Black subject to four invariants:

  1. Root Rule: The root is always Black.
  2. External Leaf Rule: Every null leaf sentinel is Black.
  3. Red Rule (No Red-Red Parent-Child): If a node is Red, both of its children are Black.
  4. Black-Height Rule (Perfect 2-3-4 Balance): Every simple path from any node $u$ down to any descendant null leaf contains the exact same number of Black nodes, denoted $\text{bh}(u)$ (the black-height).

Sedgewick's Left-Leaning (LLRB 2-3) Simplification: If we forbid 4-nodes from persisting at rest and force every 3-node's red glue edge to lean left, then right-leaning red links are illegal and two consecutive left-leaning red links represent a temporary 4-node awaiting a split (flipColors). Every LLRB insertion ascending the recursion stack runs the exact same 3 if-statements:

  1. if (isRed(h.right) && !isRed(h.left)) h = rotateLeft(h); — Lean a right-leaning 3-node to the left.
  2. if (isRed(h.left) && isRed(h.left.left)) h = rotateRight(h); — Balance a skewed temporary 4-node so its two children are both red.
  3. if (isRed(h.left) && isRed(h.right)) flipColors(h); — Split the temporary 4-node into two 2-nodes and pass the middle key up to the parent as a red link!

Lemma: Why a Red-Black Tree of $N$ Internal Nodes Has Height $h \le 2 \log_2(N + 1)$

Step 1 (Subtree Size Lower Bound via Black-Height): By induction on black-height $\text{bh}(x)$, the subtree rooted at any node $x$ contains at least $2^{\text{bh}(x)} - 1$ internal nodes. Base case: if $\text{bh}(x) = 0$, $x$ is a null leaf with $2^0 - 1 = 0$ internal nodes. Inductive step: for an internal node $x$, each child $c$ has black-height either $\text{bh}(x)$ (if $c$ is Red) or $\text{bh}(x) - 1$ (if $c$ is Black). By the Inductive Hypothesis, each child subtree has at least $2^{\text{bh}(x)-1} - 1$ nodes, so:

$$\text{size}(x) \ge 1 + 2\left(2^{\text{bh}(x)-1} - 1\right) = 2^{\text{bh}(x)} - 1$$

Step 2 (Relating $h$ to $\text{bh}(\text{root})$): By the Red Rule (no two consecutive Red nodes on any path), at least half of the nodes along any root-to-leaf path of length $h$ must be Black: $\text{bh}(\text{root}) \ge h / 2$. Substituting into Step 1:

$$N \ge 2^{\text{bh}(\text{root})} - 1 \ge 2^{h/2} - 1 \implies 2^{h/2} \le N + 1 \implies h \le 2 \log_2(N + 1)$$

Hardware Reality: Why std::map, Java TreeMap, and Linux rbtree Choose Red-Black Over AVL

If AVL trees are shorter ($1.44 \log_2 N$ vs $2.00 \log_2 N$), why do C++ std::map, Java TreeMap, and the Linux kernel use standard Red-Black Trees instead? Because in a standard Red-Black Tree, insertion requires at most 2 rotations and deletion requires at most 3 rotations in the worst case (compared to $O(\log N)$ rotations for AVL deletion!). In concurrent or persistent environments where each rotation modifies cache lines or copies nodes along the spine, bounding structural pointer mutations to $O(1)$ worst-case rotations is decisive.

Implementation: Complete Sedgewick LLRB Insertion Engine

C++20
// C++20: Sedgewick Left-Leaning Red-Black (LLRB) Tree Insertion in 45 Lines
struct LLRBNode {
    int key;
    bool red = true; // New nodes are always inserted with a RED incoming link
    LLRBNode *left = nullptr, *right = nullptr;
    explicit LLRBNode(int k) : key(k) {}
};

inline bool isRed(const LLRBNode* x) noexcept { return x != nullptr && x->red; }

LLRBNode* rotateLeft(LLRBNode* h) noexcept {
    LLRBNode* x = h->right;
    h->right = x->left;
    x->left = h;
    x->red = h->red;
    h->red = true;
    return x;
}

LLRBNode* rotateRight(LLRBNode* h) noexcept {
    LLRBNode* x = h->left;
    h->left = x->right;
    x->right = h;
    x->red = h->red;
    h->red = true;
    return x;
}

void flipColors(LLRBNode* h) noexcept {
    h->red = !h->red;
    h->left->red = !h->left->red;
    h->right->red = !h->right->red;
}

LLRBNode* insertNode(LLRBNode* h, int key) {
    if (!h) return new LLRBNode(key);
    if (key < h->key)      h->left  = insertNode(h->left, key);
    else if (key > h->key) h->right = insertNode(h->right, key);

    // The 3-line LLRB invariant restoration pipeline:
    if (isRed(h->right) && !isRed(h->left))     h = rotateLeft(h);
    if (isRed(h->left)  && isRed(h->left->left)) h = rotateRight(h);
    if (isRed(h->left)  && isRed(h->right))      flipColors(h);
    return h;
}

Failure Modes & Adversarial Pitfalls

  • Forgetting to Force root->red = false After Insertion: When flipColors splits the root of the entire tree, root->red flips to true (which corresponds to growing the 2-3 tree upward by 1 black level). Always set root->red = false at the top-level insert(key) wrapper!
  • LLRB Deletion Asymmetry vs Standard RB Deletion: While LLRB insertion is 15 lines of code, LLRB deletion (moveRedLeft / moveRedRight) must push red links downward top-down to guarantee the target leaf is not a 2-node, performing $O(\log N)$ rotations on the way down and up, whereas classical CLRS Red-Black deletion performs at most 3 rotations.
Check yourself Question 1 of 4
Concept Check 2-3-4 Tree to Red-Black Tree Isomorphism recall

Under Guibas and Sedgewick's correspondence between 2-3-4 B-trees and standard Red-Black trees, how is a 4-node (containing 3 keys $a < b < c$ and 4 child links) represented?

In the 2-3-4 to Red-Black isomorphism, red edges bind keys that reside inside the same B-tree node. A 4-node with keys (a, b, c) is represented as a black root b connected via red links to its left child a and right child c. Flipping the colors of a and c to black and b to red corresponds exactly to splitting the 4-node and pushing middle key b up into the parent B-tree node.
Concept Check LLRB Bottom-Up Insertion Fix-Up Sequence apply

In Sedgewick's Left-Leaning Red-Black (LLRB) 2-3 tree, three local transformations are checked in exact order on the way up the recursion stack after inserting a node. What is that exact sequence of checks at node `h`?

In an LLRB 2-3 tree: Step 1 (`isRed(h.right) && !isRed(h.left)`) fixes a right-leaning 3-node or turns a zig-zag into two consecutive left red links via `rotateLeft(h)`. Step 2 (`isRed(h.left) && isRed(h.left.left)`) balances two consecutive left-leaning red links into a temporary 4-node via `rotateRight(h)`. Step 3 (`isRed(h.left) && isRed(h.right)`) splits that temporary 4-node by flipping both children to black and `h` to red via `flipColors(h)`.
Concept Check Black-Height & Maximum Path Length Bound apply

Suppose a Red-Black tree has black-height $bh = 6$ (counting black nodes on any root-to-NULL path, excluding the NULL sentinel). What are the minimum possible number of internal nodes $N_{\min}$ and the maximum possible root-to-leaf path length?

Collapsing all red nodes into their black parents yields a 2-3-4 tree where every leaf is at depth bh = 6. The minimum number of internal nodes occurs when every node is a 2-node (all nodes black), forming a complete binary tree of height 6 with 2^6 - 1 = 63 nodes. Because no two red nodes can be adjacent, any path has at most bh black nodes and at most bh red nodes (if root were red, or bh-1 if root is black), giving at most 2*bh = 12 nodes (depth 11).
Concept Check Why LLRB Deletion Requires `moveRedLeft` and `moveRedRight` staff

In standard Red-Black trees, deletion uses a bottom-up fix-up with 4 symmetric cases. In an LLRB tree, deletion instead pushes a red link down from the root using `moveRedLeft` and `moveRedRight` before deleting, then fixes up on the way back.

Deleting a black leaf (a 2-node) would violate the uniform black-height invariant. LLRB deletion implements top-down 2-3 tree deletion: on the way down, if the target child is a 2-node (`!isRed(h.left) && !isRed(h.left.left)`), `moveRedLeft` borrows from a 3-node sibling or merges with a 2-node sibling so we always land on a 3-node or 4-node leaf. While concise in code, this top-down restructuring performs O(log N) rotations on every deletion, unlike standard RB-trees which perform at most 3 rotations.

Key Takeaways

Red-Black Trees are an exact binary representation of 2-3-4 B-trees where Red edges glue keys horizontally inside a single 3-node or 4-node and Black edges represent vertical B-tree child links.
Every node x of black-height bh(x) roots a subtree of at least 2^bh(x) - 1 internal nodes; combined with bh(root) >= h/2, this proves height h <= 2 log₂(N + 1).
Classical Red-Black Trees require at most 2 rotations on insert and at most 3 rotations on delete in the worst case.
Sedgewick's Left-Leaning Red-Black (LLRB) Tree enforces a 1-to-1 bijection with 2-3 trees, reducing bottom-up rebalancing to rotateLeft, rotateRight, and flipColors.
