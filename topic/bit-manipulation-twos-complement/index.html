Intuition first

Every $w$-bit signed integer in modern hardware is represented in two's complement, where the most significant bit $b_{w-1}$ carries negative weight $-2^{w-1}$ and negation is defined by the ring identity $-x \equiv \sim x + 1 \pmod{2^w}$. Because $+1$ ripples a carry across all trailing $0$s and flips the lowest set bit $1 \to 0$, combining $x$ with $-x$ or $x - 1$ isolates or clears the lowest set bit in a single clock cycle.

Two's Complement Ring Algebra & Lowest-Bit Identities

In a $w$-bit two's-complement register, a bit vector $b_{w-1} b_{w-2} \dots b_1 b_0$ represents the signed integer value:

$$x = -b_{w-1} 2^{w-1} + \sum_{i=0}^{w-2} b_i 2^i$$

Why did two's complement universally triumph over sign-magnitude and ones' complement? Because addition, subtraction, and multiplication use the exact same ALU circuitry for both signed and unsigned integers modulo $2^w$, and zero has a unique representation. Suppose a non-zero integer $x$ has its lowest set bit ($1$) at index $k$, so its binary representation splits into an arbitrary prefix $P$, bit $k$ equal to $1$, and $k$ trailing zeros: $x = [P \;\vert\; 1 \;\vert\; 00\dots0_k]$. Observe what happens under subtraction of $1$ and under negation ($\sim x + 1$):

  • Subtracting 1 ($x - 1$): Borrowing from bit $k$ flips bit $k$ to $0$ and turns all $k$ trailing zeros into $1$s, leaving prefix $P$ untouched: $x - 1 = [P \;\vert\; 0 \;\vert\; 11\dots1_k]$.
  • Brian Kernighan's Clear-Lowest-Set-Bit ($x \mathrel{\&} (x - 1)$): ANDing $x$ with $x - 1$ preserves prefix $P$ and zeroes out bit $k$ and everything below it: $x \mathrel{\&} (x - 1) = [P \;\vert\; 0 \;\vert\; 00\dots0_k]$. This clears the lowest set bit in $O(1)$ time, and equals $0$ for $x > 0$ if and only if $x$ is a power of two!
  • Isolating the Lowest Set Bit ($x \mathrel{\&} -x$): Bitwise NOT gives $\sim x = [\sim P \;\vert\; 0 \;\vert\; 11\dots1_k]$. Adding $1$ ripples a carry through the $k$ trailing ones and sets bit $k$: $-x = \sim x + 1 = [\sim P \;\vert\; 1 \;\vert\; 00\dots0_k]$. Therefore, $x \mathrel{\&} -x = [00\dots0 \;\vert\; 1 \;\vert\; 00\dots0_k] = 2^k$, isolating the lowest set bit (the fundamental primitive of Fenwick Trees).
Algebraic Invariant: $\mathbb{F}_2^w$ XOR Vector Space & Submask Enumeration

Bitwise XOR ($\oplus$) is addition modulo $2$ in the vector space $\mathbb{F}_2^w$: it is commutative ($a \oplus b = b \oplus a$), associative ($a \oplus (b \oplus c) = (a \oplus b) \oplus c$), has identity $0$ ($a \oplus 0 = a$), and every element is its own inverse ($a \oplus a = 0$). Consequently, XORing a stream where every element appears twice except one cancels all pairs to $0$, leaving the unique element.

Even more remarkably, if two unique elements $u \neq v$ appear once while all others appear twice, the total XOR is $S = u \oplus v \neq 0$. Extracting the lowest set bit $lowbit = S \mathrel{\&} -S$ identifies a bit position where $u$ and $v$ provably differ—partitioning the stream into two disjoint subsets (those with $lowbit$ set vs. clear) that isolate $u$ and $v$ in $O(N)$ time and $O(1)$ space!

Hardware Reality: Signed Overflow UB, INT_MIN Negation, and Shift Width Modulo Traps

In C and C++, signed integer overflow is Undefined Behavior (UB)—even though C++20 standardized two's-complement representation! Specifically:

  • Negating INT32_MIN ($-2^{31} = \text{0x80000000}$) in signed arithmetic overflows because $+2^{31}$ is unrepresentable in 32-bit signed two's complement (its bitwise negation $+1$ wraps back to 0x80000000). Always cast to an unsigned type (uint32_t / uint64_t) before applying 0u - ux or bit manipulation.
  • Shifting a $w$-bit integer by $\ge w$ bits (e.g., 1ULL << 64 or 1 << 32) is Undefined Behavior in C/C++, and on x86-64 the hardware SHL instruction masks the shift count to $63$ (or $31$), turning 1ULL << 64 into 1ULL << 0 == 1 instead of 0!

Production Implementation: Single Number III, Gosper's Hack & $O(3^n)$ Submask DP

#include <bit>
#include <cstdint>
#include <utility>
#include <vector>

// Partition an array where two elements appear once and all others appear twice
std::pair<int, int> single_number_two_uniques(const std::vector<int>& nums) noexcept {
  std::uint32_t xor_all = 0;
  for (int x : nums) {
    xor_all ^= static_cast<std::uint32_t>(x);
  }
  // Isolate lowest differing bit using unsigned two's complement negation (safe for INT_MIN!)
  const std::uint32_t diff_bit = xor_all & (0u - xor_all);

  std::uint32_t group_a = 0, group_b = 0;
  for (int x : nums) {
    const auto ux = static_cast<std::uint32_t>(x);
    if ((ux & diff_bit) != 0) {
      group_a ^= ux;
    } else {
      group_b ^= ux;
    }
  }
  return {static_cast<int>(group_a), static_cast<int>(group_b)};
}

// Gosper's Hack: Compute next lexicographical bitmask with the exact same popcount
constexpr std::uint64_t next_combination_mask(std::uint64_t x) noexcept {
  const std::uint64_t c = x & (0ULL - x); // lowest set bit
  const std::uint64_t r = x + c;          // ripple carry through lowest block of 1s
  return (((r ^ x) >> 2) / c) | r;        // shift remaining 1s to the bottom
}

// Enumerate all submasks of all n-bit masks in exactly O(3^n) steps

    for (std::uint32_t sub = mask; sub > 0; sub = (sub - 1) & mask) {
      // Process non-empty submask sub of mask
    }
    // Process sub == 0 here if empty submask is needed
  }
}
Production Pitfall: C Operator Precedence of Bitwise &, ^, | vs. == and !=

By a notorious historical accident in early B and C (before && and || were separated from & and |), Dennis Ritchie gave relational and equality operators (==, !=, <, >) higher operator precedence than bitwise &, ^, and |. As a result, writing if (mask & bit != 0) is parsed by the compiler as if (mask & (bit != 0))—which evaluates mask & 1 and silently tests the wrong bit! Always parenthesize bitwise tests: if ((mask & bit) != 0), and always write 1ULL << k instead of 1 << k when $k \ge 31$.

Check yourself Question 1 of 4
Concept Check Isolating vs Clearing the Lowest Set Bit recall

In two's-complement arithmetic, let $x$ be a non-zero integer whose lowest set bit ($1$) is at bit position $k$ (having value $2^k$).

Writing $x = [P \vert 1 \vert 0\dots0_k]$, we have $x - 1 = [P \vert 0 \vert 1\dots1_k]$, so $x \mathrel{\&} (x - 1) = [P \vert 0 \vert 0\dots0_k]$. Meanwhile $-x = \sim x + 1 = [\sim P \vert 1 \vert 0\dots0_k]$, so $x \mathrel{\&} -x = [0\dots0 \vert 1 \vert 0\dots0_k] = 2^k$.
Concept Check Single Number III: Isolating Two Unique Elements via XOR and Lowbit apply

In an array of $N$ integers, every integer appears exactly twice except for two distinct integers $u \neq v$ that appear once. You XOR all elements together to obtain $S = u \oplus v \neq 0$.

Because $u \neq v$, $S = u \oplus v \neq 0$. Any set bit in $S$ (such as the lowest set bit `diff_bit = S & -S`) must be $1$ in either $u$ or $v$ and $0$ in the other. Partitioning all array elements by whether they have `diff_bit` set sends $u$ and $v$ to different buckets while sending every duplicate pair $(y, y)$ to the same bucket where $y \oplus y = 0$.
Concept Check Exact Complexity of Submask Enumeration apply

In Bitmask Dynamic Programming over $n$ items, you iterate over every mask $M \in [0, 2^n - 1]$ and then iterate over all non-empty submasks $s$ of $M$ using `for (uint32_t s = M; s > 0; s = (s - 1) & M)`.

Each element $i \in \{0, \dots, n-1\}$ has 3 mutually exclusive states across a valid $(M, s)$ pair with $s \subseteq M$: (1) $i \notin M$ and $i \notin s$, (2) $i \in M$ and $i \notin s$, or (3) $i \in M$ and $i \in s$. By the product rule, there are $3^n$ such pairs!

During a security audit of a C++ cryptography and bitboard library, you encounter the following three expressions on `int32_t x` and `int k` (where $0 \le k \le 64$): 1. `if (x & 1 << k != 0)` 2. `int32_t lowbit = x & -x;` (when `x == INT32_MIN`) 3. `uint64_t mask = (1ULL << k) - 1;` (when `k == 64`)

Even in C++20 (which mandates two's complement), signed arithmetic overflow (`-INT32_MIN`) and shifting by $\ge$ bit-width (`1ULL << 64`) remain Undefined Behavior! On x86-64, the `SHL` instruction masks the shift count with `0x3F` (`64 & 63 == 0`), so `(1ULL << 64) - 1` produces `0` instead of `UINT64_MAX`!

Key Takeaways

In two's-complement arithmetic (-x == ~x + 1), x & (x - 1) clears the lowest set bit (BLSR) and x & -x isolates the lowest set bit (BLSI) in a single ALU cycle.
To avoid signed integer overflow UB on INT_MIN (-2^31), perform bitwise negation and bit hacks on unsigned types: ux & (0u - ux).
Iterating s = (s - 1) & mask visits only valid submasks of mask; summed over all 2^n masks, this takes sum C(n,k) 2^k = 3^n total operations instead of 4^n.
Always wrap bitwise masks in parentheses before equality comparisons ((x & mask) != 0) and use 1ULL << k to prevent 32-bit shift Undefined Behavior.
