Two's Complement Ring Algebra & Lowest-Bit Identities

In a www-bit two's-complement register, a bit vector bw−1bw−2…b1b0b_{w-1} b_{w-2} \dots b_1 b_0bw−1​bw−2​…b1​b0​ represents the signed integer value:

x=−bw−12w−1+∑i=0w−2bi2ix = -b_{w-1} 2^{w-1} + \sum_{i=0}^{w-2} b_i 2^ix=−bw−1​2w−1+i=0∑w−2​bi​2i

Why did two's complement universally triumph over sign-magnitude and ones' complement? Because addition, subtraction, and multiplication use the exact same ALU circuitry for both signed and unsigned integers modulo 2w2^w2w, and zero has a unique representation. Suppose a non-zero integer xxx has its lowest set bit (111) at index kkk, so its binary representation splits into an arbitrary prefix PPP, bit kkk equal to 111, and kkk trailing zeros: x=[P  ∣  1  ∣  00…0k]x = [P \;\vert\; 1 \;\vert\; 00\dots0_k]x=[P∣1∣00…0k​]. Observe what happens under subtraction of 111 and under negation (∼x+1\sim x + 1∼x+1):

  • Subtracting 1 (x−1x - 1x−1): Borrowing from bit kkk flips bit kkk to 000 and turns all kkk trailing zeros into 111s, leaving prefix PPP untouched: x−1=[P  ∣  0  ∣  11…1k]x - 1 = [P \;\vert\; 0 \;\vert\; 11\dots1_k]x−1=[P∣0∣11…1k​].
  • Brian Kernighan's Clear-Lowest-Set-Bit (x&(x−1)x \mathrel{\&} (x - 1)x&(x−1)): ANDing xxx with x−1x - 1x−1 preserves prefix PPP and zeroes out bit kkk and everything below it: x&(x−1)=[P  ∣  0  ∣  00…0k]x \mathrel{\&} (x - 1) = [P \;\vert\; 0 \;\vert\; 00\dots0_k]x&(x−1)=[P∣0∣00…0k​]. This clears the lowest set bit in O(1)O(1)O(1) time, and equals 000 for x>0x > 0x>0 if and only if xxx is a power of two!
  • Isolating the Lowest Set Bit (x&−xx \mathrel{\&} -xx&−x): Bitwise NOT gives ∼x=[∼P  ∣  0  ∣  11…1k]\sim x = [\sim P \;\vert\; 0 \;\vert\; 11\dots1_k]∼x=[∼P∣0∣11…1k​]. Adding 111 ripples a carry through the kkk trailing ones and sets bit kkk: −x=∼x+1=[∼P  ∣  1  ∣  00…0k]-x = \sim x + 1 = [\sim P \;\vert\; 1 \;\vert\; 00\dots0_k]−x=∼x+1=[∼P∣1∣00…0k​]. Therefore, x&−x=[00…0  ∣  1  ∣  00…0k]=2kx \mathrel{\&} -x = [00\dots0 \;\vert\; 1 \;\vert\; 00\dots0_k] = 2^kx&−x=[00…0∣1∣00…0k​]=2k, isolating the lowest set bit (the fundamental primitive of Fenwick Trees).
Algebraic Invariant: F2w\mathbb{F}_2^wF2w​ XOR Vector Space & Submask Enumeration

Bitwise XOR (⊕\oplus⊕) is addition modulo 222 in the vector space F2w\mathbb{F}_2^wF2w​: it is commutative (a⊕b=b⊕aa \oplus b = b \oplus aa⊕b=b⊕a), associative (a⊕(b⊕c)=(a⊕b)⊕ca \oplus (b \oplus c) = (a \oplus b) \oplus ca⊕(b⊕c)=(a⊕b)⊕c), has identity 000 (a⊕0=aa \oplus 0 = aa⊕0=a), and every element is its own inverse (a⊕a=0a \oplus a = 0a⊕a=0). Consequently, XORing a stream where every element appears twice except one cancels all pairs to 000, leaving the unique element.

Even more remarkably, if two unique elements u≠vu \neq vu=v appear once while all others appear twice, the total XOR is S=u⊕v≠0S = u \oplus v \neq 0S=u⊕v=0. Extracting the lowest set bit lowbit=S&−Slowbit = S \mathrel{\&} -Slowbit=S&−S identifies a bit position where uuu and vvv provably differ—partitioning the stream into two disjoint subsets (those with lowbitlowbitlowbit set vs. clear) that isolate uuu and vvv in O(N)O(N)O(N) time and O(1)O(1)O(1) space!

Hardware Reality: Signed Overflow UB, INT_MIN Negation, and Shift Width Modulo Traps

In C and C++, signed integer overflow is Undefined Behavior (UB)—even though C++20 standardized two's-complement representation! Specifically:

  • Negating INT32_MIN (−231=0x80000000-2^{31} = \text{0x80000000}−231=0x80000000) in signed arithmetic overflows because +231+2^{31}+231 is unrepresentable in 32-bit signed two's complement (its bitwise negation +1+1+1 wraps back to 0x80000000). Always cast to an unsigned type (uint32_t / uint64_t) before applying 0u - ux or bit manipulation.
  • Shifting a www-bit integer by ≥w\ge w≥w bits (e.g., 1ULL << 64 or 1 << 32) is Undefined Behavior in C/C++, and on x86-64 the hardware SHL instruction masks the shift count to 636363 (or 313131), turning 1ULL << 64 into 1ULL << 0 == 1 instead of 0!

// Partition an array where two elements appear once and all others appear twice
std::pair<int, int> single_number_two_uniques(const std::vector<int>& nums) noexcept {
  std::uint32_t xor_all = 0;
  for (int x : nums) {
    xor_all ^= static_cast<std::uint32_t>(x);
  }
  // Isolate lowest differing bit using unsigned two's complement negation (safe for INT_MIN!)
  const std::uint32_t diff_bit = xor_all & (0u - xor_all);

  std::uint32_t group_a = 0, group_b = 0;
  for (int x : nums) {
    const auto ux = static_cast<std::uint32_t>(x);
    if ((ux & diff_bit) != 0) {
      group_a ^= ux;
    } else {
      group_b ^= ux;
    }
  }
  return {static_cast<int>(group_a), static_cast<int>(group_b)};
}

// Gosper's Hack: Compute next lexicographical bitmask with the exact same popcount
constexpr std::uint64_t next_combination_mask(std::uint64_t x) noexcept {
  const std::uint64_t c = x & (0ULL - x); // lowest set bit
  const std::uint64_t r = x + c;          // ripple carry through lowest block of 1s
  return (((r ^ x) >> 2) / c) | r;        // shift remaining 1s to the bottom
}

// Enumerate all submasks of all n-bit masks in exactly O(3^n) steps

Production Pitfall: C Operator Precedence of Bitwise &, ^, | vs. == and !=

By a notorious historical accident in early B and C (before && and || were separated from & and |), Dennis Ritchie gave relational and equality operators (==, !=, <, >) higher operator precedence than bitwise &, ^, and |. As a result, writing if (mask & bit != 0) is parsed by the compiler as if (mask & (bit != 0))—which evaluates mask & 1 and silently tests the wrong bit! Always parenthesize bitwise tests: if ((mask & bit) != 0), and always write 1ULL << k instead of 1 << k when k≥31k \ge 31k≥31.

Key Takeaways

In two's-complement arithmetic (-x == ~x + 1), x & (x - 1) clears the lowest set bit (BLSR) and x & -x isolates the lowest set bit (BLSI) in a single ALU cycle.
To avoid signed integer overflow UB on INT_MIN (-2^31), perform bitwise negation and bit hacks on unsigned types: ux & (0u - ux).
Iterating s = (s - 1) & mask visits only valid submasks of mask; summed over all 2^n masks, this takes sum C(n,k) 2^k = 3^n total operations instead of 4^n.
Always wrap bitwise masks in parentheses before equality comparisons ((x & mask) != 0) and use 1ULL << k to prevent 32-bit shift Undefined Behavior.
