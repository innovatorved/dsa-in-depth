Intuition first

Standard Dijkstra's algorithm is blind to the target's location: searching for a route from New York to Philadelphia expands a circular wave equally westward toward Ohio and eastward toward New Jersey. A Search (Hart, Nilsson & Raphael, 1968) orders the priority queue by f(u)=g(u)+h(u)f(u) = g(u) + h(u)f(u)=g(u)+h(u), combining the exact distance from the start g(u)g(u)g(u) with a heuristic estimate h(u)h(u)h(u) of the remaining distance to the target ttt.

The deepest mathematical insight of A is that a consistent heuristic is nothing more than a Johnson potential reweighting: running A* with priority g(u)+h(u)g(u) + h(u)g(u)+h(u) is algebraically identical to running standard Dijkstra on reduced edge weights wh(u,v)=w(u,v)−h(u)+h(v)≥0w_h(u, v) = w(u, v) - h(u) + h(v) \ge 0wh​(u,v)=w(u,v)−h(u)+h(v)≥0.

Production Implementation: A* Search on a Weighted Graph

C++2041 lines
#include <vector>
#include <queue>
#include <limits>
#include <functional>

struct AStarEdge {
    int to;
    long long weight;
};

long long astarShortestPath(int n, int start, int target,
                            const std::vector<std::vector<AStarEdge>>& adj,
                            const std::function<long long(int)>& heuristic) {
    constexpr long long INF = std::numeric_limits<long long>::max() / 4;
    std::vector<long long> gScore(n, INF);
    std::vector<uint8_t> closed(n, 0);

    using State = std::pair<long long, int>; // (fScore = g + h, u)
    std::priority_queue<State, std::vector<State>, std::greater<State>> openSet;

    gScore[start] = 0;
    openSet.emplace(heuristic(start), start);

    while (!openSet.empty()) {
        auto [f, u] = openSet.top();
        openSet.pop();

        if (u == target) return gScore[target];
        if (closed[u]) continue; // Sound and optimal when heuristic is consistent!
        closed[u] = 1;

        for (const auto& e : adj[u]) {
            long long tentativeG = gScore[u] + e.weight;
            if (tentativeG < gScore[e.to]) {
                gScore[e.to] = tentativeG;
                openSet.emplace(tentativeG + heuristic(e.to), e.to);
            }
        }
    }
    return -1; // Target unreachable
}
Failure Mode — Using Manhattan Distance on an 8-Directional Grid

On a grid where diagonal movement is allowed with cost 111 (or 2≈1.414\sqrt{2} \approx 1.4142​≈1.414), moving from (0,0)(0, 0)(0,0) to (1,1)(1, 1)(1,1) has true distance 111 (or 1.4141.4141.414), but Manhattan distance gives h=∣1−0∣+∣1−0∣=2>δh = |1 - 0| + |1 - 0| = 2 > \deltah=∣1−0∣+∣1−0∣=2>δ. Because Manhattan distance overestimates diagonal shortcuts, it is inadmissible on 8-way grids and can return suboptimal paths! Always match the norm to the allowed move set (L1L_1L1​ for 4-way, L∞L_\inftyL∞​ / Octile for 8-way, L2L_2L2​ for any-angle).

Key Takeaways

A heuristic h(u) is admissible if 0 <= h(u) <= dist(u, t), and consistent if h(u) <= w(u, v) + h(v) for every edge (u, v).
Consistency is mathematically equivalent to Johnson's potential reweighting w_h(u, v) = w(u, v) - h(u) + h(v) >= 0, proving that A* with a consistent heuristic never needs to re-expand a closed vertex.
Every vertex u with g(u) + h(u) < dist(s, t) must be expanded by A*, whereas vertices with g(u) + h(u) > dist(s, t) are pruned completely.
Never use L1 Manhattan distance on an 8-directional grid where diagonal moves cost less than 2, as it violates admissibility.
