Sublinear Average-Case Matching: Boyer-Moore Bad-Character/Good-Suffix & Horspool

7 min read Module 4.1: Tries, Exact String Matching & Multi-Pattern Automata Updated Oct 23, 2026
📄 Cheat Sheet
Ben Langmead Boyer-Moore String Search Algorithm Watch on YouTube ↗

Ben Langmead explains how scanning the pattern right-to-left while shifting the alignment window left-to-right yields O(N/M) average-case character comparisons.

Intuition first

Both KMP and the Z-algorithm inspect every single text byte at least once because they scan the pattern from left to right; if the last byte of an $M$-byte window does not even appear in the pattern, they still must read the preceding $M - 1$ bytes before discovering that fact. Boyer-Moore (1977) flips the inner comparison direction: it aligns the pattern at text offset $s$, compares characters from right to left ($j = M - 1$ down to $0$), and uses a mismatch at the rightmost end to leap the entire alignment window forward by up to $M$ bytes at once, achieving sublinear $O(N / M)$ average-case work on large alphabets.

In modern production code, full Boyer-Moore's complex Good-Suffix table is rarely worth its branch overhead. Instead, Boyer-Moore-Horspool (1980) drops the Good-Suffix table and indexes the Bad-Character shift exclusively by the text byte aligned with the last character of the pattern ($T[s + M - 1]$), which in turn enables vectorized SIMD pre-filters (memchr / AVX2 rare-byte scanning) that check 32 alignments per clock cycle.

1. Right-to-Left Comparison & The Two Shift Rules

Suppose pattern $P[0..M-1]$ is aligned at text offset $s$, so $P[j]$ sits above $T[s + j]$. We compare from $j = M - 1$ down to $0$. When a mismatch occurs at pattern index $j$ ($P[j] \neq T[s + j]$), we have already verified that the suffix $P[j+1..M-1]$ matches $T[s+j+1..s+M-1]$. Boyer-Moore takes the maximum shift proposed by two independent rules:

  • Bad-Character Rule: Let $c = T[s + j]$ be the mismatched text byte, and let $\text{last}[c]$ be the rightmost index in $P[0..M-2]$ where byte $c$ appears ($-1$ if absent). To align $T[s + j]$ with that occurrence in $P$, we shift the window right by $\Delta_{\text{bad}} = \max(1,\; j - \text{last}[c])$. If $c$ does not appear in $P$ at all, $\Delta_{\text{bad}} = j - (-1) = j + 1$; when the mismatch happens immediately at $j = M - 1$, the window leaps by a full $M$ bytes!
  • Good-Suffix Rule: Let $t = P[j+1..M-1]$ be the matched suffix before the mismatch. We shift $P$ right to align $T[s+j+1..s+M-1]$ with the rightmost earlier occurrence of $t$ in $P$ that is not preceded by the same mismatched character $P[j]$ (the strong good-suffix rule), or, if no full copy of $t$ exists inside $P$, with the longest prefix of $P$ that matches a suffix of $t$.

Combined with the Galil rule (which remembers matched prefixes across shifts so characters are never re-compared), full Boyer-Moore runs in $O(N + M)$ worst-case time (at most $3N$ comparisons on non-periodic patterns) and $O(N / M)$ average time.

2. Boyer-Moore-Horspool (BMH): Simplifying the Inner Loop

Nigel Horspool observed in 1980 that on natural alphabets ($|\Sigma| = 256$), the Bad-Character shift dominates the Good-Suffix shift almost everywhere, while computing and branching on two tables slows down the CPU pipeline. Horspool's algorithm always computes the shift using the text byte aligned with the last position of the pattern, $c_{\text{end}} = T[s + M - 1]$, regardless of where the mismatch occurred inside the window:

$$\text{shift}[c] = \begin{cases} M & \text{if } c \notin P[0..M-2] \\ M - 1 - \max\{k < M - 1 : P[k] = c\} & \text{otherwise} \end{cases}$$

Note that $P[M - 1]$ itself is deliberately excluded when building $\text{shift}[c]$ so that $\text{shift}[c] \ge 1$ is strictly guaranteed, preventing zero-length infinite loops.

Boyer-Moore-Horspool Safe-Shift Invariant

For any alignment offset $s$, let $c = T[s + M - 1]$. Every occurrence of $P$ in $T$ at any offset $s' > s$ must align some character $P[k] = c$ with $T[s + M - 1]$ whenever $s' \le s + M - 1$. Because $\text{shift}[c] = M - 1 - k_{\max}$ picks the largest index $k_{\max} < M - 1$ with $P[k_{\max}] = c$ (or $k_{\max} = -1$ if none exists), no valid match can exist in the open interval $(s,\; s + \text{shift}[c])$, and $\text{shift}[c] \ge 1$ ensures strict forward progress.

SIMD Two-Byte Guard Filter (AVX2 _mm256_cmpeq_epi8)

Even Horspool's $O(N / M)$ scalar skip loop suffers from a data-dependent branch and unpredicted memory load s += shift[T[s + M - 1]] every iteration. Modern standard libraries (glibc memmem, Rust memchr::memmem) select the two rarest bytes in $P$ at offsets $k_1, k_2$ (based on an empirical frequency table of English/UTF-8 bytes) and load 32 bytes at $T[i + k_1..i + k_1 + 31]$ and $T[i + k_2..i + k_2 + 31]$ into AVX2 registers. A single _mm256_cmpeq_epi8 + bitwise AND + _mm256_movemask_epi8 checks 32 candidate alignments simultaneously without branches, calling memcmp only when both rare bytes match.

4. Production Implementation: BMH with Rare-Byte Guard

#include <array>
#include <cstdint>
#include <cstring>
#include <string_view>
#include <vector>

// Boyer-Moore-Horspool with First+Last Character Guard before memcmp
std::vector<size_t> bmh_search(std::string_view text, std::string_view pat) {
    std::vector<size_t> matches;
    const size_t n = text.size(), m = pat.size();
    if (m == 0 || n < m) return matches;

    // 1. Precompute 256-entry Bad-Character shift table for pat[0 .. m-2]
    std::array<size_t, 256> shift;
    shift.fill(m);
    for (size_t k = 0; k + 1 < m; ++k) {
        shift[static_cast<uint8_t>(pat[k])] = m - 1 - k;
    }

    const uint8_t last_byte = static_cast<uint8_t>(pat[m - 1]);
    const uint8_t first_byte = static_cast<uint8_t>(pat[0]);

    // 2. Scan alignment windows with sublinear skips
    size_t s = 0;
    while (s <= n - m) {
        const uint8_t c_end = static_cast<uint8_t>(text[s + m - 1]);
        if (c_end == last_byte && static_cast<uint8_t>(text[s]) == first_byte) {
            if (m <= 2 || std::memcmp(text.data() + s + 1, pat.data() + 1, m - 2) == 0) {
                matches.push_back(s);
            }
        }
        s += shift[c_end];
    }
    return matches;
}
Adversarial Periodic Inputs & The $O(N \cdot M)$ Horspool Trap

Because Horspool drops the Good-Suffix and Galil rules, searching for $P = \texttt{"BAAAAA"}$ inside $T = \texttt{"AAAAAAAAAAAA..."}$ compares $M$ characters at every offset and then shifts by $\text{shift}[\texttt{'A'}] = 1$, degrading to $\Theta(N \cdot M)$ time! If input texts or patterns are untrusted (e.g., network packet inspection or web-exposed search endpoints), either track how many characters have been compared and fall back to a linear-time algorithm (like KMP or Two-Way string matching) whenever the ratio of comparisons to shift progress exceeds a constant threshold, or use full Boyer-Moore with Galil's rule.

Check yourself Question 1 of 4
Concept Check Why Horspool Excludes $P[M - 1]$ from the Shift Table recall

When building the 256-entry Bad-Character shift table for Boyer-Moore-Horspool on pattern $P[0..M-1]$, we initialize `shift[c] = M` for all $c$ and then loop `for (size_t k = 0; k < M - 1; ++k) shift[P[k]] = M - 1 - k;`.

Horspool always indexes the shift table by $c_{\text{end}} = T[s + M - 1]$. If the last character matches ($T[s + M - 1] == P[M - 1]$) and a mismatch occurs earlier at some $j < M - 1$ (or after a full match), we need to shift $P$ so that an *earlier* occurrence of $P[M - 1]$ in $P[0..M-2]$ aligns with $T[s + M - 1]$ (or shift by $M$ if $P[M - 1]$ never appears earlier). Including $k = M - 1$ would overwrite `shift[P[M - 1]]` with $0$.
Concept Check Tracing Boyer-Moore-Horspool Shifts apply

Consider searching for pattern $P = \texttt{"ABCB"}$ ($M = 4$) in text $T = \texttt{"ABXBCBABCB"}$. First compute Horspool's `shift` table over $P[0..2] = \texttt{"ABC"}$: `shift['A'] = 3`, `shift['B'] = 2`, `shift['C'] = 1`, and `shift[other] = 4`.

At $s = 0$, $T[3] = \texttt{'B'}$ matches $P[3]$, $T[2] = \texttt{'X'} \neq P[2]$; Horspool shifts by `shift[T[3]] = shift['B'] = 2` to $s = 2$. At $s = 2$, $T[2..5] = \texttt{"XBCB"}$, so $T[5] = \texttt{'B'}$ and we shift by `shift['B'] = 2` to $s = 4$. At $s = 4$, $T[4..7] = \texttt{"CBAB"}$, so $T[7] = \texttt{'B'}$ and we shift by `shift['B'] = 2` to $s = 6$, where $T[6..9] = \texttt{"ABCB"}$ matches!
Concept Check Worst-Case Pathological Input for Boyer-Moore-Horspool apply

Unlike full Boyer-Moore with the strong Good-Suffix and Galil rules, Boyer-Moore-Horspool uses only the Bad-Character shift of $T[s + M - 1]$.

When $P = \texttt{"baaa...a"}$ and $T = \texttt{"aaaa...a"}$, `shift['a'] = 1` because $\texttt{'a'}$ appears at $P[M - 2]$. At every alignment $s$, $P[M-1]$ down to $P[1]$ match $\texttt{'a'}$, $P[0] = \texttt{'b'}$ mismatches after $M$ comparisons, and $s$ advances by only $1$—resulting in $(N - M + 1) \cdot M = \Theta(N \cdot M)$ comparisons.
Concept Check Packed-Pair SIMD Guard Selection (`memchr::memmem`) staff

In Rust's `memchr::memmem` (used by `ripgrep`), single-substring search on AVX2 selects two pattern positions $k_1, k_2 \in [0, M-1]$ (`PackedPair`) and runs `_mm256_cmpeq_epi8` on 32-byte slices $T[s + k_1..s + k_1 + 31]$ and $T[s + k_2..s + k_2 + 31]$ before calling `memcmp`.

In a SIMD guard filter, the outer vectorized loop ALWAYS scans 32 bytes per step regardless of shift distance; its speed is bottlenecked only by how often the bitwise AND of the two `_mm256_cmpeq_epi8` masks produces a non-zero bit that triggers scalar verification. Selecting the two rarest bytes in $P$ minimizes false-positive hits.

Key Takeaways

Boyer-Moore scans the pattern from right to left (j = M - 1 down to 0) so a mismatch at the end of the window can skip up to M text positions at once, yielding O(N / M) average-case comparisons.
Boyer-Moore-Horspool indexes the Bad-Character shift exclusively by T[s + M - 1] and deliberately excludes P[M - 1] when building the shift table so that shift[c] >= 1 is always guaranteed.
Modern substring searchers combine Horspool's skip logic with SIMD 2-byte guard filters (_mm256_cmpeq_epi8) to inspect 32 candidate alignments per cycle, with a linear-time fallback to prevent O(N * M) periodic degradation.
