Consistent Hashing with Bounded Loads & Rendezvous (HRW) Hashing

Robert Morris and Frans Kaashoek explain how Karger's consistent hashing ring bounds key migration to O(K/N) during node churn and why virtual nodes are essential for load balance.

Intuition first

In a distributed cache or sharded database with NNN storage nodes, naive modular sharding node=hash(k) mod N\text{node} = \text{hash}(k) \bmod Nnode=hash(k)modN fails catastrophically whenever a node joins or leaves: changing N→N±1N \to N \pm 1N→N±1 alters hash(k) mod N\text{hash}(k) \bmod Nhash(k)modN for N−1N≈99%\frac{N-1}{N} \approx 99\%NN−1​≈99% of all keys, triggering a thundering herd of cache misses against the origin database. Consistent Hashing (Karger et al., STOC 1997) and Rendezvous / Highest Random Weight (HRW) Hashing (Thaler & Ravishankar, 1996) solve this by guaranteeing monotonicity and minimal disruption: when 1 of NNN nodes is added or removed, only an optimal fraction 1/N1/N1/N of keys move.

Even with V=O(log⁡N)V = O(\log N)V=O(logN) virtual nodes per physical server, traffic spikes (hot keys) can overload a single ring segment. Consistent Hashing with Bounded Loads (Mirrokni et al., Google 2017, deployed in Vimeo/HAProxy) enforces a strict capacity cap C=⌈(1+ϵ)WN⌉C = \lceil (1 + \epsilon) \frac{W}{N} \rceilC=⌈(1+ϵ)NW​⌉ per node, forwarding overflow keys clockwise along the ring while preserving O(1/ϵ2)O(1/\epsilon^2)O(1/ϵ2) expected probe hops.

Ring-Based Consistent Hashing vs Rendezvous (HRW) Hashing

Three algorithms dominate production traffic routing and shard assignment:

  • Karger's Ring with Virtual Nodes (VNodes): Map both keys and server replicas onto the 64-bit cyclic integer ring [0,264−1][0, 2^{64}-1][0,264−1]. Each physical server sis_isi​ places VVV virtual tokens h(si∥0),…,h(si∥V−1)h(s_i \mathbin{\|} 0), \dots, h(s_i \mathbin{\|} V-1)h(si​∥0),…,h(si​∥V−1) onto a sorted array or balanced BST (std::map). A key kkk routes to the first token clockwise with token≥h(k)\text{token} \ge h(k)token≥h(k) via std::lower_bound in O(log⁡(NV))O(\log(N V))O(log(NV)) time (wrapping around to index 000 if h(k)h(k)h(k) exceeds all tokens). Using V=150V = 150V=150 VNodes reduces load standard deviation to σ/μ≈1/150≈8%\sigma / \mu \approx 1/\sqrt{150} \approx 8\%σ/μ≈1/150​≈8%.
  • Consistent Hashing with Bounded Loads (Mirrokni et al., 2017): Given total active load WWW, number of nodes NNN, and slack parameter ϵ∈(0,1]\epsilon \in (0, 1]ϵ∈(0,1] (typically ϵ=0.25\epsilon = 0.25ϵ=0.25), each server is assigned a hard maximum capacity C=⌈(1+ϵ)W/N⌉C = \lceil (1 + \epsilon) W / N \rceilC=⌈(1+ϵ)W/N⌉. When a key hashes to its primary clockwise server, if that server's current load is <C< C<C, it accepts the key; otherwise the key walks clockwise to the next server with spare capacity.
  • Rendezvous / Highest Random Weight (HRW) Hashing: Requires zero ring state or VNode tables. To route key kkk across nodes {s1,…,sN}\{s_1, \dots, s_N\}{s1​,…,sN​}, compute a joint score wi=hash(k,si)w_i = \text{hash}(k, s_i)wi​=hash(k,si​) for each node and select s∗=arg⁡max⁡iwis^* = \arg\max_i w_is∗=argmaxi​wi​. Formal Specification: Karger Monotonicity & Bounded-Load Probe Theorem

Minimal Disruption Invariant: Let SSS be the set of active nodes and S′=S∪{snew}S' = S \cup \{s_{\text{new}}\}S′=S∪{snew​}. Under both Virtual-Node Ring Hashing and HRW Hashing, a key kkk changes assignment (fS′(k)≠fS(k)f_{S'}(k) \ne f_S(k)fS′​(k)=fS​(k)) if and only if fS′(k)=snewf_{S'}(k) = s_{\text{new}}fS′​(k)=snew​. No key ever migrates between two existing nodes si,sj∈Ss_i, s_j \in Ssi​,sj​∈S. Bounded-Load Forwarding Bound (Mirrokni et al., 2017): For any arrival sequence of WWW balls (even with arbitrary duplicate/hot keys), if each of the NNN bins has capacity C=⌈(1+ϵ)W/N⌉C = \lceil (1 + \epsilon) W / N \rceilC=⌈(1+ϵ)W/N⌉, the expected number of clockwise forwarding hops to locate a non-full bin is bounded by O(1/ϵ2)O(1 / \epsilon^2)O(1/ϵ2), independent of NNN and WWW.

Hardware Reality: Contiguous Sorted Array vs std::map for VNode Rings

With N=1,000N = 1{,}000N=1,000 backend servers and V=160V = 160V=160 virtual nodes per server, the ring contains 160,000160{,}000160,000 tokens. Storing the ring in a pointer-based std::map (Red-Black Tree) incurs ≈18\approx 18≈18 pointer-chasing hops across 7.6 MB of heap memory, costing ~1,200 ns per packet routed. Storing the 160,000160{,}000160,000 (token_u64, node_id_u32) pairs in a flat contiguous sorted std::vector (1.9 MB, fitting entirely inside L3 cache) allows std::lower_bound (or Eytzinger binary search) to route packets in ~45 ns—a 25×25\times25× speedup in L4/L7 load balancers like Envoy and Katran.

// C++20: Consistent Hashing with (1 + eps) Bounded Loads & Rendezvous (HRW) Hashing
#include <vector>
#include <cstdint>
#include <algorithm>
#include <cmath>

class BoundedConsistentHashRing {
    struct VNode {
        uint64_t token;
        uint32_t nodeId;
        bool operator<(const VNode& o) const noexcept { return token < o.token; }
    };

    std::vector<VNode> ring_;
    std::vector<uint32_t> loads_;
    uint32_t totalLoad_ = 0;
    double epsilon_;

    static uint64_t mix64(uint64_t x) noexcept {
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }

public:
    BoundedConsistentHashRing(uint32_t numNodes, uint32_t vnodesPerNode = 128, double eps = 0.25)
        : loads_(numNodes, 0), epsilon_(eps) {
        ring_.reserve(numNodes * vnodesPerNode);
        for (uint32_t n = 0; n < numNodes; ++n) {
            for (uint32_t v = 0; v < vnodesPerNode; ++v) {
                uint64_t seed = (static_cast<uint64_t>(n) << 32) | v;
                ring_.push_back({mix64(seed), n});
            }
        }
        std::sort(ring_.begin(), ring_.end());
    }

    uint32_t acquireRoute(uint64_t key) {
        const uint32_t N = static_cast<uint32_t>(loads_.size());
        const uint32_t cap = static_cast<uint32_t>(
            std::ceil((1.0 + epsilon_) * static_cast<double>(totalLoad_ + 1) / N)
        );

        uint64_t h = mix64(key);
        auto it = std::lower_bound(ring_.begin(), ring_.end(), VNode{h, 0});
        size_t idx = (it == ring_.end()) ? 0 : static_cast<size_t>(it - ring_.begin());

        for (size_t probes = 0; probes < ring_.size(); ++probes) {
            uint32_t candidate = ring_[idx].nodeId;
            if (loads_[candidate] < cap) {
                ++loads_[candidate];
                ++totalLoad_;
                return candidate;
            }
            idx = (idx + 1 == ring_.size()) ? 0 : idx + 1;
        }
        return ring_[idx].nodeId;
    }

    // Stateless Rendezvous (HRW) Hashing: O(N) time, O(1) auxiliary space
    static uint32_t rendezvousSelect(uint64_t key, const std::vector<uint32_t>& activeNodes) noexcept {
        uint32_t bestNode = 0;
        uint64_t maxWeight = 0;
        for (uint32_t nodeId : activeNodes) {
            uint64_t w = mix64(key ^ mix64(nodeId));
            if (w >= maxWeight) {
                maxWeight = w;
                bestNode = nodeId;
            }
        }
        return bestNode;
    }
};

Failure Modes & Adversarial Pitfalls

  • Correlated Key Hash and VNode Hash Functions: If you use the exact same unseeded hash function to map keys onto the ring AND to shard keys inside the local hash table on the target server, every key assigned to virtual node vvv falls into a narrow sub-interval of the 64-bit hash space—causing severe clustering inside the server's local hash table! Always use independent seeds for ring routing vs local bucket indexing.
  • Forgetting Wrap-Around when lower_bound Returns ring.end(): Any key whose hash exceeds the largest token on the ring belongs to ring[0], closing the circle [0,264−1][0, 2^{64}-1][0,264−1].
Check yourself Question 1 of 4
Concept Check Key Disruption Fraction in Consistent Hashing vs Modulo Sharding recall

When a cluster of N cache servers scales from N to N + 1 nodes, approximately what fraction of keys must be remapped to a different server under naive `hash(k) mod N` sharding versus Karger's Consistent Hashing?

Under `hash(k) mod N`, changing the modulus to N+1 shifts the remainder for almost all keys (only ~1/(N+1) happen to stay on the same index). Consistent Hashing preserves monotonicity: only keys landing in the new node's ring arcs (1/(N+1) of the ring) move.
Concept Check Role of Virtual Nodes (VNodes) on the Consistent Hashing Ring apply

If each of the N physical servers is placed at only a single random point (V = 1) on the 2^64 Consistent Hashing ring, what problem occurs, and how does assigning V = Θ(log N) virtual tokens per server resolve it?

Placing N random points on a circle creates highly uneven arc lengths (the max arc is Θ(log N / N) w.h.p.). Assigning V = 100–200 virtual tokens per physical server sums V small random arcs per server, concentrating each server's share tightly around 1/N by the Central Limit Theorem.
Concept Check Rendezvous (Highest Random Weight / HRW) Hashing Mechanics apply

How does Rendezvous (Highest Random Weight) Hashing route a key `k` across a set of active servers `{s_1, s_2, ..., s_N}` without maintaining a ring of virtual nodes?

In HRW hashing, `argmax_{i} hash(k, s_i)` is uniformly distributed over the N servers with zero VNode tables, and sorting the weights gives a natural deterministic primary/secondary/tertiary replica preference list.
Concept Check Consistent Hashing with Bounded Loads under Zipfian / Hot-Key Skew staff

Why do Virtual Nodes (VNodes) alone fail to prevent server overload when a single 'celebrity' key receives 30% of all cluster requests, and how does Consistent Hashing with Bounded Loads (Mirrokni et al., 2017) handle capacity enforcement?

VNodes only make the ring *arcs* uniform in length; they cannot split a point mass (hot key) that hashes to a single coordinate `h(k)`. Bounded-load consistent hashing caps each node at `⌈(1+ε)W/N⌉` and spills excess load clockwise along the ring.

Key Takeaways

Modular sharding hash(k) mod N remaps (N-1)/N of all keys when N changes by 1; Consistent Hashing and Rendezvous Hashing move only an optimal 1/N fraction of keys.
Placing V = Θ(log N) virtual nodes per physical server on the 2^64 ring reduces partition size variance to σ/μ ≈ 1/√V and enables heterogeneous hardware weighting.
Consistent Hashing with Bounded Loads caps every node at ⌈(1 + ε)W/N⌉ active requests and spills overflow keys clockwise in O(1/ε^2) expected steps.
Rendezvous (HRW) Hashing computes argmax_i hash(key, node_i) to achieve zero-VNode uniform load distribution and natural top-k replica ordering in O(N) time.
