Lab Architecture & Design Specification

Textbook sorting algorithms optimize for a single regime: Insertion Sort wins for N≤32N \le 32N≤32, Merge Sort guarantees stability and Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN) worst-case comparisons, and Exponential Galloping wins when merging clustered runs. In this lab (corresponding to the interactive workbench build-hybrid-introsort-timsort), we engineer a self-contained C++20 HybridAdaptiveSort engine that unifies all four stages:

  1. Stage 1 — Dynamic compute_minrun(n): Shifts nnn right until n∈[32,64)n \in [32, 64)n∈[32,64), setting the lowest bit to 111 if any shifted-out bit was 111, so ⌈N/minrun⌉\lceil N / \text{minrun} \rceil⌈N/minrun⌉ is close to or slightly below a power of two.
  2. Stage 2 — Stability-Safe Run Scanner (count_run_and_make_ascending): Scans from lo: if A[lo+1]<A[lo]A[lo+1] < A[lo]A[lo+1]<A[lo], continues scanning while A[i]<A[i−1]A[i] < A[i-1]A[i]<A[i−1] (strictly descending) and reverses the slice in-place; otherwise scans while A[i]≥A[i−1]A[i] \ge A[i-1]A[i]≥A[i−1] (non-decreasing).
  3. Stage 3 — Binary Insertion Extension: If the natural run length is <minrun< \text{minrun}<minrun, uses Binary Insertion Sort starting at the end of the already-sorted prefix lo + run_len to extend the run to min⁡(n−lo,minrun)\min(n - lo, \text{minrun})min(n−lo,minrun).
  4. Stage 4 — Smaller-Half Galloping Merge & 4-Condition Stack Collapse: Maintains the corrected 4-condition TimSort invariant (De Gouw et al. fix) and merges adjacent runs by copying only the smaller run into a reusable scratch buffer.
The Corrected 4-Condition Run Stack Invariant

Let the run stack hold sss runs with lengths L[0],L[1],…,L[s−1]L[0], L[1], \dots, L[s-1]L[0],L[1],…,L[s−1] from bottom to top. After pushing a new run, we repeatedly merge until all three of the following conditions hold (preventing the 2015 TimSort bug):

  1. If s≥3s \ge 3s≥3: L[s−3]>L[s−2]+L[s−1]L[s-3] > L[s-2] + L[s-1]L[s−3]>L[s−2]+L[s−1]
  2. If s≥4s \ge 4s≥4: L[s−4]>L[s−3]+L[s−2]L[s-4] > L[s-3] + L[s-2]L[s−4]>L[s−3]+L[s−2] (the De Gouw fix checking one level deeper!)
  3. If s≥2s \ge 2s≥2: L[s−2]>L[s−1]L[s-2] > L[s-1]L[s−2]>L[s−1]

Whenever any condition fails, we merge run s−2s-2s−2 with whichever of s−3s-3s−3 or s−1s-1s−1 is shorter.

Hardware Reality: Why Binary Insertion Sort Beats Linear Insertion Sort for minrun Extension

When extending a natural run of length rrr up to minrun∈[32,64]\text{minrun} \in [32, 64]minrun∈[32,64], the first rrr elements are already sorted. Using binary search to locate the insertion point for element iii takes at most ⌈log⁡264⌉=6\lceil \log_2 64 \rceil = 6⌈log2​64⌉=6 comparisons (instead of up to 64 in linear Insertion Sort)—a crucial win when comparing composite structs, strings, or user-defined comparator closures—while moving the suffix via std::move_backward compiles to a single vectorized memmove over L1-resident cache lines.

#include <algorithm>
#include <concepts>
#include <cstddef>
#include <utility>
#include <vector>

template <std::totally_ordered T>
class HybridAdaptiveSort {
public:
    static void sort(std::vector<T>& a) {
        const std::size_t n = a.size();
        if (n <= 1) return;
        if (n < 32) {
            binary_insertion_sort(a.data(), 0, n, 1);
            return;
        }

        const std::size_t minrun = compute_minrun(n);
        std::vector<Run> stack;
        stack.reserve(48);
        std::vector<T> tmp;

        std::size_t lo = 0;
        while (lo < n) {
            std::size_t run_len = count_run_and_make_ascending(a.data(), lo, n);
            if (run_len < minrun) {
                const std::size_t force = std::min(minrun, n - lo);
                binary_insertion_sort(a.data(), lo, lo + force, lo + run_len);
                run_len = force;
            }
            stack.push_back({lo, run_len});
            lo += run_len;
            merge_collapse(a.data(), stack, tmp);
        }
        while (stack.size() > 1) {
            std::size_t k = stack.size() - 2;
            if (k > 0 && stack[k - 1].len < stack[k + 1].len) --k;
            merge_at(a.data(), stack, k, tmp);
        }
    }

private:
    struct Run { std::size_t base, len; };

    static constexpr std::size_t compute_minrun(std::size_t n) noexcept {
        std::size_t r = 0;
        while (n >= 64) {
            r |= (n & 1U);
            n >>= 1U;
        }
        return n + r;
    }

    static std::size_t count_run_and_make_ascending(T* a, std::size_t lo, std::size_t hi) noexcept {
        if (lo + 1 == hi) return 1;
        std::size_t run_hi = lo + 2;
        if (a[lo + 1] < a[lo]) { // Strictly descending: safe to reverse without breaking stability
            while (run_hi < hi && a[run_hi] < a[run_hi - 1]) ++run_hi;
            std::reverse(a + lo, a + run_hi);
        } else { // Non-decreasing: !(a[i] < a[i-1])
            while (run_hi < hi && !(a[run_hi] < a[run_hi - 1])) ++run_hi;
        }
        return run_hi - lo;
    }

    static void binary_insertion_sort(T* a, std::size_t lo, std::size_t hi, std::size_t start) noexcept {
        if (start == lo) ++start;
        for (std::size_t i = start; i < hi; ++i) {
            T pivot = std::move(a[i]);
            std::size_t left = lo, right = i;
            while (left < right) {
                const std::size_t mid = left + ((right - left) >> 1);
                if (pivot < a[mid]) right = mid;
                else                left = mid + 1;
            }
            std::move_backward(a + left, a + i, a + i + 1);
            a[left] = std::move(pivot);
        }
    }

    // Corrected 4-condition TimSort invariant (De Gouw et al., 2015)
    static void merge_collapse(T* a, std::vector<Run>& s, std::vector<T>& tmp) {
        while (s.size() > 1) {
            std::size_t n = s.size() - 2;
            if ((n > 0 && s[n - 1].len <= s[n].len + s[n + 1].len) ||
                (n > 1 && s[n - 2].len <= s[n - 1].len + s[n].len)) {
                if (s[n - 1].len < s[n + 1].len) --n;
                merge_at(a, s, n, tmp);
            } else if (s[n].len <= s[n + 1].len) {
                merge_at(a, s, n, tmp);
            } else {
                break;
            }
        }
    }

    static void merge_at(T* a, std::vector<Run>& s, std::size_t k, std::vector<T>& tmp) {
        std::size_t base1 = s[k].base, len1 = s[k].len;
        std::size_t base2 = s[k + 1].base, len2 = s[k + 1].len;
        s[k].len = len1 + len2;
        s.erase(s.begin() + static_cast<std::ptrdiff_t>(k + 1));

        // Trim prefix of Run 1 already <= a[base2]
        const T* p1 = a + base1;
        const T* p1_end = std::upper_bound(p1, p1 + len1, a[base2]);
        const std::size_t skip_left = static_cast<std::size_t>(p1_end - p1);
        base1 += skip_left;
        len1 -= skip_left;
        if (len1 == 0) return;

        // Trim suffix of Run 2 already >= a[base1 + len1 - 1]
        const T* p2 = a + base2;
        const T* p2_end = std::lower_bound(p2, p2 + len2, a[base1 + len1 - 1]);
        len2 = static_cast<std::size_t>(p2_end - p2);
        if (len2 == 0) return;

        // Smaller-half copy merge
        if (len1 <= len2) {
            tmp.assign(std::make_move_iterator(a + base1), std::make_move_iterator(a + base1 + len1));
            std::size_t i = 0, j = base2, dst = base1;
            while (i < len1 && j < base2 + len2) {
                if (a[j] < tmp[i]) a[dst++] = std::move(a[j++]);
                else               a[dst++] = std::move(tmp[i++]);
            }
            while (i < len1) a[dst++] = std::move(tmp[i++]);
        } else {
            tmp.assign(std::make_move_iterator(a + base2), std::make_move_iterator(a + base2 + len2));
            std::ptrdiff_t i = static_cast<std::ptrdiff_t>(base1 + len1) - 1;
            std::ptrdiff_t j = static_cast<std::ptrdiff_t>(len2) - 1;
            std::ptrdiff_t dst = static_cast<std::ptrdiff_t>(base2 + len2) - 1;
            while (i >= static_cast<std::ptrdiff_t>(base1) && j >= 0) {
                if (tmp[j] < a[i]) a[dst--] = std::move(a[i--]);
                else               a[dst--] = std::move(tmp[j--]);
            }
            while (j >= 0) a[dst--] = std::move(tmp[j--]);
        }
    }
};
Right-to-Left Merge Tie-Breaking Must Remain Stable!

Look closely at the right-to-left merge branch when len2 < len1: we compare if (tmp[j] < a[i]) and move a[i--] only when a[i] is strictly greater than tmp[j]! If a[i] == tmp[j], the element from Run 2 (tmp[j]) originated to the right of Run 1, so when filling from the back (dst--), tmp[j] must be placed at the rightmost slot first to preserve relative stability!

Check yourself Question 1 of 4
Concept Check Boundary Trimming Before Allocating the Temporary Merge Buffer recall

In `HybridAdaptiveSort::merge_at`, Run 1 is `A[base1 .. base1 + len1 - 1]` and Run 2 is `A[base2 .. base2 + len2 - 1]`. Before copying anything to `tmp`, we find `skip_left = upper_bound(Run1, A[base2])` and `len2 = lower_bound(Run2, A[base1 + len1 - 1])`.

If an element at the start of Run 1 equals `A[base2]`, stability dictates that Run 1's copy must stay *before* `A[base2]`—so it is already in its final position (`upper_bound` skips `<= A[base2]`). Symmetrically, if an element at the end of Run 2 equals `A[last1]`, stability dictates that Run 2's copy must stay *after* `A[last1]` (`lower_bound` trims from the first element `>= A[last1]` onward).
Concept Check Stability in Right-to-Left Smaller-Half Merging apply

When merging Run 1 (`len1 = 500`) and Run 2 (`len2 = 80`), `len2 < len1`, so `merge_at` copies only Run 2 into `tmp[0..79]` and merges backwards from the right end (`dst = base2 + len2 - 1`, `i = base1 + len1 - 1`, `j = len2 - 1`).

In a left-to-right merge (`dst++`), equal elements take from Run 1 first so Run 1 sits at the smaller index. In a right-to-left merge (`dst--`), we are filling the *largest* indices first! Therefore, on a tie (`!(tmp[j] < a[i])`), the element from Run 2 (`tmp[j]`) must take the larger index (`a[dst--] = std::move(tmp[j--])`), leaving the smaller index for Run 1 (`a[i]`).
Concept Check Why `binary_insertion_sort` Accepts a `start` Offset apply

In `HybridAdaptiveSort::sort`, after `count_run_and_make_ascending` finds a natural run of length `run_len = 12` (which is `< minrun = 36`), it calls `binary_insertion_sort(a, lo, lo + 36, lo + 12)`.

The natural run detector already established that `a[lo .. lo + run_len - 1]` is monotonically non-decreasing. Starting the insertion extension at `lo + run_len` reuses that natural sorted prefix as the initial binary search range for zero extra comparisons.
Concept Check Worst-Case Scratch Buffer Allocation Bound in `HybridAdaptiveSort` staff

During the execution of `HybridAdaptiveSort::sort` on an array of NNN elements, `merge_at` resizes `tmp` to `std::min(len1, len2)`.

Because `merge_at` only copies the smaller of the two runs being merged (`min(len1, len2)`), even the final top-level merge of two runs summing to N copies at most `⌊N / 2⌋` elements. Moreover, because `tmp` is lazily resized *after* `upper_bound` / `lower_bound` boundary trimming, inputs consisting of concatenated non-overlapping sorted segments never allocate a single byte of heap memory!
