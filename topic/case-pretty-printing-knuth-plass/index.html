Intuition first

Why do paragraphs typeset in LaTeX look like a master printer crafted them, while greedy word-wrappers create hideous 'rivers' of stretched whitespace? Because greedy wrapping packs each line to the brim until a long word overflows, leaving the previous line sparse. Knuth and Plass (1981) formulated paragraph justification as a Shortest Path DAG where vertices are word boundaries, edges are candidate lines, and edge weights are cubic/quadratic 'badness' penalties.

1. Why Greedy Word Wrapping Fails & The Knuth-Plass Badness Function

Given nnn words of widths w0,w1,…,wn−1w_0, w_1, \dots, w_{n-1}w0​,w1​,…,wn−1​ and target line width LLL, a greedy line breaker (used in basic web browsers and early word processors) packs words onto the current line until the next word exceeds LLL. This local myopia often packs 99%99\%99% of lines tightly and then encounters a long URL or technical identifier, leaving a massive gap on the preceding line.

In 1981, Donald Knuth and Michael Plass revolutionized digital typography in TeX\TeXTE​X by optimizing global paragraph demerits across all lines simultaneously:

2. From TeX\TeXTE​X Paragraphs to Code Formatters (prettier, clang-format, rustfmt)

Modern source code formatters (clang-format, Wadler/Oppen pretty-printers in prettier and rustfmt) extend Knuth-Plass from flat word arrays to Abstract Syntax Trees (ASTs):

  • Each token break has a syntactic penalty weight (breaking after a , or ; is cheap; breaking inside a + b is expensive) and an indentation level III.
  • Because indentation changes the remaining line budget L−IL - IL−I for subsequent tokens, the state in clang-format is (token_index, column_offset, paren_stack_state) explored via Dijkstra / A∗A^*A∗ on the formatting DAG.

4. Reference C++20 Implementation

#include <algorithm>
#include <cstdint>
#include <string>
#include <vector>

struct LineBreakPlan {
    long long total_demerits;
    // Pairs of [start_word_idx, end_word_idx_exclusive) for each formatted line
    std::vector<std::pair<int, int>> lines;
};

// Knuth-Plass Optimal Paragraph Line Breaking with Cubic Badness Penalty
LineBreakPlan knuth_plass_line_break(const std::vector<int>& word_widths, int line_width) {
    const int n = static_cast<int>(word_widths.size());
    if (n == 0) return { 0, {} };

    std::vector<int> pref(n + 1, 0);
    for (int i = 0; i < n; ++i) pref[i + 1] = pref[i] + word_widths[i];

    auto line_len = [&](int i, int j) -> int {
        return (pref[j] - pref[i]) + (j - 1 - i);
    };

    constexpr long long INF = 1LL << 60;
    std::vector<long long> dp(n + 1, INF);
    std::vector<int> next_break(n + 1, n);
    dp[n] = 0;

    // Evaluate suffixes i = n-1 down to 0
    for (int i = n - 1; i >= 0; --i) {
        for (int j = i + 1; j <= n; ++j) {
            int width = line_len(i, j);
            if (width > line_width) {
                // Only exception: a single word wider than line_width must still be placed on its own line
                if (j == i + 1) {
                    dp[i] = dp[j];
                    next_break[i] = j;
                }
                break; // Monotonicity of width: no larger j can ever fit on this line!
            }
            long long slack = line_width - width;
            // Last line (j == n) has 0 badness penalty in standard typography
            long long badness = (j == n) ? 0LL : (slack * slack * slack);
            if (badness + dp[j] < dp[i]) {
                dp[i] = badness + dp[j];
                next_break[i] = j;
            }
        }
    }

    // Reconstruct optimal line breaks from parent pointers <code>next_break</code>
    LineBreakPlan plan{ dp[0], {} };
    for (int cur = 0; cur < n; cur = next_break[cur]) {
        plan.lines.emplace_back(cur, next_break[cur]);
    }
    return plan;
}

Production Pitfall — Penalizing the Final Line (j=nj = nj=n) or Crashing on Overlong Words (wi>Lw_i > Lwi​>L)

In real-world typesetting and code formatting, two edge cases must be handled explicitly: First, the final line of a paragraph (j=nj = nj=n) is ragged-right and should incur 000 badness penalty for leftover slack (otherwise the solver will artificially pull words down from earlier lines just to pad the last line!). Second, if a single word or URL has wi>Lw_i > Lwi​>L, breaking immediately when width > line_width at j=i+1j = i + 1j=i+1 leaves dp[i] = INF; a production formatter must allow single overfull tokens (j=i+1j = i + 1j=i+1) as a fallback.

Key Takeaways

Knuth-Plass line breaking formulates paragraph justification as a DAG shortest path problem over word boundaries with quadratic or cubic slack penalties.
Terminating the inner loop as soon as W(i, j) > L reduces runtime from O(N^2) to O(N * max_words_per_line), which is O(N) for standard column widths.
The final line of a paragraph (j == n) has 0 slack penalty so earlier lines are not distorted to pad the last line.
Modern code formatters (clang-format, prettier, rustfmt) generalize Knuth-Plass to AST token streams with syntax-weighted break demerits and indentation states.
