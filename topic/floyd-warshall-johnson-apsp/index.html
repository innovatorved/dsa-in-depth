All-Pairs Shortest Paths: Floyd-Warshall DP Transitive Closure & Johnson's Potential Reweighting

7 min read Module 5.2: Disjoint Sets, Minimum Spanning Trees & Shortest Paths Updated Oct 23, 2026
📄 Cheat Sheet
William Fiset Floyd-Warshall All-Pairs Shortest Path Algorithm Watch on YouTube ↗

Explains the intermediate-vertex DP state transition and negative cycle detection on the matrix diagonal.

Intuition first

When an application needs shortest-path distances between every pair of vertices $(u, v) \in V \times V$, the optimal algorithm depends on graph density and negative edge weights. On dense graphs ($V \le 500$), Floyd-Warshall's $O(V^3)$ DP consists of three tight nested loops with virtually zero constant-factor overhead.

On sparse graphs with negative edge weights (but no negative cycles), running Bellman-Ford from every vertex takes $O(V^2 E)$ time. Johnson's Algorithm (1977) solves sparse All-Pairs Shortest Paths in $O(V E + V^2 \log V)$ by running Bellman-Ford once to compute vertex potentials $h(v)$ that shift every edge weight to be non-negative ($w_h(u, v) \ge 0$) without altering shortest paths, then running $V$ fast passes of Dijkstra!

1. Floyd-Warshall: Intermediate Vertex Set Induction

Define $d^{(k)}[i][j]$ as the minimum weight of any path from $i$ to $j$ whose intermediate vertices belong strictly to the prefix set $\{0, 1, \dots, k\}$. Considering whether vertex $k$ is used as an intermediate stop along the shortest path from $i$ to $j$ yields the recurrence:

$$d^{(k)}[i][j] = \min\Big(d^{(k-1)}[i][j],\; d^{(k-1)}[i][k] + d^{(k-1)}[k][j]\Big)$$
Formal Invariant — Why $k$ Must Be the Outermost Loop & In-Place Space Compression

Why can we overwrite a single 2D matrix $d[i][j]$ in-place without corrupting phase $k$'s dependencies? Notice that during phase $k$, $d[i][j]$ reads $d[i][k]$ and $d[k][j]$. In phase $k$ itself, $d[i][k]$ is updated to $\min(d[i][k], d[i][k] + d[k][k])$. As long as no negative cycle passes through $k$ ($d[k][k] \ge 0$), $d^{(k)}[i][k] == d^{(k-1)}[i][k]$ and $d^{(k)}[k][j] == d^{(k-1)}[k][j]$! Thus in-place updates are exact.

Negative Cycle Detection: A vertex $u$ lies on a negative cycle if and only if after completion (or during execution) its diagonal entry satisfies $d[u][u] < 0$.

2. Johnson's Potential Reweighting Theorem (1977)

How can we eliminate negative edge weights without changing which path between $u$ and $v$ is shortest? (Simply adding a constant $+C$ to every edge is a classic blunder: it penalizes a 5-edge path by $+5C$ and a 2-edge path by $+2C$, changing the optimal path!)

Instead, assign every vertex $v \in V$ a scalar potential $h(v) \in \mathbb{R}$ and define the reweighted edge cost:

$$w_h(u, v) = w(u, v) + h(u) - h(v)$$

Along any path $P = \langle v_0, v_1, \dots, v_k \rangle$ from $v_0 = u$ to $v_k = v$, the intermediate potentials telescope and cancel completely:

$$w_h(P) = \sum_{i=1}^k \big(w(v_{i-1}, v_i) + h(v_{i-1}) - h(v_i)\big) = w(P) + h(u) - h(v)$$

Because $h(u) - h(v)$ depends only on the endpoints $(u, v)$ and not on the path $P$, every path from $u$ to $v$ shifts by the exact same constant $h(u) - h(v)$! To guarantee $w_h(u, v) \ge 0$ for all $(u, v) \in E$, we need $h(v) - h(u) \le w(u, v)$—which is satisfied by setting $h(v) = \delta(s^*, v)$ from a single Bellman-Ford run starting at a virtual super-source $s^*$!

Hardware Reality — Auto-Vectorization & Cache Row-Major Access in Floyd-Warshall

In Floyd-Warshall's loop order for k ... for i ... for j, the inner loop over j streams sequentially across row d[i][0..V-1] and row d[k][0..V-1] while holding d[i][k] in a scalar register. Compilers (-O3 -mavx2) auto-vectorize this inner loop using VPMINSD / VPADDD SIMD instructions, processing 8 distances per clock cycle!

Production Implementation: Floyd-Warshall & Johnson's Potential Reweighting

#include <vector>
#include <algorithm>
#include <limits>

void floydWarshall(int n, std::vector<std::vector<long long>>& dist) {
    constexpr long long INF = std::numeric_limits<long long>::max() / 4;
    for (int k = 0; k < n; ++k) {
        for (int i = 0; i < n; ++i) {
            if (dist[i][k] >= INF) continue; // Crucial overflow guard + branch skip!
            for (int j = 0; j < n; ++j) {
                if (dist[k][j] < INF) {
                    dist[i][j] = std::min(dist[i][j], dist[i][k] + dist[k][j]);
                }
            }
        }
    }
}
Failure Mode — Writing for i ... for j ... for k in Floyd-Warshall

Permuting the loops of Floyd-Warshall to place k on the inside (for i ... for j ... for k) is one of the most notorious bugs in competitive and production programming: it only considers paths of length $\le 2$ (single intermediate hop $i \to k \to j$) or corrupts transitive dependencies across multi-hop paths! The intermediate vertex k must always be the outermost loop.

Concept Check Why Intermediate Vertex k Must Be the Outer Loop recall
Section: Floyd-Warshall Loop Order

In Floyd-Warshall's triple nested loop, why must the intermediate vertex `k` be the outermost loop (`for k ... for i ... for j`) rather than the innermost loop?

If `k` is placed innermost (`for i, for j, for k`), computing `dist[i][j]` only concatenates two paths `i ~> k` and `k ~> j` whose own intermediate vertices were not yet relaxed through larger `k'`.
Concept Check Detecting Negative Cycles in the Distance Matrix apply
Section: Negative Cycles in Floyd-Warshall

After running Floyd-Warshall on a graph with $V$ vertices, how do you check whether the graph contains a negative-weight cycle?

`dist[i][i]` initialized to 0 represents the minimum weight of a non-trivial cycle starting and ending at vertex `i`; `dist[i][i] < 0` iff `i` lies on (or can traverse) a negative cycle.
Concept Check Recovering Original Distances After Potential Reweighting apply
Section: Johnson's Algorithm

In Johnson's algorithm, Bellman-Ford computes potentials $h(v)$ from a super-source, edges are reweighted to $w'(u, v) = w(u, v) + h(u) - h(v) \ge 0$, and Dijkstra computes reweighted shortest distances $d'(u, v)$. How is the true distance $d(u, v)$ in the original graph recovered?

Because `d'(u, v) = d(u, v) + h(u) - h(v)` by telescoping along any u->v path, subtracting `h(u) - h(v)` yields `d(u, v) = d'(u, v) - h(u) + h(v)`.
Concept Check Asymptotic Crossover Between Floyd-Warshall and Johnson's Algorithm staff
Section: Sparse vs Dense APSP

On a sparse graph with negative edge weights (no negative cycles) where $V = 4{,}000$ and $E = 12{,}000$, how do the operation counts of Floyd-Warshall ($O(V^3)$) and Johnson's Algorithm ($O(VE + V(V+E)\log V)$) compare?

When E = O(V), Johnson's algorithm runs one O(V^2) Bellman-Ford pass plus V runs of O(V log V) Dijkstra = O(V^2 log V), saving a full factor of V / log V ≈ 330x over O(V^3).

Key Takeaways

Floyd-Warshall relaxes paths by expanding the allowed set of intermediate vertices {0..k}; therefore k must always be the outermost loop.
Adding a uniform constant +C to every edge alters shortest paths because paths with more edges are penalized more heavily.
Johnson's reweighting w_h(u, v) = w(u, v) + h(u) - h(v) telescopes along every u->v path to shift all path weights by the same constant h(u) - h(v), preserving shortest paths while making all edge weights non-negative.
After Floyd-Warshall finishes, vertex u belongs to a negative cycle if and only if dist[u][u] < 0.
